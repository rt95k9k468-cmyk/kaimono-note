# 📗 くらしノート

暮らしのことを一冊に。**やること（Todo）**、**買うもの**、
**「この洗剤はどのお店が一番安いか」**、そして **からだ（ダイエット）** の記録が、
同じアプリの中にあります。

> もとの名前は「かいものノート」でした。買い物だけのアプリではなくなったので、
> 名前とアイコンを変えています。データの保存先（`kaimono-note-v2`）はそのままなので、
> 入れてある中身は何も失われません。

ビルド不要・サーバー不要のPWA。スマホのブラウザから「ホーム画面に追加」すると、
ふつうのアプリと同じように起動でき、電波がなくても使えます。

---

## できること

### やること（Todo）

左のタブで、**アプリを開くとここから始まります**。手に取ったときの
問いは「何を買うんだっけ」より「今日なにをするんだっけ」のほうが多いので。
買い物は、お店に着いてから一押しで開けます。

- 下の**＋**から追加。**押した瞬間から打てます**（キーボードも一緒に上がります）。
  iOSがキーボードを出すのは「タップと同じ一拍のうちに入力欄へ移ったとき」だけ
  なので、一拍でも遅らせるとカーソルだけが点滅して、もう一度タップする羽目に
  なります。買うものタブの＋も同じです。
  やること・**いつまでに**・**時刻**・**くりかえし**・★・メモを一枚で。**シートの中の選択肢は折り返して全部見えます**——横に流れる並びだと、
  390pxの画面では「1か月後」と「なし」が右の外に隠れていました。
  **日付と時刻の欄も画面に収まります**——Safariはこの二つを「入れ物」ではなく
  「描きたい部品」の大きさで作るので、iPhoneでは日付欄が右にはみ出していました。
  部品づくりを止めさせて（`appearance: none`）ただの箱に戻し、消えるカレンダーの
  絵は自前で描き足しています
- 日付は**今日 / 明日 / 明後日 / 明々後日 / 1週間後 / 1か月後 / なし**から一押し。
  ほかの日はカレンダーから。**最初から「今日」が入っています**——日付なしで
  足すと「いつか」の棚に落ち、そこは見に行かないと目に入らないので
  （その場で外せます）
- **画面のいちばん上に、その月のカレンダー**があります。**今日は赤く塗った丸**。
  **下までスクロールしても消えません**（上のバーの下に貼りつき、そのぶん
  一段小さくなります）。そして**スクロールに合わせて月が変わります**
  ——9月の棚まで下りればカレンダーも9月に。逆に ‹ › や左右のフリックで
  月を変えれば、下のリストもその月の頭まで動きます。同じ場所を、上と下の
  二つの描き方で見ているだけにしたいので。
  （その月の棚がまだ無いときは、リストは動かず、カレンダーだけがその月を
  出したまま待ちます。次にあなたがスクロールしたときに、また追従します）
  下の棚は「カレンダーを縦にほどいたもの」で、「次に何をするか」にはよく答えますが
  「今月のどのあたりにいるのか」には答えません——4画面下の「8月17日」は、
  日付ではあっても形ではないので
  - やることのある日には**小さな点**が付きます（その日の棚と同じ色なので、
    赤から寒色への流れがここでも見えます）。多い日でも点は3つまで
  - **くり返しの日には点を打ちません。** 毎週火・金の「ゴミ出し」は月の9日に点を
    付けることになり、正しいけれど役に立ちません——点は「ほかと違う日」を
    見つけるためのもので、毎週あるものは全部の日に共通する要素だからです
  - **日を押すと、その日の棚まで飛び、その日の項目が一度光ります。** 飛んだ先の
    棚は「◯月 第△週」のように日付より広いことがあるので、着いてから
    どれを押したのか探すことになるので。二度光ってすぐ消えます
    （消さないと、消すべき状態がひとつ増えるので）
  - **月をめくれます**。**左右にフリック**するか、‹ › を押すか。指について盤が
    動き、半端なところで止めれば元に戻ります。縦の動きは下の一覧のものなので
    横取りしません。よその月にいるときは「今日へ」が出ます。
    見ている月は項目を書き替えても動きません。探しているあいだは出しません
    （絞り込んだ一覧は、もう月ではないので）
- 見出しの下に「残り◯件」は出しません。アプリについての事実であって
  その日についての事実ではなく、いま手をつけられる数はタブにもアイコンにも
  棚の見出しにも出ているので
- **カレンダーが縦に並んでいる形**です——期限切れ / **今日** /
  この先1週間は**1日ずつ**（「8月18日 火 明日」「8月19日 水 明後日」
  「8月20日 木」）/ **◯月 第△週** / **◯月** / **いつか**（日付を決めていないもの）。
  **明日・明後日にも日付が先に付きます**。呼び名だけだと、下に並ぶ
  「8月20日 木」と読み方が変わってしまうので
- **中身のない棚も細い一行で残ります。** そこへ運べるようにするためです——
  空っぽの棚は「置き場所」であって、無い日ではありません
- **棚と棚のあいだには線が入り、見出しにはその棚の色がうっすら乗ります。**
  日付の見出しが15行も続くと、どこで明日が終わって明後日が始まるのかが
  読めませんでした——項目を持ち上げて運んでいるときにこそ効いてきます
- **今日のぶんは囲みの中**にまとまります（買うものタブの「今回買うもの」と同じ形）。
  **中はひと棚です**——「朝」「午後」「夜」の区分けはやめました。時刻そのものを
  書けるようになり、項目を持ち上げて好きな場所に置けるようにもなったので、
  「振り分けることしかできない見出し」が三行、毎日並んでいるだけになったからです
  （中身の無い「午後」を毎日見ることになります）
- 残したのは日の**両端**——**「毎朝」「毎晩」**です。その日のどこか、ではなく、
  その日の**はじめ**と**おわり**（起きてすること、寝る前にすること）なので、
  **同じ日のほかの用事はこの二つに挟まれて並びます**（毎朝 → 今日 → 毎晩）。
  「毎」と名乗る以上くり返しなので、選ぶと**毎日**になります
  （「毎朝だが一度きり」は言葉と食い違うので、そこは選べません）。
  **見出しは持ちません**——今日の枠の中の見出しは「今日」ひとつだけです。
  ほかの日はどれも見出しが一つなのに今日だけ三つあるのは、同じ「一日」を
  別の作りで描いていることになるので。毎朝・毎晩であることは、**並び順と
  行の左の小さな字**が言います
- **時刻も決められます**（任意）。行に **19:30** と出て、その日の中では
  **時計の順**に並びます（時刻の無いものが先、そのあと早い順）。
  **時刻と「毎朝・毎晩」は片方だけ**です——同じ問いへの二つの答えなので、
  あとから決めたほうが残ります。
  なお**アラームは鳴りません**（並び順と目印です）。シートにもそう書いてあります
- **行の左端の色が、その日までの近さ**です。今日が赤、離れるにつれて
  オレンジ→黄→緑→青。いつかは灰色。見出しの丸も同じ色です
- **★**を付けると、同じ日のなかで先に出てきます
- **長押しして動かせます。** 同じ棚の中では並べ替え、**別の棚へ運べば日付が変わります**
  ——「今日」から「8月16日 日」へ、「9月」へ、「いつか」へ。
  運んでいる先の棚が光るので、どこに落ちるか見ながら決められます。
  運んで変わるのは**日付だけ**で、時間帯も時刻もそのままです。
  「いつか」は日付ごと外します
  （毎朝・毎晩は棚ではなくなったので、シートのチップで決めます）
- **くりかえし**（毎日・毎週・毎月）は、済ませても終わりません。**次の日に動きます**
  ——「ゴミ出し」を毎週にしておけば、押すたびに来週の日付になります。
  何日か遅れて押しても、次はちゃんと未来の日になります
- **毎週は曜日で決められます**（複数可）。「燃えるゴミ＝火・金」なら、
  火曜に済ませた次は金曜、金曜に済ませた次は来週の火曜。
  日付を決めてあっても、選んだ曜日に自動でそろえます
- **毎月は「◯日」と「第◯◯曜日」から選べます**。「第2火曜日」「最終金曜日」は
  月ごとに日付が変わるので、そのように数えます（第5週の無い月は飛ばします）。
  「◯日」のほうは、その日の無い月は月末になります
- **行は買うものタブの三分の二の高さ**です（71px → 46px）。買うものの行は絵・
  内容量・値段・お店を載せるための箱ですが、やることは一行の文字と、あっても
  「いつ」だけ。同じ三階建てを借りて、二階の半分をいつも空けていました
  - **項目名は行の上下まんなか**、左そろえ。長い名前は2行で折り返します
  - **「いつ」は選択ボタンの上下に**——**19:30 が丸の上**、**火・金 が丸の下**。
    その丸を押すことが、その二つの言っていることなので。「毎週」の文字は
    要りません（丸の中の↻が言っています）
  - 残り（日付・メモ・「しまった」・アーカイブの時刻）は**名前の右隣に同じ行で**。
    入りきらないときに縮むのは**メモだけ**です——日付が半分になると別の日付に
    見えてしまうので（「8/26」が「6」に見える）
- **くりかえしの行は、丸の中に↻が入ります。** 押しても終わらずに金曜へ動く、
  という点でこのボタンだけ意味が違うので、印は結果の出る場所に置きました。
  チェックが付けば↻は引っこみます
- **くりかえしの行の左端は灰色です。** 赤から寒色への流れは「締切まであとどれだけか」
  の話で、「ゴミ出し」にはその答えがありません——本当に今日でなければ困るものと
  並べて赤くすると、赤のほうが安くなります
- どの曜日かは丸の下の小さな文字が言います（「火・金」「第2火」「毎日」）。
  **控えめな色**で——ずっと変わらない性質であって今日の知らせではないので、
  探せば読めて、探していなければ目に入らない濃さにしてあります。
  毎朝・毎晩もここに出ます（棚が言わなくなったので、行が言います）
- 行を**右にスワイプ**で「今日にする」、**左にスワイプ**で**アーカイブ**
  （削除ではありません。取り消せます）。行をタップすれば直せます。
  ほんとうに消したいものは、その行のシートの「削除」から
- 済ませたものも、しまったものも**アーカイブ**に、片付けた**日付と時刻**つきで
  残ります。買うもの・価格のアーカイブと**同じ見た目**——薄くなって、名前に線が
  引かれ、期限の色も抜けて灰色になります。終わった用事に「今日」の赤を
  着せたままにしておく意味はないので
- **行 / タイル**を切り替えられます（買うもの・価格と同じボタン、同じ設定）
- **日付を決めたものは、その日が来るとアプリのアイコンに数が出ます**
  （期限切れも数えます。来週のぶんは、来週になるまで数えません）。
  タブにも同じ数が出ます。**設定がまだオフのときは、日付を決めた画面から
  そのままオンにできます**
- **時刻を決めたものは、その時刻が来るまで数に入りません。** 「19:30に薬」を
  朝から1と表示しても、まだ手のつけようがありません——ずっと置きっぱなしの数字は、
  読まなくなる数字です。**昨日ぶんは時刻に関係なく数えます**（遅れているものは
  待ちません）
- **時刻が来たら知らせます**（設定 →「やることの時刻を知らせる」）。同じ時刻に
  何件あっても通知は一本にまとめます。
  ただし——**アプリを閉じているあいだは鳴りません。** 決まった時刻に閉じたアプリを
  起こすには、送り手になるサーバーが要ります（iOS 16.4以降のWeb Pushでも、
  誰かが押してやらないと届きません）。このアプリはGitHub Pagesに置いた
  ファイルの集まりで、データもお使いの端末の中だけにあります。iOSには
  ローカルで時刻を予約する仕組み（Notification Triggers）もありません。
  **できるのは「開いているあいだに鳴ること」と「次に開いたときにまとめて出ること」**
  です。設定の文言もそう書いてあります——鳴ると思っていたものが鳴らないのは、
  いちばん困るのが「当てにしていた時刻」だからです
- 日付が変わると、並びも色もバッジも自動で言い直します。時刻が来たときも同じです

### 買うもの（買い物リスト）
- 画面の下に浮いている**＋**から追加（帯ではなくボタンだけなので、
  そのぶんリストが広く使えます）。**押した瞬間から打てます**（キーボードも
  一緒に上がります）。商品名・**今回買う（★）**・カテゴリ・メモを
  一枚で入れられます。個数はここでは聞きません（あとから行をタップして直せます）。
  **カテゴリは名前から自動で振り分け**（「牛乳」→ 冷蔵・冷凍、「シャンプー」→ 日用品）。
  自分で選び直せば、その振り分けを覚えます
- 打っている間に**登録済みの商品を候補表示**（最安値つき）。タップすればその商品として
  追加され、同じ名前の商品が二つできることはありません。
  **かなの違いは気にしません**——「え」で「エマール」、「きゅうり」で「ｷｭｳﾘ」が出ます
- 追加すると**シートは閉じます**。増えた行がその場で見えて、次の一件は
  ＋をもう一度押すだけです
- カテゴリごとにまとめて表示。**カテゴリは行の左端の色**で分かります
  （見出しの行は置きません）。チップをタップすれば絞り込みも
- 数量・メモ・買ったかどうかのチェック
- **買ったものは「アーカイブ」へ**、買った**日付と時刻**つきで（新しいものが上）。
  一日に何度も買い物に出れば同じ日付が並ぶので、どちらが先だったかを言えるのは
  時計のほうです。まとめて削除するボタンはありません——買ったことは消す理由に
  なりませんし、買い物中に押したくなる場面もないので。やること・価格の
  アーカイブも同じ名前・同じ書き方です
- **メモは普段そのまま読めます。** 記入欄ではなく本文が折り返して全部出て、
  **鉛筆マーク**（かメモ自体）をタップすると書けるようになります。
  一行の入力欄では、二行のメモは横に切れて読めませんでした。
  リストの行にも2行ぶんまで出ます
- 行を**右にスワイプ**で★（今回買うもの）の出し入れ、**左にスワイプ**で
  **アーカイブ**（その行はリストから外れ、価格タブの一覧からも下がります）。
  どちらも指を離すと元の位置に戻り、取り消しはトーストから。
  スワイプで出てくる面は**その行のカテゴリの色**です
- 入力中のキーボードは、**画面を下にスワイプ**すればしまえます
- 右上の**虫めがね**で検索。商品名・メモ・カテゴリのどれでも引っかかります
  （価格タブとやることタブにも同じ虫めがねがあります。使うときだけ開くので、
  ふだんは一行ぶん画面が広く使えます）
- **★で「今回買うもの」を選ぶ**と、その品だけが**ひとつの囲みの中**にまとまります。
  タブのバッジもその買い物ぶんだけを数えます。
  選ばなかった品は囲みの下に「そのほか」として残るので、
  買うものリストと買い置きメモを一枚で持ち歩けます
- **買い物リストに合計は出しません。** 値段が分かっている品だけを足した数は
  カゴの合計ではないのに、リストの下に置かれた数字はその合計に見えてしまいます。
  行ごとの値段（事実）は出しますが、足し算はしません
- ★が一つも付いていないうちは、リストが並ぶだけです。「気づいたこと」も
  出しません。買い物の予定が決まっていないのに助言をしても、
  何についての助言なのか言えないからです

### 価格の記録
- 商品ごとに、お店ごとの値段を登録 → **いちばん安いお店に🏆バッジ**
- **長押しして動かすと、同じカテゴリの中で並べ替えられます。**
  並べ替えられるのは**同じ仲間の中だけ**です——カテゴリをまたいで運べると、
  運んだこと自体が「これは野菜ではなく飲みものだ」という宣言になってしまい、
  それは持ち上げる動きが意味していることではありません（仲間分けは商品の画面で変えます）
  - 触っていないうちは**五十音順**のままです。並べた覚えのない棚が勝手に
    並び替わっているのは、便利ではなく不気味なので
  - 一度でも動かすと、**その棚は並べたとおり**になります（初めてのときだけ
    そう言います）。あとから増えた商品は、その棚のいちばん後ろに付きます
  - タイルのときは並べ替えません。買うものの画面と同じ約束で、三つ並びの
    格子は「どこに差し込むか」が読めないので
- 行に書くのは**商品名・内容量・1個あたり・値段・最安の店**だけ。
  「3店舗で比較中」のような、アプリ自身の記録の件数は出しません
- **右にスワイプ**すると、その商品が買い物リストに出入りします
  （入っていなければ入れる、入っていれば外す）。出てくる面は**その商品の
  カテゴリの色**——入っているものを外すときだけ、灰色になります。
  **左端が塗られている**商品が、いま買うものです（色は同じくカテゴリの色）。
  リストで「買った」を押すと、**その塗りつぶしは消えます**——カゴに入ったものは
  もう買うものではないので。そのままもう一度右にスワイプすればチェックが外れて、
  また買うものに戻ります（リストから消えるわけではありません）
- 商品の追加も、リストと同じ**画面の下に浮いた＋**から（右上ではありません。
  どちらの画面も、足す動きは同じ場所・同じボタンです）
- **左にスワイプ**すると**アーカイブ**。めったに買わない物は、いちばん下の
  「アーカイブ」にたたまれて一覧から消えます（**しまった日付と時刻**が付きます）。
  しまった商品は、買うものタブの「買った」行と**同じ見た目**——薄くなって、
  名前に線が引かれます。値段の記録は消えません。
  もう一度左にスワイプすれば戻ります。商品名で探したときは、アーカイブも
  開いて一緒に出てきます
- アーカイブは**買い物リストとひとつながり**です。しまえば買い物リストからも
  外れ（左端の色も消えます）、リストに入れれば自動で戻ってきます。
  買い物リストの行を左にスワイプしても同じアーカイブに入ります
- 比べるのは**値段そのもの**。同じ物を同じ大きさで買うので、
  100mlあたりのような割り算はしません
- **入数のあるものだけ1個あたり**：「10個」「12ロール」と入れておくと
  「1個あたり ¥26.8」も添えます（「500ml」は目印として表示するだけ）
- 同じ店の値段を何度も記録すると、**値段の推移がグラフ**で見えます
  （最新の値段が「今の価格」として比較に使われます）
- 「値段を追加」は、**まだ値段の無いお店**から始まります。直前に入れたお店が
  そのまま選ばれていると、次の一件が同じお店に入って前の行が消えたように
  見えるので。値段のあるお店を選ぶとボタンが**「更新」**に変わり、
  今いくら入っているかも出ます（前の値段は履歴に残ります）
- 値段の欄は**電卓**になっています。＋−×÷ のほか、「税+8%」「税+10%」と
  「割引−%」（398に12と入れれば350）。式を打つと「確定」が「＝」に変わり、
  答えを見てから確定できます
- **電卓を出したまま「追加」を押しても大丈夫**です。電卓は指が離れるまで
  引っ込みません——先に引っ込むと画面が三分の一ぶん下にずれて、押したはずの
  ボタンではなく、そこへ滑り込んできた行の🗑が押されていました
  （「確定」を押さずに足した値段も、そのまま記録されます）

### ダイエット

体重を書くだけのアプリではありません。**体重・食事・活動・睡眠を長く貯めて、
まとめて眺めるための場所**です。だから作りの重心は「毎日たくさん書く」ではなく、
**取れるものは機械から取り、人が書くのは最小限**に置いてあります。

#### ホーム

開いて数秒で「いまどうなっているか」が終わるように並べてあります。

- **今日の体重**が大きく出て、その下に**前回比・7日平均・目標まで**。
  数字をタップすればその場で記録・修正できます
- **グラフ**——実測の点、**7日移動平均**（太い緑）、30日以上なら**14日移動平均**、
  そして**目標線**（オレンジの破線）。期間は **7日 / 30日 / 90日 / 1年 / 全部**
  （はじめは7日。30日は入り口としては長すぎて、一日ぶんが10pxほどになり
  日々の上下が読めません）。**記録は左端から始まり、一日の幅は期間から決まります**
  ——両端に貼り付けて引き伸ばすと、三日ぶんしかない週でも毎日量ったように見えます。
  下の「並べて見る」で、**摂取kcal・歩数・総消費kcal・睡眠・飲酒**のどれか一つを
  背後の棒として重ねられます。飲んだ日には🍺の印が付き、押すとその日の中身が出ます
- **今日のからだ**——**歩数・総消費kcal・睡眠・飲酒**の四つ。総消費は
  安静時＋アクティブをこちらで足したもので、歩行距離はここには出しません
  （記録としては持っていて、「記録を見る・直す」から見えます）
- **今日の食事**——合計kcalと**残り**、PFCの棒、朝昼夕間食の4枠
- **気づいたこと**——貯まった記録から読めること（後述）
- **目標**——BMI、いまの傾き、届く見込み

日々の上下ではなく**移動平均の向き**を読むための画面です。体重は前の日の
塩と水で1kg動きます。太い線のほうが、あなたの一週間を言っています。

**単位の違うものを同じ縦軸に重ねません。** 体重は 68〜70 の狭い幅で動き、歩数は
0〜12000 です。同じ軸に置けば体重は一本の水平線に潰れます。だから主役は体重の線の
ままにして、関連データは**自分の最大値を天井とする別のものさしの棒**を背後に敷きます。
目盛りは書かず、いちばん大きい日の値だけを凡例に添えます——棒の高さどうしは
見比べられて、体重と絶対値では比べられない。それが正しい読み方だからです。
一度に選べるのは一つです（二つ重ねると、どちらの棒か分からなくなり、線も埋もれます）。

#### 体重

日付・時刻・体重・体脂肪率・**量ったとき（食前/食後）**・**服装（着衣のあるなし）**・
メモ。**一日に何度乗っても、グラフの点は1つ**で、採るのは**その日の最初の一回**です
（起き抜けがいちばん条件がそろうので）。

**量る条件を残すのは、それが体の変化と同じくらい数字を動かすからです。**
食前か食後かで1kg近く、着ているかいないかで0.5kg以上。書き留めておかないと、
その差が「増えた」「減った」として並びに混ざります。

- **書かなければ未記入のまま**です。「たいてい食前だろう」とこちらで埋めると、
  埋めた値がそのまま統計の材料になります
- **次からは前回と同じものが選ばれます。** 量る条件はふつう毎日おなじなので、
  毎回二つ選ばせるのは手数の無駄です（一度も選んでいなければ、未記入のまま）
- 「気づいたこと」が、その差を**数で出します**——
  「着衣ありは着衣なしより平均 +0.8kg でした（着衣あり 14日 / 着衣なし 14日）。
  体の変化ではなく、量り方の差として読めます」
- ここだけは、7日平均ではなく**期間ぜんぶに引いた直線**からのずれで比べています。
  7日平均はその点自身を含む後ろ向きの窓なので、一日おきに条件が変わる人だと
  窓の中に自分と同じ条件の日が多め（4日対3日）に入り、差が実際より小さく出ます
  （0.8kgの差が0.69kgに見える）。直線なら条件は傾きに乗らないので、そのまま出ます
- **片側が3日に満たなければ、その差は言いません。** かわりに「量り方が
  混ざっています」と、何通り混ざっているかを言います
- **二つの条件が一緒に動いていたら、そう書きます。** 食後にはいつも服を着て、
  食前にはいつも脱いでいる人の記録では、出てくる二つの数はどちらも両方の
  差の合計です。切り分けられないことは、切り分けられないと書きます

**手で書いたものと、ヘルスケアから来たものは区別されます**。グラフでは中を
抜いた丸が機械の値。そして**手で直した値は、次の取り込みで上書きされません**
——本人が直したということは、その値のほうが正しいと本人が思ったということです。

#### 食事

食品名を書けば、カロリーとPFCが付いてきます。

```
ご飯150g        → 234kcal  P3.0 F0.5 C55.7
鶏むね肉100g    → 105kcal  P23.3 F1.9 C0.1
卵2個           → 170kcal  P14.6 F12.2 C0.5
オリーブオイル大さじ1 → 107kcal
```

- **全角・漢数字・呼び名**でも通ります（「ご飯１５０ｇ」「卵二個」「とりむね200g」）
- **量を書かなければ一食ぶんの目安**で入ります（納豆なら1パック45g）
- **単位は g / kg / ml / 個 / 枚 / 本 / 杯 / 枚 / 丁 / パック / 大さじ / 小さじ …**
- 何行かまとめて貼っても、行ごとに読みます
- **表に無いものは「無い」と言います**。勝手に100kcalを置いたりはしません。
  名前だけ入れて、数はあなたが決めます。直した値はあなたの食品として残ります

値は**日本食品標準成分表2020年版（八訂）をもとにした概数**です。同じ「鶏むね肉」
でも部位の取り方で1割は動きますし、炊いたご飯は水加減で変わります。
**1gずつ量るかわりに、だいたいの線を引くための数**だと思ってください。
どの値もその場で直せます。

食品は**出どころで分けて**持っています——基本食品（成分表）、市販商品、
あなたが登録・修正したもの、AIの推定。将来データベースを入れ替えても、
過去の食事記録は壊れません（記録は数字を自分の中に持っているので）。

#### ヘルスケア（Apple Health）との連携

**まず結論から。おすすめは「iPhoneのショートカット＋アプリの取り込み口」です。**
やり方はアプリの中（ダイエット → 右上の取り込みボタン）に書いてあります。

なぜそれなのか、五つの道を並べて比べました。

| | 自動化の度合い | 実装の重さ | 安定性 | 保守 | プライバシー | 将来性 |
|---|---|---|---|---|---|---|
| ① Webアプリだけ | **不可** | — | — | — | — | — |
| ② ショートカット＋取り込み口 | 高（1タップ） | **軽い** | 高い | **ほぼ不要** | **端末内で完結** | 高い |
| ③ ショートカット＋中継所（自前） | 最高（0タップ） | 中 | 高い | ほぼ不要 | 数字だけ一瞬外を通る | 高い |
| ④ 小さなネイティブアプリ | 最高（0タップ・常時同期） | **重い** | 高い | **7日ごとに再インストール**※ | 端末内で完結 | 最高 |
| ⑤ 市販の書き出しアプリ＋サーバ | 高 | 中 | 他社次第 | 他社次第 | 外に出る | 中 |

※ App Storeに出さない前提だと、無料のApple IDで署名したアプリは**7日で起動
しなくなり**、Macに繋いで入れ直すことになります。有料の開発者プログラム
（年間 約12,800円）に入れば1年になります。

- **① は不可能**です。WebKitはHealthKitを露出していません。「今は難しい」ではなく、
  **APIが存在しない**ということです。ここを曖昧にしたまま作ると、後で全部を
  やり直すことになります
- **② を選んだ理由**は、③④の「0タップ」との差が実質**1タップ**しかないのに、
  払うものが桁違いに小さいからです。サーバも鍵もApple IDの署名も要りません。
  健康データは**iPhoneの外に一歩も出ません**。そして毎朝どのみち体重を書くために
  アプリを開くので、そのついでの1タップです
- **③④への引っ越し道は開けてあります**。取り込み口が受けるのは
  **決まった形のテキストかJSON**なので、送り手を差し替えるだけで済みます。
  アプリ側は1行も変わりません
- **③は、そのあと実際に用意しました**（下の「中継所」）。②で残っていた
  「アプリに戻って一度押す」も要らなくなります。②を壊さずに**入口を一つ
  足しただけ**なので、中継所を立てない人の動きは今までと完全に同じです

**やり方**（アプリの中にも同じ案内があります：ダイエット → 右上の ⤓）

**まず、ショートカットを作る前に手で一度試してください。**「① まず、手で試す」の
欄に打つと、**読めたものがその場に出ます**。入る形を先に見ておくのがいちばんの
近道で、あとはこの文字をショートカットに書かせるだけになります。

```
day=2026-08-15
steps=8432
sleep=7:12
```

**ショートカットは「歩数」だけで作って、動いてから残りを足します。**
先に16個のアクションを並べてから動かない理由を探すのは、いちばん心の折れる
順番です。

1. 「ショートカット」アプリ →「＋」で新規作成
2. **「ヘルスサンプルを検索」**を追加。**種類**を「歩数」、**フィルタ**を
   「開始日」が「今日」に
3. **「統計を計算」**を追加。**合計**を選び、対象は上の結果
4. **「テキスト」**を追加。`steps=` と打ち、その右に一つ前の結果の変数を差し込む
5. **「クリップボードにコピー」**を追加
6. 実行 → アプリに戻って「コピーしたものを取り込む」

これが通ったら、2〜4をもう一度ずつ足せば種類が増えます。「テキスト」は
**一つにまとめて**、行ごとに `distance=` `sleep=` …と並べます。全部そろうと
こうなります。

```
くらしノート健康データ v1
day=2026-08-15
steps=8432
distance=6.1km
activeEnergy=430
restingEnergy=1520
sleep=7:12
weight=68.4
bodyFat=21.3
heartRate=62
workout=ウォーキング,42,210
```

- **値が取れなかった行は、空のままで大丈夫**です。空欄は「無かった」として
  扱い、**0にはしません**（歩かなかった日と、歩数が取れなかった日は違います）
- **歩行距離だけは、足すと二重になります。** Apple Watch と iPhone がどちらも
  一日ぶんを持っているためで、実測では 7.8km と 6.0km を足して 13.9km になりました
  （ヘルスケアの表示は 7.9km）。`source=` を書いて機械ごとに分けて送れば、
  **Apple Watch のほうを採ります**。分けずに一つだけ送るぶんには、これまでと
  何も変わりません。歩数・アクティブ・安静時は実測でほぼ一致していたので、
  取り方は変えていません
- **「統計を計算」を挟み忘れても通ります。** 同じ日の同じ種類が何行も来たら、
  歩数・距離・エネルギー・睡眠は**合計**され、心拍数は**平均**されます
  （ワークアウトだけは一本ずつ残ります——朝のランと夜のヨガは別の運動なので）
- **うまく読めないときは、読めたものを見てください。**「手で試す」の欄は、
  打つそばから「歩数 8,432歩 / 今日」のように読み下します。クリップボードや
  ファイルの取り込みに失敗したときも、その中身がこの欄に落ちてきます

**開いたときに、そのまま読みます（半自動）**

ダイエットタブを開くのは、たいてい「ショートカットを走らせた直後」です。
だから**タブを押した時点で一度クリップボードを読みにいきます**——押すボタンが
一つ減ります。三つ気をつけてあります。

- **黙って失敗します。** クリップボードに買い物のURLが入っている日のほうが
  多いので、読めなかった・健康データでなかったときは何も言いません。
  知らせるのは**入ったときだけ**
- **同じものを二度は知らせません。** 一度読んだ中身は覚えておいて、
  変わっていなければ触りません（タブを行き来するたびに「1件を更新」と
  出るのは、報告ではなく騒音です）
- **切れます。** 設定 → ダイエット →「開いたときに自動で読む」

読み取りを断られる端末（後述）では、この自動読みは走りません——貼り付けの欄が
勝手に開いてしまうので。そこは今までどおり手で押します。

**「コピーしたものを取り込む」が失敗する場合**

ブラウザからクリップボードを読む API（`navigator.clipboard.readText()`）は、
**環境によっては断られます**。とくに**ホーム画面に追加したアプリ**（standalone）
では、iOSが読み取りを許さないことがあります。ほかにも、保護されていない接続
（http）、画面に焦点が無い、ユーザーが「ペースト」を押さなかった、などで失敗します。

そこで失敗を行き止まりにしていません。読めなかったときは**貼り付けの欄**が
開きます——**長押しして「ペースト」**を押せば、そこから先は手入力とまったく
同じ処理に渡ります。iOSのペーストはブラウザの権限を通らないので、API が
断られる端末でも必ず通ります。

- 読み取れた文字列は、**成功しても失敗しても生のまま画面に出ます**
  （「クリップボードから取得した文字列（25文字）」）
- 読めなかったときは、**理由**が畳んで置いてあります
  （`NotAllowedError：Read permission denied. / ホーム画面から起動したアプリでは…`）
- 一度断られた端末は**それを覚えて**、次からは貼り付けの欄をまっすぐ開きます。
  欄の中に「自動で読めるか、もう一度試す」を残してあるので、いつでも戻せます
- 睡眠は `412` `7:12` `7時間12分` `7h12m` のどれでも通ります
- 距離は `6.1km` でも `6100m` でも通ります
- **オートメーション**で毎朝走らせておけば、アプリを開いて取り込みボタンを
  1回押すだけになります
- JSON（`{"samples":[{"type":"steps","day":"…","value":8432}, …]}`）でも読めます。
  HealthKitの識別子（`HKQuantityTypeIdentifierStepCount` など）もそのまま通ります

**同じデータが二度入ったら**——歩数のように*一日にひとつ*と決まるものは
**新しいほうで差し替え**（夜に取り込んだ歩数のほうが一日を写しているので）、
ワークアウトのように一日に何本もあるものは**印（UUID や 日時＋長さ）で照合**します。
朝と夜に二度取り込んでも、記録は増えません。

#### お酒

**一行書けば済みます。**「ビール350mlを2本」。種類を選んで、量を選んで、本数を
選んで……を毎晩やらせると、三日でやめるからです。

```
ビール350mlを2本      → ビール 350ml × 2本  純アルコール 約28g  約280kcal
ビール2本とワイン半分   → 二つに分けて、それぞれ記録
日本酒1合            → 180ml（一合＝180ml）
ウイスキー ダブル      → 60ml
ワイン 200ml 14%     → 度数を書けば、推定ではなくなります
飲んでない           → 何も記録しません
```

**押す前に、入る中身が見えます。** 打つそばから「ビール 350ml × 2本 / 5%（推定）/
純アルコール 約28g / 約280kcal」と読み下しが出るので、確認の画面を別に挟まずに、
違っていればその場で書き直せます。

**純アルコール量**は `ml × 度数% ÷ 100 × 0.8` です（0.8 はエタノールの比重。
厚生労働省の「節度ある適度な飲酒」もこの式で、ビール500ml・5%＝20g と数えます）。

**カロリー**は種類ごとの 100ml あたりの目安から出します。アルコール1gは約7kcalですが、
ビールには糖質があり蒸留酒にはほとんど無いので、純アルコール×7 だけで済ませると
ビールは低く出ます。

**飲むたびに書き足せます。** 一件ごとに**時刻**（既定はいま）と、**そのときの気分**を
残せます。気分は自由入力と札の併用です——自由記述だけでは数えられず、札だけでは
実感が落ちるので。

**札の中身は決め打ちしません。** よくある言葉を五つ並べておくのは簡単ですが、並べた
瞬間、人はその中から選びます。自分の言葉ではなく、こちらが用意した言葉で自分の
飲み方を記録することになり、それはたいてい少しずつずれています（「付き合い」と
「断れなかった」は違う）。だから**はじめは空欄だけ**で、書いた言葉をそのまま覚え、
二度目からはそれが押せる札になります。

- **推した値には「約」が付きます。** 度数や量を書かなければ、それは推定です。
  量った値と推した値が同じ顔で並ぶと、記録全体の信頼度がいちばん低いところに揃います
- **書いた文はそのまま残ります。** 読み取りはあとで良くできますが、本人が書いた文は
  もう手に入りません。読み違えていても、元の文が残っていれば直せます
- **一日に何種類でも**、別々の記録として残ります。合計（容量・純アルコール量・
  カロリー・酒類数）は一日単位で出します
- **食事のkcalには混ぜません。** お酒は栄養の内わけを持たないので、PFCの棒にも
  入れません。そのうえで「お酒のぶんを足すと◯◯kcal」と別に書きます

#### 中継所（コピーも貼り付けもやめる）

②まで来ると、毎朝の手間は**「アプリに戻って一度押す」だけ**です。それも消したい
ときは、**中継所**を一つ立てます。コードと建て方は [`relay/`](relay/) にあります
（Cloudflare Workers・無料枠・10分ほど）。

```
ショートカット（毎朝、オートメーションで無人）
  ↓ POST（本文は手入力とまったく同じ「steps=8432」の形）
中継所（自分で立てる小さな郵便受け）
  ↓ GET（取ったら郵便受けからは消える）
くらしノート（ダイエットタブを開いた時に、自分で受け取る）
```

**なぜ端末の外を一周させるのか。** iPhoneの中だけで渡す道が、Webアプリには
残っていないからです。

| 方法 | 使えるか | 理由 |
|---|---|---|
| URLスキーム（`kurashi://…`） | ✕ | ネイティブアプリの仕組み。Webアプリは名乗れません |
| ユニバーサルリンク | ✕ | 同上。受け取るのはネイティブアプリだけ |
| Web Share Target | ✕ | Safariが実装していません（WebKit bug 194593、いまも open） |
| URLを開いてパラメータで渡す | △ | **開くのはSafariのほう**。ホーム画面のアプリとSafariは保存領域が別なので、入れたデータはホーム画面側から見えません |
| クリップボード | △ | ②のやり方。ホーム画面のアプリでは読み取りが断られるので、毎回「ペースト」が要ります |
| **中継所** | ○ | 外を一周するので、保存領域の分断を越えられます |

**iPhoneだけで建てられます。パソコンは要りません。** 手順はぜんぶ
**設定 → ダイエット → 中継所**の中にあります（①〜④）。作業をアプリの中に
置いたのは、手順を読むために別の端末を開かせるのが本末転倒だからです。

中継所のコードは、このリポジトリの [`relay/`](relay/) にあります。
**GitHubからそのまま配置できる構成**です——貼り付けも、KVを手で作って結ぶ
作業も要りません。仕掛けは二つだけ。

- `wrangler.jsonc` の `kv_namespaces` に **`id` を書いていない** → Cloudflareが
  「まだ無いので作る」と解釈して置き場を用意し、id を書き戻します
- `.dev.vars.example` に `RELAY_PATH=` がある → 配置の途中で
  **Secret として尋ねられます**

だから手順は四つで済みます。

1. **道をつくる** — アプリのボタン。80ビットぶんを端末の中で作ってコピーします
   （iPhoneに `openssl` はありませんし、人が思いつく「適当な文字列」は
   適当ではありません）
2. **Cloudflareに置く** — アプリのボタンが
   [配置画面](https://deploy.workers.cloudflare.com/?url=https://github.com/rt95k9k468-cmyk/kaimono-note/tree/main/relay)
   を開きます。登録 → GitHubをつなぐ → `RELAY_PATH` に①を貼る → Deploy
3. **道をつなげる** — `…workers.dev` を貼れば、①の道を後ろに付けます
   （長いURLを指で打ち継がせない）
4. **中継所を確かめる** — その場で一往復して、置けた／取れた／消えた／
   道が違えば渡さない、を一行ずつ出します。止まった所と直し方も言います

うまくいかないときは、Cloudflareの **Create → Import a repository** から
`kaimono-note` を選び、**Root directory** に `relay` と入れても同じです
（あなた自身のリポジトリなので一覧に出ます）。**コードを手で貼るやり方は
iPhoneでは勧めません**——編集画面はパソコン向けの部品でできていて、指での
「すべてを選択 → ペースト」が効かないことがあります。

パソコンがあるなら `relay/setup.sh` が①〜④を一度にやりますが、無くても困りません。

**設定するもの**は一つだけ、**中継所のURL**です。このURLの道そのものが合言葉なので、
`/kn-7f3a9c1d4e8b2` のような**当てられない長い道**にしてください（アプリが作ります）。
ヘッダで認証しないのは手抜きではなく、追加のヘッダを付けるとブラウザが
事前問い合わせ（preflight）を挟むためです。合言葉を道に含めれば、ただの
GET と POST で済みます。

**ショートカット側は、最後の1アクションだけ差し替えます。**
「クリップボードにコピー」を消して、

1. **「URLの内容を取得」**を追加、URLに中継所のURL
2. **▸を開いて 方法＝`POST`**、**本文を要求＝`ファイル`**、
   **ファイル＝一つ前の「テキスト」の結果**

（「本文を要求」を `JSON` のままにすると `{"key":"value"}` の形で送られます。
`ファイル` にすると、テキストがそのまま本文になります。）

あとは**オートメーション**で毎朝走らせておけば、押すボタンはゼロになります。

- **受け取ったら中継所から消えます。** 同じ便を二度読むことはまずありません
  （KVは結果整合なので、置いた直後は届いていないことが、消した直後は同じ便が
  もう一度来ることが、それぞれ稀にあります。二度来ても同じ日の同じ種類は
  差し替えなので、記録は増えません）
- **自動のときは黙ります。** 電波の悪いところでタブを開くたびに赤い字が出るのは
  報告ではなく邪魔なので、繋がらなくても空でも何も言いません。入ったときだけ
  「中継所：1件を追加（今日）」と出ます。自分で押したとき（設定の
  「つないでみる」／取り込みシートの「中継所から取り込む」）は**黙りません**
- **「つないでみる」は、届いていればそのまま取り込みます。** 中継所は渡したら
  消す作りなので、覗いて捨てるとその日のぶんを失くすからです
- **読み方は増えていません。** 受け取った文字列は、手入力・貼り付けと**同じ
  処理**に渡ります。手で書いた値が中継所の便に上書きされないのも、これまでと同じ
- **手入力・貼り付け・ファイルは、そのまま残っています。** 中継所を設定していない
  アプリの動きは、これまでと1つも変わりません
- **中身は暗号化されません。** 通信はHTTPSですが、中継所の中では平文です。置かれる
  のは歩数・睡眠・体重といった数字だけで、名前も端末IDも含みません。それでも
  他人のサーバを通したくないなら、自分のサーバに同じ10行を置いても構いません

#### 入った数を、あとから直す

取り込んだ数は読むだけのものではありません。**「今日のからだ」の枠はどれも
押せます**——押すと「からだの記録」が開き、そこで

- 歩数・歩行距離・アクティブ・安静時・睡眠・心拍数を**手で直せます**
- **欄を空にして保存すると、その値は消えます**
- **‹ › で前の日・次の日へ移れます**（未来には行きません）。昨日の歩数が
  おかしければ、昨日に移って直します
- ワークアウトを**足す・消す**ことができます

手で書いた値には「手入力」の印（✎）が付き、**次の取り込みで上書きされません**。
体重と同じ考え方です——打ったということは、その数を正しいと思ったということ。
取り込みは黙って諦めるのではなく、「1件は手入力のまま」と結果に書きます。

また機械に任せたくなったら、**その欄を空にして保存**してください。消せば、次の
取り込みからまたヘルスケアの値が入ってきます。

#### 自動で取るもの／手で書くもの

**機械から**：歩数・歩行距離・アクティブエネルギー・安静時エネルギー・
ワークアウト・睡眠・体重・体脂肪率・心拍数

**人が書く**：食事・食品・量・飲酒・間食・体調・メモ

この二つは**別の入れ物**に入っています。混ぜてしまうと、取り込みのたびに
「これは前に自分で書いたやつだろうか」を値で当てにいく羽目になり、いつか必ず外します。

#### 気づいたこと（統合分析）

貯まった記録から、たとえばこういうことを出します。

- 30日間の変化（7日平均で −1.4kg など）
- 体重が減った週と増えた週の、**平均歩数**の違い
- 体重が減った週と増えた週の、**平均摂取カロリー**の違い
- **睡眠6時間未満の日**の体重が、その週の平均からどれだけずれているか
- **休日と平日**の差
- 直近7日のPFC

守っていることが二つあります。

1. **少ない標本で言い切りません。** 片側が3件（週なら2週）に満たなければ、
   その項目は**出しません**。そして必ず「何件ぶんの話か」を書きます
2. **「原因」とは言いません。** 出るのは並んだ数どうしの**関連**です。
   「〜の傾向があります」「関連が見られます」で終わり、
   「〜のせいで太った」とは書きません——このやり方で分かるのは、それが
   一緒に動いたということだけだからです

素の体重どうしではなく、**その日の7日平均からのずれ**で比べています。長い減量の
途中なら後の日ほど軽いに決まっているので、素で比べると「最近の日はどれも軽い」
という当たり前しか出てきません。

#### AIの窓口（写真の推定・AI相談）

**APIキーはこのアプリには置きません。** 方針というより事実で、ここは静的な
ページなので、埋めた鍵は誰でも読めます。玄関マットの下に鍵を置いて出かけるのと
同じことです。

かわりに**窓口のURLを一つ**だけ設定に持ちます（設定 → ダイエット → AIの窓口）。
その先（Cloudflare Workers など）に鍵を置いて、そこがAIを呼びます。
窓口が満たす約束はこれだけです。

```
POST <窓口のURL>   Content-Type: application/json

① 相談  { "kind":"coach", "question":"…", "data":{ …本人の記録… } }
        → { "text": "…" }

② 写真  { "kind":"photo", "image":"data:image/jpeg;base64,…", "hint":"…" }
        → { "items":[ {"name":"ご飯","grams":180,
                       "kcal":281,"p":4.5,"f":0.5,"c":66.8} ],
            "note":"…" }
```

- 送るのは**ダイエットの記録だけ**です。買い物リストとやることは送りません
- AIには一般論ではなく**実際に貯まった本人のデータ**を渡します
- 写真から返る数は**推定**です。アプリは `推定` の印を付けて保存し、画面でも
  「約」と書きます。**あなたが直せば印は外れます**——直したということは、
  それはもう推定ではなくあなたの申告だからです
- 窓口を決めていなければ、写真とAI相談のボタンは**出ません**（押せない
  ボタンを並べても仕方がないので）

#### まだ無いもの

正直に書いておきます。

- **バーコードからの商品特定**——入れ物（市販商品として別に持つ仕組み）は
  できていますが、読み取りとデータ源はまだです
- **写真のAI解析**——アプリ側は動きますが、**窓口を自分で立てる**必要があります
- **ネイティブアプリでの常時同期**——②で十分に回るので、要ると分かってから

### お店くらべ

タブではなく、**リストと価格の右上のお店ボタン**（くらべる印の付いたお店の絵）から開きます。
毎日開くものではないので、タブ1つぶんの場所は「やること」に譲りました。

**右上のボタンの並びは、右端から 設定（歯車）→ 行/タイルの切り替え → さがす
→ お店くらべ** です。右端がいちばん押しやすいところなので、どの画面にもある
ものから順に置いてあります。お店くらべは買うもの・価格にだけあるので、
いちばん左（やることでは3つ）。
- 買い物リスト全体で、**どのお店を中心に買うと総額いくらか**を自動計算
- 同じ買い物カゴで比較するので、取扱商品数が違うお店同士でも公平に並びます
  （その店にない物は「最安の店で買う」前提で計算）
- **最安の組み合わせ**（各商品を最安店で買った場合）との差額も表示
- 商品ごとの最安店を一覧表示

### 気づいたこと

登録した値段を読んで、そのとき言えることだけを出します。

- 「今回は業務スーパーだけで足ります」／「店を分けると ¥320 安くなります」
- 「牛乳がイオンで ¥218 → ¥248 に上がりました」（同じ店の前回の値段と比べます）
- 「お米の値段が古くなっています」（3ヶ月以上前の記録）

すべて端末の中の計算です。外部に問い合わせないので、通信も費用も要らず、
機内モードでも出ます。出てくる数字はあなたが入れた値段そのものなので、
それらしいだけの推測が混ざることはありません。言える材料が無いときは
黙っています。

### 商品の絵
- 商品の絵は**全部このアプリの中で描いています**（約555種）。名前から自動で選びますが、
  商品の詳細から**自分で選び直せます**
- 食べものと消耗品だけではありません。**家具・寝具**（椅子・机・ソファ・ベッド・布団・
  カーテン・本棚…）、**文房具**（鉛筆・シャーペン・蛍光ペン・修正テープ・印鑑…）、
  **キッチングッズ**（片手鍋・おたま・泡立て器・おろし金・急須・弁当箱…）、
  **カトラリー**（スプーン・フォーク・ナイフ・れんげ・箸）、
  **家電**（電子レンジ・冷蔵庫・洗濯機・扇風機・ドライヤー・ノートパソコン…）も
  それぞれの絵です。これらは**日用品**に振り分けられます（もちろん選び直せます）
- **一枚が何役も兼ねない**ようにしてあります。大根とごぼうは別、そばとうどんも別、
  かまぼことちくわも別です。以前は「キャベツ」一枚が白菜もレタスもほうれん草も
  引き受けていて、絵で見分ける意味がありませんでした
- 選ぶ画面では、名前から**「もしかして」**の候補を上に出します。
  「食器用洗剤」なら食器用洗剤と洗濯洗剤——取り違えやすい相手こそ隣に並べます
- 名前で絵をさがすこともできます。自分で選んだ絵は、名前を変えても動きません

### 並べ方（行 / タイル）

やること・買うもの・価格の3画面とも、**行**と**タイル**を切り替えられます。
どの画面の右上のボタンからでも切り替わり、全部に効きます。

- **行**：商品名・値段・最安の店が一行に並びます
- **タイル**：一行に3つの正方形。絵が大きく、商品名は折り返して全部出ます。
  一画面に3倍入るので、探すときはこちらが速いです。
  価格タブのタイルには、値段の下に**いちばん安いお店**も出ます

**スワイプはどちらでも同じです**——右がそのタブの「する」（やることでは今日に、
買うものでは★、価格ではリストへの出し入れ）、左がアーカイブ。タイルでは幅がないので
文字は出さず、絵だけが出ます。並べ替え（長押しして動かす）は行だけです。

### 下のタブ

**やること │ 買い物 │ ダイエット** の**三等分**。この本が扱うのは三つ——
一日のこと、買うもの、からだのこと。

買うものと価格は**1つのボタンを分け合います**。同じ商品・同じアーカイブ・同じ
タイルを、お店で持ち歩くときは一覧として、値段を調べるときは表として読んで
いるだけなので。**すでにそこにいるときにもう一度押すと、裏返って**もう一方に
なります。

そのとき**絵は二つ並んでいます**——いま見ているほうが真ん中で大きく色つき、
もう一方は**脇に小さく灰色**（重ならないよう5pxあけて、丸い下地の外に置いて
あります。下地は「いま居るほう」の印なので、待っているほうが外にいるのが
正しい絵です）。押すと二つが**中心を通ってすれ違い**、色と大きさが
入れ替わります。一枚の絵が差し替わるだけでは何が起きたのか読めませんが、
すれ違う動きなら「同じ持ち場を分け合っている」ことがそのまま見えます。
名前も**両方**出したまま、いま見ているほうが明るく、もう一方が暗い字。
離れて戻ってきたときは、**最後に見ていたほう**が開きます。

設定はタブをやめました。設定は「場所」ではなく、たまに開いて閉じるものなので、
**右上のいちばん右の歯車**から開いて、来た画面へ戻ります（お店くらべと同じ扱い）。

### そのほか
- **iPhoneのノッチ（上の帯）をタップすると、一番上まで一気に戻ります。**
  iOSはこの操作を「ページを上へ」として送ってくるのですが、このアプリの
  ページ自体は動きません（一覧はそれぞれの画面の中でスクロールします）。
  そこで**文書に1pxだけ余白を持たせて、そこに停めて**あります——その1pxが
  iOSに取れる唯一のもので、取られたことが合図になります。1pxはノッチの下に
  隠れ、すぐ返すので、見た目も操作も変わりません。
  **画面の見出し（「やること」などの文字）を押しても同じ**です（ボタンは別）
- ライト / ダークテーマ（自動切り替え対応）
- **ホーム画面のアイコンに残り数**を出せます（設定 → 表示、または
  やることに日付を決めるときにその場で）。数えるのは
  **「今回買うもの」の残り＋今日までのやること**です。
  iPhoneでは**設定をオンにしていないと出ません**（タブのバッジは設定なしで出ます）。
  iOS 16.4 以降のホーム画面アプリで使えます。iPhone ではバッジが通知の許可に
  ぶら下がっているので、オンにするとき通知の許可を聞かれます（通知は送りません）。
  数はアプリに戻るたびに言い直します——iOSは再起動や強制終了でバッジを
  勝手に消し、ページには何も言わないので。許可が外れているときは、
  設定のスイッチが「許可が必要」と出ます
- お店・カテゴリの追加、名前や色の変更、並び替え
- JSONでバックアップ・復元
- **自動バックアップ**：1日1回と、削除・復元などの危ない操作の直前に、
  アプリが自動で控えを残します（最新7件）。うっかり消しても設定から戻せます
- データは**この端末の中だけ**に保存されます（サーバーに送信しません）

> 自動バックアップはこの端末の中に置かれるものです。機種変更や端末の紛失に
> 備えるには、設定の「バックアップを保存」でファイルを書き出してください。
> しばらく書き出していないと、アプリがそっと知らせます。

## スマホにインストールする

### 1. GitHub Pagesを有効にする（最初の1回だけ・手動）

1. このリポジトリの **Settings → Pages** を開く
2. **Build and deployment** の **Source** を **GitHub Actions** に変更する
3. **Actions** タブ → 「Deploy to GitHub Pages」→ **Re-run all jobs**

この1手順だけは手作業が必要です。ワークフローから自動で有効化することは
できません（`GITHUB_TOKEN` にPagesサイトを作成する権限がないため）。

一度有効にすれば、あとは `main` に push するたび自動で公開されます。

### 2. スマホで開く

公開URLはこちら：

**https://rt95k9k468-cmyk.github.io/kaimono-note/**

初回のデプロイは1〜2分ほどかかります。
リポジトリの **Actions** タブで緑のチェックが付いたら準備完了です。

### 3. ホーム画面に追加する

- **iPhone（Safari）**
  共有ボタン <kbd>􀈂</kbd> → 「ホーム画面に追加」
  ※ Chrome や他のブラウザではなく **Safari** で開いてください
- **Android（Chrome）**
  右上の <kbd>⋮</kbd> → 「アプリをインストール」または「ホーム画面に追加」

追加すると、アドレスバーのないふつうのアプリとして起動します。
一度開いておけば、**電波がなくても使えます**。

### 更新するとどうなる？

`main` に push すると自動でデプロイされ、**ホーム画面のアプリも次に開いた
ときに新しくなります**。アプリストアの審査も再インストールも要りません。

仕組みとしては、デプロイのたびにコミットIDを `sw.js` に埋め込んで
キャッシュ名を変えています。これをしないと、Service Worker が
入れ替わらず古いJS/CSSが返り続けてしまいます。

反映は「更新をpush → アプリを開く（新しい中身を裏で取得）→ もう一度開く」
の流れになるので、変更が見えるのは次回起動時です。
