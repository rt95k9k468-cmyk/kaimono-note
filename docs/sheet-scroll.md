# 紙と、送る器（丸角・送る器・閉じ方・指につく）

本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも

### 外枠と、その中を流れる中身（丸角が消えないための作り）

**送る器は、画面ではなく紙です**（やること・daily・買うもの）。

前はひとつでした——`.screen` が送る器で、紙（`.tl-sheet`）はその中のふつうの
ブロック。だから下へ送ると、丸角のついた紙の上端はそのまま上へ流れて消えます
（実測：送り 270px で紙の上端が **-140px**）。手当てとして掴み手に sticky と
同じ丸角を着せていましたが、掴み手の地も紙の地も同じ白（当時どちらも実測
rgb(255,255,255)。いまは 253 ——下の「紙の地は 253」参照）なので、角を落とした
隙間から覗くのは紙自身の白
——**丸角は最初から見えていませんでした**。しかも流れてくる行がその隙間を
通る、という禁じ手そのものの構造でした。

外枠（丸角＋掴み手）と、中身を送る器を分けます：**紙が器になり**、上のバー・
探す欄・暦・カテゴリの札は紙の外に留まる。中身は紙の中だけを流れます。
実測：送り 600px でも紙の上端も掴み手も **130px から動かない**。丸角の外側の
画素は地の色（240,239,243）、内側は白。

- **ダイエット・価格・設定は、これまでどおり画面が送ります。** ダイエットの紙は
  `is-bare` で丸角を持たない（隠れる角がない）うえ、あの画面だけは引いて更新と
  キーボードの送りが画面そのものの `scrollTop` に乗っています。価格と設定は紙を
  持ちません。
- **器がどちらかは `KN.app.scrollerOf()` が `overflow` を見て答えます。**
  決め打ちにしないこと——`root.scrollTop` と書いてある古い場所が残っていると、
  そこだけ動かない画面を触りにいきます。直した先：`is-stuck` の見張り
  （todo/archive/list）、組み直しの位置を保つところ、「いま」へ寄せるところ、
  運んでいる最中の自動送り、`cal-peek` の送りの覚え書き。
- 高さの割り当ては `.stack` → `.js-body`/`.arc-body` → `.tl-sheet` と
  `flex:1; min-height:0` で通します。途中が欠けると紙は中身ぶんに伸びて、
  器になりません。
- 下の帯のぶんの余白は、**紙の中の `padding-bottom`** が持ちます（器の外に
  置いても、中身の下には空きができない）。画面から紙を引き出していた負の
  マージンは要らなくなりました。
- 掴み手の sticky は `top: 0`（紙の中で貼りつくので、上のバーや暦の厚みを
  数える必要がない）。
- `overscroll-behavior` は紙に付けていません——ブラウザ本来の跳ね返りが
  そのまま効くので、`pull-refresh` の帯（fling）が要りません。

#### 紙の地は 250、ふちは純白 255

`--c-sheet`（`#fafafa`）と `--c-sheet-edge`（`#ffffff`）。紙（`.tl-sheet`）も
下から出る紙（`.sheet`）も、地はこの一段下げた白。

**ふちの純白の一本は、前から引いてありました**（`.tl-grip` の
`box-shadow: inset 0 1px 0`）。地も純白だったので、**一度も見えていません**
でした——白の上に白を引いていた。地を下げると、その一本が「紙のいちばん上で
光が当たっている」ふちとして立ちます。

**落ち影ではなく inset**（内側の一本）なので、紙が浮いて見えるようにはなりま
せん。`border-radius` が box-shadow にも掛かるので、丸角にもそのまま沿います。
暗いほうは逆に、地より**明るい**灰（`#33333c`）でなぞる——暗い面に純白を引くと、
線だけが浮き上がって紙のふちではなく別の部品に見えます。

**掴み手の地は、紙の地とまったく同じにすること**（貼りついたまま行がその下を
通るので、少しでも違うと帯に見えます）。

**紙の上に乗る帯も、白は `--c-surface`（純白）ではなく `--c-sheet` を見る
こと。** daily の月のまとめ・Daily Log・積み上げの一覧（`.card.arc-log` /
`.card.arc-counts` / `.card.arc-list`）は `.card` の既定（純白）のままだと、
紙の地を下げた瞬間だけ**純白の段として浮いて**見える——地の白と紙の白が、
目には同じでも数字としては違うので。ダイエットの三つの帯（`.diet-block` の
`is-body` / `is-meal` / `is-weight`）も同じ理由で、混ぜる相手を
`--c-surface` ではなく `--c-sheet` にしてある（ダイエットの紙は
`.tl-sheet.is-bare` で面を持たないので、この三つが実質の紙）。
**一つの変数（`--c-sheet`）から出すこと**——紙の色を動かすたびに、これらも
ついてくる。

### 送る器を変えたら、pull-refresh にも教えること

`pull-refresh.js` は `.screen.is-active` を測っていました。紙が器になった
三画面では画面が送れないので `scrollHeight === clientHeight`——**上端にも
下端にも同時に居る**ことになり、縦の指を毎回「下端の give」として取って
`preventDefault` します。**時間割が一切スクロールできなくなっていました**
（実測：touchmove 7回すべてが既定阻止、送り 0。黙らせると 275px 送れた）。
`KN.app.scrollerOf()` を通すこと。**設定も同じ轍を踏みかけました**——紙の
重なり（`.set-layer`）が器になったので、`scrollerOf` にそれを教えてあります。

**拾い残しが一つありました**（2026年9月20日に直した）。`renderBody` が暦に
`is-stuck` を付けるかどうかを `root.scrollTop > 4` で決めていた——送る器は紙の
ほうなので、根っこはいつも 0。**送った先で組み直すと境目の線が消えて**、次に指が
動くまで戻りませんでした。すぐ上で `scrollerOf(root).scrollTop` を `keepTop` に
取ってあるので、それを使い回します。**測り直さないこと**——あそこは
`innerHTML = ""` のあとなので、測ると組み立ての途中でレイアウトが強制されます
（render 1回あたりのレイアウトが 3.1回 → 2.1回になったうちの、1回ぶんがこれ）。

### 「下に引いて更新」は、もうどこにも無い

ダイエットにだけ残していたが、**それも外した**（`pull-refresh.js` の頭の
but that was retired）。中継所は開けば勝手に覗きにいくし、押して取りに行く道は
別にある（下の「中継所は、見えているあいだ覗き続ける」）。

いま `pull-refresh.js` に残っているのは**端の give だけ**——下端まで送った指に
返す遊びと、勢いのついた指が端を越えたときの帯（`onScroll` → `fling`）。
あれは更新ではなく、ブラウザ本来の跳ね返りを返しているだけで、無くすと一覧が
壁に当たったように止まる。`[data-pull-own]` も、その give を譲るための印として
そのまま生きている。

**復活させるなら、器のことを先に思い出すこと**（一つ上の節）。`.screen` を
測る作りのままでは、紙が器になった三画面で「上端にも下端にも同時に居る」
ことになり、縦の指を毎回取って時間割が一切スクロールできなくなる。
- **段を替えられるのは掴み手（`.tl-grip`）からだけ。** 紙のどこを持っても
  下へ引けば暦が出る、という作りにしていた時期があるが、**戻した**
  ——読んでいて下を見ようとするたびに暦が伸びてきて使いづらい。途中で
  離すと中途半端に開いたまま残るのも、これが原因だった。掴み手は
  `touch-action: none` で、見えている棒（5px）より広く**上下12pxずつ**
  （29px）取ってある。
- **掴み手は sticky。** スクロールしても居なくならない。貼りつく高さは
  `calc(var(--topbar-h) + var(--cal-h))` ——上のバーも暦も sticky で上に
  居るので、数えないと掴み手はその裏へ潜って消える（実際そうなっていた）。
  暦は組み直しのたびに別の要素になるので、そのつど測り直して見張る相手も
  付け替える（`fitCalH`）。**ダイエットは `--topbar-h` を誰も測っていな
  かった**ので、この画面だけ床が 0 で、下まで送ると掴み手が上のバーの裏に
  潜って掴めなかった（＝段を替えられなかった）。いまは `fitTop` が測る。
- **「引いて更新」に譲る印（`data-pull-own`）は掴み手だけに付ける。** 紙
  ぜんぶに付けていた時期があり、そのあいだダイエットでは引いて更新がまるごと
  効かなかった。段を替えられるのが掴み手だけになったいま、紙の本体は
  引いて更新のもの。
- 取ると決める前でも、掴み手にいてその向きへ行けるあいだは `touchmove` を
  渡さない——送るのを止められるのは `pointermove` ではなく `touchmove` のほう。
- 指を離したら、行き先まで滑らせて**から** `setCalPref` に書く。先に書くと
  暦が組み直されて、途中の姿から跳ぶ。
- `settlePeek` の途中で選択中の字を放す。マウスで引くと字が選ばれ、次に
  その上から引いたときブラウザが「選んだ字を運ぶ」と判断して
  `pointercancel` を投げてくる。
- 週で見ているあいだ、紙は `data-pull-own` を持つ。`pull-refresh.js` は
  この印の中から始まった手つきを拾わない（同じ指を二つが取ると、暦が
  伸びながら画面ごと下がる）。**月が出ているあいだは印を外す**ので、
  下向きは「引いて更新」に戻る。

### 紙を閉じると、書きかけは**保存される**（`ui.js` の `tryClose`）

×・下へ払う・外を押す・Escape——どれも「やめる」の合図だが、**書いたものを
捨てる合図ではない**。`guard: true` の紙は、閉じようとした時点で中身が変わって
いれば、**保存のボタンをそのまま押す**。聞かない——保存のボタンがそこにあって、
押せる状態で、中身が変わっているなら、答えはもう決まっている。

聞くのは、**押しても保存が通らなかったとき**だけ（体重が空、のような検算で
止まる紙）。どの保存も最後に `handle.close()` を呼ぶので、**閉じたかどうか**が
そのまま「保存できたか」の返事になる。閉じていなければ一度だけ聞く
——「保存しない」を選ぶ道が無いと、直せない欄を抱えた紙から出られなくなる。
`confirm` は流された（外を押した・Escape）ときに `false` を返すので、
**「捨てる」ほうを ok に置く**（false ＝ 何もしない＝紙は開いたまま、が安全側）。

**見張る範囲は紙ぜんぶ。** `.sheet-body` の中しか数えていなかったが、
**やることの題の欄は頭（hero）にいる**——題を打ち替えただけだと「何も変わって
いない」と判定され、下へ払うと**黙って捨てられていた**。欄がどの段にあるかは、
書いた人にとって何の意味も持たない。数えないのは帯（footer）の中だけ
（押せば決まるもの）。

Escape も `tryClose` を通す（`handle.tryClose`）。閉じ方が四つあるなら、
四つとも同じ扱いにする。

### 紙は、指につく（`ui.js` の下へ払って閉じる）

三つ直した。**どれも「指と絵が切れていた」ことの別の顔**：

- **① 紙が指についてこなかった。** 指の位置を毎フレーム書いているのに、
  `.sheet` は「`--m-sheet-close` かけて動く」を着たままで、一フレームごとに
  なめらか移動がやり直されていた（実測：指の位置を当てても移動時間は 0.3秒の
  まま）。**掴んでいるあいだは `transition: none`。**
- **② 速さを見ていなかった。** `dy > 90` の距離だけだったので、**ぱっと弾くと
  戻り、のろのろ 95px 引くと閉じる**——iPhone の紙と逆。境目は**紙の丈の 22%**
  （56〜140px で頭打ち。短い紙で 44px、長い紙で 154px では同じ手つきが紙に
  よって別物になる）＋**勢い**。実測で、同じ 44px が速さだけで閉じたり戻ったり
  する。
- **③ 上へは道が無かった**（`dy > 0` 以外を無視）。`rubber` でついてはくる形に。

閉じるときは**下へ帰す**（指が下へ送ったものが ＋ へ飛んで戻るのは、いま
自分がした動きと逆なので）。**保存が通らなかった紙は閉じない**ので、下げた
ぶんを戻してやること——さもないと開いたまま画面の外に居る。

**掴み手（`.sheet-handle`）は 40×4px だが、指の的は 96×40px**（`::after`）。
見えている棒は 4px のまま。`touch-action: none` は掴み手と頭の行の両方に
——止めるのはブラウザの送りであって、押したことではない（× は押せる）。
