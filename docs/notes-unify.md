## 形（データ。移行なし）

- 入れ物 `kaimono-note-notes` の版も棚も変えない。足す欄は、どれも**無ければ今のまま**の意味：
  - `parent`：親のノートの id。無い・見つからない・親が消えた → 一番上に並べる（書き換えない）。
  - `emoji`：Notion のページの絵文字。持つだけで画面には出さない。
  - `src`：取り込んだもの `{from, key, batch}`。二度取り込んでも増やさない（`key`）・取り込みごとに取り消せる（`batch`）。
- ノートブックは今のまま名前の札（1ノートに一つ）。**子は親と同じ値を持つ**——別のノートブックへ移したら子孫まで
  書く。読む側（絞り込み・検索・書き出し）は今のまま `notebook` を見ればよく、1件ずつのファイルもそれだけで分かる。
- 輪（自分の子孫の下へ移す）は作らせない。二台が同時に移して輪になったら、輪の中で id の一番小さいノートを
  一番上へ出す（どの端末でも同じ答えになる）。
- 親を消すと子孫も同じ時刻の印で消す。戻すと一緒に戻る。
- 印はノートブックの色の丸（`.chip-dot`）だけ。ノートごとの絵・色は持たない。

  ノートブックの行の頭に「すべてのノート」＝**今の一覧そのまま**（平らに全部・並び・絞り込み・検索）。

- 数は出さない（中のノートの件数も）。ノートの面は daily と同じ「評価しない」の見張り（`tests/daily-rules.js`）の下。

## 書き方：見たまま（notes.md 段4の「書くときは印」から上げる）

- **しまう形は今のまま Markdown（打ったまま）**。見たままは画面の上だけ：開くとき Markdown → 行の並び、
  しまうとき行の並び → Markdown。同期・書き出し・出口はこの形に頼る。
- 一行が一つの塊（段落・見出し・箇条・番号・チェック・引用・線・画像）。一行の中は太字とリンクだけ。
  行頭に「# 」「- 」「[] 」と打つと、その形に変わる。
- **知らない形はそのままの行**（表・コード・HTML・斜体など、取り込みで来るもの）：素の字で見せ、字として直せる。
- 開いたとき「並べて→戻す」が元と一字でも違うノートは、黙って今の「印」で開く（崩して保存しない）。
  「⋯」からいつでも印に切り替えられる。
- 罠：変換中は画面の中身に触らない（`compositionend` まで待つ）。確定の Enter と改行を取り違えない
  （`tests/ime-enter.js`）。iPhone の Safari は Claude が試せない → 段ごとに実機で。

## 同期（Dropbox。ノートだけ）

daily・やること・買うもの・ダイエットは今の控え（一方通行）のまま。記録本体（localStorage）には触れない。
つなぎ方・権限・App folder は今のまま。

### 置き場

| 場所 | 中身 |
|---|---|
| `kurashi-latest.json`・`daily/`・`images/` | 今の控えと画像（変えない） |
| `notes/<題> <id の頭6字>.md` | **本物**。1件1ファイル、平らに置く |
| `notes/.trash/` | 消した印のノート（30日で本当に消す） |
| `files/<SHA-256>.<拡張子>` | PDF・原本の画像。名前＝中身なので上書きしない |
| `notes-sync/pack.json` | まとめの写し（作り直せる） |
| `notes-sync/labels.json` | ノートブック・タグの色 |
| `imports/<日付>/` | 取り込んだ元のファイル（`.enex`・Notion の zip）をそのまま |

- **入れ子のフォルダにしない**：親の題を変えるたびに子孫が全部動き、二台で同時に動かすと割れる。階層は YAML の
  `parent` で持ち、フォルダの入れ子は書き出し（出口）で作る。
- 名前は見るためだけ、**id は YAML の中**。題を60字まで（出口7）、使えない字（`\ / : * ? " < > |`・頭と尻の空白と点）
  は置きかえ、NFC にそろえる。後ろの id の頭6字で、同じ題・大文字小文字だけ違う題でもぶつからない（それでも
  ぶつかれば字を足す）。題の無いノートは作った日。題を変えたらファイルを移す。
- 中身：頭に YAML（`id`・`title`・`created`・`updated`・`notebook`・`tags`・`favorite`・`parent`・`deleted`・
  `emoji`・`source`・`format: 1`。時刻の書き方は書き出しと同じ）、続けて本文を打ったまま。**`# 題` を足さない**
  ——読むときに外し損ねると、合わせるたびに見出しが増える。

### 合わせ方

- 端末ごとに覚える（入れ物の meta、ノートごとに `sync:<id>`）：Dropbox のファイルの id・場所・版（rev）と、
  最後に合わせたときの欄（題・ノートブック・タグ・★・親・消した印）と本文のハッシュ＝**元**。
- **送る印は、ノートを書くのと同じ取引で**付ける（`out:<id>`。前の版と同じ）。ノートを書く道はすべて付ける
  （★・札・名前の付け替え・移す・消す・戻す・本当に消す）——漏れた直しはほかの端末へ行かない。題も本文も空の
  新しいノートは送らない。取ってきた中身と覚えた rev も同じ取引で書く。
- 送る：`mode: update(<覚えた rev>)`。間にほかの端末が直していたら断られる → 取ってきて三方で合わせてから送る。
  **上書きを時計で決めない**（ずれる）。
- 三方で合わせる：片方だけが変えた欄はその変更を取る。両方が本文を変えたときだけ、`updated` の新しいほうを本文に、
  もう片方を前の版へ（「⋯」の前の版に「二つの版」の印）。どちらの中身も残る。
- 取る：`list_folder` の続き（cursor は meta）。開いて見ているあいだは `longpoll` で待つ。**外から来た変更には
  送る印を付けない**（付けると送り返し合う）。合わせるのは一度に一本（送ると取るを重ねない）。
- 開いて書いているノートに変更が来たら、紙を閉じてから合わせる（書いている字の下で中身を替えない）。
- 消す：消した印 → ファイルを `notes/.trash/` へ。30日で本当に消す → ファイルも消す。ほかの端末は「覚えたファイルが
  無い」で消す。だから消した印を長く持たなくてよい（久しぶりの端末も覚えた rev で見分ける）。ただし手元で直して
  いたら**直したほうが勝つ**（送り直す。消えるより残るほうへ倒す）。
- **一度にたくさん消えたら止まる**：覚えたファイルの多くが一度に無くなっていたら（`notes/` ごと消した・別の Dropbox
  につないだ・Dropbox 側の事故）、手元は消さずに止めて一言訊く。
- はじめて合わせる端末：**足し合わせる。どちらも消さない**（手元にだけ → 送る、Dropbox にだけ → 取る、同じ id が
  両方 → 元が無いので本文の新しいほうを、もう片方を前の版へ）。始める前に控えを取る。別の Dropbox につなぎ直した
  ときも、覚えたものを捨ててここから。
- 新しい端末は先に写し（`pack.json`）を読み、`list_folder` の rev と違うものだけを1件ずつ取る。**写しよりファイルが
  正**。写しは合わせ終えた端末が1日1回まで書き直す（誰が書いてもよい）。
- 画像は今の `images/<id>.jpg`（名前＝中身）。手元に無い画像は、開いたときに取ってしまっておく。
- 外で直した `.md`（YAML に id のあるもの）は取り込む。id の無い `.md`・読めない YAML は**読まず・消さず・上書き
  せず**、手元を変えない。
- 取るのは同時に4本まで。書くのは一本ずつか束（`upload_session/finish_batch`）で——同じ Dropbox へ同時に書くと
  429（`too_many_write_operations`）。429 は `retry_after` だけ待つ。
- 前の版は端末ごと（合わせない）。Dropbox の版の履歴（期間はプラン次第。B4）も控えになる。

### 守り

- **二台めからは控えを送らない（同期より先に入れる）**：ノートのために iPad・パソコンをつなぐと、記録の空の端末が
  今の控え（`kurashi-latest.json` の上書き・その日の `daily/` の先取り）を空の記録で埋めうる。控えを送るのは記録の
  ある一台（今の iPhone）だけ。見分け方は作るときに（控えに端末の印を入れる案）。
- 色は `labels.json` で合わせる。端末での置き場（今は store の `settings.noteColors`）をノートの入れ物の meta へ
  写すかは、作る前に利用者に言う（写しても元は消さない）。
- 鍵（`lock.js`）はそのまま。なくした端末は Dropbox の「接続済みのアプリ」から切る（`invalid_grant` →
  「つなぎ直しが要ります」）。
- 復元（ファイル・自動の控え）で足したノートは、ほかの端末にも行く（消したはずのノートも戻る）。
- 画面：合わせている最中の印は出さない。送れないまま3日で歯車に点（今の控えと同じ）。設定のノートに「同期」
  （入り切り・最後に合わせた時刻・今すぐ合わせる）。

## 取り込み（Notion・Evernote。パソコンで）

- 流れ：設定 → ノート → 取り込む → ファイルを選ぶ → **先に見せる**（件数・画像・PDF・表・落ちるもの。数を出すのは
  この紙の中だけ）→ 控えを取る → 取り込む（途中で閉じても続きから）→ 元のファイルを `imports/<日付>/` へ。
- 取り込んだノートは `src.batch` を持つ → 「この取り込みを取り消す」で消した印（30日）。取り込んだあと直したノートは
  残す。二度目は `src.key` が同じものを飛ばす。
- 日付は元の作った日・直した日（Notion は無いことがある → 取り込んだ日）。
- ノートブック：Evernote はファイル（ノートブック）ごと、Notion は一つ（名前は先に見せる紙で変えられる）。
- 本文は Markdown に。取り込んだ中のノートへのリンクはつなぎ直す（`[題](note:<id>)`）。外へのリンクは字のまま
  （押すと開く。fetch しない）。
- 画像：縮めたものを今の画像の入れ物へ、原本は `files/` へ。PDF は `files/` へ置き、字は取り込むとき一度だけ
  pdf.js で取り出して検索に使う（meta `ft:<SHA-256>`）。
- Evernote：ENML → Markdown（見出し・箇条・チェック `en-todo`・太字・リンク。表はそのままの行）。暗号化した文は
  一行の印にする（元は `imports/` の原本に残る）。スタック・リマインダーは落ちる（先に見せる）。
- Notion：`<題> <32字の id>.md` と同じ名前のフォルダ → 親子。`key` はその32字。データベースの CSV → 表のノート
  （下）、行のページ → その子。大きいワークスペースは zip が分かれ、zip の中に zip がある。
- 罠：落ちるものは消さずに見せる。読めないファイルが一つあっても、ほかは取り込み、読めなかったものの名前を残す。

## 表（取り込んでから決める）

- それまで、Notion のデータベースは「表のノート」：本文に CSV（`files/`）を指す一行を置き、読むときは表の形
  （横に送れる）で、読むだけ。行のページは子のノート。
- 取り込んだ実物を一緒に見て、作る列の種類（字・数・日付・チェック・選ぶもの）と並べ替え・絞り込みを決める。
  数式・リレーションは値（字）だけ。

## 懸念・限界・デメリット

### A. データの安全

1. **同期は間違いも広げる**。一台で消した・壊した・取り込み損ねたものが全部の端末へ行く
   → 同期とは別に日付つきの控え。消すのは印だけ（猶予つき）。取り込みは控えを取ってから。
2. **同じノートを二台で直す**と、後から書いたほうだけ残せば片方が消える → 両方残す（競合の写し・前の版）。
3. **端末の時計のずれ**で新旧を取り違える → 時計でなく Dropbox の版（rev）で上書きを確かめる。
4. **長く開かない端末**：消したものが生き返る → 覚えた rev で見分ける（上の「合わせ方」の「消す」）。
5. **端末の保存が消える**（iPhone の空き不足・Safari の掃除）→ Dropbox を正、端末は写しに。ホーム画面のアプリで使う。
6. **取り込みは一度に数千件** → 件数と落ちるものを先に見せる・控え・取り込んだ分だけ消せる印。パソコンで。
7. **鍵の端末が増える**：なくした端末から読まれうる → Dropbox 側で接続を切れる。端末のパスコード頼み。
8. **暗号化するか**：Dropbox に素のまま置けば、乗っ取られたとき読まれる → しない（答え7。Dropbox の2段階認証で守る）。

### B. 同期の限界

1. iPhone は閉じているあいだ同期しない（Safari に裏の同期が無い）。開いた直後の数秒は古い。
2. 電波が無いと他の端末の変更は来ない（書けはする。戻ったら合わせる）。
3. 新しい端末の初回は時間がかかる（数千件＋画像・PDF）。画像・PDF を要るときに取る形にすると、
   電波の無いところで古いものが出ない。
4. Dropbox 頼み：アカウント・API の変更・接続切れ（つなぎ直し）。Dropbox の版の履歴はプランで期間が限られる。
5. 二人で同時に書く（共同編集）は作らない。

### C. Notion・Evernote にあって作らないもの

- 共有・共同編集・Web 公開・AI・埋め込み（動画・地図）・段組み・同期ブロック。
- 表の数式・リレーション・ロールアップ・ボード／カレンダー表示（要るものだけ一部）。
- ブロック（入れ子のブロック・つまんで並べ替え）。見たままは行ごと（上の「書き方」）、一行の中は太字とリンクだけ。
- ページの絵文字アイコン（UI に絵文字を出さない決まり）→ 色の丸だけ。絵は描かない。
- Web クリッパー（共有シート＋ショートカットで近いものは作れる）。
- 画像の中の文字で探す：新しく撮る分は iPhone のショートカット（テキストを抽出）でなら。Windows では無し。
- 手書き（いつか6つ目のタブ）・音声メモ・リマインダー（やることタブが代わり）。Windows ではショートカット連携
  （カレンダー・健康）なし。

### D. 移行で落ちるもの

- Evernote（`.enex`、ノートブックごと）：スタック、ノート間のリンク（切れうる）、暗号化した文、
  リマインダー、凝った Web クリップの見た目（字と画像になる）。
- Notion（Markdown と CSV、ワークスペースごと）：表示の切り替え、数式（値だけ）、リレーション（名前の字だけ）、
  ページのアイコン・カバー、作った日（残らないことがある）、コメント、埋め込み。
- 画像は今、長辺1600px に縮めて持つ（image-design.md）→ 書類のスキャンは細部が落ちる。原本は Dropbox の `files/` へ。
- 移したあとも、しばらく Notion・Evernote は消さない（読み比べの期間）。

### E. 見た目・使い勝手

- iPad の分割表示（狭い幅）・キーボードの有無・Windows の字（游ゴシックは細く見える）は実機で見る。
- iPhone では木を出さない（ホームから降りる）。深い階層は道すじが長い（「…」で畳む）。
- 日本語入力：変換の確定の Enter と改行を取り違えない（`tests/ime-enter.js` の決まり）。見たままで一番崩れやすい。
- **数が増えると重い**。見本で CPU を4倍遅くして（電話のつもり）3000件：起動0.7秒・一字の検索0.02秒、
  30000件：起動2秒・一字の検索0.2秒。全件を記憶に読む今の作りの限界 → 数万件なら索引・後から読む工夫が要る。

### F. 作る・保つ費用

- 10〜15セッション。段ごとに実機（iPhone・iPad・Windows）で触ってもらう。Claude が試せるのは
  Linux の Chromium だけ（Safari と Windows の実機は確かめられない）。
- 足すほど不具合の余地が増え、ほかのタブに響く恐れ → ノートは記録本体と分けて作る。
- 保つのも Claude 頼み。止めても読める形で持つことが保険。
- 自由を足しすぎると Notion の重さ・迷いが戻る → 作るのは上の答えの分だけ。
- 配信は GitHub Pages 頼み。止まってもデータは Dropbox に残り、アプリは1ファイル版
  （`build-standalone.js`）でも動く（そのときは控えから戻す）。
- ホーム画面のアプリの扱いは Apple 次第（2024年に EU で一度外されかけ、撤回された）。

## 出口：長く持つ・ほかへ移れるための決まり

1. 開いた形で持つ：本文は Markdown（UTF-8）、頭に YAML（id・題・作った日・直した日・ノートブック・親・タグ）。
   表は CSV（Excel 用に BOM）。画像・PDF は元のファイルのまま。
2. 書き出しでは、階層はフォルダの入れ子（Obsidian・Notion の取り込みが読める形。見本の書き出しで確かめられる）。
   Dropbox の同期の置き場は平ら（階層は YAML の `parent`）。
3. id と日時を必ず持ち出す（移った先で並びと日付を保てる）。
4. 原本を残す（縮めた画像だけにしない）。
5. 年に一度、丸ごとの書き出しを日付つきで Dropbox の別の場所へ（版の履歴は期間が限られるので）。
6. 書き出し→取り込みで同じに戻ることを試験で見張る。形を変えるときは版の印（`format`）を上げる。
7. Windows のパスの長さ（260字）：深い階層×長い題で開けなくなる → 名前は60字で切る（見本はそうしている）。
