### 一日の道（Task / Schedule 2.0・`js/day-road.js`）

2026年9月29日。利用者の声「どのアプリを使っても、タスク管理・スケジュール管理が
うまくいかない」と、手描きの絵（左上の「5:30」から右へ伸び、端で折り返しながら
「22:30」で終わる太い道。病院は道の上のふち取りした区間、いまの自分は道に立つ人、
そばに色の丸がふたつ）から。やることの紙の頭に、その日を**一本の道**にした地図を
置く。下の時間割は残す——道は**一日の地図**、時間割は**一つずつ手を動かすところ**
（まず全体、細部は求めに応じて）。設定「一日の道を出す」（`todoRoad`、既定で出す。
`!== false` なので移行なし）で外せる。
- **tasks の席をもう一度押すと時間割へ、また押すと道へ**（2026年10月6日・`again()`）。道が半分以上見えていれば
  時間割の頭へ、そうでなければいちばん上へ。道を出していなければ今までどおり（`app.js` の席の click）。

#### なぜ道か
**なぜ道か。** 時間割の行は時間に比例しない（Structured の作り）ので、午後が
6時間空いていても15分の隙間と同じ高さにしか見えない。「今どこで、この先に何が
あって、あいだがどれだけ空いているか」が形で読めない。道は時間に比例し、蛇行
（すごろくの道）で一枚に一日ぶんの長さを稼ぐ——まっすぐ縦だと 18時間を 250px に
詰めることになり、30分が10pxになる。

#### 決めごと（ここを崩すと、道が嘘をつく）
**決めごと（ここを崩すと、道が嘘をつく）**

- **時刻を決めたものは停留所。** 長さを決めたものは区間、決めていないものは点
  （丸薬と同じ：決めていない長さは描かない）。ふちは塗りの色、中はまだなら白。
- **時刻を決めていないものは、道に置かない。人と一緒に歩く「連れ」。** 人の頭の
  高さで、人の**後ろ**に並ぶ（丸の中は丸薬と同じシルエット）。道に置けば
  「10:42 書類整理」という、決めてもいない約束に見える——予定が崩れるたびに嘘に
  なる時刻（計画の錯誤で、見積もりはたいてい短い。暦に書くのは決まった約束だけ、
  という GTD の考えと同じ）。
  - **連れを道の上（人の後ろの道）に並べるのは試して外した。** 道の上は時刻そのもの
    なので、「7:20 にメール」と、過ぎた時刻に置いたように読めた。
  - 後ろに入りきらない（段の頭に居る）ときは、まとめて前へ。5件を超えたら最後の
    丸を「+n」にして、押すと時間割へ送る。
  - 時間割のほうの「ごろ」（B6）はそのまま。「順にやると、このあたり」という目安で、
    道の「時刻を決めていない」と食い違わない。
- **毎晩の、時刻を決めていないもの**（`part: "dusk"`）だけは連れにせず、夜の組み立ての
  場所に**点線のふち**と「◯◯ごろ」で置く（寝る前のことは夜に居るほうが本当）。
- **済ませた、時刻の無いものは、押した時刻の道の上に足あと**（白い粒）。写さず引く
  ——`doneAt` からそのつど。時刻を決めたものは停留所が塗りきられ、札の題に取り消し線。
- **歩いたぶんの道は塗り、これからは薄く**（時間割の `--pass` と同じ言い分）。今日だけ
  人が立つ。先の日はぜんぶがこれから。
  - **歩いたぶんの道と、通った・済ませた停留所は少し薄い塗り（`--road-past`、塗りの 65%）。
    いまの丸（`.is-live`）だけ濃い**（2026年10月3日・利用者が 45%／65% と今の一色を並べて
    選んだ）。上の時刻は白のまま（「過去のものとして目立ちすぎなくていい」）。橙の延び
    （`.is-late`）は薄めない。過ぎた日の停留所は塗ったまま（上の A）。停留所は `.is-past`。
  - **過ぎた日は、道を「これから」の薄い色のまま、停留所だけ塗る**（2026年9月29日・A）。
    前は道ぜんぶを歩いたあとの色に塗っていて、停留所（ふちも塗りの色）が道の塗りに沈み、
    その日に何があったかが形で読めなかった。
  - **過ぎた日は、押した時刻（`doneAt`）まで区間を延ばさない**（同じ日・C）。決めた区間の
    まま描き、押した時刻に足あとと同じ小さな白い粒（`.road-steps.is-stops`、区間の中なら
    その車線に）。延びは「いま」に向けた今日だけの話で、振り返りでは決めた形のほうが
    読める。今日の描き方（橙の延び・済ませた時刻で止まる・歩いたぶんの塗り）は変えない。
    試験：`tests/road-late.js` の「過ぎた日」、`tests/day-road.js`。
  - 道の「これから」は灰色ではなく**塗りの24%**。道は面が広く、灰色だと紙の地に沈む。
  - 停留所の中に居るときは、人は**ふちの上**に立つ（道の太さに立たせると足が埋まる）。
- **次の一行**：「次は 13:00 病院 · あと5時間17分」／停留所の途中なら「いまは 病院
  （14:30まで）· 次は …」／この先に無ければ「このあと、決まった予定はありません」。
  「あと」は次の決まった予定までの**空き**で、急かす数ではない。今日だけ。
- **評価しない。** 遅れ・予定通り・達成・割合・警告の色を出さない。空きを「埋める
  べき余白」として描かない（空いた道は、ただ道）。試験が禁止語と絵文字を見る。
#### 道は一本
- **道は一本**（2026年10月3日・利用者の声「時間を超過した方が超過したところまで伸びて、
  次の予定がそこから始まった方がいい」、`shape`）。時刻の重なった停留所も車線に割らない。
  - **押すのは始まりが重なるときだけ**（同日・利用者の声「始点が重なるのは困るけど、途中から
    途中まで、途中から終わり過ぎまでで重なるならまだ判別できる」）。前の丸薬の途中から始まる
    ものは予定どおりの位置に**上に重ねて**描く（あとに始まるほうが上。paint が `.road-stop` と
    `.road-hit` を `d0` 順に並べ替える＝押しても上のものが開く）。
  - **上に重なった丸薬は中を斜線に**（同日・利用者の声「重なっている丸薬の見た目同士が全く同じ」。
    色・点々・細く・背景色の縁・組み合わせを見比べて、斜線だけに）。`s.over`→`.is-over`、
    `.road-stop-hatch` を道ごとの `mask`（斜線の形）で抜く＝色は `--road-go` のまま（橙・過ぎた日にも合う）。
    歩いた塗り（went）は上に来るので、塗ったぶんには `.road-stop-went-hatch`（同じ形の白い斜線）を重ねる
    （10月6日・利用者の声「片方は斜線になるんじゃなかったっけ」。前は過ぎると斜線が塗りに隠れた）。
  - 始まりが停留所の太さ（`STOP`＝丸い端の径）より近い丸薬があれば、その（延びた）終わり
    （`eu`）から始まったものとして描く（描く始まりは `ga` と `d0`）。**終わりは動かさず、始まり
    だけ遅らせて縮める**（就寝を越えない）。押されて始まりが決めた終わりを越えても最低1分。
  - **札は予定・道は実際の流れ。** 札の時刻は `clock(s.at)` のまま。予定（`at`/`until`）も記録も
    書き換えない（描くたびに引き直す）。
  - 前の用事のあいだに済ませたもの（`doneMin` が前の終わりより前）は押さず、本当の時刻に置く
    （後ろへ回すと、済ませた時刻と違うところに立つ）。前の丸薬の上に重なって描かれる。
  - 押し合った用事どうしは一つの群（`cl`）。札が入りきらなければ群の札に「ほか n」。
  - 前は車線に割っていた（9月29日〜10月3日、`laneOut`・`LANE_P`・`.is-lanes`・`bump`。外した）。
    内側の車線へずれた丸薬が道から浮いて見え、済んだ長い用事が中心を取ると、まだの用事が
    はじかれた。`geom` の `point` / `path` の `off`（進む向きの左が正）は残っている（いまは常に 0）。
#### 過ぎてもまだの区間は、人の足もとまで延びる
- **過ぎてもまだの区間は、人の足もとまで延びる**（2026年9月30日・利用者の声「朝のルーティンは
  7時までなのに過ぎている。でも表示は何も変わらない」、`shape`）。長さのある停留所が、今日・
  まだ・終わりを過ぎていれば、終わりを「いま」に延ばし（`eu`）、済ませるまで**色を変える**
  （`.is-late`、`--road-late` の橙。塗りと同じ明るさで、赤＝警告にはしない）。済ませたら押した
  時刻（`doneAt`）で止まり、色は戻る（決めた終わりより後に済ませたときだけ延ばす）。
  - **「警告の色は出さない」をここだけ変えた。** 利用者が「普通の色とはちょっと変えて」と
    決めたもの。字では言わない（「遅れ」「超過」は出さない。試験が見る）。
  - 記録は書き換えない。描くたびに `doneAt` と時計から引く（写さず引く）。
  - 延びた終わりで札を見る。**まだの延び（橙）は次の停留所の上に重ねて人の足もとまで**、次の用事は
    ずらさない（2026年10月3日・利用者の声「超過オレンジは、次のタスクの上に重なるように。次の
    タスクは全くずらさずに」。前は次の始まりで止めていた＝押し出しがあったころの名残）。延びたぶんは
    押し出し・斜線の勘定に入れない（`own`）。橙はいちばん上に描く（押しても橙が開く）。
    済ませた延び（`doneMin`）は今までどおり次の始まりまで。
  - 道筋は paint が引く（`build` は空の path だけ）。形の見分け字（`st.sig`）が変わったとき
    だけ引き直す。（区間の終わりの時刻の札は、いまはどの区間にも出さない。下の「札の置き方」。）
  - 時間割の丸薬も「いま」まで伸びる（10月6日・下の「伸びる丸薬」）。**橙は道だけ**。段5の「時刻を過ぎたもの」とは別の話で、両方出る。
  - **決めた終わりより前に済ませたら、押した時刻で縮む**（2026年9月30日・利用者の声「12:00-12:30 の
    タスクを 12:02 で終えたのに、丸薬はそのままの長さ」）。延びと同じ言い分で、道の形はいまの本当を
    言う。始まりより前に押しても最低1分（丸い端どうしで、ほぼ丸）。今日だけ——過ぎた日は上の C の
    とおり決めた形のまま（押した時刻は白い粒）。
  - **済ませた時刻まで延ばすのは、次の停留所の始まりまで**（2026年10月1日・利用者の声「朝の
    ルーティンと朝のBabyのたった2つが重なったくらいで、道がおかしくないか」）。6:00〜7:00 を
    10:49 に押すと 8:00〜11:00 の用事まで延びて車線に割れ、塗りきった二本が一つの塊に見えた。
    押すのが遅れただけのことが多いので、決めた予定どうしが重ならないのに延びで重ねない
    （`shape` の `next`）。次が無ければ前のまま押した時刻まで。まだの延び（`is-late`）も同じく
    次の始まりで止まる。決めた予定どうしが重なっていれば、延びたぶん次が押される（一本道）。
  - **始まりより前に済ませたものは、済ませた時刻に置く**（同じ日・利用者の声「夜のルーティンは
    19:39 にすでに終わってるのに、道ではまだきていない20時に終わってることになってる」）。前は
    決めた始まりに1分の丸で残り、人より先の道に済んだ停留所が立っていた。`build` が `at` を
    済ませた時刻にし（長さのあるものは1分の丸、無いものは点）、札の時刻もその時刻（道の物差しと
    同じ）。記録は書き換えない。今日だけ（過ぎた日は C のとおり）。
  - 試験：`tests/road-late.js`、`tests/road-done.js`。

#### 寸法（`day-road.js` の頭）
**寸法（`day-road.js` の頭）**

- viewBox 幅 360（≒ iPhone の紙の中身の px）。広い画面では 440px で止める。
- **道の端は設定の一日（`dayStart`〜`dayEnd`）に固定**（`reach`、2026年10月6日・利用者の声「日によって
  動くのがとても分かりにくい。設定の一日の始まりと終わりの通り、固定で」）。起きた時刻でも、はみ出す
  停留所でも伸び縮みさせない。終わりより後の用事は端へ寄せる（`dist`）。
  **中身は実際に合わせる**（同日・利用者の声「長さは固定でも中身は実態を。改悪しないで」）：起きた時刻
  （`dayLog.wake`）が始まりより後なら始まり〜起床を寝床の紫（`.road-slept`・`--bed-frame` を薄くなった寝床と同じ 16%
  に紙の色と混ぜたもの。同日・利用者の声「紫が濃すぎる」）に塗り、
  起床より前の用事は起床に始まったものとして長さはそのまま後ろへずらす（`build` の `sh`・済ませた時刻
  まで延びるのはそのまま）。寝た時刻（`dayLog.sleep`）が終わりより前なら、そこから終わりも紫。寝床の下の
  時刻は実際の起床・就寝（無ければ設定の端）。試験：`tests/road-wake.js`。
  **早起き**（起床が始まりより前。10月7日・利用者の声「道の場所は固定して、寝る人を左にずらし道を左に長く」）：
  段の割り（`start`・`rowSpan`）は設定のまま、`geom` の `early` で道の頭（`begin`・`d0`）だけ一段目の左へ伸ばす
  （`point`・`path` は負の長さも一段目のまっすぐの延長）。寝床が `.day-road` の左の余白に半分入るところ（`EARLY_X`）
  が限り（5:30〜22:30 で 4:36）。それより早い起床は道をそこまで・寝床の下は本当の時刻（`st.woke`）、いびきも
  起床で止む。起床より前の用事は道の頭へ寄せる。
  **遅寝**も同じ（同日・利用者の声「道は絶対に変えずに、最後の道だけ右に長く。限界なら下の時刻だけ本当の時刻」）：
  `geom` の `late`（`bedIn` した就寝）で道の尻（`end`・`total`）だけ、最後の段のまっすぐを進む向きへ紙の端
  （`EARLY_X` と同じ余白）まで。最後の段は `point`・`path` が角を描かずまっすぐ延ばす。段の数と割りは変えない。
  限りより遅ければ寝床の下だけ本当の時刻、就寝まではいびきにしない。以下は経緯。
- **道の端（`reach`、2026年9月29日〜10月5日）**：設定の一日を、**はみ出す
  停留所まで伸ばし**（10月6日にやめた）、始まりは**ちょうどの時へ切り下げる**。終わりは切り上げない（手描きも
  22:30 で止まっていた）。描くだけで、設定も記録も書き換えない。
  - 利用者の画面（起きる時刻 6:30・毎日 5:30 の朝のルーティン）で、道が 6:30 から始まり、
    5:30 の用事が道の頭に**点で押しつぶされて**「5:30」の札が 6:30 の場所に立っていた。
    その下に区間の終わりの「6:30」も出て、「6:30」が二つ並んだ（二つ目は R17 の直しで消える）。
  - 始まりが「〜:30」だと、角は「〜:30」・目盛りは「〜:00」で、物差しが二つになっていた
    （利用者の声「曲がる部分の時刻がよくわからない。1時間ごとの切れ目は白い線？」）。一段は
    1時間単位なので、始まりをちょうどの時にすれば角もちょうどの時になる。
  - **切り下げるのは段の割りだけ。道そのものは 5:30 から**（2026年9月30日・利用者の声
    「やっぱり 5:00 じゃなく 5:30 スタートに。1行目の道が短くなってもいい」）。`geom(begin, end)`
    は `start`（ちょうどの時へ切り下げ。段・角・目盛りの物差し）と `begin`（道の始まり）を持ち、
    道筋・歩いたぶん・押せる道は `g.d0`（= `dist(begin)`）から。一段目は頭の30分ぶん短い。
    `dist` は `begin` より前を始まりに寄せる。空いた頭には朝の寝床が入る（下の「寝床」）。
    試験：`tests/road-bed.js`、`tests/day-road.js` の「道の端」。
- **目盛りは停留所の上にも**（同じ日）。道の目盛り（毎時ちょうどの白い短い線）は停留所の
  太い線の下に隠れて、利用者の一日では16本のうち5本しか見えていなかった。`paint` が停留所の
  中の目盛りを引き直す：塗ったところは白（`.road-ticks.is-over`）、まだの白い中は塗りの色
  （`.is-ink`）。停留所の始まりと終わりちょうどは札と丸い端が言うので置かない。車線に割った
  ものは車線の中（車線も同じ太さなので、長さは割らない）。夜のごろ（点線のふち）には置いていない。
- **停留所の太さ**（`STOP`、2026年9月30日・利用者の声「タスクの丸薬の太さを少し細く」）：
  ふち 21 → 16、中の白 16 → 11、塗り 17 → 12（ふちの幅 2.5 は同じ）。段7の点線の帯も 17 → 13。
  道（9）より太く、中の白が読める細さ。CSS の数と `day-road.js` の `STOP` はそろえること。
- **丸い端の外がちょうど始まりと終わり**（`capIn`、2026年9月30日・利用者の声「6:00 に始まるなら
  そこに始点が来るべきなのに、それより早いところにあるように見える」）。丸い端は線の端から太さの
  半分（8）外へ出るので、道筋を両端で8ずつ内へ詰める。塗り（`.road-stop-went`、半径6）も塗った
  時刻で止まるよう `to − 6` まで。太さより短い区間はまん中の丸。押す的（`.road-hit`）は詰めない。
  `tests/day-road.js` が端の位置を見る（区間の長さを比べる試験は +16 して比べる）。
- **済ませた停留所の札は、時刻も細い灰色**（同じ日・利用者の声）。題の取り消し線はそのまま。
- 一段は一日を**六段**（`ROWS`）に割って**1時間単位に切り上げ**（5:00〜23:00 なら一段3時間：
  8:00・11:00・14:00・17:00・20:00 で折り返す）。割り切れない日は最後の段が余りだけで、
  道はそこで終わる（7:00〜22:00 なら五段）。
  **（2026年10月2日から、角も時間を持つので割り方が変わった。下の「曲がり角も時間を持つ」。

#### 曲がり角も時間を持つ
- **曲がり角も時間を持つ**（2026年10月2日・利用者の声「1日の道の曲線部分にも、時間を
  持たせよう。結局は元に戻すことになるかもしれないけど、やってみよう」）。道は**どこでも
  同じ長さが同じ時間**（まっすぐも角も）。
  - 前は**折り返しは時間を持たない**（段の尻と次の段の頭が同じ時刻）だった。持たせると
    角の時刻が半端になり、角の札で物差しを言えない、というのがその理由。区間の終わりが
    境目ちょうどなら前の段の尻へ（`dist(t, true)`）寄せていた。角をまたぐ用事は時間の無い
    線を回り込み、人は角で次の段へ跳んでいた。
  - いまは**角のまん中（いちばん外へ張り出したところ）がちょうどの時**。角どうしの
    あいだが一段（`rowSpan`、1時間単位）。角 j のまん中が `start + (j+1)·rowSpan`。
    角の札は前と同じ場所（角の内側、まん中の高さ）で、前と同じく物差しを言う。そこに
    目盛りも置く（角の上の目盛りは外向き。`point` の `nx, ny`）。
  - そのかわり一段目の左の端と最後の段の終わりは半端な時刻（道は begin から描くので
    見えない）。一段のまっすぐは `rowSpan` の 65% ほど、角が 35% ほど。
  - `geom` は小さい `rowSpan`（2時間から）から、始まりと終わりがどちらも**まっすぐの上**に
    来て六段以内に入るものを探す（寝床は道の端の延長に置くので、端が角の上だと困る）。
    同じ一日が前より少ない段に入る：5:30〜22:30 は一段4時間の五段（角は 8・12・16・20時、
    高さ 516 → 428、15分は 21 → 24 単位で細かくなった）。5:00〜23:00 も五段。
  - 角の上で始まる停留所の札は、近いほうのまっすぐの端から置く（`flat`：角の前半はその段の
    尻、後半は次の段の頭）。角の前半で始まるものは、進む向きが角へ突き当たるので**逆向きを
    先に**試す（「買い出し 15:40」。進む向きのままだと「15:40 買…」に縮んだ）。

    （`standAt`）。向きは進む向きの角度で、角の中を **右 → 右下 → 下 → 左下 → 左** と移る
    （角の八分の一・四分の一・四分の一・四分の一・八分の一。`faceOf`。2.0 の V7、10月4日。それまでは
    左右だけで、角のまん中で返っていた）。5:30〜22:30 の五段の一つ目の角（7:18〜8:42）なら、
    右下は 7:29 から、下は 7:50〜8:10、左下は 8:31 まで。分が変わって歩くときは道の長さで進む（角を
    まっすぐ横切らない）。角の上に居るときの札の通りは、近いほうの段（`rowAt`）。
  - 元に戻すなら、この節の前の版（`geom` の `dist(t, tail)`）と `tests/day-road.js` の
    「折り返しは時間を持たない」の試験を戻す。

#### 札の置き方（`marks`）
**札の置き方（`marks`）**

札は段の上か下の「通り」に一行。置く順がそのまま譲る順：人の頭・連れ・いまの時刻
→ 停留所の「時刻 題」→ 夜のごろ。入らないものは出さない（区間は道に残り、押せば開く）。

- **区間の終わりの時刻は出さない**（2026年9月30日・利用者の声「時刻が書かれ過ぎていて
  読みにくい」）。前は45分以上の区間の尻に小さく「12:00」「15:30」と置いていて、角の時刻・
  札の時刻と合わせて一日に15ほど時刻が並んでいた（利用者の画面）。長さは道の形が言い、
  いまの区間の終わりは次の一行（「いまは 病院（14:30まで）」）、細かくは押して開く紙が言う。
  残る時刻は二段：札の太字（停留所の始まり）と、灰色の小さな物差し（道の端と角）。
  `tests/day-road.js` が `.road-until` の無いことを見る。

- **いまの時刻は人の頭の上**（2026年9月30日・利用者の声「現在時刻は分かりにくいので、人の頭の
  上に」）。前は人の足もとの下の通りにあり、隣の札の時刻（「12:00」と「12:20」）と並んで読み分け
  られなかった。高さは停留所のふちに立ったときの頭に合わせ（`STOP / 2 + ME_HEAD`）、上の段の下の
  通りに食いこむときだけそこを空けさせる。下の通りは札に空いた。
  10月6日（利用者の声「道と被ってしまう時はずらして」）：角のそばでは頭の真上が角や上の段の道に
  かかるので、かかるときだけ角の内側へ横に、要れば頭の高さまで下へずらし、人にいちばん近い所
  （`hypot(横, 下)`）を選ぶ。下げたら頭にはかぶらない。まっすぐな段のなかでは動かない。`tests/road-now-clear.js`。
- **入りきらない題は `cut` が見積もりで切って「…」を付ける**（同じ日・利用者の声「ジモティー
  受け渡し…   12:00 と、時刻と字の間が空き過ぎて同じだと思わなかった」）。CSS の省略は字の境目で
  切るので、かな漢字だと最大一字ぶんの空白が「…」の後ろに残り、左向きの札（時刻が右）ではそれが
  題と時刻のあいだに来ていた。見積もりで切れば余りは札の外側に出る。CSS の省略は 360 より狭い
  画面の受け止めに残す。`aria-label` は全文のまま。
- 停留所の札は始まりの点から**進む向きへ**。左へ進む段では並びを返して、時刻が
  始まりの側に来る（「病院 13:00」）。
- 試す順は、上に全部 → 下に全部 → 上で縮めて → 下で縮めて → 逆向き → 時刻だけ。
  **縮めるより、下の通りへ移すのが先**（「朝のル…」より、一段下で全部読めるほうがいい）。
- 出だしに人の頭などが居たら、**28単位までその先へずらす**（7:43 に立つと 8:00 の札の
  頭が人の頭に当たって、次の予定の札が消えていた）。
- 通りの**曲がり角の側は、角の手前まで**（特大の字で、札の尻が角の道に触れた）。
- 角の時刻（「10:00」）は、人がそこに立っているときは出さない（頭と重なる）。
- **同じ時刻を二度言わない**（R17、2026年9月29日）。7:00〜8:00 が段の終わりで曲がると、
  角の「8:00」と区間の終わりの「8:00」が上下に並んでいた（そのころは `said` に控えて
  区間の終わりを外していた。9月30日に区間の終わりの時刻そのものを出さなくなり、`said` は
  消えた）。`tests/day-road.js`。
  **角ちょうどに始まる停留所**も同じ（同日、iPhone で「8:00」と「朝のBaby **8:00**」が上下に）：
  札が置けたら、角の小さな時刻（`turnAt` で覚えた `out` の位置）を空にする。札が置けなかった
  ときは角の字を残す（時刻が消えないように）。
- **車線に割った群で札が入りきらなければ「ほか1」**（2026年9月29日）。道には車線が見えて
  いるのに札が黙って消えていたので。数は、入りきらなかった停留所と時間が重なり、札の出た
  停留所のうち**始まりがいちばん近いもの**へ寄せる（群の最初の札に付けたら、朝の長い用事に
  「ほか1」が付いて、昼の込み合いから遠かった）。「ほか1」の幅は一度目には分からないので、
  入りきらない札が出たときだけ、その幅を足して置き直す（足さずに添えると題が「…」につぶれて
  「11:30 ほか1」になる）。押せば添えた札の用事が開き、残りは時間割にある。
- **済んだものの札（名前だけ・丸薬のまん中）の引き出し線（`.road-ties`）は、要るときだけ**
  （2026年10月5日・利用者の声「その時間帯にひとつしかないなら、自明なので線はいらない」）。
  引くのは、その丸薬にほかの停留所が時間で重なる（長さなしどうし・片方が長さなしなら丸薬一つぶん
  の近さ）か足あとが触れる（`crowded`）、足あとがほかの停留所に触れるか「ほか n」でまとまる、
  または札が丸薬から `LANE + FS` より離れたとき。端が触れ合うだけの続きの丸薬は重なりに数えない。
  **曲がり角からは引かない**（同日・利用者の声「曲線から線を引くのはおかしい。文字の置き方で
  分かるように」）。まん中が角なら、札は角の内側の同じ高さ（上下一行ぶんまで、`placeArc` の
  `near`）に角の縁へ寄せて置く。入らなければ丸薬のまっすぐな部分のまん中（こちらは上の決めごと
  どおり線あり）、それも無ければ角の内側のどこか（線なし）。`tests/road-done.js`。
- **同じ時刻に始まる停留所は、短いほうを斜線**（同日）。前の用事のあいだに済ませたもの
  （`inside`）は押さずに置くので始まりが揃うことがある。`over` は「前の丸薬の途中から始まる」に
  加えて「始まりが同じで終わりが早い（同じなら一覧で後のほう）」。描く順も斜線が上。長さまで同じなら
  丸薬は全部が斜線に見え、下の用事は道からは押せない（札から開く）。

#### 描き直し（`paintNowAll`）
**描き直し**：組み直しはしない。**分の変わり目**の見回り（`paintNowAll`。2026年9月30日
までは30秒ごとで、時計が進んでから最大30秒遅れていた）と、アプリへ戻ってきた
とき（`wakeNow`：`visibilitychange` / `pageshow`）に `KN.dayRoad.paint` を呼び、**分が
変わっていたときだけ**歩いたぶん・停留所の塗り・人・札・次の一行を置き直す。

- **分が変わったら、人が歩いて次の足もとへ**（2026年9月30日・利用者の声「時刻が1分進むなど
  変わると、人が動くように」）。一分は道の上で1〜2単位しかなく、跳んでも見えなかった。
  `paint` が `walk(el)` を呼び、四歩のあいだに前に見た点（前の分）から今の足もとへ、道に
  沿って（角も回って）進む（下の「歩く」の追いつき。進み方は脚と同じ速さの台形）。組み直した
  直後の一度目の paint では歩かない。置き場所は `me.__at`・分は `me.__min` に覚え、歩き終わりに
  そこへ書き戻す。

#### 歩く
**歩く（2026年9月29日・利用者の声「タブを開いた瞬間、歩くみたいに」）**：やることを
開いた瞬間（`onEnter`）と、アプリへ戻ってきたとき（`wakeNow` の `visibilitychange` と、
bfcache からの `pageshow`）に、人が四歩あるいて、いつもの形で止まる
（`KN.dayRoad.walk`）。一歩は `--m-walk`（.3s）、速さの台形（はじめ15%で上がり、
おわり25%で止まる）を足して全体 1.5s。試験は `tests/road-walk.js`。

- **前に見た点から「いま」まで、道に沿って追いつく**（2026年10月4日・2.0 の V6。それまでは
  その場で四歩で、道の上は進ませなかった）。前に見たときから時間が進んだことは、道の上でしか
  言えないので。止まるのはいつも「いま」で、時刻の字・歩いたぶんの道・札は初めから「いま」
  ——追いつくのは人だけ（時刻は嘘をつかない）。分が変わったときの一歩も同じ歩き。
  - 前に見た点は localStorage の `kn-road-seen`（「日付 分」）。**store の外**なのでバック
    アップに入らない。日付が今日でなければ読まない（日をまたいで持ち越さない）。歩き出す
    ときに「いま」へ書き直す。寝床にいるあいだは書かない。
  - 離れすぎ（道の長さで `CATCH` = 120、約1時間より遠い。朝に見て夜に開くなど）は、終わりの
    120 だけ歩く。1.5s で一日を横切ると、歩きでなく滑りに見える。
  - 前に見た点が無い・同じ・先（時計が戻った）なら、その場で四歩。
  - 長さは「長くても約1.5秒」（V6 の決めごと）に合わせ、四歩は変えずに一歩を .4s → .3s に。
- **止まった形は、元の絵と同じ位置で、前に出ている脚を奥の脚として描いたもの**（`REST`、
  9月29日に利用者が選んだ。下の「腕」）。二周（一周で二歩）で、そこから出てそこへ戻る。
  終わりには `REST` の字をそのまま書き戻す（歩き終わりの形と字まで同じ）。
- 関節は絵から読む（腰・膝・足、肩・肘・手）。脚は二本の骨の IK で、膝は前へ曲げる。
  足の通り道は「着いたら後ろへ送られ、離れたら弧を描いて前へ」。届かなければつま先が
  浮く（蹴り出し）だけで、地面より下へは行かない。
- **腰のひねり。** 元の絵は手前の脚が長く、腰も手前が前にある（奥行きの描き方）。脚が
  前後を入れ替えるのに合わせて、腰の位置と腿・すねの長さも入れ替える。入れ替えないと
  一歩目が大股・二歩目が小股になり、足を引きずって見えた（試作で踏んだ）。
- **腕は脚と逆に、最初から最後まで振る**（9月29日・実機を見た利用者の声。それまでは最初と
  最後の一歩は腕を止めていた）。
- **腕は脚と同じ拍・同じ大きさで、はじめからおわりまで振る。歩き出しも止まりぎわも、半ばと
  同じ動きが速さの台形で速く・遅くなるだけで、腕と脚は同時に止まる**（9月29日・利用者の声
  「そのままの動きで遅くしてほしい」「①で足も同時に」）。脚とのずれはいつも **0.95π**：腕の端を、
  足がいちばん前（着いたところ）と、いちばん後ろ（一周の `stance` = 0.55）の**ちょうど中に**置く。
  - 9月29日は π（前に合わせる）で、腕が約18°早く返り、半ばでも一瞬「同じ側」になった——試験で
    踏んだ。そこで後ろに合わせて 0.9π にしたが、こちらは同じだけ遅れていた。足が入れ替わる瞬間に
    腕が同じ側に残る窓は、π でも 0.9π でも元の絵の単位で 88（`pose(τ)` で測った）。0.95π で 56 に
    なり、半ばの試験の 60 を割る（右下・下は 14）。
  - 10月4日に直した（2.0 の V7 の途中）。V6 で一歩を .3s にしてから、`tests/road-walk.js` の
    「半ばの腕は脚と逆」が毎回その窓（約13ms）を一コマ踏んでいた。門に入っていないので気づかれずにいた。
  振りの端は
  元の絵の腕と、その左右を入れ替えた角度（振りの幅も肘の曲がりも、二本の腕の差から出す）。
  - **元の絵は歩きに出てこない形**（手前の脚が前・手前の腕も前。歩けば手前の脚が前のとき、
    手前の腕は後ろ）。だから元の絵で止めようとすると、どこかで腕だけ別の動きが要った。
    **前に出ている脚を奥の脚として描けば**、同じ位置のまま「奥の脚が前・手前の腕が前」という
    歩きの一瞬になる（`REST_PH` = 0.5：奥の脚が前に着き、手前の脚が後ろ）。脚は元の絵の字と
    ぴったり同じ（前後の字が入れ替わるだけ）、腕は手の位置で 0.1px ほど（0.9π のときは 0.3px）、浮きは 0。見た目で
    変わるのは、前の脚が一段濃く（奥の脚の色）、後ろの脚が薄くなることだけ。
  - ここに来るまでに五つ試して外した（どれも 9月29日、利用者が実機で見て）：
    - ずれを途中で動かす（0 → 0.9π → 2π、はじめとおわりで大きく送る3乗）：脚が止まりはじめる
      70〜85% で腕がいちばん速く振れた（肩から手の向きの速さの最大：半ば 10.1 に対して 16.4）。
      歩き出しも 15.8。「人のアイコンも最後だけ動きが速くなっておかしい」。
    - 後半はずれを戻す（0.9π → 0）：急ぎは消えたが、後半ずっと腕が脚の半分の拍。脚が一周して
      同じ形に戻っても、手の位置が元の絵の単位で 355 ずれた。「まだ腕と足の速さが合ってない」。
    - ずれは一定、振りの大きさを 0 から育てて 0 へしぼませる：拍は合ったが、止まる直前（最後の
      15%）で脚はまだ進むのに腕だけ引き返した。「終わり方が不自然」。
    - 止まった形の腕だけ左右を入れ替える（手前の腕が後ろ）：動きはなめらかになったが、止まった
      形が「歩き掛け」に見えた。「最後のポーズがこの歩き掛けの感じなのは違和感がある」。
    - 両足がそろうところで立ち止まる（最後の一歩で後ろ足を前足の横へ下ろし、腰を伸ばす）：
      絵で見せて、利用者は元の絵の形を選んだ（試作だけ）。
  - 試験は `KN.dayRoad.pose(τ)`（経った割合 τ での形）を引いて、フレームの揺れなしに見る：
    歩きの頭から尻まで、脚が一周して同じ形に戻ると腕も同じ形（同じ拍・同じ大きさ）。はじめ・
    おわりの腕が半ばより速くない。止まった形は元の絵と同じ位置。
- 体は一歩ごとに少し浮く（片足で立つところがいちばん高い。元の絵の単位で 18）。腕は
  体と一緒に上下するので、「腕を振ったか」は字ではなく肩から手への向きで見る（試験）。
- 縁（halo）と絵は同じ形で動く（`data-w` で両方を引く）。書き換えるのは人の中の `d` と
  `transform` だけで、組み直しも測ることもしない。
- 歩いている途中にもう一度呼ばれても、頭からやり直さない（止まった形へ跳ぶので）。
  組み直しで人が DOM から外れたら、そこでやめる。読み込みの `pageshow`（persisted で
  ない）では歩かせない——そちらは `onEnter` が歩かせていて、挟まる組み直しで途中から
  頭へ跳ぶ。
- 動きを減らす設定では歩かない（`KN.motion.still()`）。
- **向きごとの歩き**（2.0 の V7・10月4日）。拍（一周の位置・浮き・腕のずれ）は五つの向きで同じ。
  向きごとに作り（`rig(face)`）を持ち、`walkPose(τ, face)`（試験からは `pose(τ, 向き)`）で引く。
  関節はどれもその向きの絵から読む。
  - 右（横）は上のとおり：両脚が同じ足の通り道を、腰のひねりを入れ替えながら歩く。
  - 右下と下は、**脚がそれぞれの列を離れない**（腰を入れ替えない）。足の通り道は自分の腰から引く。
    右下は、前の脚と後ろの脚の足の位置（腰からの差）を二本で使い、膝は前へ（二次元の IK）。
    腕は横と同じ回し方。
  - 下は足が横へ動かず、手前（画面の下）と奥（上）にだけ動く。**膝は二次元の IK で解かない**。
    縮んだ脚の膝が横へ折れるので、描いた脚の形を腰から足へ伸び縮みさせて置く（`shrink`。縮めた
    二本の骨）。腕も手前（長く下がる）と奥へ：描いた腕と、反対の腕を左右に返したものの間を振る。
  - 角を回りながら追いつくと、一コマごとにその点の向きで描く。向きが替わっても歩きは続き、
    それまでの向きは止まった形へ戻してから替える（隠れた形が、次に出たとき歩きの途中にならない）。
    歩き終わりは「いま」の向きの止まった形。
  - 試験は `tests/road-face.js`（8:00）。`tests/road-walk.js` は右向きを見るので 9:43（二段目の
    まっすぐ）に置いた。前の 7:43 は一つ目の角の上で、右下を向く。

#### 道の上で決める（段2）
**道の上で決める（段2・2026年9月29日）**：空いた道を押すと、その時刻と前後の空きを
出す紙（`as: "dialog"`）が開き、「時刻を決めていないもの」（連れと毎晩のごろ）から一つ
選ぶと、その時刻が付いて停留所になる（`decideOnRoad`：時間割で時刻の列へ運んだときと

- **押せるのは、これからの道だけ**（`.road-free`、`paint` が人の足もとから引き直す）。
  歩いたぶんに時刻を付けても過ぎた約束になるだけなので。過ぎた日は無し、先の日は道ぜんぶ。
  停留所の太い線（`.road-hit`）が後ろにあるので、重なれば停留所の紙が開く。
- 時刻は押した点にいちばん近い道の上の時刻を**1分ずつなぞって**探し（逆算の式は
  持たない）、**15分きざみ**に丸める（`snap`）。空きの頭より前・空きの尻（次の停留所の
  頭、一日の終わり）ちょうどへは丸めない。
- 空きは前後の停留所のあいだ（長さを決めていない停留所は点なので始まりで区切る）。
  **今日は「いま」から**（過ぎたぶんを空きと言うと嘘になる。`freeAhead` と同じ言い分）。
- **決めるのは本人。** 選ぶものが無ければ「時刻を決めていないものはありません」と
  言うだけ。新しく書く欄は出さない（入力を増やさない）。空きは長さを言うだけで、
  埋めるべきものとして言わない。
- くり返しの用事は**やる日（`due`）を動かさず**時刻だけ付ける（動かすと、その日より前の
  回が消える）。
- **札の層（`.road-marks`）は `pointer-events: none`、中の button だけ押せる。**
  層が図の上に一枚かぶさっているので、そうしないと下の透明な線に指が届かない
  （段1の停留所の太い線は、札を押す試験しか無かったので見逃していた）。

#### 崩れたときの置き直し（段3）
**崩れたときの置き直し（段3・2026年9月29日）**：済まなかったものは、前のとおり日の
変わり目に黙って今日へ運ぶ（docs/todo-items.md「期限切れは作らない」。9月27日の決めごと
を覆すか訊き、利用者は「自動で運ぶのは残し、上に置き直しを足す」を選んだ）。そのうえで、
運んできたものがある朝だけ、やることの頭（`.js-late`、期限切れの札と同じ置き場）に
「n 前の日から運んだもの · 置き直す」（`.tl-carry`）。押すと紙（`carrySheet`）で一件ずつ
「今日のどこか・明日・今週・長期タスクへ・やめる」。

- **運ぶとき時刻を外す**（`rescheduleOverdue`）。昨日の約束を今日の停留所にしない。
  外した時刻は印 `carried: { on: 運んだ日, time }` に控え、紙の「前は 13:00」にだけ使う。
  二日続けて運べば最初の時刻を持ち続ける。印は新しい欄で、無ければ「運んでいない」
  （移行なし・既存の記録は書き換えない）。
  - **印は `reconcile()` を通す**（`carriedField`）。はじめは通しておらず、同じ日に二回目に
    開くと印が落ちて頭の一行が消えていた（9月29日に直した）。日の読めない印は落とし、時刻だけ
    崩れていれば null。印の無い記録に欄は足さない。
- 対象は、くり返しでない用事と、期限の過ぎた長期タスク。**ルーティンは前のまま**（次に
  当たる日へ、時刻も持ったまま）。買い物の一件も前のまま。
- 数えるのは `carried.on === 今日` で、やる日が今日のものだけ（`store.carriedToday`）。
  日が変われば印ごと古くなり、また過ぎていれば運び直されて印も今日になる。
- 五つ（`store.settleCarried`、どれも「元に戻す」を返す）：
  - 今日のどこか → 印だけ外す（時刻はもう無いので「連れ」）。
  - 明日 → やる日を明日。
  - 今週 → 長期タスクにして期限を週の終わり（`weekOf(today).to`。週の始まりの設定に
    従う）。週の終わりまで二日を切っていたら**来週**の終わりで、札も「来週」。前から
    それより早い期限を持っていれば、そちらを残す。期限を越えれば、期限切れを作らない
    決まり②でまた今日へ来る。
  - 長期タスクへ → やる日を外す。過ぎた期限を持っていれば外す（持ったままだと見回りが
    すぐ今日へ運び返す）。
  - やめる → アーカイブ（消さない）。赤くしない——やめるのは失敗ではなく、選んだこと。
- 日か時刻を自分で決め直したら（紙で直す・道の上で決める・時間割で運ぶ）、もう
  「運んできたもの」ではないので印が外れる（`updateTodo`）。
- **評価しない**：件数だけ言う。「できなかった」「遅れ」「◯日持ち越し」は出さない。
  開いたときに割り込む紙にはしない（押したら開く）。
- 試験：`tests/carry.js`。復元の練習（`tests/restore-practice.js`）は、読み直しで付く
  `carried` と外れる `time` を「決まりどおりの動き」に数える。

  作ったので、**2026年10月27日ごろ**、溜まった控えを見て分け方（時刻の区切り・長さの区切り・件と回）を見直すこと。
- 試験は `tests/slips.js` の後ろ。

#### 組み直し（3.0 の B3・2026年10月6日）
- **口は理由があるときだけ**、時間割の頭（`.tl-sum`）に一行：「寝る時刻を ◯ すぎます」を**押せる**ように（`plan.over > 0`、
  今日だけ。`.js-refit`）。入りきっていても、時刻を過ぎたものが2件以上なら「組み直す」。色は変えない。
- **見積もりは `KN.plan.refit`**（何も書かない）：残り＝一日の終わり−いま−動かさないもの。動かさないのは時刻の決まった
  これからの用事（重なるぶん）とくり返し（時刻の無いくり返しは、組み立てでほかに押されて一日の外へ出ることがあるので、
  長さをそのまま）。入れるのは時刻なし・時刻を過ぎたもの。期限の近いもの（7日以内、近い順）→ いまの並び順で、
  **入るところまで**（一つ入らなければ、そこから後ろは全部入らない。並びの意味を崩さない）。長さは `minutesOf`。
- **紙**（`refitSheet`）：「残り ◯」・入るもの・入らないもの。入らないものに行き先の札：明日（既定）・後日（暦）・これから
  （3回以上置き直したものの既定）・いつか・今日は半分（45分以上。Reclaim の伸び縮み）・分ける（C1。紙を閉じて開く）。
- 「この形にする」で全部を一度に書く（`store.applyRefit`。明日・後日は控え hand）。**元に戻す一回で全部戻る。**
  紙を閉じれば何も変わらない。AI に組ませない・自動で動かさない（4節）。試験は `tests/refit.js`。

#### 自分の速さ（段4）
**自分の速さ（段4・2026年9月29日）**：くり返しの用事は、済ませた記録（写し）から
「いつもの長さ」をそのつど引き（`store.usualMinutes`）、決めていない長さの既定に使う。

- **記録は増やさない**（利用者に訊いて決めた。ほかの案は「手順の印に時刻を足す」
  「始めるを押す」）。始めた時刻は無いので、**時刻を決めてあった回だけ**、
  「済ませた時刻（`doneAt`）− 決めていた時刻（`time`）」を長さの代わりにする。
  時刻を決めていない用事は、いつもの長さが出ない（一つ前に済ませたものからの間を使う手は、
  あいだの休みが混ざって嘘になるので採らない）。
- 遅れて始めた日・あとでまとめて済ませた日は長く出る。だから **1〜240分の回だけ、新しい
  8回の中央値、5分に丸める**。別の日に済ませた回は数えない。**3回に満たなければ言わない**。
- 写しと元は `undoTrace` と同じく**題と区分**でつながる。題を変えるとそれまでの記録から
  切れる（ID で結ぶ欄は、記録を増やすことになるので足していない）。
- 数は保存しない（写さず引く）。`version` が変わるまで索引を使い回す。
- 使う場所：
  - `plan.minutesOf`：人が決めた長さ → いつもの長さ → 30分。時間割の「ごろ」と空き、
    持ち上げたときの長さ。
  - 編集の紙の「時間」の札（9月29日に「時刻と長さ」から分けた。docs/todo-items.md の「時間の札」）：「決めない」の次に「いつもの25分」の札（同じ長さの札は
    これに置き換え）。**押すまで決めない**（黙って `minutes` に入れない）。時刻の紙の下は
    「（長さを決めていないので、いつもの長さで）」。
  - 道の上で決める紙：選ぶものに「いつもは15分くらい」。
- **道には描かない**（決めていない長さは描かない、のまま。停留所は点）。
- **評価しない**：言うのは「いつもは◯分くらい」だけ。速い・遅い・前より・今日は長かった、
  は出さない。
- 試験：`tests/usual-pace.js`。

#### その日のうちの置き直し（段5）
**その日のうちの置き直し（段5・2026年9月29日）**：段3は日をまたいだ崩れを拾うが、
**その日のうちに崩れた瞬間**（10:00 にやるつもりの用事が、11時を過ぎてもまだ）を拾う
ものが無かった。道では時計が通った停留所は塗られ（済んだものとの違いは札の取り消し線
だけ）、「10:00」という過ぎた約束のまま後ろに残る。そこで、時刻を過ぎたのにまだのもの
がある間だけ、段3の札の隣（`.js-late`）に「n 時刻を過ぎたもの · 置き直す」（`.tl-passed`）。
押すと段3と同じ形の紙（`passedSheet`）で一件ずつ選ぶ。

- **数えるもの**（`store.passedToday`）：今日・時刻あり・まだ・くり返しでないもので、
  終わり（長さがあれば `time + minutes`、無ければ30分後）を過ぎたもの。いま中に居る
  停留所は数えない。時刻の早い順。
- **ルーティンは入れない**（時刻を外すと毎回の時刻が消える。段3と同じ言い分）。
- 五つ（`store.settlePassed`、どれも「元に戻す」を返す）：
  - いまから（`いまから（11:15）`）→ いまの次の15分きざみに付け直す。
  - 時刻を外す → 今日のまま時刻なし（連れ）。紙の頭に「時刻を外すと…連れに戻ります。道の
    空いたところを押せば、また時刻を付けられます」（段2へつなぐ。提案では「この先の道で
    選び直す」だったが、逆向きの時刻選びを新しく作るより、外して段2で選ぶほうが道具が
    増えない）。
  - 明日 → やる日を明日にして**時刻も外す**（過ぎた「10:00」を明日の約束にしない）。
  - 長期タスクへ → やる日を外す（過ぎた期限も外す。段3と同じ）。
  - やめる → アーカイブ（消さない。赤くしない）。
- **黙って時刻を外さない**（決めるのは本人）。開いたときに割り込む紙にもしない。
- 見ているあいだに時刻が過ぎることのほうが多いので、30秒の見回り（`paintNowAll`）でも
  数え直す（`paintPassed`。数が変わらなければ触らない）。今日を見ているときだけ。
- **評価しない**：件数だけ。「遅れ」「できなかった」「予定通り」は出さない。
- 試験：`tests/passed.js`。

#### 明日の最初の停留所（段6）

#### 出る時刻（段7）
**出る時刻（段7・2026年9月29日）**：病院や駅のように移動のある約束は、13:00 という時刻と
別に「何時に出るか」がある。停留所に「前に 15分／30分／1時間」を付けられるようにした。

- 新しい欄 `lead`（分。`store.cleanLead`：5分きざみ・3時間まで）。**無ければ前の時間なし**
  （reconcile で null。移行なし・既存の記録は書き換えない）。時刻が無い用事は持たない。
  時刻が外れたら一緒に外れる（`updateTodo`）——あとで別の時刻を付けたとき、前の
  「前に30分」が黙って蘇らないように。置き直しの元に戻す（段3・段5）も `lead` を戻す。
- 入力は編集の紙の「時刻」、時刻の下の「前に出る」。**時刻を決めた用事にだけ**
  出る（`paintLead`。時刻が変わる合流点の `paintSpanNote` から呼ぶ）。札は なし・15分・
  30分・1時間（打ちこむ欄なし）。選ぶと「12:30 に出る」。
- 道：停留所の手前に**点線の区間**（`.road-lead`、道の下に敷いた点線の帯で、道の上下に
  点がのぞく）。決めた約束そのものではない「向かう時間」なので、夜のごろと同じく点線。
  済ませた停留所には描かない。札は増やさない（次の一行が言う）。
- 次の一行：「次は 13:00 病院 · 12:30 に出る · あと1時間20分」。**「あと」は出る時刻まで**
  （空いているのは、出るまでなので）。出る時刻を過ぎたら（向かっている途中）「出る」は
  言わず、あとは停留所まで。停留所の中なら「いまは 病院（14:00まで）· 次は … · 15:30 に出る」。
- 鳴らす：`todoBell` が入っていれば出る時刻にも鳴らす（`bell.plan`。回の名前と題は
  docs/health.md の「閉じていても鳴る通知」）。ページの中の `notify.js` の `tick()` は
  前のまま時刻だけ（閉じていても鳴るほうに寄せた）。
- **評価しない**：「急いで」「間に合う／遅れる」は言わない。出る時刻は約束の手前の時刻
  というだけ。
- 試験：`tests/road-lead.js`（段6も）。

#### 道へ運ぶ（段8）
**道へ運ぶ（段8・2026年9月30日）**：段2の「空いた道を押して、選ぶ」とは逆向きの入口。
連れ（今日・時刻なし・人の後ろの丸 `.road-bead`）を**長押しで持ち上げて道へ運び**、離した
ところの時刻が付いて停留所になる。計画は利用者と合意（段A＝連れ、段B＝長期タスクのくぼみ）。

- **手つきは時間割の「つまんで、置きなおす」と同じ作り**（`screen-todo.js` の `wireDrag` /
  `lift`。道のほうは `day-road.js` の `wireCarry` / `lift` / `follow` / `dropCarry`）。
  0.38秒押さえたら持ち上がり（`CARRY_HOLD`）、その前に 8px 動いたらただの送り
  （`CARRY_SLOP`）。短く押せば今までどおり紙が開く。見張りは document（day-swipe の
  `setPointerCapture` 対策）。持ち上げたら document の touchmove を `preventDefault`
  （passive: false）、離したあとの click を一度食べる。**動かさずに離せば何もしない**
  （連れは道から 19 しか離れていないので、人が段の頭に居て連れが前に出ていると、置いた
  だけで時刻が付いてしまう）。端の自動送りは付けない（道は一画面に入る）。
- **ほかの手つきは `KN.dayRoad.carrying()` を見て、この指を取らない**：day-swipe の `busy`
  （`screen-todo.js`）・`pull-refresh.js`（`blocked()` と `onMove`。紙が上端にいるので、下へ
  運ぶと上端の give が紙を引いた）。分の見回り（`nowTick`）も運んでいるあいだは描き直さない
  （時間割の `tlDrag` と同じ）。
- **時刻は段2と同じ**：指にいちばん近い道の時刻を1分ずつなぞって探し（`roadPts` を持ち上げた
  ときに一度作り、`nearest`）、15分きざみ（`snap`）。指が道の中心から **24 以内**
  （`AIM_NEAR`）のときだけ、狙いの点（`.road-aim`、道の上の置く時刻）と時刻の札
  （`.road-carry-time`）を出す。置けるのは**これからの道だけ**（`.road-free` と同じ：今日は
  いま以降、過ぎた日は無し、先の日は道ぜんぶ。`carryAt`）。停留所と重なってもよい（車線に
  割れる。警告の色は出さない）。道の外・歩いたぶん・取り上げられた（pointercancel）ときは
  何も書かず、丸は元へ戻る。
- **狙うのは指ではなく、指の上に浮いた写しの位置**（`follow` の `gy = y - GHOST_UP`。
  2026年10月3日、利用者：「浮いている丸のところが操作する場所に」）。試験の指は狙う点の 40px 下。
- **連れを道の外で離すと長期タスクへ戻る**（同日、利用者の頼み）。写しが道の中心から
  `OUT_FAR`（34）より外・道の絵の中なら札は「長期タスク」、くぼみの塗りが濃くなる
  （`.is-carry-out`）。離すと `o.unplan`＝`screen-todo.js` の `unplanOnRoad`（due と time を
  外す。時間割で長期タスクの欄へ運んだときと同じ書き換えと「元に戻す」）。くり返しは戻さない
  （due を外すと回が消える。`canOut`）。長期タスクを外で離しても何もしない。24〜34 は何もしない帯。
- **書き換えは段2と同じ `decide`**（`screen-todo.js` の `decideOnRoad`：time を書き、due が
  無ければその日。くり返しは due を動かさない。「元に戻す」付き）。新しい欄・データ移行なし。
  位置も並びも保存しない。
- **見た目**：元の丸はその場で薄く残り（`.is-lifted`、どこから来たか）、写し（`.road-ghost`、
  body に置く fixed、`--z-lift`）は指の上 40px、時刻の札はその上（札の下端が指から 58px。

  - **写しの位置は `translate:` プロパティで書く。** `transform: translate()` で書くと、

#### 連れ→停留所（V8）
**連れ→停留所（V8・2026年10月4日）**：時刻を決めた瞬間、連れ（くぼみの長期タスクも）の丸が
道の上の停留所の頭へ飛び（`--m-swipe`・`--ease-glide`）、停留所の丸い頭になって、そこから終わりまで
伸びる（`--m-grow`。道筋の `stroke-dasharray` を 0→長さ。丸い端なので長さ0は頭の丸）。時刻を外せば
逆（前の道筋を一度だけ描いて頭へ縮め `.road-leave`、丸が連れの位置へ）。運んで離したときは、離した
写しの位置から（`dropCarry` が `landing` に道の単位で渡す。2秒で捨てる）。

- **道は組み直しで作り直される**（render が古い道を外してから build する）ので、前の道は見られない。
  `paint` のたびと分の見回りで、日ごとに丸の位置（`marks` が書く `st.beadAt`）と停留所の頭・道筋を
  覚え（`remember`、`seen`）、build が paint の**前に**取り出して `arrive` に渡す。動かすのは
  **連れ⇄停留所が入れ替わった用事だけ**。覚えが 45秒（`SEEN_MS`）より古い・道の始まりが変わった

    段のあいだ（`XL` より外）。**右を先に、足りなければ左。** 一つに丸18が2列×3段（段から
    24・44・64 の高さ、道に近い列から）。
  - **札のほうが先。** `marks` の最後（4.）で、置いた札の通り（`lanes`、`dy` 込み）・道の端の
    時刻・人・人の頭の上の時刻（`keep`）の箱と、道と停留所（車線も。`clearOfRoad`、丸の半径＋
    停留所の太さの半分＋1.5）に重なる場所を外す。右向きの段の終わり近くの札は右のくぼみへ
    伸びる（13:40 の札で、右の下の段が空いた）。

  - **並びは期限の近い順**（同じ期限・期限なしは手で決めた `order`）。位置が時刻を言って
    いるように読めないように。**過ぎた日には出さない**（置ける道が無い）。今日と先の日に出す。
  - **連れより一段淡く**（`.is-someday`：ふちと絵を紙の色と半々に）。淡さは色で——`opacity`
    は持ち上げた印（`.is-lifted`）が使うので、同じ詳細度で取り合わない。「+n」の字は
    `--c-primary` のまま（淡くすると読めない）。
  - 連れはくぼみへ移さない（二か所に同じ用事を出さない）。毎晩のごろは運べないまま。
  - **くぼみは薄く塗り（`.road-hollow`、使った丸の外接＋5）、丸はゆっくり浮き沈みする**

### 「やること」は Structured に寄せてある

動画（Structured のタイムライン）を実測して、レイアウト・色・情報配置・
操作感を合わせた。ここを触るときの決めごと：

- **行は時間に比例しない。伸びるのは丸薬のほうだけ。** ここには「丸は
  伸びない」と書いてあったが、**測り直したら違った**——静止画（1284×2778、
  3倍）で見ると、15分の用事は真円、45分・1時間のものは縦に伸びた丸薬で、
  重なった二つは丸薬どうしがぶつかっている。あちらは「行は並び順、丸は
  時間」の二本立てだった。
  こちらもそう直した（`nodeH`）：30分までは真円50px、そこから 1分＝0.8px、
  170pxで頭打ち。**長さを決めていない用事は伸ばさない**（組み立ての既定
  30分は置き場所を決めるための仮の数で、絵にすると決めた数のように読める）。
  行そのものは伸びず、丸が入るぶんだけ背伸びする
  （`min-height: max(60px, --tl-h + 10px)`）。空きは相変わらず一定
  ——610分の空きと325分の空きが同じ高さ、という実測はいまも本当。
- **余白は詰めた**（行 64→60px、空き 56→36px）。**破線がすでに「ここは
  離れている」と言っている**ので、同じことを高さでも言う必要が無い。
  二つで言っていたぶんを一つに戻したぶんが、一日が一画面に入ることに回る。
  ここを動かしたら、重なりの育てる量（下記）も直すこと。
#### 過ぎたぶんは色、まだは灰色・線の色（`--pass`）
- **過ぎたぶんは色、まだのぶんは灰色**（`--pass`、`markPass`）。行ごとに
  0〜1 で、その行の始まり〜終わりを時計がどこまで通ったか。丸薬の塗り・
  背骨・破線の色が、すべてこの一つの数から出る。一日が進むと、時間割が
  上から染まっていく。進行中の一件だけ、塗りの境目をぼかす。
  **今日を見ているときだけ**（`nowMin == null` なら全部1）——明日を開いて
  一日ぶんが灰色だと、これから組む画面として読めない。灰色が言っている
  のは「まだ来ていない」ではなく「**今日のうちで**まだ来ていない」。
  済ませたものは、時計より先でも 1（色のまま）。
  - 開いたときは、この色が上から流れて「いま」に着く（`passAt`。時計を早回しするだけ。U16・
    motion.md の「開いたとき、満ちる」）。
  - **`paintNow` は、先に測って、あとから書く。** 前は `markPass`（書く）→
    `nowY`（読む）→ `clearOfClocks`（読む）の順だった。書いたすぐあとに測ると、
    ブラウザはそこでレイアウトをやり直さないと答えられない——組み直しのたびに、
    余分な一回。入れ替えても答えは同じ：`markPass` が書くのは色（`--pass`・
    線の色・`is-live` のうすい地）だけで、**高さも位置も動かさない**ので、
    測る前に書いても後に書いても、測れる数は変わらない。
- **薄くするのは字だけ。線は薄くしない。** `.tl-free-row.is-past` に
  `opacity: .6` が残っていて（`--pass` を入れる前の決めごと）、同じことを
  二つが別々に言っていた。実測で、丸薬をつなぐ線が (225,113,107)、すぐ下の
  点線が **(236,169,165)**——「丸薬の間の線の色が周囲と合わない」の正体。
- **`--tl-wait` は一色の灰**（棚の色を混ぜない）。かつて棚の色を6%混ぜて
  いたが、行ごとに灰色がわずかに変わり、空きの行の境目でぶつかった。
  一色に戻してある。
- **線の色は、丸薬の地とまったく同じ**（`--tl-fill` ／ `--tl-wait`）。
  前は線だけ濃く（`--cat` そのまま）、破線はさらにその62%で、縦一列に
  三つの濃さが並んでいた。丸から丸へ続く一本なら、丸と同じ色が素直。
  **一つの変数から出すこと**——二か所に書くと、片方だけ直した日に割れる。
#### 線を丸薬の上端・下端で割る
- **用事の行の線は、丸薬の上端と下端で三つに割る。割る場所は丸薬の寸法から
  出す**（`--node-top` / `--node-bot` / `--rail-p`、`--tl-node-h` と
  `--node-dy` から）。行の高さを決めるのは題とメモで、**時間ではない**。
  時間を持っているのは丸薬だけ。上は始まっていれば色（`--rail-top-c`）、
  下は終わっていれば色（`--rail-bot-c`）、中は丸薬の地とまったく同じ式。
  `0 ≤ pass ≤ 1` である限り、色の変わり目は必ず丸薬の中に落ちる
  ——**線が丸薬を追い越すことが、式として書けない。**
  「行の 50% で二値に割る」と書いてあった時期があるが、あれは「丸薬は行の
  まん中にいる」という前提に寄りかかった数で、**当たっていただけ**だった。
  空きの行のほうは、そこが時間そのものなので pass の位置で切る。
  - **丸薬のずらしは `transform` に直書きしない**（`--node-dy`）。線の境目が
    この数から出るので、位置だけ動かすと線が置き去りになる。
  - **いちばん下の行の線を切るのは `clip-path`。`height` ではない。**
    高さを縮めるとパーセントの基準がその箱に変わり、境目が丸薬からずれる
    （実測 2.5px、まだ始まっていない丸薬の**上**に色が出た）。
- **丸薬の外の線（上・下）の色は、行ごとの pass ではなく「いま」の位置一つで
  決める**（`markPass`。2026年9月27日）。いまの行（`nowY` と同じ引き方＝時刻の
  順に見て、まだ終わっていない最初の行）より上の線は色、下は灰色。いまの行は
  上だけ「始まっていれば色」。前は行ごとに「上＝始まったか・下＝終わったか」で、
  二つの場面で**色の付いた 5〜10px の短い線**が丸薬の上下から灰色の中へ
  突き出た（利用者の言う「丸薬に線が刺さっている」）：
  - 済ませたもの（pass は時計に関わらず 1）… 21:00 の用事を朝に済ませると、
    その丸薬の上下だけ色。
  - 重なり … 8:00〜12:00 のルーティンの途中で済ませた用事は上下とも色、
    上のルーティンは終わっていないので下は灰色——灰色→色→丸薬→色→灰色。
  線は**時間**、丸薬の塗りは**その用事**（進み具合・済んだか）。だから済ませた
  用事の丸薬は色のまま、線だけ灰色、はあり得る絵。試験：`tests/timeline-rail.js`。
  （例外は一つ：下の用事とぶつかった上の丸薬。下の「ぶつかった上の丸薬は」の項。）
#### 長さのある用事の中で起きた用事は、上の丸薬とぶつける
- **長さを決めた用事の時間の中で起きた用事は、すぐ上の丸薬とぶつける**
  （`landsInside` → `is-clash`。2026年9月27日）。組み立ての `clash` は時刻を
  決めたものどうししか見ない。済ませたものは押した時刻に置かれる（`doneSpan`）
  ので、4時間のルーティンの途中で済ませた用事がルーティンの**下の行**に線で
  つながって並び、「ルーティンが終わってから次」と読めた——上の丸薬がまだ
  途中なのに、下の丸薬だけ色が付いている、と見えた正体。
  - **決めた長さどうしのときだけ**：上の行が `minutes` を持ち、下の行の**本当の
    時刻**（決めた時刻・長さから出した始まり・済ませた時刻）がその中にあるとき。
    長さを書いていない用事の 30分は仮の数なので、続けて二つ済ませただけで
    ぶつかってしまう。
  - 「前と重なっています」の字は、組み立ての `clash`（時刻を決めたものどうし）
    のときだけ。済ませた記録に注意書きは要らない。
  - **`clash` の「前」は時刻の順の前**（`plan.js`、並べ終わった `sorted` で見る。
    2026年9月29日）。置きながら「先に置いた固定と」見ていた時期があり、置く順は
    毎朝→あいだ→毎晩なので、20:00〜22:00 の夜のルーティン（毎晩）が 20:55 の
    テスト（あいだ）より**あと**に置かれ、**早いほうの**ルーティンに字が付いた。
    絵では、ルーティンが `is-clash` も持って、上の空きの点線とのあいだに白い
    抜きが出て、丸薬がそちらへ14px伸びた（ぶつかる相手がいないのに）。
    試験：`tests/timeline-overlap.js`。
- **ぶつかった上の丸薬は、下の用事が始まるまでを受け持つ**（`shownSpan`。
  2026年9月29日・利用者の声「被った時の色のつき方に違和感」）。上の「線は時間、
  丸薬は用事」のただ一つの例外。
  - 20:00〜22:00 のルーティンの途中に 20:55 のテスト、いま 20:57。ルーティン自身の
    進み具合（47%）で塗ると、「20:57」がルーティンのまん中に出て、その下の
    **もう始まっている**テストが灰色——上から下へ読むと時間が戻る。9月27日の
    「ルーティンの途中で済ませた用事」（上が途中まで・下が色）も同じ形で、
    ぶつける絵だけでは消えていなかった。
  - 一本の線の上で、同時に進む二つの進み具合と「上から下へ一度だけ色が変わる」
    は両立しない。**上から下へ**を取った。上の丸薬の見えているところは「下の
    用事が始まるまで」なので、そこまでで塗り切る。運ぶときの目盛り（`axisOf`）は
    もとからそう読んでいた（節を y で並べ直して、分は戻さない）。
  - 手放したもの：ぶつかった上の用事の**自分の**進み具合は丸薬から読めない
    （9:04 に 8:00〜12:00 のルーティンが塗り切られて見える）。まだ続いている
    ことは、うすい地（`is-live`）が言う——`is-live` だけは本当の終わり
    （`end`）で決める。
  - `markPass`（塗り・線・どこで「いま」に着いたか）と `nowY`（いまの札）は同じ
    `shownSpan` から引く。片方だけ直すと、札と色の境目が別の丸薬に出る。
  - 同じ時刻に始まる二つは、上の受け持ちが 0分になる（始まったら塗り切り、
    その前は灰色）。
#### `--pass` を貼る場所・空きの線・重なり
- **`--pass` を、時間ではない高さへ貼らないこと。** `--p`
  （＝`--pass × 100%`）が掛かる相手は、その要素自身の高さ。使ってよいのは
  高さが時間そのものである二つ——**空きの行**と**丸薬**——だけ。
  手順の段の背骨（`.tl-sub-wrap::before`）に貼っていた時期があり、あそこの
  高さは**手順の件数**で決まるので、丸薬の下端より **62px 下**まで色が
  下りた（実測：6:30〜7:30 の用事を 6:49 に、手順4件をひらいて）。
  「線が丸薬を追い越す」の正体はこれ。あの段は丸薬の下端より下＝終わった
  あとの場所なので、境目を持たず `--rail-bot-c` の一色でよい。
- **30分以内の空きは実線、それより空いたら点線**（`TL_JOIN_GAP`）。十分や
  そこらの隙間は「途切れ」ではなく、ひと続きの時間のなかの余白なので。
  点は6px・間は4px（前は7pxと8pxで、間のほうが長く点々の列に見えた）。
  破線は**マスクで抜く**——地の色と点々を一つの背景で兼ねると、過ぎたぶんと
  これからで色を変えられない。
- **重なった二つは、丸薬どうしがぶつかる**（`is-clash` ／ `is-clash-above`）。
  線でつながない——重なりは「順番に並んでいない」ことなので、つなぐと
  そこだけ嘘になる。上の行の丸薬は下へ、下の行の丸薬は上へ14pxずつ育て、
  めり込み18pxの真ん中に白い抜き（`.tl-row.is-clash .tl-rail::after`、
  30×12px の楕円）。**めり込みの18pxが決めごと**で、育てる量（14px）は
  行間（5+5=10px）から逆算した数——行の余白を詰めたら、ここも直すこと。
  **行は詰めない**——行の高さは題とメモが決めるので、詰めた瞬間に字が噛む。
  実測（丸薬56px／めり込み20px／抜き34×13px）を50px幅に縮めた寸法。
  **三つ以上重なったら、まん中の一件は両方向へ**
  （`.tl-row.is-clash.is-clash-above`、＋32px・位置は動かさない）。ここは
  一度こわした：上の二つは詳細度が同じなので、両方を持つ行にはあとに
  書いたほうだけが効き、まん中の丸薬が下へしか育たない。上の継ぎ目は
  めり込むどころか2px離れて、白い抜きだけが宙に浮いていた。
#### 一画面に一日ぶん・立ち上げ・端で送る
- **一画面に一日ぶんだけ。** 棚を縦に積むのはやめた（`daySection`）。
  日を変えるのは、週の帯を押す／`‹ ›`／左右に払う、の三つ。払うと**紙そのもの**
  が横に流れて、隣の日の時間割が指のぶんだけ入ってくる（`js/day-swipe.js`。
  daily・ダイエットと分け合う一つ）。
  用事を**週の帯の日へ運ぶ**と日付が変わる（棚またぎドラッグの後継）。
- **立ち上げたときは tasks**（`app.js` の `HOME = "todo"`。2026年10月3日まで daily だった。
  daily に鍵（docs/daily.md の「鍵」）をかけると、開くたびに Face ID が出るので）。
  試験の `tl.js` の `boot()` は やること までめくる（`stay: true` を渡すとめくらない）。
  **daily の画面も最初から DOM にいる**ので、`.cal-day` / `.tl-sheet` / `.js-now` のような
  両方にあるものを掴むときは、出ている画面に絞ること。
- **運んでいる最中、画面の端で自動的に送る**（`EDGE_BAND` 84px、端に近い
  ほど速い）。指は画面から出られないので、これが無いと画面の外にあるもの
  ——下に隠れた長期タスクの欄や、朝の時間帯——へは運べない。送ったあとは
  狙いを取り直すこと（中身が指の下で動いたので）。
#### 左の列は一本の時間軸
- **左の列は、まるごと一本の時間軸。「置き場」という考え方は捨てた。**
  縦の座標が、そのまま15分きざみの時刻になる。丸薬の上でも、丸薬と丸薬の
  あいだでも、空きでも、同じ一本の軸の上の一点として読む——**そこに何が
  置いてあるかは、置けるかどうかに一切関わらない**。
  - **目盛りは丸薬に合わせる**（`axisOf` の `pts`）。節は丸薬（`.tl-node`）の
    上端＝その用事の始まり、下端＝終わり。あいだは前の終わりから次の始まりへ
    まっすぐ。実測で、丸薬の上端・中心・下端の**ずれは 0分**。
    - **`.todo-mark` を測らないこと。** あれは丸薬の中の32pxの絵で、4時間の
      用事も15分の用事も同じ32pxになる。丸薬そのものは `.tl-node`。
    - **まっすぐ一直線（列の上端＝日の始まり、下端＝終わり）は試して外した。**
      px あたりの分はどこでも同じになるが、行の高さは題とメモが決めていて
      時間に比例しないので、**丸薬の時刻と最大 327分ずれた**——「12:30
      旅行準備」の真横で札が「18:12」と出る。
    - 代わりに px あたりの分は場所で変わる（実測 0.30〜1.76分/px、ただし
      13:00〜22:00 のような**長い空きだけ 11.7分/px**）。置けない高さは無いが、
      空いた夕方は粗い。気になるなら直すのは**休みの行の高さ**のほうで、
      運んでいる最中に広げるのではない（それが次の項）。
  - **破線の帯（`.tl-band`）は廃止。** 掴んだ瞬間に空きの行が 64〜220px へ
    広がり、その中だけが細かく狙えた＝「置ける場所」を、そこに何が置いて
    あるかが決めていた。広がるぶん（実測：帯5つで490px）行が押し下がるので、
    **狙っていた先が指の下から逃げる**。運んでいるあいだ、行は一切動かさない。
  - **狙いの線は一枚の層**（`.tl-aim`）に置く。行に仕込むと、線は必ず行の
    境目へ吸い寄せられる。実測で、線は指の高さと 0px ずれ。
  - **左右の境目は行の列の切れ目**（`grid-template-columns: 44px 56px 1fr`
    の 100px ＝ `.tl-item` の左端）。前はここが `.tl-rail` の右端＝**73px**
    だった——レールは2pxの線なので、その右端で切ると**題を掴んだ指はいつも
    外側**にいて、実測 x=170 では y 150〜780 の全点で時刻が取れなかった
    （＝毎回「並び順」に落ちていた。動画のトーストが全部「動かしました」
    だったのはこれ）。
  - **運んでいるあいだ、軸の幅にうすい地を敷く**（`.tl-aim::before`）。帯を
    外したぶん「どこが時計か」の手がかりが絵から消えた。「左＝時刻、右＝
    並び順」は位置で言っていることなので、その位置が見えていないと言えて
    いない。
  - **狙っている時刻の札は、線の上へ逃がす**（`.tl-band-time`、線から30px）。
    線と同じ高さに置くと、そこは指が乗っているところ——いちばん読みたい
    数字が指の腹でちょうど隠れる。実測で 18px では 4px かぶった（指の腹は
    触れた点からおよそ24px 外へ広がる）。列のいちばん上だけは上に場所が
    ないので下へ返す（`is-under`、`AIM_LABEL_GAP`）。
    **札は掴んだ瞬間から出ている**——`lift()` の最後の `aim()` が列の中
    （x = 行の左端+20）を渡すので、指を動かす前から行き先が読める。
  - 重なってはいけない理由は無い——15分の隙間へ1時間の用事を置いたなら次と
    重なるが、それは利用者が決めたことで、重なりは丸薬どうしがぶつかる絵で
    ちゃんと見える。題のほうは「順番で置きなおす」まま（別のことを言って
    いるので）。
#### 長期タスクとのあいだ・済ませた時刻・一覧
- **長期タスクの欄へ運ぶと、日付と時刻が外れる。** 探すのは節（`.tl-someday-sec`）
  のほう——中の `ul.tl-someday` は一件も無いと組まれないので、いちばん要る
  「空っぽの長期タスクへ最初の一件」が落とせない。
- **長期タスク → 時間割の落とし先は `.tl-list`。`.tl` ではない。**
  `.tl` は**二つの別物**に付いている——行を並べる `<ul class="tl tl-someday">`
  と、その日の時間割を囲む `<div class="tl">`。`.tl:not(.tl-someday)` が拾うのは
  後者の**囲い**で、中の `<ol class="tl-list">` ではない。囲いの子は `.tl-sum` と
  `<ol>` だけなので行を数えると 0 件になり、**長期タスクから運ぶと時刻が一度も
  取れなかった**（実測：列の真上 x=20 でも y 160〜710 の全点で null。帯だけは
  `querySelectorAll` で深く探していたので出ていて、「箱は見えるのに使えない」
  状態だった）。
- **済ませた時刻を、題の下に出す**（`.tl-doneat`）。左の時刻の列は**予定の
  時刻**で、別のもの。`doneAt` は UTC の ISO なので読むのは `getHours()`。
- **期限切れ・もっと先・済んだものは「一覧」が受け皿。**
  `settings.todoTimeline` オフで棚の積み上げに戻る。時間割の頭には
  期限切れがあることだけ出す（`.tl-late`）。2026年9月27日から期限切れは日の変わり目に
  今日（ルーティンは次の回）へ運ぶので、ふだんは出ない（docs/todo-items.md の
  「期限切れは作らない」）。
#### 「いま」・済ませたもの・進んでいる用事の見た目
- **「いま」は太字の時刻ひとつ**（`.tl-now`）。点（`.tl-now-dot`）と右へ
  流れる線（`.tl-now-line`）は外した——塗りの境目がすでに「いま」を
  言っているので、重ねると三度同じことを言うことになる。残したのは、
  境目が**何時なのか**だけ（それは色では言えない）。丸薬が時間ぶん伸びる
  ようになったので、置き場所も行の**中**に取れる（`nowY` は丸薬の中を
  割る）。30秒ごとに軸の層（`.tl-axis` / `paintNow`）だけ描き直す。
  組み直しはしない。

### 組み直しは、変わったものだけ（`calDigest` / `sheetDigest`）

やることの `renderBody` は、長いあいだ **毎回ぜんぶ作り直して**いました
（`els.body.innerHTML = ""` → 約700要素）。実測（2026年9月21日・CPU 4倍・
390×844）で **99.5ms**。この画面に残っていた長タスクは、全部これでした。

いまは**二つの塊を、入力が変わっていなければ使い回します**。

| | 見分けるもの（digest） |
|---|---|
| 暦（`.cal`） | 月・今日・棚の色と、**日を持つ用事**の（id・日・くり返し・絵・題） |
| 日の紙（`.tl-sheet`） | 日・今日・**今日なら分**・設定ぜんぶ・ひらいている手順・**用事ぜんぶ** |

- **使い回す一枚は、外さないこと。** `innerHTML = ""` で一度外すと、付け
  直したところでブラウザはその木ぶんのレイアウトをやり直すので、組み直さ
  なくても値段が残ります（実測：外して付け直す **37.8ms** ／ 外さない
  **28.7ms**）。中身を空にするのは「残す一枚」を決めたあと、**その一枚だけ
  残して消す**形にします。だから暦と紙を決めるのは、消すより**先**です。
- **数える範囲は、塊によって違ってよい。** 暦が描いているのは「その月の、
  日ごとの絵と件数」だけなので、絵を変えるものだけ数えれば足ります。紙の
  ほうは題・メモ・時刻・長さ・手順・期限……とほとんど全部を描くうえ、
  組み立て（`KN.plan.buildDay`）が**いま何時か**まで見る（時刻を書いて
  いないものが、いまから先に並ぶ）ので、**丸ごと見ます**——`todos` 65件で
  **0.076ms**、組み直し一回の 0.15% です。**選ぶと、いつか選び落とします。**
- **`fillCalendar` は二つに割れています**——盤（高い・使い回す）と、
  **いま見ている日**で変わるぶん（安い・毎回やる：期限切れの帯・週の印・
  輪＝`fillCalTail`）。生きている盤へ直に描く道（`setCalMonth`）を通ったら、
  控えの見分け字は捨てます。
- **`is-stuck` は `add` ではなく `toggle`。** 盤を使い回すので、いちど
  貼りついた盤がいちばん上へ戻っても線を持ったままになります。
- **組み直しを通らずに中身を替える道があったら、そこでも控えを捨てること。**
  いまあるのは一つ——払って着いた一枚を据える（`day-swipe` の `commit` の
  `kept`）。捨てないと、今日→明日と払ってから「今日へ戻る」を押したときに
  **題と暦だけ今日になって、紙は明日のまま居座ります**（実測で踏みました）。
- **`is-arriving` は、名乗り終わったら外します**（`ui.js` の `flipRows`）。
  `is-arriving`（元の `row-arrive`、いまは `m-add`）は `animation-fill-mode: both` なので、終わったあとも
  `transform: none` を押さえ続けていました（U5 で `translate:` に書き直してからは押さえませんが、外すのはそのまま）——アニメーションはインラインの style
  より強いので、**札を持ったままの行は二度と FLIP で滑れません**。行が毎回
  新しく組まれているあいだは札も一緒に消えていたので、出ませんでした。
- **絵の引き当ては覚えます**（`cachedArt`）。`findKey` は品物2131語・こと
  684語を順に当てにいくので、実測で組み直し一回に **12.9ms**、長期タスクが
  5行で **28.8ms** かかっていた中身のほとんどがこれでした。辞書は動かない
  ので、（引きかた・保存済みの絵の名前・題）が同じなら答えも同じ。
  `iconMarkHtml` と `tlMark` は引く順番が違うので棚を分けます。
  **`iconOverrides` が動くようになったら、この覚えを捨てること**（いまは
  書く側に呼び出し元がありません）。

実測（CPU 4倍・390×844。場面は7回の中央値・長タスク（50ms超）の合計。
`0ms` は「50msを超える塊が出なかった」）：

| | before | after |
|---|---|---|
| `render()`（何も変わらない） | 99.5ms | **10.8ms** |
| 何も変わらない組み直し | 96ms | **0ms** |
| 中身が変わったときの組み直し | 130ms前後 | **74.9ms** |
| 席を移る（往復） | 264ms | **172ms** |
| 暦を開く／収める | 112ms | **73ms** |
| 暦の日を押す | 112ms | **58〜67ms** |
| 済ませたを押す | 103ms | **85ms** |

**ここで止めました。** 残っている 74.9ms の内訳は、**レイアウト 41.9ms**・
`node()` の字→要素 22.9ms・暦 17.8ms・日の紙 14.1ms。あのレイアウトは
「木が変わったから要る」ぶんで、組み直しを減らしても消えません（`flipRows`
が先に測っているだけで、測るのをやめても同じ一回をブラウザがやります
——実測：`flipRows` を丸ごと外して 66.2 → 62.3ms、たった 4ms）。席を移る
ときの残りも、`display:none` から出てくる面の**初回レイアウト**が主で、
使い回しでは減りません。ここから先（行単位の差分）は、行ごとの素性・運ぶ
配線・手順の段・FLIP の対応づけを全部自前で持つことになります。**得られる
のは「中身が変わったとき」の数十msだけ**なので、割に合いません。

### 押した行の丸薬が、頭の丸薬へ伸びる（C2・`ui.js` の `morphPill`）

2026年9月27日。紙は押した点から育つ（`seedFrom`）が、それだけでは頭の粒が
**どの行の続きなのか**を絵が言えなかった。

- **動くのは影武者の一枚**（頭の丸薬の写し、`.sheet-morph`）。紙のほうは縮んだ姿で
  押した点から育ってくる途中なので、頭の丸薬を紙に乗せたまま動かすと行き先が
  毎フレーム動く。飛んでいるあいだ、行の丸薬と頭の丸薬の本物は `visibility: hidden`。
- **行き先は、開き終えたときの箱。** rAF の中で、紙に `.is-open` を付けた姿を
  **動きを止めたまま**一度だけ測る（`seedFrom` と同じ「止めて、読んで、戻す」）。
  `sheet()` を呼んだあとで頭の字（いつ・印）が埋まり、丸薬の縦の位置が変わるので、
  開く前に測ると外れる。
- **速さと曲線は紙が育つのと同じ**（`--m-sheet-grow` / `--push-e`）。同じ時に着くので、
  着いた瞬間に本物へ入れ替えても継ぎ目が出ない。絵は行の 32px → 頭の 38px へ一緒に育つ。

  覚えた点が古い）と、＋から足す紙。途中で閉じたら `close()` が後始末を呼ぶ。
- **閉じると、頭の丸薬が行の丸薬へ帰る**（`morphBack`。2026年9月27日）。保存で
  時間割が組み直されると行の丸薬は別の要素になり、FLIP で滑ってくる最中になる。

  `.tl-row[data-todo-id] .tl-node`）、毎フレーム引き直して、動きの終わりの形だけ
  `setKeyframes` で書き換える。速さは FLIP と同じ `--m-settle` / `--ease-settle`。
  帰らない：行が無い・画面の外・行きの影武者がまだ飛んでいる（出どころが決まらない）。
  途中で見失ったら、その場で薄れる。
- **影武者は紙の外にいるので、頭から継いでいたものを写す。** 字の色（絵は
  currentColor。写さないと黒いシルエットになった）。行の丸薬の見た目は、算出された
  値を焼きつけた写し（`freeze`）を上に重ね、飛ぶあいだに薄めて消す——頭の色へ
  一度に塗り替えると、押した瞬間にパッと色が変わって見える。
- **大きさは変形の掛からない値で測る**（算出された width）。頭の絵は縮んだ紙の中に
  あるので、`getBoundingClientRect()` で測ると倍率が狂い、絵が 2.4 倍に膨らんだ。

## 活動（3.0 の A1・2026年10月6日・`js/activity.js`）

一つの活動を、予定（`act` 付きのやること）・実績（`minutes`・`at` 付きの積み上げ）で持つ。二度入れさせない。
計画は `docs/roadmap-3.0.md` の A1。

- **結び**は `act.entry` と `entry.todo` が**指し合っているときだけ**（`store.actEntry` / `entryTodo`）。片方を消しても
  相手は消さない——ふつうの用事・ふつうの記録に戻るだけ。
- **済ませると**（`store.toggleTodo` の中の `actDone`。済ませる入口が時間割・紙・通知・手順と四つあるので store で）
  積み上げが一件生まれる：題は予定の題「読書『…』」の中、種類は `act.type`、読書なら著者・書籍／論文は同じ題の
  前の記録から（`readingCandidates`）。長さは予定の長さ（無ければ30分）、始まりは決めた時刻（済ませた時刻より後なら、
  済ませた時刻から長さぶん前）。メモは空。**タイマーは作らない**。もう結んであれば作らない（外してまた済ませた）。
  くり返しはその日の写し（`doneId`）に結ぶ。「元に戻す」は生まれた積み上げも消す（済ませた直後なので書き足しは無い）。
- 知らせは「30分で残しました」と「直す」（`KN.activity.fixLength`：長さだけ。札 15・25・30・45・1時間と ±5分）「元に戻す」。
- **道は実績を引く**（`KN.activity.forRoad`。描く前に用事を読み替えるだけで、記録は書き換えない）：結んだ積み上げに
  時刻と長さがあれば、その日の道はそちらで描く。済ませた時刻（`doneAt`）は描くときだけ終わりちょうどに置く
  （`shape` が済ませた時刻で縮めるので）。用事に結ばれていないその日の積み上げ（「道に記録する」）は、済んだ活動
  `arc:<記録の id>` として足し、押せば記録の紙（`KN.screens.archive.openEntry`）。時間割には足さない。
  やることの画面の組み直しの見分け（`sheetDigest`）に、時刻か結びのある積み上げを入れた（入れないと、長さを直しても道が古いまま）。
- **見た目**：`.road-stop.is-act`（`o.actOf` が種類の色を `--act-c` に）。縁は種類の色、中は紙の色に寄せ（10%）、
  **塗らない**（`paint` が went を引かない。時の数字も中の色のまま）。過ぎたら `opacity .6`。延び（is-late）も
  橙にしない（種類の色のまま）。形は見比べ（A 縁取り・B 中を薄く塗る・C 細い縁）で A を既定に置いた。
- **入口**：記録の紙（新しく書く）の「道に置く」→ 時刻と長さの紙（`askSpan`：時刻の紙と同じ `.tw-card`・車輪・札）→ その日に
  `act` 付きの用事（記録はまだ作らない。打ったメモは予定のメモへ）。前の記録の紙の「道に記録する」→ 同じ紙で `at`・`minutes`
  だけ書く（**用事は作らない**。直しかけは先に保存）。空いた道の紙（段2）に「活動」の行（`KN.activity.recent`：
  読書と学習の最近の題、四つまで。選べばいつもの長さ）。「道に置く」「活動」は**読書と学習だけ**（達成・種・変化は
  予定にしない。「達成『…』」は評価の言葉に見える）。「道に記録する」は種・変化のほかは出す。
- 詳細の紙の頭に「積み上げ『…』」の札（`.js-act-src`、`dest-chip` と同じ形）。押せば記録の紙。
- **ノートから**（A2）：ノートの「⋯」に「道に置く」（書いたノートだけ）→ 時刻と長さの紙（札 15・20・25・45、既定25分）→
  今日に「『題』について考える」（`act: { type: "seed", note }`）。詳細の紙の頭に「ノート『…』」（`.js-act-note`）、押せば
  ノートの書く紙（閉じればやることの画面のまま）。済ませた積み上げも `note` を持ち、記録の紙の頭の「ノート『…』」から同じ
  ノートへ。ノートが無い・最近削除へ移したときは札を出さない（`KN.activity.noteOf`）。
- daily：積み上げの行（`entryRow` の小さな段・その日の枠の行 `.arc-feed-len`）に長さ、積み上げの枠の頭にその日の合計
  （`.arc-feed-sum`。事実だけ、月比べ・平均は出さない）。結んだ用事はやることの枠に出さない（`dayFeed`。同じことを二度並べない）。
- 試験は `tests/activity.js`。


### 道具箱（3.0 の A3・2026年10月8日）

道の右下の空きに読書・思考・ノートの丸（左から。10月8日に並べ替え）。運んで道に置けば事後の記録にも、これからの予定にもなる。計画は
`docs/roadmap-3.0.md` の A3（①は (a)・②は電球・③は見本の形）。

- **置き場**（`day-road.js` の `toolSlot`）：いちばん下の「右が開いた段のあいだ」（奇数の i で i + 1 < rows の最大）の
  段と段のまん中に、右詰めで三つ（丸 24・間 30・右の丸の中心 `W − PAD − 12`）。二段は左のくぼみ (0,1)、一段は置かない。
  夜の寝床の z Z とぶつかれば上へ。`build` で一度だけ置く（`.road-tools` は `.road-marks` の外。毎分の `marks` で動かさない）。
- **道具箱が先**：`marks` が箱を `keep` と重なる高さの通りに入れ、札・角の札がよける。長期タスクは道具箱のくぼみを使わない。
- **手つき**：`wireCarry` が `.road-tool` も受け、0.38秒で `liftTool`（道具箱の丸は残り、写し `.road-tool.road-ghost` を運ぶ）。
  見張りは連れと同じ `grab`。狙うと札「11:00から30分」と下書き（`.road-draft`、種類の色を薄く・長さぶん）。空いた道は光らせない。
  短く押せば `askSpan`（題は道具の名、下敷きは「いま − 長さ」）。
- **記録か予定か**（`toolAt`）：寝ていた紫・道の外は null。今日のいまより前・過ぎた日は記録、いま以降・先の日は予定。
  15分きざみ。長さはその道具で前に残した長さ（`toolMinutes`、無ければ30分）を、次の停留所の頭と（記録なら）「いま」で止める。最短5分。
- **書くもの**（`activity.js` の `toolsFor(day).put`）：記録は `addEntryUndoable({ type, date, at, minutes, title, note })`（store が置いた直後の undo を返す）、**用事は作らない**
  （`forRoad` が `arc:` で描く）。知らせ「思考 7:00から30分」「直す」（`recordOnRoad`）「元に戻す」（記録を消す）。予定は `plant` に
  `bare`（題をそのまま）・`note` を足して `act` 付きの用事。種類：思考＝種（題「思考」）、ノート＝種（その日に作った・直したノートが
  一つなら結ぶ＝`noteOfDay`、題はノートの題、無ければ「ノート」）、読書＝読書（記録の題は空、予定の題は「読書」）。
- 着く動き：`dropCarry` が離した時刻といま道にある id を `landing` に残し、`arrive` が新しい停留所（済んだ `arc:` も）へ飛ばす。
- 記録の紙（`screen-archive.js`）：種を保存しても前からある題を残す（前は空にしていた。A2 の「…について考える」も）。題のある種はメモ無しで保存できる。
