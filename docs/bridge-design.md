# 積み上げ⇄ノートの橋（docs/notes.md の段6）設計書

積み上げ（種・読書など）とノートを行き来する橋の設計。**2026年10月11日に作り、12日に積み上げごと外した**
（docs/thinking.md の「積み上げをやめた」）。`tests/bridge.js` も消した。以下は経緯。
2026年10月11日に利用者が承認（下の5・6は、設計を示したときの案のまま）。時間割・やることには触れない。

## 決めたこと

1. つながりは記録の側にだけ保存する。ノート側は逆引きで表示する（ノートの入れ物には何も足さない）。
2. 1つの記録がつながるノートは1冊まで。1冊のノートには何件つながってもよい。
3. ノートの中から新しい種をまける。その種は「生まれた元のノート」を、つながりとは別の欄に持つ。
4. ノートが見つからない記録は、記録を残したまま「つなぎ直す／外す」を出す。
5. つながりの欄は、もうある `entry.note` を使う（新しい `noteId` は作らない）。T0（docs/roadmap-3.0.md）で
   入れた「結んだノートの id」で、A2・A3 で済ませた記録が既に持ち、記録の紙も札を出している。
   同じ意味の欄を二つにすると、移し替え（移行）か二重の読みが要る。
6. ノートでまいた種は、まいたときからそのノートにつながる（`note` と `fromNote` が同じ）。
   つなぎ直しても外しても `fromNote` は変えない。

## データ

置くのは記録（localStorage `kaimono-note-v2` の `archive.entries[]`）だけ。ノートの入れ物
（IndexedDB `kaimono-note-notes`・版1）・noteBook（`v:1`）・`emptyState` は変えない。

| 欄 | 値 | 意味 | 書くもの |
|---|---|---|---|
| `note` | ノートの id か null | つながっているノート（1冊まで） | つなぐ・つなぎ直す・外す・種をまく。前からの A2・A3 |
| `fromNote` | ノートの id か null | 生まれた元のノート | 種をまくときに一度だけ。以後は変えない |

- 読み方は T0 と同じ：欄が無ければ null と読む。`reconcile()` に `fromNote` の一行（`note` と同じ形：
  空でない文字ならそのまま、崩れていれば null）。無い欄は足さない。一行は下の const を使わない（TDZ）。
- `store.setEntryNote(id, noteId|null)`：★（`toggleFavorite`）と同じく `updatedAt` も並びも動かさない
  （中身を直したのではないので）。入れるのは空でない文字か null だけ。
- `store.entriesOfNote(id)`：`note === id || fromNote === id` の記録を、最後に触った順（`byRecent`）。
  どこにも保存せず、そのつど記憶の上で引く（写さず引く）。
- 種をまく＝`addEntry({ type: "seed", memo, note: N, fromNote: N })`。日付は渡さない（`dayKeyOf` が
  ローカルの今日。`KN.util.today()` は UTC）。記録・つながり・生まれた元が一度の保存で入る＝途中の形が無い。
  `addEntry` は `fromNote` を `note` と同じ書き方で受ける（無ければ欄を足さない）。
- 種を達成に変えても（`promoteSeed`）同じ一件なので、二つの欄はそのまま。

### 見つかる・見つからない・分からない

- 見つかる：入れ物が `on`、その id のノートがあり、最近削除に無い。
- 見つからない：入れ物が `on`、その id のノートが無い／最近削除にある（今の `activity.noteOf` と同じ物差し）。
- 分からない：入れ物が `idle`・`loading`・`off`。何も出さず、何も書かない。開けたら `KN.notes.onChange` で描き直す。
- **見つからないことを理由に、欄を消す・書き換えることはしない。** ノートは同じ id のまま戻ってくる
  （最近削除から戻す・控えの `merge` は id を保つ）。変えるのは本人が押したときだけ。
- 三つを返す小さな口を `screen-notes.js` に足す。`activity.noteOf` は道のために今のまま。

## 画面（最小。言葉は要る一言だけ・数は出さない）

### 記録の紙（`screen-archive.js` の `openEntrySheet`、今の札の場所）

- 見つかる：札「ノート『題』」。今の `.js-note-src` のまま（`tests/activity.js` が押す）。押すとノートを
  開く（`KN.screens.notes.open`）。下に同じノートが開いているとき（ノートの小窓から来た）は、閉じて戻るだけ。
- 生まれた元が今のつながりと違い、見つかる：芽の絵（`icon("sprout")`）の札をもう一つ。押すとそのノート。
  生まれた元が見つからないときは何も出さない（直すものではない。id は残す）。
- 見つからない：「つなぎ直す」「外す」の二つ。題は出さない（id しか持たない）。
- 分からない：何も出さない。
- 「⋯」（今は `delMenu` だけ）の前に、入れ物が `on` のときだけ：つながっていない →「ノートにつなぐ」、
  つながっている →「つなぎ直す」「外す」。`delMenu` は配列を返すので ui.js は変えない。
- 外したら「外しました」と元に戻す（前の id を戻す）。
- つなぐ先を選ぶ紙：消していないノートを新しく直した順（`KN.notes.list()`）、行は題（`headOf`）と
  更新日。上に検索の欄（題・本文、`foldKana`）。押せば決まって閉じる。

### ノートの紙（`screen-notes.js` の `openNote`）

- 「⋯」に「種をまく」。出すのは書いたノートだけ（`stored && !blank()`。道に置くと同じ条件。`roadItem` は
  変えずに隣へ足す）。種の形の記録の紙が重なって開き、閉じればノートへ戻る。紙の頭には最初から
  つながる先の札。`openEntrySheet` に「新しい種・つながり付き」を渡せるようにし、`KN.screens.archive`
  の口から開く。iOS はメモの欄へ、押した流れのまま同期で focus（`KN.ui.focusNow`）。
- 日時・タグの行（`.note-sub`）に、`entriesOfNote` が空でないときだけ札を一つ（絵だけ・数なし）。
  押すと小窓（`popOver`）に記録の行：種類の絵・題（種はメモの頭）・日付。行を押すと記録の紙が
  重なって開く（`KN.screens.archive.openEntry`）。種をまいて戻ったら描き直す。
- `finish`：空のまま閉じた新しいノートでも、つながった記録があれば `drop` しない（条件を一つ足す）。

## 旧データ（移行なし）

- 記録の形・入れ物の版・noteBook は変えない。読み込みで欄を足さない＝今の記録は一文字も変わらない。
- `note` を持つ既存の記録（A2・A3）は、そのまま橋のつながりとして読む（ノートの札にも出る）。
- 消えたノートを指す既存の `note`：今は札を出さないだけ。これからは「つなぎ直す／外す」が出る。データは同じ。
- `fromNote` は種をまいたときだけ書く。過去の記録にさかのぼって付けない。
- 古い版（iPhone に残る前の版）：`note` は T0 から知っている。`fromNote` は知らない欄だが、`reconcile()` は
  記録を一件ずつ直すだけで作り直さず、`updateEntry` は `Object.assign` なので残る（試験で確かめる）。

## 壊れないことの確かめ

理屈は二つ。つながりは記録の一件の中にしか無い——記録が残る・写る・戻るところへ必ず一緒に付いてくる。
ノート側に何も持たないので、二つの保存場所が食い違うことが無い。もう一つは上の太字（見つからなくても消さない）。

| 場面 | つながり |
|---|---|
| 記録を消す | 記録ごと消える。元に戻す・さっき消したもの（`takeOut` の写し・`keepGone`）は丸ごとなので一緒に戻る |
| ノートを最近削除へ | 記録はそのまま。「つなぎ直す／外す」が出る。ノートを戻せば札も戻る |
| ノートが30日で本当に消える（`purge`） | id は残す。控えから同じ id のノートが合わされば、つながりも戻る |
| 空のまま閉じた新しいノート（`drop`） | 種をまけるのは書いたノートだけ。そのうえ、つながった記録のあるノートは空でも残す |
| 記録の保存に失敗（容量） | 記憶と記録の写し（live-idb は元が書けなくても写す）に残り、次に開くと写しから戻る（`older`） |
| ノートの保存に失敗 | 橋はノートに書かないので、橋の操作は失敗しない。種をまいた直後にノートが書けずに消えても、種は残り「つなぎ直す／外す」 |
| 入れ物が開けない日 | 札も「つなぎ直す／外す」も出さない。何も書かない |
| バックアップを保存 | `exportJSON` は state 丸ごと＋noteBook。つながりは記録の中 |
| ファイル・自動の控え・Dropbox の控えから戻す | 記録は置き換え、ノートは id を保って合わせる（`restoreText`・`backup.js`）。ファイルの記録は同じファイルのノートを指すので合う。後から作ったノートは逆引きが空になるだけ（ノートに印を持たないので古い印が残らない）。合わせられなかった日・こちらで最近削除のノートは id のまま待つ |
| 記録の写し（live-idb） | 元と同じ文字列なので一緒に写る |
| Dropbox へ送る | 「前と同じか」のハッシュに記録が入るので、つなぎ替えだけでも送られる。送るだけの片道で、合わせる処理は無い |
| 点検（B4）・大きく減る前の見張り | 数で見るので変わらない（つないでも数は同じ） |

## 試験

新しい台本 `tests/bridge.js`（`open()` を使う。書き方は tests/README.md）：

1. 種をまく：note・fromNote が N、日付はローカルの今日。ノートの札 → 小窓 → 記録の紙 → 札でノートへ戻る
2. つなぐ：`updatedAt` も並びも動かない。ほかの記録は1バイトも変わらない
3. つなぎ直す：A でまいた種を B へ → note は B・fromNote は A。A・B どちらの小窓にも出る
4. 外す → 元に戻す
5. ノートを最近削除へ →「つなぎ直す／外す」、記録の文字列は同じ → ノートを戻す → 札が戻る
6. 30日を過ぎたノート（古い deletedAt を入れ物に書いて開き直す）→ id は残り「つなぎ直す／外す」
7. 入れ物を塞ぐ・読み込み中：何も出さず、記録は変わらない
8. 記録を消す → 元に戻す／さっき消したもの → つながりごと戻る
9. 書き出す → 全部消す → ファイルから復元：note・fromNote が残り、合わせたあとに札。noteBook の無いファイルでも id は残る
10. 自動の控えから戻す：同じ
11. Dropbox（fetch を差し替え）：つなぎ替えだけで送る・送った中身に note・fromNote
12. 記録の写しの json に、つなぎ替えが入る
13. 古い形：note・fromNote の無い記録は読み込みの前後で同じ文字列。崩れた値（数・空）は null、知らない欄は残る
14. fromNote が `updateEntry`・`promoteSeed`・`takeOut`/`putIn` を通っても残る
15. 空のまま閉じた新しいノートでも、つながった記録があれば残る

回す既存：`activity.js`（変えない）・`notes.js`・`note-v19.js`・`notes-restore.js`・`dropbox.js`・
`backup-budget.js`・`live-idb.js`・`break.js`・`undo-gone.js`・`update-path.js`・`daily-rules.js`。
store.js を触るので最後に `run-all.js`（裏で）。
