### ガラス（liquid glass）は、一か所から出す

**「ガラスなのは三つだけ」は、もう違う。** いまは**七つ**——下の帯
（`.tabbar::before`）・＋（`.add-fab`）・＋から立ち上がる札（`.fab-menu-b`）・
トースト（`.toast`）・電卓（`.keypad`）・設定の下の帯（`.set-bar`）・
探す欄（`.search-bar`）。**増えたことが、材を一か所から出す理由そのもの**
——三つなら手で写しても揃うが、七つは揃わない。数えているのは
`--glass-sheen` / `--glass-tint` / `--glass-blur` を読んでいる器なので、
増やしたらここも直すこと。

**席の印（`.tab-lens`）は、ここに入らない。** あれは `--c-primary-soft` の
べた塗りで、ガラスではない——一度ガラスにして（乳白の地・縁の輪・後ろの
ぼかし）、**外した**。経緯は「席の印を歪ませるレンズは、試して外した」。

材は `css/base.css` の `--glass-*` 一組：

- `--glass-sheen` 面のつや ／ `--glass-crown` 上の縁で拾う光 ／
  `--glass-base` 地 ／ `--glass-rim` 縁の一本（上下で明るさが違う輪）
- **`--glass-cast` … ガラス自身の色。** 地（明るい面では純白）をそのまま
  使っていたので、**明るい画面ではガラスが見えていなかった**——実測
  （2026年9月20日、390×844）でカプセルの中 254,254,254 ／ すぐ外の紙
  245,245,245、**差は 9階調**。透かしていないのではない（帯の裏に青い板を
  置くと中は99階調ぶん青へ寄った）。**後ろに白い紙しか無い**うえ、
  `--glass-blur` の `brightness(1.06)` がその白を 255 へ押し上げるので、
  白の上に白を 52% 重ねていた。差すのは**地と同じ寒色**（`#cfcdd9`）を
  一段深くしたもので、**主色ではない**——帯まで主色にすると＋が帯に埋もれる。
  押した姿は `--glass-cast-lit`（薄いほうへ振る＝「より多くの光を拾った」）。
- **`--glass-a` … 地の濃さ（52%）を一つの札で持つ。** 材ぜんぶを夜へ
  差し替えるときと、ぼかしの効かない環境（下）が、ここ一つを動かす。
- `--glass-blur` ぼかし。**`backdrop-filter` と `-webkit-backdrop-filter` は
  同じ一つを見ること。** 以前は prefixed の側にだけ `brightness` が無く、
  「brightness を上げるのが iOS 26 の効きどころ」と自分で書いた一手が
  **iPhone では一度も効いていなかった**（3か所とも）。
- **`--glass-edge` / `--glass-edge-w` … 縁の屈折。** ガラスには厚みがあり、
  厚いものの縁では後ろの景色が解像しなくなる。本物の屈折（`feDisplacementMap`
  を `backdrop-filter: url(…)` で呼ぶ）は Safari で当てにならないので、
  **縁の帯（14px）だけもう一段ぼかす**。重ね順は「地 → 屈折 → 縁の光」。
  **ぼかしだけにすること**——brightness や saturate を足すと、一様な地の上でも
  白い縁取りになる（それが実際に起きた）。
- **`--glass-sweep`（0〜1） … 鏡面光の居場所。** ガラスは**まわりを映す**ので、
  まわりが動けば映りこみも動く。固定のグラデではなく、送っている器の位置から
  この一つの数を出して（`js/app.js` の `paintGlass`、`.5 + .38 * sin(top/115)`）
  縁の光の山を横へ走らせる。止まっているときは**まん中**（端に寄った姿から
  始まると「左が明るい絵」に見える）。
  **書き込む先は `:root` ではない。ガラスの器そのもの**（`.tabbar` /
  `.add-fab` / `.fab-menu-b` / `.toast` / `.search-bar` ＝ 縁の光の `::after` を
  持つ5つ。`app.js` の `GLASS`）。
  - ここは長いあいだ `:root` だった。「`--glass-rim` がそこで組まれるので、
    同じところに居ないと焼きつく」——理屈は正しいが、**代償を測っていな
    かった**。カスタムプロパティは継承するので、`:root` の書き換えは読む5つ
    だけでなく**文書のすべての要素**の style 再計算を呼ぶ。実測（2026年9月20日、
    CPU 4倍・390×844）：一覧を縦に送ると **p90 50.0ms・96フレーム中21落ち**。
    **この一行を止めるだけで p90 16.7ms・0落ち**（書き換え1回 48.9ms。帯の裏を
    読む `backdropLum` は 2ms しかない＝重いのは読むほうではなく**書くほう**）。
    **「どの画面でもうっすら重い」の正体がこれ。**
  - 直しかたは、焼きつきのほうを**使う側で組む**に変えること。`--glass-rim` は
    二つに割った——**動く鏡面（`--glass-rim-spec`）と、動かない輪
    （`--glass-rim-ring`）**。材は `:root` の一か所のまま、`radial-gradient` に
    並べるのは `.tabbar::after` ほかの側。`--glass-fill` の罠
    （「三枚は、使う側で並べること」）と**同じ決めごとの裏返し**。
  - **片方だけ直さないこと。** CSS で `:root` に組み直すと、器へ書いた数は
    焼きついた既定値に負けて動かなくなる。逆に JS だけ `:root` へ戻すと、
    器の `--glass-sweep` が既定の .5 のまま動かない。
  - 直す前後で**画素は 1つも変わらない**（実測：帯・全画面とも差 0／1,316,640）。
    変わったのは値かせぎの場所だけ。
  - 同じ数なら書かない（`el.dataset.sweep`）。書き換えはその器の中を巻き込む
    ので、sin の折り返しで同じ数を置き直す意味がない。
- **`--glass-night-*` … 夜のガラス。二人が同じここを見る。** 一人は暗い面の
  テーマ、もう一人は**明るい面で「帯の後ろが暗い」と分かったとき**
  （`.is-on-dark`。iOS 26 でいう adaptive contrast）。見張るのは `app.js` の
  `watchBackdrop`／`backdropLum` で、帯の裏を三点つまんで地を持つ要素の
  明るさを読む。**境目は二つ**（暗いと決めるのは .42 未満、明るいへ戻すのは
  .52 超え）——一つだと、そのあたりを漂う地の上で帯が明滅する。
  `.is-on-dark` は**字も一緒に返すこと**（ガラスだけ暗くして字を黒のままに
  すると、読めるようにする仕掛けが読めなくするだけのものになる）。ただし
  選ばれている席の色は `--c-primary` を**上書きしない**で `color:` 側で白を
  混ぜる——上書きすると、基調色を変えている人の帯だけコーラルに戻る。
- 縁の光（`::after`）は**七つで一枚の規則**（base.css）。形だけ
  `border-radius: inherit` で器から継ぐ。帯だけは inset を言い直す。
- 暗い面は `--glass-*` を差し替えるだけ。**ぼかしは明暗で変えない**
  ——変わるのは光であって、ガラスの厚みではないので。

**ぼかしの効かない環境の受け皿は、`@supports` 一か所だけ。**
`backdrop-filter` が無いと、ガラスは**半分透けただけの板**になって下の行が
素通しで読める。受け皿が用意してあったのは**トーストだけ**だった（帯も＋も札も
透けたまま）。直しかたは一つ、**地を濃くする**こと——`--glass-a` を 96%（夜は
94%）へ上げれば、七つとも、**あとから足したものも**まとめて受かる。
器ごとに書かない。

#### 教訓（どれも一度こわした）

- **カプセルの形をしているものは四つある**——地（`.tabbar::before`）・縁の光
  （`.tabbar::after`）・縁の屈折（`.tab-edge`）・押しているあいだの光
  （`.tab-hold`）。`.has-fab` で＋のぶんだけ短くするときは、**四つとも、
  同じ一か所で**。`.tab-edge` をその並びに書き忘れて、縁の屈折だけが帯の端まで
  伸びたまま残り、**カプセルと＋をまとめて囲む大きな輪**が出た（内と外で材が
  違うので、別々のものを重ねて置いたように見える）。押しているあいだの光は
  自分の `right` を別の行に持っていて、それが「三つ」と数え違えた元。
- **地の濃さを動かしたら、縁の白も動かす。** 縁の一本は長いあいだ「白の上の
  白」で、**一度も見えていなかった**（実測：カプセルの中 250、縁も 250——
  段差 0）。その見えない線に合わせて白を強く（.62／.95）置いてあったので、
  地を一段落とした（250 → 225）とたん、**縁だけが明るい輪郭線として立った**
  （段差 **+12**、＋は -5 → +9）。そうなるとガラスの縁ではなく「濃い板の
  まわりに白い線を引いたもの」に見える——実際そう見えた。いまは **+4**。
- **縁の屈折は、小さくて丸いもの（＋・札・トースト）に着せない。** あれらは
  **自分の落ち影がすぐ真下にいる**ので、縁の帯が影をいっしょにぼかして
  **暗い輪**になり、丸の中にもう一つ丸が入っているように見えた（実測：＋の
  斜めの断面で、帯の内ふちに **7〜9階調**の段差。カプセルでは 1階調以下）。
  着せるのは帯のカプセルだけ。

**三枚を一つの札にまとめてはいけない。** `--glass-fill: var(--glass-sheen),
var(--glass-crown), var(--glass-tint)` と書いたら、**＋のコーラルが消えた**。
`var()` の中身は**その変数を書いた要素の上で**解決されるので、`:root` で組んだ
一枚は `:root` の `--glass-tint` を焼きつけて配られる。＋が自分の
`--glass-tint` を上書きしても手遅れ。**三枚は、使う側で並べること。**
色を差したい器（＋）は `--glass-tint` を、押した姿は `--glass-sheen` /
`--glass-crown` / `--glass-base` を、**その要素の上で**差し替える。
同じ罠は `--face-fade`（価格に着いた紙の薄れ）でも踏みかけた——`--face-cut`
を読む一枚は、`:root` ではなく**それを使う要素の上で**組むこと。
