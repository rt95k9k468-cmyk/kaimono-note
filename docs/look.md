# 見た目の決めごと（重なりの順・絵文字・席の名前・色）

CLAUDE.md から見出しごと移した、詳しい決めごと（2026年9月26日）。
本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも
踏む罠は CLAUDE.md にある。**新しい決めごとは、ここ（該当する docs）に書く。**

### 重なりの順は、名前で持つ（`--z-*`）

**数を勘で選ばない。** ここは 0 から 600 まで**17通りの数**がばらばらに
書いてあった（帯 30・紙 100/101・トースト 200・電卓 400・火花 600…）。名前が
無いので、新しく重ねるものを足すたびに勘で数を選ぶことになり——**そして勘は、
どれか一つと必ずぶつかる。**

段はこれだけ（`css/base.css`）。**数そのものより、順番と理由**のほうが大事
なので、名前にはその段が何であるかを持たせる：

| | | |
|---|---|---|
| `--z-stick` | 12 | 貼りつくもの（暦）。上のバーの**下**に潜る |
| `--z-head` | 20 | 画面の頭（上のバー・設定の帯・ドックの器） |
| `--z-bar` | 30 | 浮いているもの（下の帯・＋） |
| `--z-lift` | 60 | 指が運んでいるもの。どの面よりも上、紙よりは下 |
| `--z-sheet` | 100 | 紙と、その覆い（`js/ui.js` が重なった深さぶん足す） |
| `--z-toast` | 200 | お知らせ。紙の上にも出る |
| `--z-pad` | 400 | 字を打つための道具（電卓）。紙の**上**でないと使えない |
| `--z-top` | 600 | いちばん上。一度だけ出る光 |

**行や札の中の 0〜6 は、ここには含めない。** あれは「この部品の中でどちらが
手前か」の話で、画面の段ではない——含めると、名前の並びが部品の都合で
にぎやかになって、段の順が読めなくなる。

### 絵文字は、もうどこにも無い（カテゴリ色の丸）

「アプリ内UIに絵文字を使わない」は最優先の約束事なのに、**カテゴリ9つ全部が
絵文字を持ち、五か所で描かれていた**（買うもの・価格の札、設定のカテゴリ一覧、
トーストの文、カテゴリを直す紙）。しかも設定には**絵文字を打ちこませる入力欄**が
あった——**打てるのに出ない、では打った人の字が消えたように見える**ので、欄ごと
出さない。

- かわりに置くのは**カテゴリ色の丸**（`.chip-dot`、9px）。色はこの画面がすでに
  「どの棚か」を言うのに使っているもの（行の丸・暦の丸・丸薬）なので、**同じ
  言葉を札でも一度使うだけ**で済む。新しく描くものは無く、利用者が足した棚にも
  自動で付く。
- **選ばれた札の中では白抜きに戻す**（`currentColor`）。あちらは地が `--cat`
  そのものなので、同じ色の丸を置くと消える。
- **保存済みの `emoji` 欄は消していない。** 描くのをやめただけで、
  `DEFAULT_CATEGORIES` も既存の記録もそのまま。**編集の保存では `rec.emoji` に
  触らない**（触ると保存済みの値が黙って消える）。新しい棚は `emoji: ""` で形だけ
  揃える。
- カテゴリの一覧の行は、**すぐ左の色の帯が同じことを言っている**ので、絵文字の
  列を抜いただけ。`.chip-emoji` / `.manage-emoji` の CSS は消した（描くところが
  もう無い）。
- **途中で一度こわした**——入力欄を消したときに `const emoji` も消したが、新しい
  棚を足す `s.categories.push({ … emoji … })` がまだそれを参照していた。
  構文は通るので `node --check` では出ず、**試験が「編集」しかしていなかった
  ので、そこも抜けた**。試験には「追加」も入れること。

### 席の名前は英語、中身の名前は日本語

帯は daily / tasks / shopping / health、題は shopping / prices と英語なのに、
**設定だけ「設定」**で、設定画面では「shopping」の下に「一般」が並んでいた。
**同じ系列の中でそこだけ言葉が変わる**のが、混ざって見えていた正体。

- 席の名前は英語で通す：設定の帯・大きな題は **Settings**、節の見出しは
  **General**。
- **線は「席か、中身か」で引く。**「›」の先（外観・バックアップ・
  カテゴリ…）は**中身の名前**なので日本語のまま。中身の行はもともと日本語。
  英語にするのは**画面を指す言葉だけ**。

### 文字の大きさは、倍率一つ（`--fs-k`・B11）

設定 → 外観 → 文字の大きさ：**標準**（1）・**大きめ**（1.12）・**特大**（1.25）・
**端末**。保存は `settings.textSize`（`std` / `l` / `xl` / `auto`、知らない値は
`reconcile()` で `std`）。既定は標準で、**入れる前と一画素も変わらない**
（倍率 1 のときは `:root` に何も書かない）。

- **字の大きさは、どれも `--fs-k` を掛けて書く。** `--fs-*`・ダイエットの
  上書き・`--set-fs*`・直に px で書いてあった42か所・JS の中の11か所を
  `calc(Npx * var(--fs-k))` にした。**掛け忘れた字だけが、大きくしても
  取り残される**——新しい字を足すときは `--fs-*` を使うか、掛けること。
- **掛けていないのは、グラフの軸（`.diet-axis` / `.diet-goal-tag`）だけ。**
  SVG の寸法計算がその大きさを前提にしているので（screens.css のダイエットの節）。
- 行の高さ・余白・絵は変えない。字だけ。特大で四つの席と設定を撮って、重なり・
  はみ出しが出ないことを見た（長い店名は「…」、長い品名は折り返す）。
- **「端末」は iPhone の「文字サイズ」を読む。** Safari は `font: -apple-system-body`
  に端末の文字サイズを載せるので、それを素の 17px で割る（`app.js` の
  `deviceTextK`）。**0.9〜1.3 に収める**——「さらに大きな文字」は3倍まで行くので。
  アプリへ戻るたびに読み直す（`visibilitychange`）。ほかのブラウザはこの書体名を
  知らないので 1（標準と同じ）。
- `--fs-k` は `:root` の style に書く。一度きりの書き込みなので、「毎フレーム
  書くものは `:root` に書かない」には当たらない。
- 試験は `tests/text-size.js`。

### 書体は三つ（2026年10月8日）

設定 → 外観 → 書体：**ゴシック**（既定）・**丸ゴシック**・**明朝**。札は `<html data-font>`（既定は付けない）。
中身は `css/base.css` の `:root` を閉じたすぐ下の規則で `--font` を入れ替えるだけ（札は増やさない）。
選ぶボタンも同じ `data-font` を持ち、自分の書体で名前を出す。試験は `tests/typeface.js`。

- **選べるのは、iPhone に最初から入っていて字の欠けない面だけ。** Apple の書体表で「iOS system font」の日本語は
  ヒラギノ角ゴ（Hiragino Sans W3〜W8）・丸ゴ ProN W4・明朝 ProN W3/W6 の三つ。Klee・Hiragino Sans W0〜W2/W9
  などは「downloadable」で、入っていない端末では web から呼んでも出ない。ProN は JIS X 0213 の字まで持つ。
- **web フォントは入れていない。** 削って持っていた BIZ UDPゴシックは、削った外の字（人の名前）だけが別の顔で
  出た（base.css の「書体」の節）。削らずに持つと一本 数MB・太さ二本で倍、配布物は base64 でさらに膨らむ。
  字ごとに分けて配るもの（Google Fonts）は、まだ取りに行っていない字がオフラインで別の顔になる。
- 丸ゴは W4 一つなので、太字（700）はブラウザが太らせた字。明朝は W3/W6 で 400/700 とも本物。
- iPhone・Mac のほかには、どちらも無い。丸ゴはその端末のゴシック、明朝は游明朝 → Noto Serif JP → serif。

### 説明は書かない（2026年9月30日）

利用者から「何でもかんでも説明している。いまの設計はおかしい」と言われ、
全画面の説明文を削った（設定の注記・ダイエットの注記・入力欄のヒント・
空の画面の文・選ぶ紙の副題、25ファイル）。**足す前に、まず書かずに済まないかを疑う。**

- **書かないもの**：題・ボタン・スイッチがもう言っていること／押せば分かる
  こと／安心させるための言い回し（「〜で大丈夫です」「〜は変わりません」）／
  仕組みの説明（「端末の中で計算します」）／経緯（「前は〜でしたが」）。
- **残すもの**：押すと戻せないこと・黙って裏切ること（通知は閉じていると
  鳴らない、など）・つまずいたときの逃げ道。**一文で。**
- **めったに要らない手順は畳む**：`KN.settingsParts.more(見出し, 本文)`
  （`<details class="set-more">`）。閉じているあいだは見出しの一行だけ。
- **字は大きく、薄くしない**：残した説明は 15px 前後（`--set-fs-foot` 15px、
  `.diet-note` `.field-hint` `.diet-steps` は `--fs-md`）、色は `--c-text-2`。
  小さく薄く長く書くのが、いちばん読まれない形だった。
- 空の欄（`.field-hint:empty` / `.icon-pick-sub:empty`）は出さない。

### 色

`--c-primary` と `--c-primary-fill` は**役目が違う**。字に使うのは
`--c-primary`（`#b84944`）のほうで、39か所が字の色として参照して
いるので、ここを塗りの色にすると画面が読めなくなる。

**そして逆もやっていた——塗りの色を、字と絵に使っていた。** 6か所：
日付の題の年（`.day-y`）と当日の日にち（`.day-d.is-today`）、買うもの・
価格の題（`.tab-title`）、「今日へ戻る」の矢（`.topbar-today`）、詳細の紙の
行の絵（`.d-ico`）。実測 **1.80:1**——3画面のいちばん上の字が、ほとんど
見えていなかった。全部 `--c-primary` へ。

**これは事故ではなく、意図だった。** 当時のコメントに「白の上で 2.25:1 しか
なく、ふつうの本文には使えないが、隣に並べたときに同じ色に見えることのほうが
要る」と書いてある。ただし**そのあと塗りの色をさらに淡くした**（2.25 → 2.06、
地の上では 1.80）ので、判断のもとになった数が古くなっていた。**同じ色に見える**
は、どちらもコーラルの系統なので `--c-primary` でも保たれる。

#### 薄さで引っこめるのは、やめた（`--c-text-3`）

`#8e8e93` は地の上で **2.85:1**。曜日の行・設定の見出しと説明・作成の札・
からだの項目名と目標値・買うものの補足——**読ませたい細かい字**が軒並みこの
濃さだった。**`#686870`（4.51〜5.52）へ。**

そうすると `--c-text-2`（`#636363`、4.90〜6.01）と**ほとんど同じになる**。
それでいい——**三段目の墨は、読める濃さと見分けのつく薄さを両立できない**
（実測：どの地でも 4.5 を満たす値は、もう text-2 の隣にしかない）。
引っこめるのは**小ささと空き**の仕事で、薄さの仕事ではない
——daily の節に書いてある「静けさは字の小ささではなく、空きの多さで持たせる」
と同じことを、色の側でも言うだけ。段を広げたくなったら、**濃いほう
（text-2 を黒へ寄せる）から広げること。** 暗い面は `#7c7c83` → `#92929a`。

**時間割の左の時刻**（`.tl-time`）も `--c-text-3` だった（2.99:1）。
CLAUDE.md の実測は「副題と左の時刻は #636363」なので、`--c-text-2` へ戻した。

#### 太さは 400 と 700 の二つだけ

`500` / `600` / `800` が **12か所**残っていた（`.cal-wd` `.cal-n` /
`.set-nav-title` `.set-head` / `.arc-log-head h2` `.arc-log-day b`
`.arc-stack-head h2` `.tl-time.is-now` `.tl-band-time` `.arc-counts-head`
`.arc-counts-days b` `.arc-counts-n`）。日本語の書体は中間の太さを持たないので、
ブラウザが**自前で太らせた字**（縁がにじむもの）になる——書体の節が、まさに
それを避けるために二値へ揃えた決めごと。見出しを立てたいときは、太さではなく
**大きさか色**で言う。

#### 実測（明るい面・地は `--c-bg` #f0eff3 ／ 紙 #f5f5f5 ／ 灰の札 #e8e8e8）

| | |
|---|---|
| `--c-text` #111113 | 16.5〜18.9 |
| `--c-text-2` #636363 | 4.90〜6.01 |
| `--c-text-3` #686870 | **4.51〜5.52**（もと 2.66〜3.26） |
| `--c-primary` #b84944 | **4.21〜5.15**（もと #bf4f49 で 3.87〜4.74） |
| `--c-primary-ink` #8f3833 | 6.16〜7.55（灰の札の上の字、`.low-add`） |
| `--c-accent` #2072ab | **4.23〜5.18**（もと #2f7fb8 で 3.53〜4.33） |
| `--c-primary-fill` #f49e98 | 1.80〜2.06（**塗り専用**） |

**`--c-primary` の「4.7:1」は、白の上の数字だった。** アプリの地は白では
ないので、もとの `#bf4f49` は実際は **4.14（地）〜4.35（紙）** で、小さい字の

値札の `--c-accent` `#2f7fb8` も **3.78〜3.97**（`.item-price-amount` の ¥）。

**決めた（2026年9月26日）：明るい面の `:root` だけ、`--c-primary` を
`#b84944`（地で 4.50）、`--c-accent` を `#2072ab`（地で 4.52）へ。**

- どちらも **OKLCH で色相と彩度を保ち、明るさだけを下げた最小値**。
  総当たりでも、これより小さい色差で地の上 4.5 に届く色は無い。
- 前に書いていた候補 `#b94b45` / `#2a73a8` は、地の上で **4.42 / 4.46** で、
  4.5 に届いていなかった（書いてあった 4.64 / 4.68 は紙の上の数で、地の上では届かない）。
- **灰の札（`#e8e8e8`）の上は、新しい色でも 4.21。** そこに乗る字——
  「そろそろ切れそう」の「入れる」（`.low-add`）——は、字の色だけ
  `--c-primary-ink`（`#8f3833`、6.16）にした。札の地も絵の形も変えていない。
  **明るい面だけ**——暗い面の `-ink` は淡い桜色 `#f8c5c1` で見た目が変わるので、
  暗い面の「入れる」は `--c-primary` のまま（地 `#26262d` で 6.68）。
- **変えなかったもの：** 暗い面（どちらも地の上で 5.9 以上ある）、塗りの
  `--c-primary-fill`、ほかの7色の基調（ローズ・マスタード・アプリコットの
  規則にも `#2f7fb8` が直書きで残っている）、それらの値札のオレンジ `#d8722f`。
  この三つは、測り直すなら別の回で。
- 見比べたページ：claude.ai の artifact「BBkMnmSiA8orTH8NsogL1V」。

**塗り（`--c-primary-fill`）は参考画面（Structured）と同じ `#f49e98`。**
白の上で 2.06:1。濃さは 4.28 → 3.10 → 2.72 → 2.06 と下げてきた終点で、
**白抜きはそのぶん薄くなる**（丸薬の中の絵と、暦の日の下の丸）。上げるなら
この一行だけ——`--c-primary` は字の色なので、そちらを塗りに使わないこと。

（以下は経緯）**塗りは実測の `#f2938e` から `#d34c45` へ濃くした（2.25:1 → 4.28:1）。**
丸薬の中を白抜きにした以上、この色は「白が乗る地」になった——2.25:1 では
白抜きが消える。夜の色（`#55799f`、4.54:1）と釣り合う濃さに揃えてある。
丸薬の地も **42%混ぜをやめてべた塗り**（`--tl-fill`）。混ぜていたのは中の絵が
色つきの手描きだったころの話で、いまは中が白抜きなので濃いほうが読める。

設定の基調色の札の id は `"orange"` のままだが、中身はコーラル。保存済みの
値を書き換えずに色だけ入れ替えるため。

上のバーと暦は**すりガラスにしない**（下を白い紙が流れるので、透かすと
行の字が重なる）。

（19・24px）。商品の紙の数量だけは `font-weight:800` が残っていたので 700 にした（二つだけ、の決めごと）。

**寄せなかったもの（わざと）：**
- **色と影。** 札は暗い面で値が変わるので、明るい面の値と同じ直書きを札にすると、暗い面の見た目が
  変わる。直書きの色は CSS に約370（絵・グラフ・基調色ごとの規則が多い）。寄せるなら一つずつ両面を撮って。
- **字の 11〜16px。** `.diet` が `--fs-xs`〜`--fs-lg` を大きく上書きしている（ダイエットの字）。
  `calc(14px * var(--fs-k))` と直に書いた字は、ダイエットの中でも 14px のまま——札にすると大きくなる。
- **札に無い値**（角の 2・7・14・18px、行の高さ 1.25・1.4 など、余白の二つ以上の並び）。札を増やさない。

### 「元に戻す」（roadmap-2.0 の V18・2026年10月4日）

- 出る場所は一つ（`KN.ui.toast`）。**押せるものが付くトーストは既定 5 秒**（`TOAST_ACT_MS`）、無いものは
  3.6 秒。押しに行くあいだに消えないように。長さを数では渡さない（U1）：読むのに時間がかかる文は
  `long: true`（8 秒）、答えを待つあいだの「…しています」は `until: true`（呼ぶ側が閉じる。上限 60 秒）。
- ボタンの言葉は**「元に戻す」だけ**（「戻す」と割れていた4か所を揃えた）。分けたものを戻す「ひとつにする」
  と、行き先を開く「見る」は、何が起きるかを言う言葉なので別。消したトーストは**「消しました」**（「削除
  しました」を揃えた。確かめの紙の言葉は触っていない）。
- 消す・済ませる・送るには「元に戻す」を付ける。無かったところに足した：daily の記録・体重・食事・お酒・
  衝動・運動（store の `remove*` が `takeOut` で**同じものを同じ場所へ戻す関数**を返す。記録の形は
  変えない・二度押しても増えない）、商品の価格の一件・商品ごと（一緒に外したリストの項目も）。
  確かめの紙はそのまま残し、「元に戻せません。」の一文だけ外した（戻せるようになったので）。一件の記録の確かめの紙は U11 で外した（下の「消すとき」）。
- 設定の店・カテゴリを消す・データをすべて消すは、言葉だけ揃えた（戻すは付けない：まれ・三段奥）。
- **時間と割り込みで奪わない**（roadmap-seamless の N13・2026年10月10日）：見えていないあいだは数えない（戻ったら残りから）。
  押せない知らせは前の押せない一枚だけを替え、「元に戻す」の上に短く出て消える。押せるもの付きが続いたら新しいほう。
- 試験：`tests/undo-toast.js`（長さ・言葉をソースで見張る・六つの記録の戻し・daily の記録を画面から・裏へ回る・割り込み）。

### 言葉の札（roadmap-unify の U10・2026年10月7日）

同じことは同じ言葉で言う。新しい紙・ボタン・知らせを足すときは、この表から選ぶ。

| 何を | 言い方 | 使わない |
|---|---|---|
| 消す | 「消す」（ボタン・⋯・aria）／知らせは「消しました」 | 「削除」（iPhone と同じ「最近削除した項目」と、控えの名前「削除前」だけ残す） |
| 確かめの紙の題 | 「〜を消しますか？」／決めるボタンは「消す」 | 「〜を削除しますか？」「〜を消す」 |
| 足す紙の題 | 書くもの（daily・ノート）＝「〜を書く」、測ったもの（体重・食事・お酒・運動）＝「〜を記録」、品物・用事・店・カテゴリ＝「〜を追加」 | 「〜を足す」 |
| 直す紙の題 | 「〜を直す」 | 「〜の編集」 |
| 主ボタン | 新しく作る紙は題の動詞（書く・記録する・追加）、直す紙は「保存」 | 直す紙の「直す」「書く」 |
| 終わりの知らせ | 題の動詞＋「ました」（追加しました・記録しました・保存しました） | — |
| 書いた先から残す紙を閉じた | 変わっていれば「更新しました」（daily の log・ノート・品物の紙。新しいノートは「保存しました」）。消した・外したときは出さない（「元に戻す」の知らせを残す）。試験は `tests/close-toast.js` | 開いて閉じただけで出す |
| 見つからない | 「見つかりませんでした」（句点なし） | 「見つかりません」で止める |
| 写した・写せなかった | 「コピーしました」「コピーできませんでした」の二つ（iPhone と同じ「コピー」） | 「〜をコピーしました」「長押しで…」を知らせに足す |
| AI の入口 | 「AIに〜」（AIに相談・AIに渡す文・AIにほどいてもらう・AIに分けてもらう） | 「AIと〜」「AI用〜」 |

- 残したもの：「食事を書く」（時間帯ごとに書きためる紙。項目で入れる「食事を記録」とは別の紙なので、題を
  分けたまま）。日記の「本文が見つかりません」（探した結果ではなく、本文が無いという状態）。ノートブック・
  タグ・中継所の「外す」（消すのとは別の動き）。「AI推計」「AIの窓口」（入口ではなく名前）。
- 試験：`tests/words.js`（門。画面を開かずにソースを読む）。

### 消すとき（roadmap-unify の U11・2026年10月7日）

- **一件の記録は紙の頭の ⋯ から消す。確かめずに消し、「元に戻す」（5秒）だけ付ける**——やること・ノートと同じ形。
  daily の記録・体重・食事・お酒・飲みたくなった・価格の一件。作りは `KN.ui.delMenu(remove, { sheet, after })`
  （`remove()` は store の `remove*` と同じく戻す関数を返す）。紙の足もと・中身に「消す」のボタンを置かない。
- 確かめの紙を残すのは、**まとめて消す・戻せない・設定の奥**だけ（商品ごと・店・カテゴリ・データ・中継所）。
- 一枚の中に何件も並ぶ行（からだの紙の運動・商品の紙の価格の行）は、行のゴミ箱のまま（確かめずに戻すだけ）。
- 紙を開いたときの最初の焦点に ⋯ を選ばない（`sheet()`）。
- 試験：`tests/del-rule.js`（門。画面を開かない）・`undo-toast.js`・`diet.js`。

### 数字は丸い字（2026年10月8日、利用者が見比べの画像で選んだ）

- 日付・時刻・体重など、数字を読ませるところは `--font-num`（`ui-rounded, var(--font)`）＝ iPhone・Mac の Safari では
  SF Pro Rounded。漢字・かなは後ろの `--font` へ落ちる。Chromium などは ui-rounded を読めないので今までどおり。
- 当てる先は base.css の一つの規則に並べる（`.mono-num`・帯の日付・暦の数・時刻の札ほか）。数字の場所を足したらそこへ一つ足す。
- 明朝を選んだ人には効かせない（`--font-num` が `--font` のまま）。試験は `tests/look-1008.js`。
