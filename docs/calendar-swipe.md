# 払う・暦（day-swipe / cal-swipe / cal-peek・暦の三段）

CLAUDE.md から見出しごと移した、詳しい決めごと（2026年9月26日）。
本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも
踏む罠は CLAUDE.md にある。**新しい決めごとは、ここ（該当する docs）に書く。**

### 紙を横に払うと、日が動く（三画面共通・`js/day-swipe.js`）

やること・daily・ダイエットは、どれも**一日ぶんの紙**を出しています。隣の日へ
行く道は暦にもありますが、「昨日はどうだったか」を見るのに毎回上まで戻るのは
遠い。紙そのものを払えば、日が動きます。仕掛けは `js/day-swipe.js` が持ちます
——**三画面が同じ一つを分け合います**（書き写すと、片方だけを直した日に三つの
紙が違う動きをします）。画面が答えるのは四つだけ：いま見ている日は何か
（`day`）、その隣はどこか（`step`、行けないなら null）、その日の紙をどう組むか
（`slide`）、決まったら何をするか（`commit`）。

- **動くのは紙そのもの。** やること・daily は、指を離してから中身を差し替えて
  22px ぶん横から入れていました（`.tl-sheet.is-from-right`）——払っている最中は
  何も動かないので、**どこまで行けば送られるのかが絵に出ていません**でした。
  いまはダイエットと同じで、隣の日の本物の紙が指のぶんだけ連続して入ってきます。
- **隣の紙は、指が触れる前に、DOM の外で組んでおく**（控え＝`ready`）。
  ダイエットは三枚を最初から並べていましたが、あの画面は一日ぶんが軽いので
  通っていただけです。やることの時間割を毎回三日ぶん組むと、store が動くたびに
  三倍の絵を捨てて組み直すことになります。だから「横だと決まった瞬間（5px）に
  その場で組む」にしていた——**これが、払いはじめのカクつきの正体でした**
  （実測 2026年9月20日・CPU 4倍：払い始めから 70ms の地点で **237ms** の
  長タスク。指はもう動いているのに、そこで二日ぶんの絵を組んでいた）。
  いまは組み直しが済んで暇になった拍（`requestIdleCallback`）に、**一度に
  一枚ずつ**組んで控えておきます。掴んだら差し込むだけ。控えが無ければ、
  これまでどおりその場で組みます（落ちない形を残す）。
  **「ふだんの DOM には、今日の紙しか居ません」はそのまま**——控えは
  `document` に繋がっていないので、`.todo-day .tl-list` や `.tl-now` のような
  「一枚しか無いはず」を探している側は、一枚も掴めません。
- **差し込むのは、指が向いている側の一枚だけ。** 実測で、差し込みそのものの
  JS は **0.8ms**、**そのあとのレイアウトが 113.6ms**——費用は組むことではなく
  **画面に置くこと**のほうでした。右へ動いているあいだ左の一枚は一度も
  見えないので、その半分は払いません（237ms → **88ms**）。指が戻ってきたら、
  そのときに反対側を差し込みます。**前に一枚増えると真ん中の居場所がずれる**
  ので、`originX` を同じ拍で直して描き直すこと——直さないと指の下で紙が
  一枚ぶん跳びます。
  - `contain` / `content-visibility` も試しましたが、**どれも効きませんでした**
    （131〜171ms、ぜんぶ誤差の内）。費用は囲い込みで減る種類のものではない、
    というのが実測の答えです。**入れないこと。**
- **払い終わりに、画面を組み直さない。** 滑りきった時点で、画面に出ている紙は
  もう「その日」の正しい紙です。捨てて同じものを組み直していたので、指を
  離したあとに **134ms**（＋後続 71ms）固まって、次の日が「いきなり出てきた」
  ように見えていました。いまは滑りきった一枚を**真ん中に据えて**（`adopt`）、
  その紙そのものを `commit(day, kept)` の二つめで渡します。画面の側は
  **変わったものだけ**を塗ります——日付の題・暦の輪・週の帯。
  - **`inert` と `is-peek` を落とすこと**——残すと、着いた先の行が一つも
    押せません。
  - **月をまたいだときだけ、暦の盤を差し替える**（`setCalMonth` ／ daily は
    `render`）。盤は月ぶんなので、日が変わっただけなら塗り直す必要がない。
  - **daily は `is-here` も付け替えること。** あの画面には やること の
    `paintHere` にあたるものが無く、印は `fillCalendar` が組むときに書いて
    いるので、組み直さないと前の日に残ります（輪だけ動いて、色の付いたマスが
    一日ずれる）。
  - **ダイエットだけは、着いてから組み直します**（`kept` を受け取らない）。
    あの画面の隣の二枚は `peek: true` ——押せない・打てない作りで、食事の段も
    別に組まれている（`buildSlotBoxes` の `!peek`）。据えると、着いた先の紙に
    **何も書き込めません**。払いはじめのカクつきのほうは控えが受け持ちます。
- 器は `.day-car`（`overflow: hidden` ＋ `touch-action: pan-y`）、中身は
  `.day-track` に並ぶ `.day-slide`。既定の transform は**素のまま**（一枚しか
  居ないので）。**行けない側には何も置きません**——動くのは transform だけ
  なので、置いても置かなくても同じ絵で、置いたぶんだけレイアウトの費用が
  かかります（`.is-void` の場所取りは、そのぶんごと外しました）。
- **daily の段の間（`gap: var(--sp-8)`）は `.day-slide` が持つ。** 中身が紙から
  一枚下へ移ったので、余白の役目もそこへ移します——移さないと六つの段が隙間なく
  積み上がります。
- 行けない向き（daily・ダイエットの「今日より先」）は 0.3倍に重くします。
  やることは先の日へも行けます（これから何をするか組む画面なので）。
- **待っているあいだの長押しの見張りは `document` で。** `wireDrag` は一覧
  （`.tl-list`）に付けていましたが、払いはじめると day-swipe が**外枠**で
  ポインタを捕まえます（`setPointerCapture`）——捕まえた先は一覧より外なので、
  以後の `pointermove` も `pointerup` もそこまで降りてきません。見張りが黙ると
  長押しの時計は止まらず、**払い終わったあとに行が持ち上がりました**。
  `reorder.js` も同じ作り（document）です。
- 用事を運んでいる最中（`tlDrag` / `KN.reorder.isActive()`）は取りません
  ——`busy()` がそれ。掴んでいるあいだは `lock()` で組み直しを止めます。

### 暦を横に払う（三画面共通・`js/cal-swipe.js`）

月めくりと週送りの手つき。**三画面が同じ一つを分け合う**（前は
`wireMonthSwipe` を三つに書き写していた）。画面が答えるのは五つだけ：
週だけ出しているか（`isWeek`）、いま見ている日は何か（`here`）、週を送った
先はどこか（`step`、行けないなら null）、その月の日のマスはどれか
（`monthGrid`）、決まったら何をするか（`go`）。

- **月と週で、動くものが違う。** 月ぜんぶのときは、これまでどおり盤ごと
  横へずらして薄くする（月は一枚の紙なので、押して送るのが素直。隣の月を
  先に組んでも、ほとんどは目に入らないまま捨てることになる）。
  **週のときは本物を先に並べる**——指のぶんだけ隣の週が連続して入ってくる。
  動くのは一行で、その行の中身は「先週の日にち」というはっきりした行き先
  なので、どこまで行けば送られるのかが絵に出る（day-swipe と同じ考えかた）。
- **真ん中は、生きている `.cal-slide` をそのまま運ぶ。** 組み直した写しを
  置くと、選んでいる日の輪（`.cal-ring`。枠ごとに描かず一つだけ置いて
  滑らせるもの）が払っているあいだだけ消える。片づけるときに元へ戻すので、
  いた場所（親と次の兄弟）を覚えておくこと。
- **隣の週のマスは、行き先の月の盤から抜く。** 週は月をまたぐので、着いた
  先の暦から見て隣の月の日は薄い字（`.is-out`）になる。いまの月の盤から
  抜くと、**払っているあいだだけ濃くて、指を離すと薄くなる**。
  盤は `monthGrid(y, m)` が返す——いま出している月なら生きている盤を
  そのまま、そうでなければ `fillCalendar(sec, {year, month})` で組む。
- **`fillCalendar` に月を渡したら、最後の二つ（週の印と輪）は置かない。**
  離れたところへ組むぶんは画面に出ないので、置くと出ていない盤のために
  生きている題まで塗り直すことになる。
- **先に見せる二枚から `data-day` を外すこと。** あの二枚は `.cal` の中に
  居るので、付けたままだと `cal.querySelector('.cal-day[data-day=…]')` で
  探している側（輪を置く `paintHere`、週の外に印を付ける `tagOffWeek`）が、
  生きている盤より先にこちらを掴む——輪が別の週へ飛び、先に見せている週が
  「週の外」と判定されて消える。絵として要るのは見た目だけ。
- 隣の二枚は clone なので押せない（`inert`）。押す相手は、着いてから本物に
  戻る。ふだんの DOM には**いまの週しか居ない**（day-swipe と同じ理由）。
- 行けない側（daily・health の「今日より先の週」）は中身の無い一枚
  （`.is-void`）で場所だけ取り、指は 0.3倍に重くする。やることは先の週へも
  行ける（これから何をするか組む画面なので）。
- 払っているあいだ（`KN.calSwipe.isActive()`）は cal-peek に渡さない
  ——同じ盤を二つが取り合うと、運んでいる最中に高さまで動く。

### 暦は、紙を引くと出てくる（やること／daily 共通）

仕掛けは `js/cal-peek.js` にある。**やることと daily が同じものを使う**
（書き写さない——片方だけ直した日に、二つの暦が違う動きをするので）。
画面側が答えるのは「何が『いま見ている日』か」「いつ引いてよいか」だけ。

暦（`.cal`）は三層：曜日の行（`.cal-wds`）／伸び縮みする窓（`.cal-clip`）／
その中のずらし（`.cal-slide`）＋日のマス（`.cal-grid`）。
**縦の transform は `.cal-slide`、横は `.cal-grid`**（月めくりの
`wireMonthSwipe` が横を持っているので、同じ要素に二つは書けない）。
`.cal-wd` は `.cal-grid` の外に出した——伸ばしても曜日が動かないように。
組むのは `KN.calPeek.mount(sec)`。**やること・daily・ダイエットの三つとも
この組み**（日付の題／三層／掴み手／引いて開く）。daily の暦だけは、日を
選んでいなければ題が「8月」まで（月ぶんを出す画面なので）。

開き具合は数**ひとつ**（`--cal-p`：0＝週、1＝月）に集約してある。窓の高さ、
ずらし、隣の週の濃さ、題の右の「›」の傾きが、すべてこれから出る。途中で
指を離しても全部が同じところにいる、というのがこの作りの理由。

- **どのスクロール位置からでも引ける。** 前は「いちばん上にいるときだけ」
  だった（`root.scrollTop > 0` で降りていた）。掴み手はどこまで送っても上に
  居る（sticky）ので、そこを掴んだのに何も起きないのは筋が通らない。
- **動かすのは暦の高さ。紙はそのぶんだけ上下する。** 数（p）から出るのは
  `visibleH` ひとつで、窓の高さ・曜日の行・上下の余白・**掴み手の貼りつく床
  （`--cal-h`）**が、すべてそこから毎フレーム出る。紙の上端（丸角＋掴み手）が
  いつも暦のすぐ下に来るのは、床が同じ数から出ているからで、実測で ±1px。
  - **紙のほうを transform で動かす作りは、試して外した。** 暦を月の姿で
    留めて紙を平行移動させれば組み直しが要らない、という話だったが、それには
    紙が暦の**上**を通らなければならない（上へ押して暦を消すのは「紙が覆う」
    ことなので）。ところが紙の箱は画面の上へはみ出している——送った先では
    紙の頭は viewport のずっと上だ。上に乗せた瞬間、**紙の地が暦を丸ごと
    隠した**（実測：ダイエットで下まで送ってから引くと、暦が一度も見えない）。
    紙のはみ出しを切るには clip-path を毎フレーム計算することになり、高さを
    書き換えるより高くつく。**暦が前、紙はその下を流れる**——この順が正。
- **引きはじめたら、送りを覚えて戻す。** 測るために隠していた週をいったん
  出すので、そこでブラウザの「読んでいた場所を保つ」が働き、伸びたぶんだけ
  画面が黙って送られる（実測 196px＝月と週の差ぶん、指の下で跳ねた）。
  `begin` で `scrollTop` を控え、正しい高さを書いたあとに戻す。収まった
  あと（`done`）も同じところへ。`.cal { overflow-anchor: none }` では
  止まらない（目印は紙の中にあるので）。
- **`fitCalH` は、引いているあいだ書き換えない。** 引くと暦の高さが毎フレーム
  変わって ResizeObserver が鳴る。床は `cal-peek` が持っているので、
  `.cal.is-peek` / `.is-settling` のあいだは画面側が黙る。
- **毎フレームの数（`--cal-p` / `--cal-h`）は、根っこではなく読む相手そのものへ
  書く。** ふだん（止まっているとき）この二つを持っているのは画面の根っこで、
  それでかまいません——書くのは組み直しのときだけなので。**引いているあいだは
  違います。** カスタムプロパティは継承するので、根っこに毎フレーム書くと、
  読む相手が何個であろうと**画面ぜんぶ**（やることで575要素）の style を計算し
  直します。実測（2026年9月20日・CPU 4倍）：引いているあいだの style 再計算が
  **64回で 1385ms**（1回 22ms）、81フレーム中 **22落ち**。レイアウトは 48回で
  116ms しかないので、重かったのは**測ることではなく、配ること**のほうでした。
  読む相手は実際には二つだけ——`--cal-p` は `.cal.is-peek .cal-day.is-off-week`
  （暦の中だけ）、`--cal-h` は `.tl-grip`（**一つの要素だけ**）。だから引いて
  いるあいだはそこへ直に書き、離したら `bare` が剥がして根っこの数へ返します
  ——**根っこの値には一度も触れない**ので、剥がした瞬間に正しい姿へ戻ります。
  実測：p90 50.0ms → **16.7ms**、落ちるフレーム 22 → **3**。掴み手と暦の下端の
  すきまは、引く前・引いている最中・離したあとのどれも **0px**（三画面とも）。
  - 掴み手は組み直しのたびに別の要素になるので、**掴んだ時点で見つけておく**
    こと（`m.grip`）。`--glass-sweep` を `:root` から降ろしたのと同じ話です。
- **health（ダイエット）で貼りつかないのは、月だけ。週の一行は貼りつく**
  （`#screen-diet .cal.is-week`）。「下にあるのは一日ぶんの記録で、月とは
  関係がない」という理由は**五、六行ぶんの話**で、一行には当たらない。
  やること・daily では週の帯がずっと上に居るのに、この画面だけ送ると
  消えていた——同じ暦が画面によって違う顔をすることになるうえ、消えたあとの
  戻り道が掴み手（引いて開く）しかなく、「いつの週を見ているか」が分からない
  まま記録を読むことになる。貼りついた印（`is-stuck`）は暦にも付けること
  ——付けないと境目の線が出ないまま記録の字が下をくぐる。
  引いているあいだは、月でも貼りつく（`#screen-diet .cal.is-peek`）。
  下まで送った先で掴み手を引いたとき、暦が画面の外に居ては出てくるものがない。
  収めたあと、**開くほうへ行ったときだけ上まで戻す**——せっかく開いた月が
  指を離したとたんに見えなくなるので。畳んだときは読んでいたところに居させる。
- 引く向きは片道ずつ。閉じているとき＝**下**、開いているとき＝**上**。
  逆はスクロールに渡す。

### 暦は三段（暦なし／週／月）

`--cal-p` は 0〜1 のまま（週→月）だが、`cal-peek.js` の中の `p` は
**-1〜1** に広がった。-1＝暦なし、0＝週、1＝月。

- 週から**上へ押せば暦が消え**、そこから下へ引けば戻る。月への上げ下げは
  これまでどおり。上へ押すのは掴み手（`.tl-grip`）からだけ。
- 畳むのは日のマスだけでは足りない。**曜日の行（`.cal-wds`）と暦の上下の
  余白も**一緒に畳む（`weekSpan`）——さもないと消したはずの場所に
  「日 月 火…」と余白だけが残る。
- しまってある暦も、引いているあいだは場所を取る
  （`.cal.is-hidden.is-peek { display: block }`）。ここが無いと三段目から
  戻る道が始められない。
- `commit` は `{shown, open}` を受ける（`store.setCalPref` の二つの札）。
- 段のあいだの道のりは、**取ると決めた時に一度だけ**決める（`span`）。
  途中で測り直すと、境目をまたぐたびに指の下で速さが変わる。
- **速く払ったら、短くても行く**（`FLING_V` 0.35px/ms ／ `FLING_MIN` 8px。
  day-swipe と同じ数）。ここは長いあいだ距離だけ（`DONE`）で決めていたので、
  **ぱっと弾いても戻り、のろのろ引くと開く**——紙の節（「紙は、指につく」）で
  一度直したのと、まったく同じことが残っていた。向きは指の速さの符号で決める
  （下へ払えば開くほう、上へ払えば畳むほう）。
- **離したあとの滑りも `KN.motion.glide` から。** ここだけ決まった長さ
  （`--m-grow`）で、ゆっくり引いても勢いよく弾いても収まる時間が同じだった
  ——day-swipe・cal-swipe・edge-back・紙の面はもう glide を通っているのに、
  ここが残っていた。数は `--cal-ms` / `--cal-ease` に置き、**transition の
  宣言は CSS のまま**（どこがどう動くかは CSS が持つ、という決めごと。
  読めなければ `--m-grow` に落ちる）。保険の時計も glide の長さに合わせること
  ——決め打ちの 420ms が残っていると、短い滑りのあとに長く待つ。

### 滑っている最中に、掴み直せる（day-swipe）

隣の日へ滑っている途中にもう一度触ると、**紙が真ん中へ跳び戻っていた**。
`mount()` が `if (peeks) return` で素通りし、位置を書く者が誰も居なくなる、
というのが正体。いまは**いま居るところ**（`liveX()`）を起点にする。

- **黙らせるのは、横だと決まった瞬間**（`gen++`）。指が触れた時点ではない
  ——触れただけで離した指のために、滑りを止めてしまうので。
- **`settle()` は `false` を返して「掴み直された」と言う。** 受けた側は
  `unmount()` も `commit()` もしない。
- **`mx` は `let`。** `x0` を引き直したら、**その一回ぶんも測り直すこと**
  ——`const` のままだと、拾った位置を同じ一回の中で古い `mx` が上書きする
  （実測：160px 跳んだ）。
