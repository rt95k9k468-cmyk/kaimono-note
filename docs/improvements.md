### A. 不具合・データ保全（優先）

**A1. 日記の本文が約5MBの箱に入り続けている【最重要・要相談】**

- 日記は今、ほかの記録と同じ localStorage（約5MB）に入っています。
- 大きな箱（IndexedDB、数百MB）に暗号化してしまう仕組み js/diary.js は作ってあるのに、どの画面からも呼ばれていません。参照はゼロでした。
- tools/diary-import.html の説明にある「設定 → 日記を取り込む」も、アプリ側にありません。
- 厳密に言うと：diary.js 自身の実測で「2151日×600字＝4.1MB」です。自動控えも同じ箱を最大1.5MB使うので、本体に使えるのは3.5MB前後です。満杯になるとデータは消えませんが、その後の変更が保存されなくなります（store.js:1031）。
- 日記を移すのはデータ移行なので、決めごとどおり実行前に相談します。先に「使用量を設定に出す」（読むだけで安全）から始められます。

**A2. 自動控えは、記録が増えるほど黙って効かなくなる**

- 控えは毎回データ全体を写します（backup.js:167）。上限は合計1.5MBです（backup.js:49）。
- 本体が1MBになると控えは1個しか残らず、「昨日の状態に戻す」ができなくなります。
- 控えを IndexedDB へ移すのが直し方です。backup.js を触るので要相談です。

**A3. 「バックアップを保存しました」が、保存したか分からないうちに出る**

- iPhone の保存画面でキャンセルしても「保存しました」と出て、30日ごとの催促も止まります（screen-settings.js:2192）。
- iPhone の共有シートに変えると、保存できたかどうかを受け取れます。そこから iCloud Drive・AirDrop・LINE へ一押しで出せるので、端末をなくしたときの備えにもなります。

**A4. 復元すると「絵の報告」だけが戻らない**

- importJSON()（store.js:3291〜）の戻す一覧に、iconReports と iconOverrides がありません。
- 書き出しには入っているので、「書き出したのに戻すと消える」形です。直すのは2行ですが、復元処理なので相談のうえで。

**A5. 日付が欠けた記録が、どの日にも出ない記録になる（今は起きていない不具合）**

- 体重・お酒・食事・健康の記録で日付が欠けると、「今日」ではなく時刻つきの UTC 文字列が入ります（store.js:269/347/472/521 の || today()）。
- その文字列はどの日とも一致しないので、記録が画面に出なくなります。todayKey() にすべきところです。
- 取り込みや AI の返事を通ると起こりえます。読み込みの経路なので相談のうえで。

**A6. 設定を開くと、下の帯の印が席と席のあいだに取り残される（実測で確認）**

- 設定では＋ボタンが消えて帯の席が広がります（health の席は 239–314 → 287–378）。印は 242–312 のまま動きません。

**A7. Android のショートカット「お店くらべ」が daily に飛ぶ**

- #compare に当たる画面がありません。
- テーマ色 #2f8f5b も、manifest と index.html の両方で昔の緑のままです。

**A8. ソースに見えない NUL 文字が2か所ある**

- 場所は ui.js:835 と screen-settings.js:1956 です。これのせいで GitHub の差分が「バイナリ」扱いになり、中身が読めません。
- "\u0000" に書き換えれば、動きは同じまま差分が読めるようになります。

### A1 日記の保存場所

- **いま**：日記の本文は `state.archive.days[].memo`。買うもの・やること・からだと
  同じ localStorage の一本（`kaimono-note-v2`）に、**平文で**入っている（書くのは
  `screen-archive.js` の `openLogSheet` → `store.setDayLog`、975行）。
- `js/diary.js`（IndexedDB `kaimono-diary` と AES-GCM の暗号）は、index.html・sw.js・
  build-standalone.js に登録されて読み込まれているが、**どこからも呼ばれていない**
  （`KN.diary.` の呼び出しはゼロ）。冒頭のコメント「だから本文は state に入れません」
  は、いまの実際と食い違っている。
- `tools/diary-import.html` が作る `kurashi-diary-◯days.json`（`kind: "diary-sealed"`）を
  アプリへ入れる口も無い（`importSealed` を呼ぶ画面が無い）。
- **起こりうること**：
  - 容量。diary.js 冒頭の実測で「2151日×600字＝4.1MB」、iOS の localStorage は
    原点あたり約5MB。**live と自動控え（上限 150万字、ただし最低一世代）が同じ枠を
    分け合う。** 日記が伸びると、先に控えの世代が減り（A2-3）、やがて live の保存
    そのものが「保存できませんでした」になる。
  - 手が止まるたび（500ms）に state 全体を書き直す。量に比例して重くなる。
  - 平文なので、端末の中・書き出したファイル・自動控えのどれからも読める。
- **直し方の案**：
  - (a) 置き場所はそのまま、容量を見張る。設定に使用量（live・控え）を出す。live の
    保存が容量で落ちたら、控えの細かいほうを間引いて一度だけ書き直す（A2-4 と同じ直し）。
  - (b) 本文を IndexedDB へ移す（diary.js を使う）。暗号にするかは利用者が決める
    （鍵を失うと二度と戻らない）。書き出し・自動控え・復元の**三つ全部**に日記を
    足すこと（足さないと、そのまま A4 の漏れになる）。
- **移行**：(a) は無し。(b) は**要る**（`archive.days[].memo` を IndexedDB へ写す）。
  やるなら「写す → 読み比べて一致を確かめる → 元は消さずに残す」の順で、実行前に報告。
- **状態**：**(a) を済ませた**（2026年9月26日、下の「やったこと」）。(b) は、設定に
  出るようになった使用量を見てから利用者が決める。diary.js の冒頭に「まだ
  使われていない」と書き足した。→ **(b) は4回目に済ませた**（暗号なし・二重に持つ時期。

### A2 自動控え

## やったこと（2026年9月26日、4回目のセッション）

A1(b) と、A2 の原文の直し方（控えを IndexedDB へ）。決めごとは `docs/storage.md`。

- **大きな保存場所** `js/idb.js`（IndexedDB `kaimono-note`）。使えない端末では、
  どちらも前のまま localStorage だけで動く。
- **日記の本文の写し** `js/diary-idb.js`。はじめて開いたとき、本文のある日を全部
  写し、読み直して全部の日で一字も違わないことを確かめる（違えば写しを捨てて、元だけで）。
  **元（localStorage）からは外していない**——元はこれまでどおり書き続け、写しは書くたびに
  同じものを書き足し、開くたびに突き合わせる（二重に持つ時期）。
  - どちらが新しいかは番号で比べる：元は書くたびに `lsSeq` を一つ進めて一緒に書き、
    写しは「元の何番に合わせたか」を持つ。元の保存が容量で落ちたあいだに書いた日記は、
    写しの側に残り、次に開いたときに戻る。元だけが消えても、写しから戻る。
  - 食い違いを直すときは、置き換わる側の本文を先に自動の控えへ（「日記の突き合わせ前」）。
- **書き出し・自動控え・復元の三つに日記**：どれも記憶の中の state（本文つき）を
  そのまま使うので、三つとも入っている。復元・すべて削除・サンプルは、元を書いた直後に
  写しも同じに合わせる。書き出しは、開いた直後の突き合わせが済む前だけ断る。
- **自動の控え** `backup.js`：大きな保存場所へ（見出しと中身を分けて置く）。移し方は
  日記と同じで、元の localStorage の控えは消さずに残す（もう書き足さない。容量で本体が
  落ちたときだけ makeRoom が手放す——写しがあるので戻せる控えは減らない）。上限は
  150万字 → 2,000万字。控えを取る・戻すは約束（Promise）で返るようにした（設定の
  `keepBefore`・「自動バックアップから戻す」も合わせた）。
- **設定の「バックアップと書き出し」の下**：控えが記録とは別の大きな保存場所にあること、
  日記の写しの様子（開いた回数と、食い違いがあったか）を出す。書いた日の数は言わない。
- 直している途中で見つけて塞いだもの：元が読めない日に写しへ書くと番号が 1 から振り
  直され、次に元が読めた日に古い元が勝つ（`store.seqAtLeast`。直す前のコードで試験が
  落ちることを確かめた）。同じ名前の IndexedDB が棚の無いまま先にできていると開けない
  （版を決め打ちにせず、足りない棚を作り足す）。

試験：Playwright で91件（リポジトリの外）。はじめての写し（空白だけ・5万字・結合文字・
孤立サロゲート・NUL・CRLF を一字も違わずに）、書くたびの書き足し（画面の紙からも）、
開き直しの一致、容量で落ちたあいだ → 写しから戻る、写しが古い → 元に合わせる、
元だけ消えた → 写しから戻る、書き出し・ファイルから復元・控えから戻す・すべて削除の
画面の道、読み比べで違ったとき、大きな保存場所が使えない日と、その次の日、写し替えの
途中で読み直されたとき、隠れたときの控え、3000日×600字の重さ、daily の非評価。
