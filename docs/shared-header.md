# 上の帯と暦は、全タブで一つ（計画と決めごと）

2026年9月27日に決めた。利用者の言葉では「一番上のタイトル帯とカレンダーは、
全てのタブで共通に。タブを移動するときも、背面としての帯と暦は微動だにせず、
紙の器だけがスライドする」。買うもの・価格にも、ほかと同じ日付の題・右上の
さがす／設定・暦を置く。暦の段（なし／週／月）は全タブで同期する。

**触る前に読むもの：** `screens-nav.md`（画面の移り変わり・題）、
`calendar-swipe.md`（暦の三段・払う）、`sheet-scroll.md`（紙と送る器）、
`shopping.md`（買うもの・価格の重なり）。どれも「一度こわした話」でできている。

## 作り方：案A「本当に一つにする」

各画面が自分の帯と暦を持ったまま中身をそろえる（案B「一つに見せる」）のでは
なく、**帯と暦を `.screens` の外へ引き上げて一つの部品にする**。タブの流れ
（`app.js` の `show()`）は、帯より下——紙（と、買うもののカテゴリの札）——だけを
動かす。帯は流れの外に居るので、動かないことが作りとして保証される。
案Bは五枚が一画素も違わないことに頼るので、印の違い・測った高さの1px・
組み直しの一拍が、そのまま「ちらつき」になる。

## 決めたこと（2026年9月27日、全部おすすめどおり）

1. **いま見ている日は全タブで一つ。** やることで未来の日を見たまま daily・
   ダイエットへ移ったら、**その未来の日をそのまま見せる**（紙は見るだけ・
   書き込めない）。今日へ寄せると、移った瞬間に題が変わる。
   - daily・ダイエットの中から未来へは進めない（これまでどおり）。ただし
     **戻る向きは通す**——持ち込まれた未来の日から、今日へ戻る道が要るので。
   - その日を見ているあいだの ＋ は、**今日へ**書く。
2. **買うもの・価格の暦は「共通の日」を動かす盤。** 日を押すと共通の日が
   変わるが、買うものの紙そのものは変わらない（「その日に買ったもの」を出す
   のは、あとで足せる拡張）。紙を横に払って日を送る手つき（day-swipe）は
   買うもの・価格には付けない。
3. **買うものの掴み手は、いまのまま価格へ**（下へ引くと紙が下がって価格の地）。
   暦の段は題を押す／ほかのタブで変える（同期しているので効く）。
4. **暦のマスの印は、タブごとに替える。** 枠は動かず、印だけ替わる。
   **全タブ共通にしてはいけない**——daily にダイエットの達成の棒が出て、
   「daily は評価しない」を破る（`tests/daily-rules.js`）。買うもの・価格は印なし。
5. **検索欄は暦の下（タブ側の、流れる部分）に開く。** 題と暦の間に開くと、
   開いているタブと閉じているタブのあいだで暦が上下する。虫めがねのボタンは
   共通、探す相手はタブごと。設定の「探す窓を出しておく」もこの位置で出す。
6. **題を押したときの応えは、いまのまま**（やること・ダイエット：週⇄月、
   daily：月を選ぶ紙）。買うもの・価格は週⇄月。見た目は同じで、応えだけが
   タブに合わせて違う。
7. **main への流し方：** 段1は単独で main へ。**段2と段3はそろってから一緒に**
   （段2だけだと、買うものへ移るときだけ帯が崩れる状態が実機に出る）。

決めなくても起きること：暦の出し入れの設定は三か所→一か所（外観の「表示」）。
だから「買い物のときだけ暦をしまう」はできない（しまえば全タブでしまわれる）。
買うもの・価格は暦のぶん縦が狭くなる。「shopping⇄prices」の題の入れ替わりは
無くなり、日付になる。設定（引き出し）は共通の帯ごと押しのける。

## 段

| 段 | 中身 | モデル / effort |
|---|---|---|
| 1 | 共通の日（`KN.util.dayShare`）と暦の段の同期（`settings.calAll`）。設定の三つのスイッチを一つに | 済（2026年9月27日） |
| 2 | 帯と暦を `.screens` の外へ引き上げ、一つの部品に。やること・daily・ダイエットをそこへ移す。タブの流れは帯より下だけ | Opus / high（大きい） |
| 3 | 買うもの・価格に載せる（題の入れ替わりを外す・掴み手は価格のまま・価格の地の位置） | Opus / high |
| 4 | 実機で気づいた点の手直し・docs の仕上げ | Sonnet / medium |

## 段1で入れたもの（2026年9月27日）

- **`KN.util.dayShare`**（`util.js`）：どの日か（null＝今日）と、変わったことを
  見分ける番号だけ。保存はしない（各画面の `viewDay` も前から保存していない）。
- **席を移るとき、`show()` が出ていく画面の `day()` を置く。** 入ってくる画面は
  `render()` の頭の `takeSharedDay()` で、番号が変わっていれば引き取る
  （日・印・暦の月の三つを書き換えてから組む）。日を持たない画面（買うもの・
  価格・設定）からは何も置かないので、前に見ていた日が残る。
  - 画面が答える `day()`：やること＝題の日（一日の紙なら `shownDay`、一覧なら
    `hereDay`）、daily＝`focusDay()`、ダイエット＝`curDay()`。
  - 自分で置いた番号で戻ってきても、同じ日なら何もしない（手で送っていた
    暦の月を巻き戻さないため）。
- **暦の段は `settings.calAll` の一つ。** 無ければ、これまでのやることの見かた
  （`calBy.todo` → 古い `calOpen`）から始まる。**`calBy` は消さずに残し、読まない
  だけ**——データの移行ではない。戻すなら `store.calPrefs` を戻せば元どおり。
  呼ぶ側の `calPrefs(tab)` / `setCalPref(tab, …)` は、引数を受けたまま使わない。
- 未来の日：daily は紙を `inert`（`.is-ahead`）、ダイエットは覗き見と同じ
  押せない紙（`peek`）。＋ は今日へ書く。

## 段2へ持ち越す注意

- 暦を組む部分（`fillCalendar`・輪・週の印・`fitCalH`・`calSwipe.wire` の五つの
  答え）は、やること・daily・ダイエットの三か所に別々にある。一つにまとめる
  とき、`calendar-swipe.md` の決めごと（`data-day` を外す・`--cal-h` の床・
  送りの覚え書き・払い終わりに組み直さない）を一つずつ引き継ぐこと。
- 暦の月（出している月）は、段1では画面ごとのまま（日が持ち込まれたときだけ
  その日の月へ寄せる）。段2で暦が一つになれば、自然に一つになる。
- 確かめ方：タブを移っているあいだ、帯と暦の位置を毎フレーム測り、**動いた量が
  0px** であることを見る台本を `tests/` に足す。掴み手は CDP の本物のタッチで。
