# 絵の系統と、絵選び紙

CLAUDE.md から見出しごと移した、詳しい決めごと（2026年9月26日）。
本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも
踏む罠は CLAUDE.md にある。**新しい決めごとは、ここ（該当する docs）に書く。**

### 絵は三系統。混ぜない

- **UIアイコン**（＋・歯車・★…）は **Phosphor Icons の Regular**。
  `icon("gear")` で引く。名前→絵は `js/icons.js` が取り次ぎ、絵は
  `js/icons-phosphor.js` にある。**画面はどの一族かを知らない**ので、
  入れ替えは `KN.icons.use("legacy")` の一行。手描きの55個は
  `js/icons-legacy.js` に**消さずに**置いてある。
- **商品アイコン**（708個の品物の絵）は、**単色シルエットに寄せました**
  （2026年9月5日）。道具など439キーが `js/icons-goods.js` の97型＋個別14枚、
  食材269キーが `js/icons-food.js` の71型。**キーは一文字も変えていない**ので、
  保存済みの `t.icon` も、キーワードの表も動きません。
  引く順番は `store.js` の `markOf()` ＝ **iconsGoods → iconsFood → 色つき**。
  **色つきに戻すのは `markOf()` の2行を消すだけ**（`icons-v2.js` は残してある）。
  **色は黒ではなく、カテゴリの色**で塗ります（`--cat` に字の色を15%混ぜたもの。
  `--cat` のままだと丸の地との明暗比が 2.2 前後で、線でできた絵が薄れる）。
  絵の入る丸はすでにカテゴリ色（16%）なので、**地と絵で同じことを言う**ため。
  暦の日の丸だけは白抜きのまま。経緯と物差しは `ICON-SILHOUETTE.md`。
- **「こと」アイコン**（108個の**行いと場所**の絵）は `js/icons-todo.js`。
  単色のシルエット。内訳は **Phosphor Fill 90／よそのセット 14／手描き 4**
  （次の節）。手描き108枚は `js/icons-todo-hand.js` に**消さずに**置いてあり、
  `KN.iconsTodo.use("hand")` の一行で戻る（`icons-legacy.js` と同じ扱い）。
- **食材のシルエット**（71型）は `js/icons-food.js`。いまは**どの画面でも**
  品物の絵の代わりに出ます（前は やること の中だけでした）。

決めごと：
- Phosphor の絵は**面**なので、CSS の `stroke-width` は効かない。太さは
  weight が決める。**weight の例外は `.check` の ✓ だけ**（白抜き15pxで
  Regular だと消えかけるので Bold）。
- 塗りは svg ではなく **path** に書く。画面に残っている
  `svg { fill:none }` / `svg { stroke:… }` に消されたり太らされたりしないため。
- 体重計（`scale`）だけ Phosphor に適切な代替が無く、手描きのまま
  （`scales` は天びんで、買うものの「比べる」と紛れる）。
- 経緯と A/B/C/D の対応表は `ICON-PHOSPHOR.md`。

### 「こと」アイコン（`js/icons-todo.js`）— やることは品物では引けない

**やること は「こと」を先に、買うもの は「品物」を先に**引く
（`screen-todo.js` の `iconMarkHtml`）。**順番が要点**——「洗濯する」は
洗濯機であってほしいが、「洗濯洗剤」はボトルであってほしい。同じ辞書を
同じ順で引くと、どちらか一方しか立たない。測定の経緯・数字は `ICON-TODO.md`。

決めごと：

- **名前には `do-` を付ける**（`RAW` の素の名前に、`ICONS` を組むところで機械的に）。
  接頭辞なしだと品物名とぶつかる（bed・camera・tv・mug・bicycle など）。
  ぶつかると `t.icon` に保存済みの絵が黙って入れ替わる。品物が増えても
  二度と当たらないように、接頭辞で分けてある。
- **保存済みの名前は両方に聞く**（`iconsTodo.byKey(k) || productIcons.byKey(k)`）。
  昔の記録は品物の名前しか持っていないので。
- **viewBox は `-8 -8 272 272`**。絵は Phosphor Fill の文法どおり 24〜232
  （256の81%）に描くが、品物の絵は 3〜21（24の75%）。同じ器に並べると
  こちらだけ大きく見えるので、器のほうを76%に広げて合わせてある。
  **絵の座標は動かさないこと**——動かすと、これから描くものが揃わなくなる。
- **色は `currentColor`**。丸薬の上では字の色、詳細の紙の頭（濃い地）では
  白抜きになる。テーマ色で塗ることもできる、というのがシルエットの取り分。
- 一覧に出す名前は `NAMES` で言い直す。引くための言葉は語幹で切ってある
  （「本を読」「振り込」）ので、そのままだと名前として読めない。
- **絵を足したら、実際に引かせて確かめること。** 目で見て良さそうでも
  取り違える（過去の事例は `ICON-TODO.md`）。
- **言葉の割り当ても、絵の慣習に合わせる。** `KEYS` は上から順に当たるので、
  ある語をAからBへ付け替えるときは、Aのほうを先に外さないと効かない。

### 絵選び紙の「ぜんぶ」は、見出しで束ねる（`SECTIONS` / `groups()`）

707枚（品物）が見出しの無い一本の格子で流れていた。探す欄で当たらなかった
人には、そこから先の手がかりが何もない。

- **`ORDER` そのものは動かさない。** 動かすと `suggest` の出る順まで変わる
  （あちらは `ORDER` 由来）。足すのは「この鍵から新しい見出し」という
  小さな表（`SECTIONS`）と、出す順（`SECTION_ORDER`）だけ——変わるのは
  絵選び紙の**描画順**だけで、`findKey`・`search`・`suggest` の答えは
  一つも動かない。
- **辞書の並びは、テーマが二周している。** 一度目の追加と、二度目の
  大きな追加とで「野菜」も「菓子」も二か所にある。同じ見出しは
  `groups()` の側で一つにまとめること——`SECTIONS` に二周目の境界
  （`lettuce`・`cherry`・`steak`・`gummy`・`cocoa` 等）を書き落とすと、
  その塊がまるごと手前の見出しに吸われる（実測：飲みものが 27→76枚）。
- **key → 見出しは `sectionByKey` の一つの表から。** `groups()` と
  `search()`（見出し名でも当たる）が同じ表を見る。二か所に別々に歩かせると、
  境界の鍵を直したときに片方だけ直る日が来る。
- **流し込みは見出し単位。** `grid()` の「最後の一本だけ生かす」札
  （`painting`）を見出しごとに呼ぶと、二つ目が始まった時点で一つ目が死ぬ。
  しかもどの見出しも CHUNK（120枚）未満なので、そもそも刻まれず全部が
  同期で入る——実機でシートが開く手が止まる、あの形に戻る。切り口を
  見出しへ移した `paintGroups()` を使うこと（フレームごとに一見出しずつ）。
  やること側は「こと」もこの一本に混ぜる——分けると同じ罠を踏む。

### 絵の名前は、ひらがな借用語を片仮名で名乗る（`LABELS`）

`LABELS` の一語目がそのまま名前になる。借用語をひらがなで書いた辞書の
語（「しりある」「こーひー」）がそのまま出ると、読むのに一段余計にかかる。

- **判定は長音符号（ー）の有無。** ネイティブの日本語の語に長音符号が
  出ることはまずない——出ていれば、まず借用語（「しゃんぷー」
  「はんばーがー」等、117語）。ひらがな＋長音符号だけでできている
  一語目だけを片仮名へ機械で直す（`toKatakana`）。
- **長音符号を持たない借用語は、機械では広げない。**「ぱん」「かぼちゃ」
  のような語は、ネイティブ語との判定がここでは割れる（店の値札では
  片仮名で書かれることも多いが、辞書としてはどちらも通用する）。
  広げるほど、人の判断が要る語が増える。
- **機械の手が届かない実例は、`LABELS` に個別で足す。** 基準は二つだけ
  ——①実在の言葉として読めない（`cereal` の「しりある」）、
  ②別の言葉に読み違える（`mascara` の「ますから」は「だから」の仲間に
  読める）。触るのはこの二条件に当たる語だけ——「とまと」「りんご」の
  ような、ひらがなのままで実在の読みが立つ語には手を出さないこと。
- **キーワードは一文字も変えない。** `LABELS` は表示だけの札で、
  引き当ての表（`KEYS`）とは別物。

### 探す欄は、見出し名にも答える（`search()`）

`findKey` は狭めるためだけの役目のまま（変えていない）。`search()`
（絵選び紙の「探す」欄）だけ、`sectionByKey` を見て見出し名にも当たる
ようにした——「そうじ」で探すと「掃除・洗濯」の棚がまるごと出る。

**空振りは行き止まりにしない。** 「合う絵はありません」の下に、いま
打った言葉をその場で記録するボタンを置く（買うもの・やること両方、
`.js-report-empty`）。腕組みボタン（`.icon-report-toggle`）を押す手間を
飛ばして、探して当たらなかった言葉を直接 `addIconReport` へ渡す一本道。
`kind` は、その言葉を `findKey` に掛けた結果で判定する（引く順番は
画面ごとに違うので、`screen-todo.js` は `iconsTodo → productIcons` の順）。
