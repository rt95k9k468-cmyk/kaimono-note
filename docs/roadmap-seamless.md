## 1. 一言でいうと

**つなぎ目で、待たせない・失わせない・驚かせない。**

画面の中は U となめらかさの総ざらいで揃った。残っている引っかかりは、つなぎ目にある：

1. **版のつなぎ目**——配るたびに、iPhone は次に開いたとき css・js を全部取り直し、開いた数秒後に読み直す。
   10月8〜9日は約30時間で27回配った。**ふだん開く回数の多くが「配ったあとの最初の起動」になっている。**
2. **中断のつなぎ目**——読み直し・iOS に閉じられたあとは、見ていた日・送り位置・開いていた紙が戻らない。
3. **指と鍵盤のつなぎ目**——日本語の変換を確定する改行で、欄が「決まって」しまう所が残る（守る欄と守らない欄が混在）。

5. **進め方のつなぎ目**——開いている項目が道のり6本に散り、iPhone で見る確かめが26項目溜まっている。

> 厳密に言うと：体験の記憶は、平均より**いちばん強い瞬間と終わり**で決まりやすい（peak-end。Kahneman ほか 1993）。

## 2. 調べたこと（2026年10月10日に確かめた事実）

### 2.1 配ったあとの最初の起動（手元で再現した）

作業用の写し（リポジトリの外）に版 A と B（js を1本だけ変えたもの）を刻印し（`stamp-build.js` は写しの中だけで
走らせた）、試験のブラウザ（Chromium）で A を入れてから、B を配ったつもりで開いた。サーバーは1本ごとに 120ms 遅らせ、
`Cache-Control: max-age=600`（GitHub Pages の値として報告されているもの。公式の明記は見当たらない）。

| 開いたとき | 最初に出た版 | 出るまで | 読み直し | 読み込み | サーバーへ行った css・js |
|---|---|---|---|---|---|
| HTTP の控え（10分）が生きている | **古い A** | 0.53秒 | **6.9秒後**に B へ | 2回 | 82本（変えたのは1本） |
| 切れている | B | **10.4秒**（js が一本ずつ、約130msおきに取りに行かれた） | **13.9秒後**（もう B なのに） | 2回 | 82本 |

コードで確かめたこと：
- `stamp-build.js` は配るたびに**全部の** css・js の URL に `?v=<commit>` を付ける。中身が同じファイルも URL が変わるので、
  Service Worker の控えに当たらず、全部ネットへ行く（82本・4.1MB、圧縮して約1.3MB）。新しい Service Worker の控えは
  HTTP の控えから埋まるので、二度は取りに行かない（再現でも82本）。
- 新しい Service Worker は `skipWaiting`＋`clients.claim` で入れ替わり、`app.js` の `controllerchange` が**いつでも**
  `location.reload()` する。画面がもう新しい版を走らせていても読み直す。紙が開いている・欄に字がある（`isBusy`）ときだけ、
  隠れるまで待つ。
- 入口（`index.html`）はネットが先（`sw.js`）。ただし HTTP の控えが10分あるので、配って10分以内に開くと古い入口が出る。
  逆に、電波が「つながっているのに返事が来ない」所（地下の売り場など）では、ネットの返事を**期限なしで**待つ。
- 入れ替えは控えが揃わなくても進む（install が `Promise.allSettled`）。取り込みの途中で電波が切れると、欠けた控えの
  まま新しい版になりうる——次に電波の無いところで開くと、欠けたファイルが読めない。
- 厳密に言うと：iPhone（WebKit）では秒数が違う。一本ずつ並んだのは試験のブラウザで見た形で、iPhone で同じかは未確認。
  確かなのは、版ごとに全部の URL が変わること・入れ替わると読み直すこと（どちらもコード）。

## 3. 全体の決まり（どの項目でも）

1. **一時の控えは記録の外。** store（`kaimono-note-v2`）に入れない。鍵は `kaimono-note-` で始め、書き出し・自動の控え・
   Dropbox に乗せない（`errlog.js` の `kaimono-note-errors` と同じ置き方）。読めなければ黙って捨てる。
2. **版の入れ替えの二つの約束**（N1〜N3）：
   - 入口（`index.html`）と、それが呼ぶ css・js は**同じ版で揃って**から入れ替える。揃わないうちは前の版のまま。
   - **端末で一度でも動いた版より古い入口を出さない。** 古い版の `reconcile()` は知らない欄を保存のたびに捨てる
     （roadmap-3.0 の6節）。電波が無い・遅いときに控えから開く道（N2）が、古い版へ戻る道にならないように。
   - 両方を満たす形：**控えから出す入口は、css・js が全部揃っている版のうち一番新しいもの。** ある版が一度でも
     組み上がったなら、その css・js は全部取り終えている（組む前に全部読む）。取ったものが控えに入りきるかは、
     N2・N3 の試験で確かめる（入りきらない道が残るなら、そこで報告）。
   - 試験（`tests/update-path.js`、2.1 の作り）で見張る。二つがぶつかる場面が出たら、作らずに利用者へ報告する。
3. **画面に言葉を足さない。** 「新しい版があります」の帯もボタンも出さない。入れ替えは見えないときに。
4. **`sw.js`・`stamp-build.js` を触る項目は、`offline`・`startup`・`csp` と `update-path` を必ず回す。** 刻印は
   リポジトリでは走らせない（作業用の写しの中だけ。CLAUDE.md）。
5. daily は評価しない。説明文を足さない。絵文字を出さない。動きを減らす設定（`still()`）では足す動きを出さない。
   音はドラムと同じ場（消音スイッチで黙る）。

### N1 読み直しは要るときだけ

- なぜ：2.1。配ったあとネットから新しい版で開いても、数秒後に Service Worker の入れ替わりでもう一度読み直す。
- 何を：`controllerchange` で、動いている版と新しい Service Worker の版（`postMessage` で訊く）を比べ、**同じなら
  読み直さない**。違うなら（古い版が動いている）、N4 ができるまでは今のまま、できたら「見えないとき」に。
  動いている版は、今は `errlog.js` と同じく自分の URL の `?v=` から読める（N3 のあとは別の札から）。
- 試験：`tests/update-path.js`（新しく。作業用の写しに版を二つ刻印し、自前のサーバーで入れ替える——`offline.js` と
  同じく別の port）。「切れている」で読み込み1回。
- 厳密に言うと：`skipWaiting` はそのまま。待たせると、閉じない限り古い版が続く（ホーム画面のアプリは何日も閉じない
  ことがある——`app.js` の注のとおり）。
- **済み（2026年10月9日）**：`sw.js` の `message`（`kn-version`）が版を答え、`app.js` の `runningVersion()`
  （`app.js` の `?v=`）と比べる。答えが無い・手元の刻印なしの版は今までどおり読み直す。

     （`rung`。Service Worker の `bellMark` と `notify.js` の `noteRung` の両方が書く）を照らす。
  2. 鳴っていない回が一つでもあれば：困ったときの記録に一行（件数だけ。題は書かない）。**次に画面を押したとき**（iPhone は押した
     流れの中でないと購読を作らせないことがある——Pushpad）、押し先を捨てて作り直し、中継所へ送り直す（`?bell=sub`。中継所は
     一つしか持たないので、二重には鳴らない）。一日に一度まで。
  3. 画面には何も出さない（3節の3）。
- 試験：`tests/bell.js` に足す（`pushManager` を頁の中で差し替える）——30分前の時刻・控え無し → 見える → 押す → 作り直して送る／
  控えあり → 何もしない／同じ日の二度目 → 作り直さない。
- 副作用：作り直すたびに中継所の KV に一回書く（無料枠は1日1,000回）。端末の電源が切れていて遅れて届いた通知も「鳴っていない」と
  数える（作り直しに害は無い）。
- 厳密に言うと：中継所の毎分の見回り（cron）が止まっても同じに見える。切り分けは、困ったときの記録の行と、設定の中継所の「確かめる」で。
  Declarative Web Push（roadmap.md 7節で様子見）に替えても、押し先が切れる問題は残る。
