### 設定は一枚。歯車を押した画面の設定と「一般」が、そこに並ぶ

二段だった——**目次**（外観・バックアップ・「画面ごと」…の行き先だけが並ぶ
一枚）と、**その中**。歯車を押すとその画面の設定がいきなり開き、戻るを押すと
目次が出てくる、という順で、目次は「行き先を選ぶためだけの一枚」だった。

**目次をやめた。** 歯車を押した指は「この画面のことを直したい」と言っている
ので、開いた一枚に**その画面の設定**と**一般**が両方並ぶ。ほかのタブの設定は、
そのタブの歯車から。**「画面ごと」というまとまりは、どこにも無い。**

- 根っこは `renderRoot()`。`KN.app.openedFrom()` のタブを `TAB` で引いて、
  その `rows()` を先に、`generalRows()` をあとに置く。価格は席を持たない画面
  なので、その席——買うもの——の設定を出す。
- **どの画面から開いたかは `onEnter` で一度だけ読む**（`fromTab`）。store が
  動くたびに `render()` が走るので、そのつど聞くと、設定を見ているあいだに
  根っこの中身が入れ替わる余地を残す。
- **「›」の先（`PAGES`）に載せるのは、一画面ぶんある中身だけ**——お店10件・
  カテゴリ9件・外観・バックアップ・アイコン。あれは「目次の目次」ではなく、
  参考画面（Structured）の `通知設定 ›` と同じ**詳細**。行の右にいまの値が
  出ていて、押すと続きが開く。（2026年9月30日から、通知・カレンダー・表示・
  書き出し・取り込みも。下の「二段の一覧」）
- いまどこに居るかは**積み木**（`stack`）。バックアップ → データを消す、と
  潜れるので、一つの変数だと二段目から戻ったときに行き先を見失う。戻るは
  一段ずつ（`back()`）、空になったら `KN.app.backScreen()`。

#### 二段の一覧（2026年9月30日）

根っこは**一覧**、長いものは「›」の先の**詳細**。歯車を押したタブの設定が先・
General があと（`renderRoot`）はそのまま——**全タブの目次は作らない**（上の
「目次をやめた」）。変えたのは**どの行をどの一枚に並べるか**だけで、保存の鍵
（`s.settings.*`・`dailyScope` など）と読み書きは一つも変えていない。新しい一枚は
`PAGES` に足しただけ（仕組みは同じ）。

なぜ：daily は根っこに十一行（見え方の十行と書き出し）が並び、歯車から開いた
一枚がそのタブの設定で埋まって、General（バックアップ）まで遠かった。tasks も
通知の二つのスイッチと長い説明が根っこを占めていた。もう一つ、「バックアップと
書き出し」に、**中身の持ち主が一つのタブだけのもの**が混ざっていた（記録を書き出す
＝ダイエット、年の本＝daily、おぼえた振り分け＝買うもの）。

|---|---|---|

| tasks | カレンダー（`cal`） | カレンダーはショートカットで入れる・ショートカットの組み方 ›（`calHow`、三段目）。ショートカット App のある端末だけ |

根っこに残したもの：tasks は時間割・一日の道・一日の始まりと終わり。daily は

- 画面の中の道案内も直した：ダイエットの取り込みの紙の「設定 → ダイエット →

#### 行は四種類。**絵が付くのは「›」で進む行だけ**

参考画面がそうなっている——絵は「押すと続きがある」の合図で、その場で
切り替わるスイッチの行には要らない。

- `navRow` … ［色の四角］［名前］［いまの値］［›］。
- `switchRow` … 題＋スイッチ。絵は無い。`role="switch"` ＋ `aria-checked`。
- `pickRow` … オン/オフではない二択（並べ方、出す範囲…）。右にいまの値、
  押すと `choose()` の紙。**スイッチにしない**——どちらがオンなのかを字で
  言えなくなる。
- `dangerRow` … 戻せない操作。**四角ではなく、赤い絵と赤い字**（参考画面の
  「アプリを初期化」と同じ）。色の付いた四角は「行き先」の印なので、そのまま
  着せると、消す操作が普通の行き先と同じ顔になる。

**スイッチ（`.toggle`、components.css）は iOS の素のものではない。** 素のものは
51×31 で丸いつまみだが、参考画面は **63×28 に 38px幅の平たいつまみ**で、
オンのときだけ中に白い縦棒が一本入る（オフの地は無地の灰——実測。iOS の
「オン/オフラベル」なら丸も出るはずなので、あちらの自前の絵）。丸いつまみの
つもりで描くと、同じ画面に並べたときに一つだけ形が違って見える。

#### 説明は、行の中ではなくカードの下

`row-sub` に詰め込んでいた。行の高さを説明が決めてしまい、設定の一覧が読み物に
なる。**`foot()`（`.set-foot`）でカードの外へ出す**。そのうえで：

- **スイッチがもう言っていることは書かない。**「オンです／オフです」を副題に
  書いていたが、それはスイッチの絵がすでに言っている。
- 押して何が起きるか分からない行にだけ、一文で残す（通知＝アプリを閉じて
  いると鳴らない、など）。ほとんどの行は説明なし（docs/look.md の「説明は
  書かない」）。
- 手順の「つまずいたら」などは `more()` で畳む。
- 紙（シート）の中では `.set-foot.is-flush`（外側の余白は紙が持っている）。

#### 消す口は持たない（2026年10月5日。前は 設定 → バックアップ → データを消す の三段奥）

利用者「データを消去したい時なんて無い」。「ダイエットの記録を消す」「サンプルデータを入れる」「すべて削除」の一段ごと外した。`store.reset()` などの関数は試験のため残す。以下は前の経緯。

参考画面が「アプリを初期化」を詳細設定のいちばん下に置いているのと同じ考え。
**「サンプルデータを入れる」も同じ棚**——見た目は足す操作だが、中身はいまの
記録を全部置き換えるもので、普通の行と同じ高さに並べていた。
「ダイエットの記録を消す」も、目標や中継所と同じ列から、ここへ移した。

#### バックアップは「取る・確かめる・戻す前に見る」（2026年9月26日）

経緯と調べは `docs/improvements.md` の A2〜A4。

- **保存できたと分かったときだけ「前回の書き出し」を記録する**（`markExported`）。
  指で触る端末で共有シートが使えればそれで渡し、終わったときだけ記録（取り消しは
  AbortError）。それ以外はダウンロードのあと「保存できましたか？」と一度だけ訊く。
  `share` は**タップの流れの中で呼ぶ**（手前で await しない）。
- **「保存したバックアップを確かめる」は、戻さずに読むだけ。** 書き出し日時と
  記録の数を、いまと並べて見せる。読めたファイルの日時を前回の書き出しにする
  （古い日時へは巻き戻さない）。
- **復元は、置き換える前に中身を確かめて見せる**（`store.inspectBackup`）。
  `kind` を持つもの（daily の月の書き出し・日記の取り込み道具の出力）は弾く。
  前は空の state で全部を置き換えて「復元しました」と出していた。
- **戻せない操作の前の控えは `keepBefore`。** 取れなかったら（`take` が
  `"failed"`）、進む前に訊く。確認の文の「直前の状態は自動バックアップに
  残る」を嘘にしないため。ダイエットの記録を消す前にも取る。`take` と
  `restore` は**約束（Promise）で返る**ので `await` する（控えは大きな保存場所に
  ある。docs/storage.md）。
- 使用量（記録・日記・控え）はカードの下に出す。控えの上限に、直近2日の細かい
  控えが入りきらない大きさになったら、そう言う（`backup.usage().tight`）。
  控えが大きな保存場所にあれば「記録とは別の、大きな保存場所にあります」と言い、
  「枠を分け合っています」は言わない。続けて日記の写しの様子（`diaryCopyText`：
  開いた回数と食い違いの有無。**書いた日の数は言わない**——daily は数えない）。
- 「バックアップを保存」は、日記の写しの突き合わせが済む前（開いた直後の一瞬）は
  断る。`await` で待たない（共有シートがタップの流れから外れる）。
- **日記を記録から外す**（2026年10月4日、段2の2b。決めごとは docs/storage.md の
  「2b で入れたもの」）：「日記を取り込む」の札に「日記を記録から外す」→ 準備する →
  「書き出して外す」（`saveBackup({ onSaved })` を押した流れのまま）。外したあとは
  「日記を記録に戻す」（枠に入るときだけ）。読めない日の書き出しは、紙
  「日記の本文は入りません」の「書き出す」から押した流れのまま共有する（`confirmBare`）。

- **記録を点検する**（R28、2026年9月29日、`js/audit.js`）：持ち主の無い品物・無い店を
  指す値段・読めない日付・同じ id の二重・日付の欠けた記録を**数えるだけ**。直す手は
  置かない（直すのは記録の作り替えなので、先に利用者へ）。確かめ・復元の確認にも
  「このファイルには食い違いが◯件」——ファイルは `reconcile()` を通す前の中身を見る
  （読み込むときに直るものも、そのファイルの食い違いなので）。`tests/audit.js`。

- **使用量の内訳と枠までの目安**（R24、2026年9月29日）：日記と並べて **AI の原文**
  （`diet.meals[].ai` の raw＋analysis）の字数、**iPhone の枠（目安でおよそ260万字）の
  何割か**（控えが記録と同じ枠にあれば控えも数える）。6割を越えたら一行「記録が大きく
  なってきました」——色は変えない・催促しない。読むだけ（backup.js には触れず、設定の
  側で数える）。R26（保存を軽くする）をやるかは、この数字を見て利用者が決める。
- **困ったときの記録**（R23、2026年9月29日、`js/errlog.js`）：一般の「›」の先。`window` の
  `error`・`unhandledrejection` と保存の失敗を、store の外の鍵 `kaimono-note-errors` に
  新しい50件（時刻・版・画面・200字までの文・ファイルと行）。日記の道（diary の名の
  ファイル）は種類だけ。続けて同じものは一件に数を足す。一覧が先に見え、「コピー」で字に。
  書き出し・控え・Dropbox に乗らず、「すべて削除」で消える。errlog.js はどのスクリプト
  より先に読む（読み込みの途中で落ちたものも拾う）。
- **二つ目の鍵（CSP）**（R29、2026年9月29日）：`index.html` の meta。`script-src 'self'`
  （直書きのスクリプトは無い）・`object-src 'none'`・`base-uri 'self'`・`img-src 'self' data:
  blob:`・`style-src 'self' 'unsafe-inline'`（style 属性）・`connect-src 'self' https:`（中継所・
  AI の窓口・Dropbox は利用者が決める URL）。**`connect-src` に data: は無い**——data: の
  URL を fetch すると止まる（写真は FileReader → Image なので当たらない）。単体版
  （build-standalone.js）は自分の頭を組むので、この meta は写らない（写ると直書きの
  スクリプトが止まる）。`tools/diary-import.html` は別の頁で、まだ入れていない。
  試験は lib.js が CSP の違反をエラーとして数える＋`tests/csp.js`。

#### 頭は、大きな題＋丸い戻る

参考画面は大きな「設定」が出て、送ると帯のまん中の小さい題に入れ替わる。
くらしノートの設定は歯車から開く引き出しなので、左上に丸い戻る（`.set-back`）が
いつも居る。

- **帯の題は、大きな題が帯の下へ隠れてから出す**（`paintNav`、`is-titled`）。
  二つ同時に「設定」と書いてあるのは、同じことを二度言うこと。
- **境目の線も同じところで引く**（`is-stuck` は `is-titled` が立ってから）。
  大きな題が見えているあいだに線が横切ると、題が帯の中身に見える。
- **すりガラスにしない**（base.css の上の帯と同じ理由——下を白いカードが流れる）。

#### 一段は紙の重なり。左端から引けば戻る（`js/edge-back.js`）

前は一枚でした。`.js-body` の中身を入れ替えて「›」の先を出していたので、
**奥へ行く動きが絵に出ていません**でした——押した瞬間に別の中身へ化けるだけで、
どちらへ進んだのか、戻る道がどちらにあるのかを、動きが何も言っていない。
戻ったときに読んでいた場所（`scrollTop`）も、そのつど失われていました。

いまは一段ごとに**本物の紙**（`.set-layer`）を重ねます。押せば右から一枚
入ってきて、下の一枚は控えへ引く。**左端から指で引いても同じことが起きます**
——押して動かすのと、指で動かすのとで、絵が一致している、ということです。

- **動くのは二枚。同じ速さでは動かない。** 上の一枚は指と 1:1 で右へ、下の
  一枚は **-28%（`--push-p`）から 0 へ**。同じだけ動かすと二枚が並んで
  滑っているように見えて、「下に居た」ことが伝わりません。影も上の一枚だけ。
- **深さの数は一つだけ**——CSS の `--push-p` と `edge-back.js` の `PARALLAX`。
  ここが割れると、押して戻るのと指で戻るのとで、同じ一段が二通りの遠さに
  見えます。
- **止まっているときの控えは百分率、指で引くあいだは px。** 百分率なら器の幅が
  変わっても（回転・キーボード）自分の幅から出た数なのでついてきますが、
  指と揃えるには px のほうが素直です。
- **影は動いている一枚にだけ**（`.is-edge-lift` / `.is-edge`）。止まっている
  あいだ画面の左端に影があると、そこに何かが重なっているという嘘になります。
  暗い面では黒い影が見えないので、**地より明るい一本**（ふち）で言います。
- **端でなければ取らない**（`EDGE` 24px）。それより内側から始まった指は、
  ただのタップか縦送りです。**右向きの横だけ**取り、左へ引くのは渡します。
- **縦は `touch-action: pan-y` がブラウザに残す**（day-swipe.js と同じ手）。
  `preventDefault` は投げません——投げると、戻らないと決めたあとの縦送りまで
  止まります。
- **紙の中の送る箱（`.set-scroll`）が器。** `KN.app.scrollerOf()` に教えてあります——教えないと
  `pull-refresh` が「上端にも下端にも同時に居る」と読んで、縦の指を毎回取り、
  設定が一切スクロールできなくなります（「送る器を変えたら〜」の節）。
  `reorder.js` の `findScroller` は `overflow` を見て登るので、こちらは自動で
  紙のほうを掴みます。
  **`.set-scroll` にブラウザ本来の跳ね返りを切らせないこと**
  （`overscroll-behavior-y: none` を付けない）。付けていたころは health と
  daily の設定で跳ね返りが甘かった（sheet-scroll の「引いて更新は、もうどこにも
  無い」）。
- **重なっている紙は、store が動いたら全部組み直す**（`render()` →
  `paintLayer`）。上の一枚だけにすると、戻ったときに古い数字が出ます
  （お店を足した直後の「3件」など。実測で、隠れている根っこも 3件 → 4件へ
  追従することを確かめてあります）。**読んでいた場所は保つこと**——`render()`
  はスイッチを一つ押すたびに走るので、0 に戻すと一覧の頭まで飛ばされます。
- **紙は重なるので、`root.querySelector(".js-…")` は根っこの一枚を掴みます。**
  探すときは、いま見えている一枚（`.set-layer:last-child`）に絞ること
  ——day-swipe.js の「隣の日の紙を掴む」と同じ罠です（試験で実際に踏みました）。
- 指を離したあと滑っているあいだ（`moving`）は、次の一手を取りません。
- **ほかの紙も借りる**（ノートの書く紙・roadmap-2.0 の V19）。もとから着ている transform は
  `data-edge-base` に（その上に重ねる）。`begin` が `here: true` を返すと、戻ると決めても滑りきらず
  その場で `commit`（呼んだ側がそこから動かす）。

- **Dropbox へ自動で送る**（「バックアップを保存」の下の一行 → その先の一枚）。
  つなぐ前は App key の欄・「Dropbox でゆるす」・「出てきたコードを貼る」。つないだ
  あとは「いま送る」・最後に送った時刻・溜まり方・赤い「つながりを切る」。
  送った／送れなかったは store の外で動くので、`KN.dropbox.onChange` で組み直す。
  中身の決めごとは docs/storage.md の「Dropbox へ送る」。

#### 中継所の設定は二枚。状態と、建てかた

下から出る一枚の紙に、①〜⑤の手順書がまるごと入っていました。**建てて
しまった人には、そのほとんどが要らないもの**です——建ったあとに開くのは
「届いているか確かめる」「ショートカットの名前を直す」ときで、そのたびに
Cloudflare の手順を五段ぶんスクロールすることになる。

- **中継所**（health の設定の「›」の先）… URLの欄・確かめる・ショートカット
  の名前・外す。**一画面に収まります**。
- **建てかた**（そのまた「›」の先）… ①道をつくる ②置く ③つなげる。
  **五段が三段になった**のは、④（確かめる）と⑤（名前）が手順ではなく
  **設定**だったからです。手順の紙から出して、状態の紙へ置きました。
- ③で「道をつなげて保存」を押すと、保存して**一つ手前へ返します**——次に
  すること（確かめる）はあちらにあるので、戻る道を探させません。
- **URLの欄を空にしても外れません。** 合言葉を含んだURLで、消すと Cloudflare
  を見に行かないと戻せないので、外すのは赤い行から（確認を挟みます）。
- 残す言葉は「押して何が起きるか分からないこと」と「つまずいたときの逃げ道」
  だけ。安心のための言い回し（「〜する必要はありません」「〜という意味に
  なります」）は全部落としました。逃げ道は**一段にまとめる**——三つに割ると、
  まっすぐ進める人にも三段ぶん読ませることになります。
- **道（合言葉）と、確かめた結果は、紙の外に持ちます**（`relayPath` /
  `relayTest`）。中継所は見えているあいだ1〜5分ごとに覗きにいき、届けば
  store が動く＝紙が組み直されるので、紙の中に持つと消えます。
- 同じ理由で、**書いている最中の欄がある紙は組み直しません**（`paintLayer`
  の頭）。離れれば `change` が走って保存され、そこで組み直されます。

#### 設定の中では、`KN.ui.sheet` が紙ではなく一枚を押しのける

「›」の先は一枚になりましたが、**その先の紙はまだ下から出ていました**
——出す範囲・見せ方・上に出すもの・並べ方・一日の始まりと終わり・月ぶんを
書き出す・記録を書き出す・自動バックアップから戻す・おぼえた振り分け・
AIの窓口・お店の編集・カテゴリの編集・目標・ヘルスケアから取り込む。
**十四か所**。一枚ずつ書き換えると、次に足す一枚で必ず忘れます。

だから `KN.ui.sheet` のほうに分岐を置きました（`KN.ui.setPageHost`）。
設定の画面が出ているあいだは、紙のかわりに**全画面の一枚**が右から入って
きます。呼ぶ側は同じ handle を受け取るので、`h.close()` も `h.tryClose()` も
そのまま——**呼び出しは一つも書き換えていません**。

- **紙のまま残すもの**：`as: "dialog"`（confirm・prompt・ほかの操作）。
  あれは**決めるためのもので、行き先ではありません**。iOS でも設定の中に
  警告は警告として出ます。頭を敷いた紙（hero）と「⋯」を持つ紙（menu）も
  紙のまま——あの二つは紙の形に寄りかかった作りなので、移すと絵が壊れます。
- **ダイエットの画面から開く同じ紙は、紙のまま。** `wants()` が
  `activeScreen() === "settings"` を見るので、目標をからだの輪から開けば紙、
  設定から開けば一枚になります。
- **閉じかたは紙と同じ**（`KN.ui.makeGuard`）。書きかけがあれば、戻るを
  押しても左端から引いても保存されます。**二か所に書かないこと**——割れると
  「下へ払うと消えるが、左端から引くと残る」が起きます。
  左端から引いて検算で止まったときだけ、**押し戻します**（指はもう出し
  きっていますが、直す欄が画面の外にあっては直しようがないので）。
- **中身は紙のつもりで組まれています**（`.field` や `.diet-note` が器の余白を
  当てにしている）。だから器の側が受けます（`.set-layer.is-sheetish .js-body`
  ＝ `.sheet-body` の実測そのまま：左右20px・下20px・段の空き16px）。
  十四か所の中身を書き換えて回るより、ここで一行ぶん受けるほうが安い。
- **押せば決まるもの（保存・外す）は、下に貼りつけた帯へ**（`.set-bar`）。
  紙のときは中身の最後に置いていましたが、一枚ぶんの高さがあると、短い欄の
  紙でボタンが画面のまん中に浮きます。
- **組み直しは通しません**（`paintLayer` が `handle` を見て素通り）。中身は
  呼んだ側のもので、組み直す型を持っていないので——紙が store の動きで
  組み直されないのと同じです。帯の題は `openAsPage` が一度だけ置きます。
- **下の帯が見えているので、この一枚からは出られます**（紙は覆いがあって
  出られない）。出ていったら畳まれ、`abandon()` が「閉じた」ことだけを
  伝えます（待っている約束を解くために）。**書きかけは残りません**
  ——そこは紙と違うところです。

帯（`.set-nav`）は**送る箱の外**へ出しました。`.set-layer` は
［帯］［`.set-scroll`］［`.set-bar`］の三段で、送るのは真ん中だけ。貼りつける
仕掛け（sticky）が要らなくなり、下の帯も中身の長さに関わらず同じところに
居ます。**`scrollerOf()` が返すのも `.set-scroll`** です。

#### いちばん外の一段は、画面そのもの

根っこで左端を引くと、動くのは紙ではなく**画面**です（設定 → 歯車を押した
画面）。戻る先はそのとき隠れているので、指が動かすものがありません
——`KN.app.underScreen()` が出します。どこから潜ってきたかを知っているのは
`drawerFrom` だけなので、出すのも app.js の仕事です。

- **出す前に組み直すこと。** 設定を見ているあいだ store が動いても、描き直され
  るのは出ている画面だけなので、隠れていた一枚は古いままです。
- 指で戻りきったら `KN.app.backScreen("settled")` ——「呼んだ側がもう動かし
  終えた」の合図で、動きを重ねません（買うもの ⇄ 価格 の `"settled"` と同じ）。
- `show()` の頭で `.is-under` の印を必ず落とすこと。残すと「後ろの一枚」の
  まま次の画面に居座ります。

#### 引き出しは押しのけ、タブは並んで流れる

タブどうし（daily → やること）は横に並んだ席を移るので、二枚が同じぶんだけ
流れます（`is-in-r` / `is-out-l`）。**設定は席ではなく上に重なる一枚**なので、
iOS の設定と同じ押しのけ（`is-push-in` / `is-push-under` / `is-pop-in` /
`is-pop-out`）——入る面は 100% → 0、下の面は 0 → -28% しか動かず、入る面の
左端に影が付きます。どちらを使うかは `pushy(from, to)`（`OFF_BAR` が絡むか）。

### ファイルの分け方（2026年9月30日）

`screen-settings.js` は約3,300行あった。**動きは一つも変えずに**、中身ごとに分けた
（保存の鍵・読み書き・見た目はそのまま。手で写さず、構文解析で行の範囲と参照を洗い出して
移したので、元の本文の行はどれも、どれか一つのファイルにある）。

| ファイル | 中身 |
|---|---|
| `screen-settings.js`（土台） | 紙の重なり（`stack`・`makeLayer`・`go`・`back`・`openAsPage`・`paintLayer`）・行の部品（`card`・`head`・`foot`・`navRow`・`switchRow`・`pickRow`・`dangerRow`・`choose`・`copyText`・`fieldCard`）・`TINT`・`TAB`・`PAGES`・根っこ（`renderRoot`・`generalRows`・`saveErrorBanner`） |
| `settings-look.js` | 外観・暦を出すか・アイコンについて・困ったときの記録 |
| `settings-todo.js` | tasks（一日の始まりと終わり・通知・カレンダー） |
| `settings-list.js` | shopping（お店・カテゴリ・おぼえた振り分け） |
| `settings-daily.js` | daily（表示・書き出し・年の本） |
| `settings-notes.js` | notes（並び・ノートブック・タグ・書き出し。2026年10月1日） |
| `settings-diet.js` | health（記録を書き出す・取り込み・AIに分析） |
| `settings-relay.js` | 中継所・建てかた・AIの窓口 |
| `settings-backup.js` | バックアップ（保存・確かめる・復元・自動バックアップ・点検・使用量・日記を取り込む・Dropbox・データを消す） |

- **部品は `KN.settingsParts`（中では `S`）で渡す。** 土台が作って部品を置き、中身の
  ファイルは読み込んだときに `const { card, navRow, … } = S` で受け取り、最後に
  `Object.assign(S, { … })` で自分の行を置く。
- **土台がいちばん先。** 中身は読み込んだ時点で `S` から部品を取り出すので、index.html・
  sw.js・build-standalone.js の三か所とも `screen-settings.js` の**すぐ後**に並べる
  （`app.js` より前——`mount` を呼ぶのは app.js）。中身どうしの順は問わない。
- **`TAB` / `PAGES` は `build: () => S.lookRows()` の形で引く。** 一つのファイルだった
  ころは関数の巻き上げで `build: lookRows` と書けたが、中身は土台より後に読まれるので、
  そう書くと `undefined` を焼きつける。組むときに引く。
- **ファイルをまたぐ呼び出しも、呼ぶときに `S.` から**（`generalRows` の
  `S.collectIconGaps()`・`S.errCount()`、health の取り込みの `S.openAiSheet`）。
- **紙の重なりの変数（`stack`・`root`・`moving`・`fromTab`）は土台の外へ出さない。** 中身は
  `go` / `back` / `render` を通してだけ触る。中継所の道（`relayPath`・`relayTest`・
  `aiPath`）は `settings-relay.js` の中だけ（紙の外に持つ理由は上の「中継所の設定は二枚」）。
- 新しい一枚を足すとき：中身は該当するファイルに書いて `Object.assign(S, …)` に名前を足し、
  `PAGES` に `build: () => S.名前()` を一行。新しいファイルを作るなら三か所に登録する
  （同じ順かは `tests/registry.js` が見る）。
