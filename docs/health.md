# ダイエット（中継所・飲みたくなったとき）

CLAUDE.md から見出しごと移した、詳しい決めごと（2026年9月26日）。
本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも
踏む罠は CLAUDE.md にある。**新しい決めごとは、ここ（該当する docs）に書く。**

### 中継所は、見えているあいだ覗き続ける（`js/health-relay.js`）

歩数・消費・睡眠は、iPhoneのショートカットが中継所へ置き、アプリが取りに
いく。**画面に出る数字の古さは、置いた時刻と、取りに行った時刻の足し算**で、
前はその両方が遅かった。

- **覗くのは `KN.healthRelay.watch()` 一本**（`app.js` の立ち上げから一度だけ）。
  前はダイエットと daily の画面がそれぞれ持っていて、**その二つが出ている
  ときしか覗かなかった**——やること・買うものを見ているあいだ、届いた歩数は
  一度も入らない。画面ごとに書き写さないこと。入った記録は store に乗り、
  いま出ている画面は `app.js` の `subscribe` が描き直すので、**覗く側が画面を
  知っている必要はない**。
- 間隔は届かなければ広げる（1分→2分→4分→5分で頭打ち）。届いたら1分に戻す。
  **見えているあいだだけ**（`visibilitychange` で止める）。
  他アプリから戻った直後は20秒、ショートカットを起こした直後は2分、
  5秒おきに刻む（`boost`）——中継所のKVは結果整合で、置いたことが伝わるまで
  最大60秒ほどかかるので、一度きりの問い合わせでは取りこぼす。
- **自動を切ってあれば（`dietAutoSync === false`）覗きにも行かない。**
  拍だけ止めて開くたびに一度ずつ覗くのでは、止めたことにならない。
  押されたとき（`pullNow({force:true})`）だけは別——そこは「自動」ではない。

**中継所（`relay/worker.js`）は、渡した便を消さない。**

- 前は GET で渡した時点で消していた。だから読む側が断ると
  （iPhoneがロック中に走ったショートカットは 0 の羅列を置く。
  `health-sync.js` はそれを正しく断る）、**その一回ぶんが永久に消えた**。
  掛け直しても郵便受けはもう空で、次に何か入るのはショートカットが次に
  走ったとき。「一時間おきに仕掛けているのに数時間前のまま」の正体。
- かわりに**版**（`X-Kn-Ver` ＝ いちばん新しい便を置いた時刻）を返す。
  アプリは最後に見た版を `?since=` で送り、変わっていなければ **204**。
  だから何度覗いてもタダで、取りこぼしも二度取り込みも起きない。
  **版は必ず進める**（同じミリ秒に二本置くと同じ数になるので、`max+1`）。
- **ひとつ前の便も残す**（`box:<slot>:prev`）。消さなくても、次の便が前の便を
  差し替えることは変わらない——良い便が空振りに踏み潰される。GET は
  **ひとつ前 → いま**の順に渡すので、読む側は順に取り込めば「いまのが読めれば
  それが残り、読めなければひとつ前が残る」になる。**中身は読まない。順番だけ。**
- **捨てる口は `DELETE`**（`?slot=` でその差出人だけ）。消えなくなったぶん、
  意図して空にする道が要る。「中継所を確かめる」の試しの便は、
  **健康データの形をしていないもの**（`kn-selftest=…`）を専用の棚へ置いて
  自分で片づける——片づけ損ねた試しの便が記録に入る道を、はじめから塞ぐ。
- `worker.js` を直したら **`node relay/embed.js`** で `js/relay-code.js` を
  作り直すこと（アプリの「コードをコピー」が配るのはそちら）。忘れると
  `relay/worker.test.mjs` の最後が落ちる。
- **`X-Kn-Replaced` は無くなった。** アプリ側にそれを読む枝が残っていた時期が
  あるが、worker は一度も送っていなかった（`Access-Control-Expose-Headers` に
  すら無かった）ので、「前の便は読まれないまま上書きされていました」は
  **一度も出たことがない**。ひとつ前も渡るようになったので、言うことも無い。

**アプリの中に、ショートカットを起こす口がある。**
からだの見出しの右の「◯:◯◯ 時点」（`.js-fresh`）を押すと、設定してある名前で
`shortcuts://run-shortcut?name=…` を開く。**指が触れている＝ロックが解けて
いる**ので、無人のオートメーションと違って空振りしない。
**戻り先（x-callback の `x-success`）は付けないこと**——ホーム画面のWebアプリへ
戻る道は iOS に無く、指定すると Safari のほうが開いて、別の保存領域の
くらしノートが立ち上がる。戻るのは指でよくて、戻った合図は
`visibilitychange` が出す。
**ホーム画面のWebアプリは、iOSの「アプリ」オートメーションの一覧に出ない**
（実機で確認済み・2026年9月12日）ので、「くらしノートを開いたら走らせる」は
あちらの道では作れない。

**「この数字は何時時点か」は `store.healthSeenAt(day, types)`** から出す。
`diet.sync.lastAt` は「最後に何かが入った時刻」で、昨日を開いていても今朝の
時刻を出す。言うのは**今日のぶんだけ**——過ぎた日はもう新しくなりようがない。
中継所を設定していない人には言わない（届く先が無いので、直しようのないことを
言うことになる）。

### 飲みたくなったとき（`diet.urges`）

お酒の記録（`diet.drinks`）が持っているのは「**飲んだという行い**」だけでした。
飲まなかった晩には何も残らないので、**飲みたくなったこと自体が起きなかったこと**に
なります。減らそうとしている人にいちばん起きているのは、そっちなのに。

`diet.urges[]` が持つのは、そのできごとの筋です——飲みたくなった → 一度立ち止まった
→ 何かを試した → 欲求がどう動いた → 最終的にどうした。

- **採点しません。** 連続日数・達成率・成功/失敗・点数・警告色は一つもありません
  （daily と同じ決めごと）。**「飲んだ」は失敗ではなく、その晩に起きたこと**です。
  点を付けはじめたら、点の悪い晩は書かれなくなります——そして書かれなかった晩
  こそ、あとで読み返したいものです。日の紙に出すのも**回数だけ**：「うち◯回は
  飲まなかった」は事実の記述ですが、並べた瞬間に分子と分母の顔をして達成率に
  なります。
- **二段に分けてあります。** 「しばらく経った後の強さ」と「どうしたか」は、
  飲みたくなった瞬間にはまだ起きていないので、一枚に並べると後ろの二つは空欄か、
  その場で作った数になります。
  - **一段目**（その瞬間）… `before`（1〜5）だけ必須。**押すもの一つで保存できます**。
  - **二段目**（あとで）… 日の紙の行を押すと `tried` / `after` / `outcome` が出る。
  - `after` / `outcome` の `null` は「**まだ書いていない**」で、0 や「無かった」では
    ありません。二段目は**書かなくてかまいません**——書かれなかった記録は「未完」
    ではなく、そこまでしか書かなかった晩です。
- **20分は線ではありません。** 「20分待てば成功」は条件であり、条件は採点です。
  出すのは経過した分数という事実だけ（`urgeElapsed`）。**タイマーも通知も持ちません**
  ——ホーム画面のWebアプリでは、どちらも当てになりません。
- **「どんなとき（`scene`）」と「どんな気持ち（`trigger`）」は、別の欄です。**
  認知行動療法の機能分析が、飲む前の状況を**外側**（いつ・どこ・誰と）と**内側**
  （気持ち・考え・からだ）に分けるのと同じ切り方です。一つにまとめると「帰宅後」と
  「疲れた」が同じ列で競合して、**「帰宅後はどんな気分でも飲みたくなる」と「疲れて
  いればいつでも」が見分けられなくなります**。手の打ち方も別で、外側は段取りを
  変えて避けられ、内側は別の行動で乗り切るものです。
- **候補（`URGE_FIELDS` の `hints`）は、欄ごとに理由があって出しています。**
  「固定の選択肢にしない」と書いてあった時期がありますが、**欄によって当たり外れが
  違う**と分かったので分けました：
  - **どんなとき**は出す。外側のできごと＝時計と段取りの話で、気持ちのような
    「その人の言い方」がありません。そして**数えるには言葉が揃っている必要が
    あります**——自由記述だけだと「帰宅後」「帰ってから」「帰宅してすぐ」が別の札に
    なり、同じ場面が三つに割れて傾向が見えません。「こういうときは、こうする」と
    段取りを決めるやり方も、場面の名前が毎回同じでないと組めません。
  - **どんな気持ち**も出す。ただし並べるのは HALT——空腹・いらだち・さみしさ・
    疲れ——を軸にしたものだけで、思いつきの八語ではありません。
  - **試したこと**は、候補そのものが道具です（対処カード）。飲みたくなっている
    その場で代わりの行動を思いつくのは難しいので、あらかじめ並べておく。ここで
    出さないのは、**いちばん要るときに白紙を渡す**ことになります。
  - どの欄も自由に打てて、**打った言葉は候補より前に並びます**（`urgeWordField` の
    `picked → urgeWords → hints` の順）。候補を先に置くと毎回そこから選ぶことに
    なって、自分の言い方がいつまでも札になりません。きっかけの語彙は**飲んだ記録の
    `moodTags` と分け合う**ので、すでにお酒を書いている人には自分の札が出ます。
- **欄はいつも全部あります。畳んであるだけです**（`.js-rest` と「詳細を書く」）。
  前は「一度保存してからでないと続きが書けない」作りで、**その場で全部書ける人の
  邪魔をしていました**。畳むのは隠すためではなく順番のため——飲みたくなったその瞬間に
  七つの欄が並んでいると、いちばん大事な一つ目を押す前に閉じられます。行を押して
  開いた紙は、はじめから開いています（続きを書きに来たので）。
- **余白は、意味の近さで決めます**（`.urge-form` の 26px と `.urge-sec` の 10px）。
  `.field-label`（12px・薄墨）が一定の間隔で並んでいた時期があり、**どこからどこまでが
  一つの問いなのかが絵に出ていません**でした。見出しは絵と題で一組（15.5px・太字、
  `urgeSec`）、説明はその下、中身はさらに下。**ここを詰めると、また読めなくなります。**
- **「15〜30分で山を越える」は情報として置き、条件にしません。** 飲みたさは山を
  越えて引いていくもので（urge surfing の考え方）、その山がどれくらい続くかを知って
  いること自体が支えになります。ただし「20分待てたら成功」にした瞬間、それは採点に
  なります。書き方は drinks の「節度ある適度な飲酒は〜とされています（個人差が
  あります）」と揃えること。
- **「飲んだ」を選んでも、`drinks` には勝手に書きません。** 量も種類もこちらは
  知らないので、書けば嘘になります。出すのは既存の `openDrinkSheet(day)` への
  一押し（`.js-go-drink`）だけ。
- `day` は **`todayKey()`（ローカル）**。`today()` は UTC なので、混ぜると JST の
  夜9時の記録が翌日に付きます——**飲みたくなるのはたいてい夜なので、この機能では
  そのずれが毎日出ます**。
- **ダイエットの記録の日は、どれも `recDay()` で埋める**（体重・食事・お酒・健康・
  飲みたくなった。2026年9月26日）。前は四つが `|| today()` で、日付の欠けた・
  読めない記録に時刻つきの UTC の文字列が入り、**どの日にも出ないうえ、画面の
  描画まで落ちていた**（改善一覧の A5）。時刻を持つ値はローカルの日に直し
  （`toDayKey`）、手がかりが無いときだけ今日。新しい種類の記録を足すときも
  これを通すこと。
- `cleanUrge()` は `reconcile()` 経由＝**load の経路にいる**ので、`function` 宣言で
  `let state = load()` より上に置くこと（`const` で下に書くと TDZ で落ちます）。
- **`diet` の中に置いてあるので、書き出し・復元・自動バックアップには何も足さずに
  乗ります**（`importJSON` は `s.diet = next.diet` で丸ごと入れ替えるので、列挙の
  足し忘れの罠にかからない）。`backup.js` の `dietRecordCount` にだけ足してあります
  ——足さないと、それしか書いていない人の控えが「空」と判定されます。
- 入口は からだ の輪のすぐ下（`renderUrges` → `.js-urges`）。飲酒の輪と同じ一日の、
  同じ面の話なので、別の段に離すと二つの別々の機能に見えます。
- 行の「4 → 2」の矢は `KN.util.raw` で通すこと——`html` は補間した値を escape するので、
  そのまま書くと「4&lt;i&gt;→&lt;/i&gt;2」という字が出ます（実際に出しました）。
- 段の選択色は `--c-primary`（字の色）で、`--c-primary-fill`（塗り）**ではありません**。
  塗りだと白抜きが 2.06:1 で 17px の数字が薄れ、すぐ下の札だけがはっきり読める、
  という見え方になります。同じ紙の `.chip.is-on` と同じ色に揃えること。
- **1〜5の段は、どれも `clearable: true`。** 「いま、どれくらい飲みたいか」
  （`before`）だけ外せない作りにしていた時期がありますが、押し直しても戻らない
  ことが**不具合として報告されました**——他の四つ（場面・気持ち・試したこと・
  あとの強さ）はどれも押し直せば外れるので、一つだけ違う手ざわりは不具合に
  見えます。必須なことは保存ボタンの活き死に（`syncSave`）が言うので、段の
  ほうまで「外せない」にする必要はありません。
- **「どんなとき」「試したこと」の下に、説明文（`urgeSec` の `note`）は
  置きません。** 見出し（絵＋題）と候補の札だけで用が足りるなら、字を足すほど
  紙が長くなるだけです。理由は `URGE_FIELDS` の頭のコメントに書いてあれば
  足ります——画面にまで出す必要はありません。
- **時刻は打たせません。** 「いつのことか」を尋ねると、**飲みたくなった瞬間
  なのか、続きを書いているいまなのかが読み手には分からず**、実際にそう聞かれ
  ました。答えは常に一つ——**その段を押した瞬間**（`addUrge`/`updateUrge` が
  自動で控える）。紙の頭（`.urge-since`）は、その控えを**見せるだけ**にします：
  続きが決まった一件は記録した時刻を、まだの一件は経過分数を。両方は出しません
  ——決まった瞬間は「あと何分」より「何時何分にどうなったか」のほうが読み
  返すときに要る情報だからです。
  - **`save()` は `time` を patch に含めません。** 新規なら `addUrge` の既定
    （`KN.util.nowTime()`）がそのまま入り、続きを書くだけなら
    `updateUrge` の `{...was, ...patch}` マージで元の時刻が残ります——ここで
    上書きすると、続きを書いた時刻で「いつ飲みたくなったか」が塗り替わって
    しまいます。**手で直す道は、いまはありません**（要るようになったら
    足すこと。無いほうが「時刻を打たなくていい」という要望に沿います）。

**まだ作っていないもの（次の段階）**：図鑑・傾向（きっかけの数え上げ、試したことの
一覧、`before → after` の分布）。置き場所は既存の「気づいたこと」（`diet.js` の
`analyze`）——新しい画面を作らない。**言い方は「あなたの記録では、こういう傾向が
ありました」まで**で、その行動が飲酒を減らした原因だとは言わない。
**データが貯まってから着手すること**（空の図鑑は、作りかたを間違えます）。

### 空の日に「—」を並べない

2026年9月26日（`docs/improvements.md` の B9）。空の日は「—」が画面で十七個並んでいた。

- **輪の中は、値が無いとき空**（`ringPct` が `""`、飲酒のまだ夕方前も）。「—」は
  下の数の欄だけが言う——輪の中にも書いていたので、一枠に二つずつ並んでいた。
  空の輪そのものが「まだ無い」を言っている。記録がある輪は、いままでどおり％。
- **食事の空の枠は、枠の名前を薄い字で**（朝食・昼食・夕食・間食。`.is-blank`）。
  行には絵しか無いので、「—」では何の枠か読めなかった。
- 残る「—」は、数の欄（4）・食事の合計（1）・今日の体重（1）・体重の三つ
  （傾き・平均・目標。記録が無いときだけ、3）。体重の記録がある人の空の日は6つ。
- 押す範囲（B2）：食事の枠は、枠のあいだの8pxの**半分ずつ**まで広げる
  （`.diet-slot-view::after`、`inset: calc(var(--sp-2) / -2) 0`）。四枠が隙間なく
  つながり、隣の枠の的には一画素もかからない。「AI推計」の帯（22px）は 44px へ。
