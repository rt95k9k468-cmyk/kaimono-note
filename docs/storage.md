# 保存の置き場（元・日記の写し・自動の控え）

`store.js` の書き込み（`writeLive`）・`backup.js`・`js/idb.js`・`js/diary-idb.js` を
触るときに読む。経緯は `docs/improvements.md` の A1・A2・A4（2026年9月26日）。
置き場の全部の一覧・枠・弱いところの点検は `docs/log/data-check.md`（2026年10月8日）。

## 置き場は三つ

| 置き場 | 中身 | 書く人 |
|---|---|---|
| localStorage `kaimono-note-v2`（**元**） | state まるごと。日記の本文は、利用者が「日記を記録から外す」を済ませるまではここにもある（済ませたあとは印の行だけ。下の「2b で入れたもの」）。`lsSeq`（書いた回数）が一緒に書かれる | `store.writeLive` |
| localStorage `kaimono-note-snapshots` | 前の自動の控え。大きな保存場所へ写したあとは**書き足さない**（写せない日だけ使う） | `backup.js` |
| IndexedDB `kaimono-note`（**大きな保存場所**） | `diary`（日記の本文の写し。一日一件、キーは日付）・`snaps`（控えの見出し）・`snapBodies`（控えの中身と、B3 からノート）・`meta`（移し替えの記録・番号・外した記録 `diaryOut`・**記録の写し `live`・開いた記録 `journal`**） | `diary-idb.js`・`backup.js`・`live-idb.js` |

- 大きな保存場所が使えない端末・使えなかった日は、**前のまま**（localStorage だけ）で
  動く。どちらのモジュールも、失敗したら「前のまま」が行き先。
- `idb.js` は版を決め打ちにしない。版を持たずに開き、棚が足りなければ版を一つ上げて
  足りない棚だけ作る。新しい棚は `STORES` に足すだけでよい。
- 暗号にはしない（利用者が決めた。鍵を失うと二度と戻らないので）。`js/diary.js`
  （暗号つき）は使っていない。

## 日記の本文：「二重に持つ時期」（外すまで）

**2b（2026年10月4日）で外す仕組みは入ったが、外すのは利用者が設定で押したときだけ。**
押すまでは**元（localStorage）から本文を外していない。** 元はこれまでどおり書き続け、写しの側は
元を書くたびに同じものを書き足し、開くたびに突き合わせる。画面・書き出し・控え・
復元は、どれもこれまでどおり記憶の中の state（本文つき）を見る——だから三つとも
日記が入っている（外したあとも、読める日は同じ）。

**はじめて開いたとき**（`meta.diary.phase` が `verified` でない）：①本文のある日を
全部、一つの取引で写す → ②読み直して全部の日で一字も違わないか（`===`）→ ③元は
消さない。②で違えば写したほうを捨てて `failed` を記録し、写しを使わない（次に開いた
とき、また試す）。途中で読み直されても（本番では Service Worker の入れ替わりで起きる）、
次に開いたときにやり直す。

**写しが正しい**（2026年9月28日、次の段の段1。それまでは「元が正しい」で、元に
無い日を理由に写しの行を消していた）。開くたびの突き合わせ（`reconcile`）は：

- **写しの行を一つも消さない。** 写しにだけある日は元へ戻す。元に無いことは消した
  証拠にならない（元だけ消えた・元の保存が落ちた・書き足しが届かなかった、どれも
  同じ形）。写しを消すのは、利用者が日記を消す・すべて削除・復元をしたとき
  ——書くたびの `diffInto` だけ。
  - その代わり、利用者が消した直後に閉じて写しへの書き足しが届かなかった日は、
    次に開いたとき戻ってくる（消えるよりマシ、のほう）。
- 元にだけある日 → 写しへ足す。
- 両方にあって違う日 → **写しを元へ**。ただし元の番号 > 写しの番号のときだけは、
  元が新しい（書いた直後に閉じて、写しへの書き足しが届かなかった）ので、元を写しへ。
  番号の比べ方：元は書くたびに `lsSeq` を一つ進めて一緒に書き、写しは書き足すたびに
  「元の何番に合わせたか」（`meta.diarySeq`）を**同じ取引で**書く。
  - 元が番号を持たない（直に書いた・古い版）は、新しいと言えない → 写しが勝つ。
  - 比べる元の番号は、いつも**読んだときの**番号（`store.loadInfo`）。読めなかった日の
    あとで読み直すときも——そのあいだは本文を書かせないので元の本文は読んだときの
    まま。進んだ番号（やること・買うものの書き込み）で比べると、古い元が新しい写しに
    勝ってしまう。
- 元が空（はじめての端末・元だけ消えた）→ 上の決まりのまま、全部が写しから戻る。
- どちらの向きでも、置き換わる側の本文は先に自動の控えへ（「**日記の突き合わせ前**」。
  PINNED＝間引かない）。置き換わる側が新しいほうの**書き出し（前方一致）**なら、
  失うものが無いので取らない。いちばん新しい控えと同じ中身なら、取らない（`"same"`）。
- 写しを元に合わせた（足した・書き直した）ときだけ、写しの番号を元の番号へ。
  写しから戻しただけのときは動かさない。
- `migrate`（はじめて写す）だけは写しを一度空にする。空にするのは確かめ終えていない
  写しだけで、それは前の `migrate` が元から写したもの（書き足しは確かめ終えるまで
  届かない）なので、元に無いものは入っていない。

**読み込み中と、読めない日**（`KN.diaryIdb.body()`。画面の決めごとは docs/daily.md）：

- `"loading"`：開いた直後、突き合わせが済むまで。**本文を書かせない**（日記の紙を
  開かない・日記の取り込みを断る）・**書き出させない**（丸ごとの書き出し・月の書き出し・
  写す）・**控えを取らせない**（`backup.take` が `ready()` を待つ）。
- `"off"`：大きな保存場所を読めなかった日（使えない端末・開けない・読み比べで違った・
  取引が落ちた）。daily の本文だけ「読めません」と出して、書かせない。ほかのタブ・
  daily の時刻は通常どおり。
  - 段1 のあいだは、読めない日も**丸ごとの書き出しと自動の控えは取る**（元に本文が
    あるので、取れば日記も入る。守るための道は止めない）。段2 では考え直す。
  - 読めない日の「復元」「すべて削除」「サンプル」は止めていない。そのあと写しが
    読めると、写しにだけある日は元へ戻る（消さない決まりのまま）。
  - 読み直し（`retry()`）：前に出てきたとき（app.js の visibilitychange）と、daily の
    本文を押したとき。記録が読めない日・IndexedDB の無い端末は読み直さない。試して
    5秒以内も。
- 次に元を書く番号は、写しの番号の続きから（`store.seqAtLeast`）。これが無いと、
  元が読めなかった日に番号が 1 から振り直され、次に元が読めた日に古い元が勝つ
  （試験で確かめた）。
- 元が書けなかったとき（`writeLive` の `finally`）も写しには書く。書けたかどうかは
  番号でしか比べないので、`ok` は表示用。

`lsSeq` は **state の欄ではない**：`load()` が読み、`reconcile()` が外す。画面にも
書き出しにも控えにも乗らない。`let lsSeq` は `let state = load()` より上にある（TDZ）。

**写しへの書き足し**（`afterWrite` → `diffInto`）は、覚えている写しの中身（`known`）
と state の差だけを一つの取引で。3000日×600字で、差分づくりは約1.3ms。取引が
落ちたら `known` を捨て、次に書くときに読み直して合わせる（元は無事なので失うもの
は無い）。突き合わせが済む前に来た書き込みは番号だけ覚えて、済んでから一度に。

**書き出し**（`saveBackup`）は、突き合わせが済む前（開いた直後の一瞬）は断る。
**`await` で待たない**——共有シートがタップの流れから外れる（docs/settings.md）。

## 自動の控え：大きな保存場所へ

- 移し方は日記と同じ（写す → 一件ずつ読み比べ → 元は消さない）。どこまで写したかを
  `meta.snaps.copiedUpTo` に覚え、それより新しい localStorage の控え（使えなかった日に
  取ったもの）だけを次に写す。
- 上限は `BUDGET_IDB`（2,000万字。localStorage のころは150万字）。500日×600字（記録
  約39万字）なら段（直近2日は一時間おき・14日）が全部入る。3000日×600字（約234万字）
  では8件で、設定に「◯件ぶんまで」と出る（`usage().tight`）。
- 取るのは**約束（Promise）で返る**。`take()` は日記の突き合わせが済むのを待ってから
  取る（済む前の控えは、写しから戻る本文を取りこぼしうる）。突き合わせ自身の控えは
  `{ now: true }` で待たない——待つと互いを待ちあって止まる。取るのは一つずつ（`chain`）。
- `list()`・`usage()` は**その場で返る**（見出しを覚えている）。中身は `restore` のとき
  だけ読む。
- 大きな保存場所に書けなかったら、localStorage へ退く（「削除前」を取れないまま
  進ませない）。
- 本体の保存が容量で落ちたら、`makeRoom` は localStorage に残した控え（写し済みの元）を
  手放す。大きな保存場所の控えは減らないので、知らせない。
- 離れる瞬間の控えは「あとで返事が来る」ので、止められると残らないことがある。本体は
  `store.flush` がその場で書いているので、次に開いたときの控えが同じ中身を取る。

## Dropbox へ送る（`js/dropbox.js`、2026年9月28日）

端末をなくした・壊れた日のための、端末の外の控え。利用者が Dropbox だけを選び、
**暗号にしない**と決めた（昔の日記の PDF も同じ Dropbox にそのまま置いている）。

- **中身は `store.exportJSON`**（「バックアップを保存」と同じ）。そのまま復元で読める。
- 置き先は App folder（「アプリ/<アプリ名>」）だけ。権限は `files.metadata.read`・
  `files.content.read`・`files.content.write`。
  - `kurashi-latest.json` … 送るたびに**上書き**（Dropbox 側の版の履歴にも前が残る）。
  - `daily/kurashi-YYYY-MM-DD.json` … その日**はじめて**送った中身。`mode: "add"` で
    **上書きしない**（その日に消しても、日付の控えは道連れにならない）。名前は
    `dayKey`（ローカル）。新しいほうから `KEEP`（30）個を残し、古いものを消す。消すのは
    この名前の形だけ。
- いつ：開いて8秒後・前に出てきたとき・書き換えてから2分後（その間はまとめて一度）・
  隠れるとき（書き換えが残っていれば）。**中身（`store.get()` の SHA-256）が前回と
  同じなら送らない。** ハッシュはキーを並べてから（`canon()`。`reconcile()` が開くたびに
  欄の順を並べ直すため）。新しい欄を `reconcile()` に足したら `addTodo` などの作る側にも
  既定値で足す（欠けると次に開いたとき中身が変わり、同じ記録を送り直す。2026年10月7日）。閉じているあいだは動けない（iOS のホーム画面アプリに定期の
  仕組みが無い）が、記録が変わるのも開いているあいだだけ。
- **門**：日記の写しの突き合わせ（`diaryIdb.ready()`）を待つ。記録に本文を外した日
  （`memoOut`）が残っていれば**送らない**（本文の無い中身で上書きしないため）。
- **鍵は store の外**（localStorage `kaimono-note-dropbox`）。書き出し・控え・
  「すべて削除」のどれにも乗らない。App key も同じところ（リポジトリには書かない）。
- つなぎ方は PKCE の**コードを貼る形**（redirect を使わない）。iPhone のホーム画面
  アプリは外へ出た先から戻るとき Safari 側で開くことがあり、置き場が分かれるので。
  `window.open` を押した流れで呼ぶため、challenge は先に作っておく（`prepare`）。
- 401 は鍵を取り直して一度だけやり直す。refresh が `invalid_grant`（Dropbox 側で
  外された）なら鍵を捨てて「つなぎ直しが要ります」。
- 二台でつなぐと `kurashi-latest.json` を取り合う（日付の控えは先に置いたほうが残る）。
  いまは一台の前提。記録もノートも空なら送らない（`"empty"`）。控えから戻すのは B2（下の
  「立て直しの計画」）。
- 試験は `tests/dropbox.js`（本物には繋がない）。

## 日記を取り込む（D7。設定 → 一般 → バックアップ）

2026年9月27日。取り込み道具（`tools/diary-import.html`）が作った控え
（`kind: "diary-sealed"`、合言葉で暗号にしたもの）を、合言葉で開いて daily の本文へ
（`store.importDiary`）。開いた本文は暗号にしないまま、ほかの日記と同じところへ。

- 入れるのは行の無い日と、行はあっても本文が空の日。同じ本文なら何もしない（二度
  読ませても二つにならない）。暦に無い日（2月30日）は入れない。
- **上掛け（2026年9月30日、利用者が決めた）**：くらしノートで書いてからジャーナルに
  写し、そこで書き足す使い方なので、本文のある日も控えの文にできる
  （`importDiary(list, { replace })`）。はじめは「本文のある日には一字も触れない」だった。
  - 比べるのは、空白・改行を抜いて NFKC にした形（PDF の読み取りで変わるので）。
    それで同じなら何もしない（くらしノートの改行を残す）。
  - くらしノートの文が控えの中にそのままある日（**書き足し**）は、控えの文にする。
  - それ以外（**中身が変わった**）は、日付だけを並べて訊く（本文は見せない）。閉じたら
    「くらしノートのまま」。置き換えたくらしノートの文は、取り込み前の自動の控えに残る。
  - 本文を外した行（`memoOut`）と、控えに無い日には触れない。「作成」「更新」も動かさない。
  - 試験は `tests/diary-import.js`。
- 取り込んだ行の「作成」「更新」は空（いま作った・直したわけではないので）。
- **入れる前に、記録の大きさを測る**。取り込んだあとの記録（JSON）が **200万字**を
  越えるなら、何も変えずに断る（`DIARY_LIVE_LIMIT`）。記録はいまも元（localStorage）へ
  一つの文字列でまるごと書くので、枠（iPhone でおよそ5MB＝日本語で260万字ほど）から
  あふれると、**日記だけでなく、やることや買うものの保存まで止まる**。大きな日記を
  入れたいなら、先に「日記を記録から外す」（下の「2b で入れたもの」）。外してあれば、
  本文は写しへ先に届け、元には印の行だけが増える（大きさもその形で測る）。
- 入れる前に自動の控え（「日記の取り込み前」）。突き合わせが済む前は断る（書き出しと
  同じ門）。件数は言わない（daily は数えない）——確かめの紙が言うのは期間と大きさ。
- 合言葉の欄は `KN.ui.prompt({ secret: true })`：伏せて打ち、前後の空白も削らない。

## 次の段：元から本文を外す（**2a・2b とも済み。外すのは利用者が設定で押したとき**）

設定の「バックアップ」の下に、開いた回数と食い違いの有無が出る
（`diaryIdb.status()`）。それを見て利用者が決める。二段に分けた：

- **段1（2026年9月28日に済み。本文はまだ外していない）**：
  - 突き合わせの向きを「写しが正しい」に（上の節）。元が空でも写しを消さない。
  - 読み込み中は本文を書かせない・書き出さない・控えを取らない（`settled()` /
    `ready()` の門を、書く側にも広げた。`body()`）。
  - 大きな保存場所を読めない日は、daily の本文だけ「読めません」、書かせない。
  - 試験は `tests/diary-idb.js`。
- **段2**：下の「段2の案」。2026年9月28日に報告し、利用者は「おすすめ通りに
  進める」と了承。**2a は2026年9月28日に済み（下の「2a で入れたもの」）。2b は2026年
  10月4日に「進めて」をもらって入れた（下の「2b で入れたもの」）。**その時点で設定の
  「食い違いを直した」は0回（325回とも食い違いなし）、記録 約56万字（うち日記 約4.0万字）。
  理由は「大きな日記を取り込みたい／先に済ませておきたい」。

### 段2の案（2026年9月28日。方針は了承済み・2b は2026年10月4日に承認）

**危ないところ**：段2のあと、読めない日のアプリは本文を持たずに動く。その日の控え・
書き出しには本文が無い。それを復元すると `importJSON` → `writeLive` → `afterWrite` →
`diffInto` が「本文の無い日＝消した日」として**写しから消す**（`diffInto` の `dels`）。
突き合わせ（`reconcile`）は写しを消さないが、書くたびの `diffInto` は消す——復元は
こちらを通る。読めない日に時刻だけ直しても、`setDayLog` が行を作り直して同じ形になる。

#### 土台
**土台**
- 外すのは**元に書く瞬間だけ**（`writeLive` の直列化で）。記憶の中の state は本文つきの
  まま——読める日の画面・書き出し・控え・復元は今のまま。記憶からも外して使う側が
  写しから引く形は、使う側を全部非同期にする大工事なので採らない。
- 外すのは**写しに届いたと確かめた本文だけ**。取引が済んで（`durability: "strict"`）から
  `committed`（日付 → 本文）に覚え、`committed.get(date) === memo` の行だけ外す。
  失敗した取引は丸ごと戻るので `committed` は失敗では変えない（`known` とは別に持つ）。
  書いた直後に閉じても元に本文が残り、今の「元の番号が新しければ元が勝つ」がそのまま効く。
- 外した行は `memo: ""` ＋ **印 `memoOut: true`**（行は残す）。**印の行は「本文がある行」**：
  消さない・空と見なさない・上書きしない・印を落とさない。印を外すのは、写しから本文を
  戻したとき（`reconcile` の bring・復元で当てたとき）だけ。印があっても `memo` が空で
  なければ、ふつうの行（段1の版が本文を書き戻した場合）。
- 同じ日付の二つ目以降は**外さない**（写しは先の一つしか持たない）→ 行を合わせる移行は不要。

#### 読めない日の控え・書き出しと復元（案B）
**読めない日の控え・書き出しと復元（案B）**——止める（案A：やること等の守りも止まる）・
復元で写しを一切消さない（案C：「取り込み前」へ戻しても取り込みが残る）・別の種類の
ファイルにする（案D）は採らない。
1. 読めない日の控え・丸ごとの書き出しは**取る**。外した行は印つきのまま入る。
2. `importJSON`：置き換える前に、印の行へ**いま持っている本文**を当てる（無ければ印のまま）。
3. 最後の砦：`diffInto` は**印の行の日を写しから消さない**。
4. 見せ方：読めない日の書き出しは確かめの紙で「日記の本文は入りません」、ファイル名に
   「本文なし」、**「前回の書き出し」に数えない**。復元・確かめる紙でも本文の無い日が
   あると言う（件数は言わない）。
5. 読めない日は月の書き出し・「写す」を断る。
6. **本文の入った最後の控えは間引かない**（読めない日が2週間ほど続くと押し出されるので）。
- 厳密には：ファイルに無い本文は戻せない（新しい端末では印の日は本文なし→「本文が
  見つかりません」）。当てるのはファイル時点ではなく、いまの本文。

#### 出し方と時期・2a

## 記録の写し（`js/live-idb.js`、2026年10月6日・二度目の消失のあと）

元（localStorage の一本）を書くたびに、**同じ文字列**を meta `live`（`{ seq, at, json }`）へ。
二度目の消失（下の「記録が見当たらない日」）は控え（一時間おき）からしか戻せず、最大一時間
ぶんを失い、本人が気づくまで空で動いた。写しは書くたびなので、開いたときに元が無ければ
**訊かずにその場で戻す**（トースト「記録を ◯ の状態に戻しました」だけ）。

- 開いたとき、**読んだときの**元（`loadInfo`）と比べる：元が無い → 写しを元へ（`restored`）／
  元に番号があり写しの番号が大きい（元の保存が落ちた・巻き戻った）→ 写しを元へ（`older`）／
  それ以外（元に番号が無い＝直に書いた・古い版も）→ 元を写しへ。
- 写しを元へ戻すのは `store.adoptRaw`（元へ書いて読み直す。書けなくても記憶はそれに）。戻す前の
  記憶に中身があれば、**戻したあとで**控え「写しから戻す前」（先に取ると、取り終わるまでに
  打った字がどちらにも入らない）。元が勝つときも、写しのほうがずっと多ければ「写しを置き換える前」。
- 比べ終わるまで写しへ書かない（空で立ち上がった元で写しを潰さない）。書きたいものは最新の
  一つだけ覚える。写しへ書くのは一つずつ・1秒に一度まで（隠れるときは待たない）。書けなければ
  10秒おいて試し直し、`errlog` に一度。
- **元が書けなかったときも写しへ**（diary-idb と同じ）。だから容量で落ちていたあいだの記録も残り、
  次に開くと `older` で戻る。
- 日記の写し（`diary-idb.js` の `boot`）と「記録が見当たらない日」（`backup.checkLost`）は、
  これが済んでから。戻したあとは `loadInfo` が「有る」なので、訊かない。
- 記録が読めなかった日（`loadError`）・大きな保存場所が使えない日は何もしない（前のまま）。
- **棚を足していない**（meta の鍵。版を上げない）。日記の本文を外したあと（2b）は、写しも外した
  形（元と同じ文字列）——本文は日記の写しにある。

**元を書く直前の見張り**（`store.watchBefore`。何が起きても保存は止めない）：

- 番号を持ってから元が無い＝**使っているうちに消えた** → 開いた記録に `vanished`。記憶は無事
  なので、この保存で戻る。読み直し（`store.reload`、引っぱって更新）で元が無ければ、空を
  読まずに記憶を書き戻す（前は空を読み込み、次の保存で消していた）。
- 元の番号のほうが大きい＝ほかの画面が書いた → `other`（記録だけ）。
- 一度の保存で記録の数（`countsOf` の合計）が `SHRINK_MIN`（10）以上減り、残りが前の7割未満 →
  減る前の元を控え「**大きく減る前**」（`PINNED`）。すべて削除・復元・サンプル・写しから戻すは
  自分の控えを取っているので除く（`bulk`）。

**開いた記録**（meta `journal`、新しい40件）：開くたびの元の有無・番号・字数・鍵の数、写しの
番号・時刻・字数、決めたこと、永続にしてもらえたか・使用量と上限（`navigator.storage`）。
ほかに `vanished`・`other`・`shrink`。数と番号だけ（中身は残さない）。localStorage と一緒に
消えないよう大きな保存場所に置く。設定 → 一般 →「困ったときの記録」のコピーに添える。
**次に消えたら、まずこれを貼ってもらう**——いつ・どの版で・容量はどうだったかが分かる。

試験は `tests/live-idb.js`。`tests/lost-record.js` は写しも消して、写しの無い日の退路を見る。
試験の罠：元を直に書き換えて読み直すとき、**`lsSeq` を写しの番号より小さく書くと写しが勝つ**
（日記の写しと同じ）。番号を消せば元が勝つ。

  ノートの字数も足す。記録だけ同じでノートが変わっても取る。ノートを読み終えていない日・
  記録を渡された控え（減る前・戻す前）・localStorage へ退いた控えには入れない。戻すと
  記録を置き換え、ノートは消さずに合わせる（`restore` が `{ notes }` を返す）。
  - 大きさ：控えは全部ノートの丸写しなので、段（約62件）が全部入るのは、記録とノートを
    足して1件 約32万字まで（`BUDGET_IDB` 2,000万字 ÷ 62）。越えると細かいほうから間引かれ、
    設定に「◯件まで」が出る（`usage().tight`）。ノートが大きく育ったら、変わったときだけ
    持つ形を考える。
- **B4**：開いたときに一度（`backup.js` の `inspectOpen`、読むだけ）。記録の数が、写し
  （開いたときに元と違っていて元が勝ったもの。`liveIdb.status().copy`）か開く前の
  いちばん新しい控えより大きく少ない（`store.shrinks`、または0）→ 設定の頭に「記録が控えより
  少なくなっています」（押すとバックアップへ）。ノートが開く前のいちばん新しいノートつきの
  控えより大きく少ない → 「ノートが控えより少なくなっています」（押すと訊いて、その控えの
  ノートを合わせる `backup.mergeNotes`）。いちばん新しい控えが PINNED（決めて変える直前）
  なら控えとは比べない。食い違いが消えれば行も消える（`doubt()` が描くたび見る）。
  開いた記録に `doubt`。記録が見当たらない日（lost）は見ない。
- **B5**：`tests/break.js`（壊し方を一本で。中身は tests/INDEX.md）。

## 記録が見当たらない日（2026年10月6日）

**記録の写し（上）が入ってからは、写しの無い日（写しを入れる前に消えた・大きな保存場所が
使えない）だけの退路。**

- 起きたこと：iPhone が localStorage だけを丸ごと落とした（記録の一本も Dropbox の設定も
  消え、大きな保存場所の控えと日記の写しは無事）。アプリは空で立ち上がり、日記だけ写しから
  書き戻し、「離れる前」の控えを空に近い中身で取りつづけた。本人が控え（19:39）から戻した。
  前の版から今の版へ上がる試験では消えず、アプリに本体の鍵を消すところは無い。
- 見分け（`backup.js` の `checkLost`）：開いた時点で本体の鍵が無く（`loadInfo().hadData`
  が偽、`loadError` なし）、開く前の控えが大きな保存場所にある。初めての端末は控えが無いので
  当たらない。印は meta `"lost"`（`{ at: 戻せる控え, found }`）。日記の書き戻しで本体は
  すぐ「有る」になるので、二度目からは印で見る。
- 印のあいだ：時刻で取る控え（自動・離れる前）は `"held"` で見合わせる（`PINNED` は取る）。
  Dropbox は `kurashi-latest.json` を上書きしない（`run` が `"held"`）。
- 訊く：「記録が見当たりません／◯ の控えに戻せます。」戻す・あとで。あとで →「このまま
  始めますか？」このまま始める・あとで。あとでは印を残し、次に開いたときまた訊く。
  控えから戻す（どの控えでも）・ファイルから復元・このまま始める で印を消す（`settleLost`）。
- Dropbox の設定は meta `"dropbox"` に写しを持つ（`save` のたび）。localStorage が空で写しが
  あれば写しから戻す（つなぎ直し不要）。`run` は戻し終わり（`recovered`）を待つ。
- 試験：`tests/lost-record.js`。

## 鳴らす役の写し（IndexedDB `kaimono-note-bell`、D1・2026年9月27日）

閉じていても鳴る通知（`js/bell.js`・`sw.js` の `push`。決めごとは docs/health.md）の
ために、**もう一つ別の入れ物**を置いた。棚は二つ：

| 棚 | 中身 | 書く人 |
|---|---|---|
| `plan` | `k: "list"` … 今日から7日先の {時刻, 題, id, 回} の列。`k: "key"` … 押し先を作ったときの鍵 | `bell.js`（毎回まるごと書き直す） |
| `rung` | Service Worker が鳴らした／アプリが鳴らした {id, 回}。一日で捨てる | `sw.js`・`bell.js` |

- **記録ではなく控え。** 元は store の todos で、消えても次に開いたときに作り直せる。
  CLAUDE.md の「記録用の入れ物を増やさない」の**例外**で、理由は二つ：Service Worker
  は localStorage を読めない（読めるのは IndexedDB だけ）／題を中継所へ渡さないと
  決めたので、押されたときに題を引ける場所が端末の中に要る。書き出し・控え・復元には
  乗せない（乗せる意味が無い）。
- **日記の入った `kaimono-note` とは別の入れ物。** `idb.js` は棚が足りなければ版を上げる
  作りで、別の版で開く者がいると `onversionchange` で日記の側の接続が閉じる。Service
  Worker がそこへ触る道を、はじめから作らない。
- 版は 1 の決め打ち（棚を変えるときは `bell.js` と `sw.js` の両方の `onupgradeneeded` を）。

## 試験の罠

- 新しい文脈で初めて開くと、Service Worker が入れ替わって一度読み直す（app.js の
  `controllerchange`）。`browser.newContext({ serviceWorkers: "block" })` で。
- IndexedDB は reload をまたいで残る。localStorage だけを書き換えて試すと、写しとの
  突き合わせが走る——**`lsSeq` を持たせずに書けば写しが勝つ**（2026年9月28日から。
  それまでは元が勝った）。元を勝たせたいなら、`lsSeq` を写しの番号（`meta.diarySeq`）
  より大きく。**元から日を消しても、写しから戻ってくる。** まっさらから試すなら
  新しい文脈で。
- 読み込み中を長くしたいとき・読めない日を作りたいときは、`IDBFactory.prototype.open`
  を `addInitScript` で包む（`tests/diary-idb.js`）。
- IndexedDB の中を覗くとき、`indexedDB.open("kaimono-note")` だけだと、無いときに
  **棚の無い入れ物を作ってしまう**（`onupgradeneeded` で `req.transaction.abort()`）。
  アプリ側は棚が足りなければ作り足すので壊れはしないが、試験の前提が変わる。
- 容量で落ちる場面は `Storage.prototype.setItem` を `kaimono-note-v2` だけ投げるように
  すれば作れる。そのとき `makeRoom` が localStorage の控えを手放すのは正しい動き。
- 試験の Chromium は、日本語の入ったダウンロード名を「download」に置き換えて保存する。
  付けた名前は `HTMLAnchorElement.prototype.click` を包んで `a.download` から見る
  （`tests/diary-out.js`）。
