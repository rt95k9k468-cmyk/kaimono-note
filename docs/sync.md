# 3台の同期（iPhone・iPad・Surface を対等に）

2026年11月4日の設計。desk の段15（読む写し＋足すだけ）の先：3台のどれでも書けて、ほかの端末へ自然に届く。
**置き場は Cloudflare の部屋、中身は端末で鍵をかけてから送る（11月4日、利用者が決めた）。**

## 決めたこと（11月4日）

- 置き場は Cloudflare の部屋（下の「形」）。Dropbox だけの同期は採らない（届くまで数秒〜十数秒・同時に書くと429・古い版や
  大量の消しを断る側が無い）。
- 記録の形（`kaimono-note-v2`・IndexedDB の棚・Dropbox の中身）は変えない＝移し替えなし。日記の一件ごとの id 化もしない。
- 変更は、保存のあと「前に合わせた中身」と一件ずつ（id か日付で）比べて拾う。書く道（`store.update` ほか）には手を入れない
  ——古い版で書いた分・書く道の付け忘れも、次の比べで拾える。
- ノート・画像・PDF は今の Dropbox 同期のまま（docs/notes-unify.md）。新しい同期へは移さない。
- 設定は送らない（端末ごと。中継所の URL・画面の鍵・Dropbox の鍵は特に）。ヘルスケアを取りに行くのも、控えを送るのも iPhone だけ（今のまま）。
- 最初に書けるようにするのは買うもの（利用者に任された）→ やること → からだ・daily → 日記。
- ネイティブの殻は遥か先（Mac が無い・費用。plan.md 3節）。Surface は Edge のアプリのまま（Tauri にしない）。
- 画面に同期の様子は出さない（10月31日に断られた）。困ったときだけ歯車の点（今の決まり）。

## 形（細かいところは段1・2で詰める）

- 端末：新しい IndexedDB `kaimono-note-sync`（版1の決め打ち。今の棚の版を上げない＝desk.md の罠）に、前に合わせた中身・送り待ち・読んだ番号。
- 部屋：新しい Worker＋Durable Object 一つ（SQLite）。**中継所とは別の Worker・別の鍵。** 一件ずつの中身と版・届いた順の番号つき履歴・
  端末と鍵（消せばその端末は切れる）。
- 送る：操作の番号（端末が振る）・記録・元の版・変えた欄。版が合えば部屋が番号を振って受け取り、合わなければ今の中身を返す
  → 端末が三方で合わせて送り直す（notes-sync の rev と同じ考え）。同じ操作の番号は二度当てない。
- 取る：読んだ番号の続きだけ。開いている端末へは WebSocket で知らせる（休眠のあいだは課金なし）。前に出た・電波が戻ったときも取る。
- 当てる：`emit()` で描き直す（`showReplica` と同じ道）。書く紙が開いている・変換中は、その一件は閉じてから（受け箱の15秒と同じ）。
  同期は一つの窓だけ（Web Locks）。
- 時計で上書きを決めない：順は部屋の番号、食い違いは版。時刻はどちらを本文にするかの目安だけで、もう片方も残す。
- **鍵**：中身は端末で AES-GCM にしてから送る。棚と記録の鍵（日付・id）も鍵つきのハッシュにする——部屋に見えるのは版・順・
  消した印・大きさ・時刻だけ。鍵は最初の端末で作り、各端末と Dropbox（App folder）に置く（利用者に打たせない）。iPhone の
  「パスワード」に写すのは任意の三つ目。Dropbox には素の控えが既にあるので、読める人は増えない。部屋は作り直せる写しなので、
  鍵を失っても記録は失わない（D7 で暗号を断った理由「鍵を失うと二度と戻らない」に当たらない）。部屋の側から中身を書き換える
  こともできない。鍵を失った・変えるとき：新しい鍵で部屋を作り直す（どれか一台から全部送る）。

## 守り（罠）

- **起動の途中は比べない。** 日記の写し・過去のやることが揃う前の state は日記が欠けて見える。欠けを「消した」と送れば全端末から
  消える。消したと扱うのは明示の操作だけ。
- 一度にたくさん消えたら止まって訊く（notes-sync と同じ覚えの1/5。部屋の側でも断る）。復元で丸ごと入れ替わったときも、送る前に訊く。
- 消すは印だけ（前の中身を部屋に残す）。直したのと消したのがぶつかったら直したほうが勝つ。
- 古い版の書き込みは部屋が断る（端末は約束の版を名乗る。中継所の「古い版の GET」の教訓）。
- 比べるのは変わった棚だけ（年を重ねても保存が重くならない。過去の年はめったに変わらない）。
- 新しい記録の棚は「送る／端末だけ」に分けないと門が止める。
- 部屋の URL・端末の鍵・中身の鍵はリポジトリに書かない（中継所と同じ）。本文をログに出さない。Cloudflare・Dropbox とも2段階認証。

## 部屋（段1で決めたこと、11月4日）

`sync/`：`room.mjs` が決まりの全部（SQL と io だけ）、`worker.mjs` は Cloudflare へのつなぎだけ、口の一覧と置き方は `sync/README.md`。
試験は `sync/room.test.mjs`（node:sqlite の上の偽の部屋で本物の worker.mjs を動かす。門は `tests/sync-room.js`）。

- つなぐ：最初の一台は `ROOM_SETUP`（Secret。一つの値で一回だけ——値を変えれば持ち主がもう一度だけ入れる＝取り戻し）。
  二台めからは `/pair` の合言葉（10字・10分・一回・5回外すと消える。一時間に10回外すと `/join` を一時間断る）。
  端末の鍵は部屋が作って一度だけ渡し、ハッシュで持つ。切れば鍵も WebSocket も消える。
- 送る：`op` は端末ごとに60日覚える。断った答えは覚えない（送り直せば今の中身で答え直す）。消しすぎ＝同じ棚で、
  この送り＋同じ端末の直近10分の消し（訊いた分は除く）が100を越えるか、10を越えて生きている数の1/5を越えたら 409 `many`。
  訊いたら `sure` に消しの数ちょうど。
- 約束の版 `schema`：書いた端末の版へ一つずつ上がり、下がらない（下げるなら部屋を作り直す）。古い端末は読めるが書けない（426）。
- 預かる形：名前は base64url 22〜86字、中身は base64 24字以上。素の JSON・日付のままの名前は 400——鍵のかけ忘れを部屋が止める。
- 取る：一件につき今の版だけを番号順。端末の番号が部屋より先なら 409 `ahead`（作り直された）。部屋の名札 `room` でも見分ける。
- **罠**：`sql.exec` で BEGIN は使えない（`transactionSync`）。tx の中で await しない（ハッシュは先に）。migrations の tag は書き換えない。
  ブラウザの WebSocket は見出しを付けられないので鍵は protocol に。CSP の `connect-src` に `wss://*.workers.dev`（段2で足した。security-gate）。
  Import の道で置くと main への push で Cloudflare が置き直す（門を待たない）——`sync/` は試験が通ってから main へ。
- 書き出さない：console を使わない・observability は切る・落ちても `{why:"room"}` だけ。

## 端末（段2で決めたこと、11月4日）

`js/sync.js`（決まりの全部）・`js/settings-sync.js`（設定 → バックアップ → 同期の部屋）。試験は `tests/sync-device.js`（門。偽の部屋は本物の room.mjs）。

- 棚：記録の欄ごとに **`SEND`／`LOCAL`** のどちらかへ（設定・`inboxSeen`・`todoOut`・`diet.sync`・`schema` は端末だけ）。
  id か日付のある配列は一件ずつ、`date` の年で棚を分ける（`archive.days:2026`）。辞書（`learned`・`iconOverrides`）は鍵ごと。
  **新しい欄を足したらどちらかに書く**（知らない欄は送らず、門が止める）。
- 一件の字は欄の名前の順（`canon`）。読み直すと `reconcile()` が欄の順を変え、既定を埋める——順は無視し、埋まった分は一度だけ送り直す（害は無い）。
- 比べるのは日記の写し・過去のやることが `on`、外した印（`todoOut`・`memoOut`）が無く、記録が見当たらない日でないときだけ。
- 訊く（設定の行・最初の一つ以外は歯車の点）：最初の中身／消しすぎ（部屋と同じ数え方）／**丸ごと入れ替えたあと**（`store.replaced()`
  ＝復元・すべて削除・サンプル・写しから戻す）。割合では訊かない——欄の既定が埋まる版を出すと全部が変わって見えるので。
- 鍵：元32バイト → HKDF で中身（AES-GCM、AAD は棚と記録のハッシュ）と名前（HMAC）。中身には素の棚と鍵も入れる（ハッシュからは戻せない）。
  元は `kaimono-note-sync` と Dropbox の `sync-key.json`（`"add"` で一度だけ。先に別の鍵があれば止めて点）。合言葉（ROOM_SETUP）も端末が作る。
- 影のあいだは書くのが一台なので、版が違えば今の版の上に送り直す（三方は段4）。送り待ちは一件に一つ、送りかけた操作は中身を変えない。
- 照らす：一日に一度、部屋を全部取って版を突き合わせ、一件を開いて読み比べる（残すのは数だけ。`status().checks`）。
- 点：切られた・古い版・鍵が二つ・3日送れない・照らしてずれ。

## 機能ごとの決まり

| 記録 | 鍵 | 合わせ方 |
|---|---|---|
| 買うもの（品物・店・分類） | id | 欄ごと。同じ品物の未チェックが二つあれば一つに寄せる（受け箱の取り込みと同じ） |
| やること | id | 欄ごと（題・メモは文の三方）。くり返し：済みの写し（`trace`）は「元＋その回の日」で一つに、`due` は進んだほうへ。限界：閉じた iPhone の「閉じていても鳴る」時刻は、iPhone を開くまで前のまま（中継所に触れない） |
| 日記 `archive.days` | 日付 | 時刻の行で一件ずつに分けて三方。同じ一件を両方で直したら両方残す（10月31日の決まり） |
| daily の積み上げ・からだ | id・日付 | 欄ごと |
| 問いの元・絵の言い換え・覚えた分類 | 鍵 | 欄ごと |

## 長く持つ（50年）

- どの置き場にも50年の保証は無い（Cloudflare・Dropbox・GitHub・Safari）。**部屋は作り直せる写し**：正は各端末と Dropbox の控え、
  出口は JSON と .md。部屋の決まりは小さく保ち、Cloudflare だけの機能に寄せない（ほかの SQLite の置き場へ移せる形）。よその同期の部品は使わない。
- 配る住所（GitHub Pages）を移す日も、部屋があれば新しい住所は「新しい端末」として取ってくるだけ（今は控えから戻す移し替え）。
- 量：部屋は一つで 1GB（有料 10GB）まで。字だけなら数十年分でも収まる。履歴は間引く（巻き戻しは30日）。
  新しい端末の最初の取り込みは量に比例する——新しい年から取る。
- 年に一度、端末の外に書き出す（年の本・書き出し）。
