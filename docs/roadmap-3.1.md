体重の「重く出た」は、半分は曜日の揺れ。揺れを事実として言えば、責める読み方を減らせる。言うのは R13 の確かめを
通ったときだけ。原因は言わない。

### S1 iOS 27 で送りが跳ねないか（利用者の手）

- なぜ：Safari 27 でスクロールの錨が入った。試験の Chromium には前からあるので、試験が通っても iPhone だけ動きが変わりうる。
  手で送りを戻している所と錨が二重に効くと、跳ねる。
- 見ること（`docs/iphone-check.md` に足す形で）：ノートで長い文を打ちながら改行・貼りつけ／daily の記録の紙で打つ／
  買うものの「今日買ったもの」の束を開く・閉じる／やることの「これから」の畳みを開く・閉じる／暦を払う。
  **見ていた行が動かないか**。
- 跳ねたら：その器だけに `overflow-anchor: none`（送る器は `scrollerOf()`）。全体には付けない——錨で良くなる所もある。
- やったこと（10月9日）：iPhone の結果が届かないまま、試験で代わりに確かめた。`tests/scroll-anchor.js` が五か所を
  「錨あり」と「錨なし」（`lib.js` の `noAnchor`＝iOS 26 までと同じ）の二通りで同じ手順だけ動かし、見ていた行の位置
  （終わり・毎フレームの最大のずれ）と、アプリが書いた送り（`scrollTop`・`scrollTo` ほか）を比べる。二十の手順すべて同じ。
  送りを書き直す所は、どれも「今の位置を測ってから直す」か「控えた値へ戻す」で、錨が先に動いても結果が変わらない作り。
  書く値まで同じなので、錨が動いたぶんを JS が打ち消している場面も無い（あれば Safari で二重に効きうる）。
  器には何も付けていない。`KN_NO_ANCHOR=1` で note-typing・shop-tuck・shelf・day-swipe・notes・fit-fields も錨なしで通した。
  届かない所：WebKit の錨そのものは試験で回せない（入っているのは Chromium だけ）。跳ねたと言われたら、その器だけ直す。

### S2 伸びる欄を CSS で

- なぜ：traps の「伸びる欄を測るために縮めない」は、JS で高さを測る作りから出た罠（打つたびに頭へ飛んだ）。
  `field-sizing: content` なら欄が中身に合わせて自分で伸び、測らないので罠そのものが消える。
- 何を：`@supports (field-sizing: content)` のときだけ、伸びる欄に `field-sizing: content` と上下の限り
  （`min-height`・`max-height`）を付け、JS の測り直しを飛ばす。効かない端末は今の JS のまま。
- 先に：`scrollHeight` を使う23か所（screen-todo 8・screen-diet 5・screen-notes 4・app 3・pull-refresh 2・screen-archive 1）の
  うち、**伸びる欄のための所だけ**を選ぶ（残りは送りの計算なので触らない）。
- 試験：試験の Chromium は対応しているので、新しい道を通る。今の JS の道は、`@supports` を偽にして一度回す。
- 厳密に言うと：Safari 26.2 からというのは二次情報（WebKit の 26.2 の記事は開けていない）。作る前に iPhone で
  `CSS.supports("field-sizing", "content")` を一度見る。
- やったこと（10月9日）：伸びる欄は四つ（やることのメモ `growMemo`・食事の枠 `grow`・ノートの題 `growTitle`・本文
  `grow`）。残り19か所は送りの計算で触っていない。効くかは `KN.util.fitFields` で一度だけ見て html に `fit-fields`、
  CSS は `@supports` の中でそれが付いたときだけ（components.css の `.grow-field`）——JS と CSS が食い違わない。
  上の限りは置かなかった（今も無い。伸びた先は紙が送る）。下の限りは今と同じ（メモは二行ぶん `calc(2lh + 27px)`、
  枠は38px、本文は38vh）。今までの JS は枠線ぶん（枠は上下1px）短く書いていたので、効く端末では枠がそのぶん高い。
  試験：`tests/fit-fields.js` が二つの道を並べて比べる（JS の道では長いメモの下で打つと頭へ飛ぶのも出る）。
  `KN_NO_FIT=1` で note-typing・notes・done-time も JS の道で通した。

### S3 起動の固まりを iOS 27 で測り直す（利用者の手）

- なぜ：R14（起動の固まり。9月の実測で約1秒、iOS 側の起動を含む）は見送ったまま。その後、立ち上げのタブは daily から
  tasks に変わり（10月3日）、Safari 27 ではウェブアプリの読み込みと JS が速くなったと報じられている。
- 何を：R14 と同じ測り方で一度。縮んでいれば R14 を閉じる。縮んでいなければ見送りのまま。

### S4 使っていない面を畳む（分かれ道 X10）

- なぜ：1節（feature fatigue）。使っていない面も、試験・読み込み・「どこだっけ」の分だけ重い。
- 何を：セッションが**面の一覧**（タブの中の欄・紙・札・設定の項目）を docs の見出しから作り、利用者が「使う／使わない」を付ける。
  使わないものは**既定で畳む**（設定から戻せる）。データ・設定・保存は消さない。コードから外すのは、利用者がもう一度
  「外して」と言ったときだけ。
- 厳密に言うと：アプリの中で使った回数を数える案は採らない（利用者を数えることになり、「数えない」とぶつかる）。訊くほうが安い。

### K1 祝日

- なぜ：暦は日曜を赤み・土曜を藍で塗る（`cal-grid.js` の `is-sun`・`is-sat`）のに、祝日はどこにも無い
  （コードにも docs にも「祝日」の字が一つも無い）。祝日が平日の色のままなのは、日本の暦として事実と違う。
- 何を：`js/holiday.js`（**新しい .js は3か所に登録**）でその年の祝日を計算する：決まった日・ハッピーマンデー・
  春分の日と秋分の日（`season.js` の黄経0°・180°を含む日。暦要項と同じ定め方）・振替休日・国民の休日。
  暦では日曜と同じ色。日の帯（`dayTitleBar`）か季節のひとことの行に、名前を小さく（どちらにするかは見比べで）。
- データ：なし（毎回計算。保存しない）。
- 試験：`tests/holiday.js` を新しく。2025〜2027年の全部を内閣府の一覧と照らす（値は試験の中に書く。通信しない）。
  境目：国民の休日（2026年9月22日）・日曜に当たった春分の日の振替（2027年3月22日）。
- 厳密に言うと：法が変われば計算も変わる。過去の特例（2019年の即位・2020〜21年の五輪の移動）は小さな表で持つ。
  先の年は今の法のまま。祝日は休みとは限らないので、くり返しの用事は動かさない。
- **作ったもの（10月9日）**：名前は daily の季節のひとことの行（K2 と同じ並び）。上の帯は、三画面で一つ・
  題の字を試験が読むので変えていない（見比べは作っていない。帯にも出すなら、そこから）。決めごとは
  calendar-swipe.md の「祝日は日曜と同じ色」と daily.md の「季節のひとこと」へ。

### K2 雑節・節句を季節のひとことに

- なぜ：くらしのこよみは、候の言葉に暮らしの行事を添える。季節のひとこと（R2）は節気と候の二行だけ。
- 何を：その日に当たるときだけ、三行目に一つ（「雑節　八十八夜」「節句　七夕」の形。今の二行と同じ並び）：
  節分（立春の前日）・彼岸の入りと明け（春分・秋分の3日前と後）・八十八夜（立春から数えて88日目）・入梅（黄経80°）・
  半夏生（100°）・土用の入り（27°・117°・207°・297°）・二百十日（立春から数えて210日目）・五節句（1/7・3/3・5/5・7/7・9/9）。
- 計算は `season.js` の黄経と日付から。表は要らない。新しいスイッチは作らない（今の「季節のひとこと」に含める）。
- 試験：2026・2027年を暦要項の雑節と照らす（値は試験に書く）。daily の禁止語に当たらないこと（`daily-rules.js`）。
- 厳密に言うと：土用の丑の日は日の十二支が要る。入れるなら、基準の日を公表の暦で確かめてから。
- **作ったもの（10月9日）**：暦要項の頁はこの環境から開けなかった。数えて決まるもの（節分・彼岸・八十八夜・
  二百十日）は節気の日（tests/season.js が暦要項と照らしている）から日付で、黄経で決まるもの（入梅・半夏生・
  土用の入り）は候の境目と四立の間で試験した。

### K3 見直す日を、次の節気の初日に揃える（分かれ道 X11）

- なぜ：区切りの日には、やり直す気が起きやすい（Dai ほか 2014）。B1 の見直す日（これから＝2週間後・いつか＝1か月後）は
  日がばらばらに来る。節気は約15日ごと＝2週間とほぼ同じ間隔なので、揃えると**見直しが同じ日にまとまる**。
- 何を：設定に「見直す日を節気に揃える」（既定はオフ＝今のまま）。オンのとき、**新しく付ける**見直す日だけ
  「2週間（いつかは1か月）を過ぎた最初の節気の初日」に。付いている見直す日は書き換えない。
- データ：設定に一つ（`reconcile()` の既定 false）。
- 厳密に言うと：研究の区切りは週・月・年の初め・誕生日・祝日で、節気は確かめられていない。季節の暦に親しんで
  いる人には区切りに見える、という見立て。
- やったこと（10月9日）：tasks の「見直す日」の行と同じカードにスイッチ「節気の初日に揃える」（`settings.reviewSekki`、
  `reconcile()` で true 以外は false）。揃えるのは `store.reviewFrom` の一か所——これから・待つ・いつかの三つとも、
  日数（設定の札）を過ぎた最初の節気の初日（ちょうど初日ならその日。`KN.season.sekkiFrom`、境目は節気の行と同じ）。
  待つ（1週）も揃えた：揃えるのは見直しを同じ日にまとめるためで、待つだけばらばらだと意味が薄い。「後日計画する」で
  暦から選んだ日・付いている日・読むときの `reviewOn` は動かさない。オンのあいだ、スイッチの下にいま入れたら付く日を一行
  （「これから 10/23・待つ 10/23・いつか 11/7」）——試さなくても、効き方が見える。試験は `tests/shelf.js`。

### K4 旬の印（分かれ道 X12）

- なぜ：くらしのこよみの芯は旬。くらしノートには品物の絵の辞書と値段の推移があり、旬は値段の上下とも重なる。
- 何を：野菜・果物・魚の辞書の鍵に、旬の月の小さな表をコードに持つ。品物の紙（`product-sheet.js`）に「旬 9〜10月」と
  事実を一行。行の絵には印を付けない（行を飾らない）。
- 出典：旬は地域と年で揺れる。公の案内（農林水産省ほか）と照らし、概数として持つ。
- 借りない：「旬だから買いましょう」の提案・献立。

### J1 体重の曜日の揺れを、気づいたことに

- なぜ：体重は週末に増え平日に減るのが、ふつうの揺れ（Turicchi ほか 2020）。月曜に量って驚くのは、揺れを知らないから。
  気づいたことは曜日を見ていない（`diet.js` の週は「今日から7日ずつ」で、曜日では切らない）。
- 何を：直近12週の朝の体重で、**曜日ごとの、7日平均からのずれ**を出す。いちばん重い曜日と軽い曜日の差が、
  前半と後半（R13）のどちらでも同じ向きで、どの曜日も3件以上のときだけ、事実だけを一行
  （「月曜の朝は、金曜より 0.4kg ほど重く出る（12週）」）。原因（食べ過ぎ・お酒）は言わない。
- データ：なし（読むだけ）。
- 厳密に言うと：7日平均からのずれで見ないと、減っている時期は「週の初めが重い」が自然に出てしまう（前の日ほど重いから）。
  量りの刻みに近い差（案：0.2kg 未満）は言わない。閾値は試験の記録で決める。

### J2 和文と数字のあいだ（分かれ道 X13）

- なぜ：Safari は18.4から `text-autospace` を持つが、既定はオフ。くらしノートは数字まじりの短い字が多い。
  和文と英数字のあいだに 1/8 字ほど空くと、数字が拾いやすくなる。
- 何を：`body` に `text-autospace: normal` を一行。手で入れた空白はそのまま（二重には空かない）。
- 確かめ：幅の決まった所（丸薬・札・ドラム・帯）で字があふれないか、390×844・375×667（`tests/feel-3.js`）。
  画面が大きく変わるものは先に見比べ、の決まりどおり、前と後の画像を利用者が選ぶ。

## 6. やらないこと（今回の調べで新しく出たもの）

| やらないこと | 理由 |
|---|---|
| 今ある小窓を anchor positioning に作り替える | 動いているものを作り替えない。新しく作る小窓だけ |
| `text-spacing-trim`（約物の詰め） | Safari 27 でも未対応 |
| 祝日の表を取りに行く（内閣府の CSV） | 通信。計算で出せる |
| 確かさを星や確率で見せる（Exist） | 点数に見える。言えるときだけ言う、のまま |
| 型を自分で作る記録帳（日々のログ） | daily は写さず引く。入れ物を増やさない |
| 家計簿（合計・予算） | 買うものの合計金額は意図して外してある（improvements.md） |
| ローリングストック・備えの数の管理 | 賞味期限の管理と同じ（書く手間と知らせ）。防災の日などのくり返しの用事で足りる |
| 月の満ち欠け・十五夜（旧暦） | 旧暦は朔と中気の計算で年の端が難しい。飾りが増える。季節の絵と空で足りている |
| 年末年始・連休の「増えた」を言う | 採点に寄る。曜日の揺れ（J1）のような、毎週くり返す事実だけにする |
| 使った回数をアプリの中で数える | 利用者を数えることになる。S4 は訊いて決める |

## 7. 進め方（制限の節約）

- 1セッション1項目（K1＋K2 は一つで）。終わったら4節の表の状態を書き換えて、main まで流す。
- S1・S3 は利用者の手だけ。セッションは要らない（結果だけ次のセッションに伝える）。
- 次のセッションに貼る文の型：

```
docs/roadmap-3.1.md の J1 をやって。この文書は4節の表とその項目の節だけ、docs は表の
「先に読む docs」だけ読む。データの形は変えない。触った画面の試験と daily-rules.js を通して、
main まで流して。終わったら roadmap-3.1.md の状態を書き換える。
```
