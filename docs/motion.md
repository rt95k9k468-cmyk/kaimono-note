本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも

### 動きの辞書（V4・2026年10月4日）

**新しい動きは、この表に行を足してから作る**（何が起きたから動くのかを、先に一行で言う）。
`--m-*` を足したらここにも行を——`tests/motion-dict.js` が base.css の名前と照らす。

種類は五つ。何が起きたかを言えない動きは作らない。

| 種類 | 何を言う | 例 |
|---|---|---|
| 押す | 押しているあいだの返事 | 帯の席がふくらむ・＋・✓ |
| 状態 | 状態が変わった | ✓が描かれる・★・選んだ札 |
| 移る | 見ている所が移った | タブ・日の横払い・設定へ |
| 変わる | 同じ物が別の形・場所へ | 行→詳細の紙・カード→紙・連れ→停留所 |
| 歩く | 時間が進んだ（道の人だけ） | 四歩・追いつく歩き |

「外」の列＝`transform`（`scale`/`translate`/`rotate` を含む）と `opacity` の**ほか**に動かすもの。
**重**＝組み直しが走る（幅・高さ・位置・余白）、**塗**＝描き直しだけ（色・影・切り抜き・ぼかし・SVG の形）。
印は直す約束ではない——直すのは触るときか V25。重を先に見る。
「減らす」＝動きを減らす設定のとき。**CSS の動きは base.css の一括で瞬時**（終わりの姿だけ出る）。
JS の動き（Web Animations・毎フレーム）にはその一括が効かないので、各々が `still()` を見る。

### 動きは、名前で持つ（`--m-*` / 曲線）

**速さを数字で書かない。** CSS の `transition` / `animation` に生の秒数を
置くと、同じ出来事が場所ごとに違う速さで返るようになる——実際にそうなって
いて、「押した」が `.08` / `.1` / `.12` / `.14` 秒の四通り、「状態が変わった」が
三通り、「画面が変わる」が三通りあった（**リテラル60か所**）。いまは **0か所**。

速さの名前（`css/base.css` の motion の節）：

| | |
|---|---|
| `--m-press` | 指の下で起きること |
| `--m-state` | 押した**あと**、札や欄が新しい姿に落ち着く |
| `--m-check` / `--m-strike` / `--m-number` | 印が付く／取り消し線／数が変わる |
| `--m-add` / `--m-delete` | 増える・減る（減るほうが速い） |
| `--m-reorder` | **位置が変わる**（よける・暦の輪が滑る・電卓の上下） |
| `--m-settle` | 組み直したあと、行がもといた場所から滑って収まる（FLIP）。閉じた紙の頭の丸薬が行へ帰るのも同じ（`ui.js` の `morphBack`） |
| `--m-sheet-open` / `--m-sheet-close` / `--m-sheet-grow` / `--m-sheet-home` | 紙が開く／閉じる／＋から育つ／＋へ帰る |
| `--m-nav` / `--m-push` | 席を移る／引き出しが押しのける |
| `--m-marks` | 席を移るとき暦の印を替える。出ていく印が半ばまで薄れたら入ってくる印が出はじめる（**半分ずつ重ねて**一回半。`head.js` の `crossMarks`） |
| `--m-swipe` | 払って、指を離してから行き先まで滑る |
| `--m-roll` / `--m-roll-step` | 題の日付が入れ替わる（変わった字だけが転がる。年・月・日・曜日の順に step ずつ遅らせる。`util.js` の `rollText`、docs/calendar-swipe.md） |
| `--m-to-top` | 上のきわ・題を押して上へ戻る。道のりの対数で 0.7〜1.6倍、6乗の ease-out で最後の最後をうんと緩める。跳ね返りは試して外した（2026年10月4日。`app.js` の `glideToTop`、`tests/top-tap.js`） |
| `--m-grow` | **器そのもの**が伸び縮みする（暦・帯・欄） |
| `--m-spark` / `--m-flash` | 一度だけ出る光／一度だけ見てほしい |
| `--m-walk` | 道の人の一歩（やることを開いたとき、前に見た点から「いま」まで四歩で追いついて止まる。台形の上がり下がりを足して全体 1.5s。docs/todo-timeline.md の「歩く」） |
| `--m-fill` | 開いたとき、輪が 0 から満ちる（health の四つの輪と真ん中の数。超えた日は 1.4 倍。下の「開いたとき、満ちる」） |
| `--m-draw` | 開いたとき、線が左から引かれる（体重の線） |
| `--m-stagger` | 並んだものを一つずつずらして始める間（四つの輪が左から順に） |
| `--m-poke` | 押した絵が一度だけ、その絵らしく応える（席の絵・歯車。docs/tabbar.md の「押した席の絵が応える」） |
| `--m-success` / `--m-warn` | うまくいった／気をつけて |

曲線も同じ（`--ease` / `--ease-out` / `--ease-in` / `--spring` / `--push-e` /
`--ease-glide` / `--ease-settle`）。**出てくるものは `--ease-out`、去るものは
`--ease-in`。** 四つの面の指定が全部 `--ease-out` で、去る面が「出てくる動き」で
出ていっていた。

- **開く速さと閉じる速さは、class の付け外しで分ける。** 素の `.sheet` に
  閉じる速さ、`.sheet.is-open` に開く速さ。`--m-sheet-close` は用意だけして
  **誰も読んでいなかった**——紙は開くのも閉じるのも同じ .3s だった。
- **JS 側に数字を二重に持たない。** `KN.motion.ms("--m-nav")` と
  `KN.motion.ease("--push-e")` が CSS から読む。`app.js` の `SLIDE_MS`/`FACE_MS`、
  `ui.js` の閉じる待ち時間、`edge-back.js` の曲線は、もうここを通る。
  `edge-back.js` は `"cubic-bezier(.32,.72,0,1)"` を**文字列でべた書き**していて、
  それは `--push-e` と同じ数だった（`--push-p` / `PARALLAX` と同じ罠）。
- **`--m-reorder` は .32s → .24s に直した。** 書いてあったが**どこからも読まれて
  おらず**、実際の CSS は .24s を直に書いていた。名前を現実に合わせた側。
- **`KN.ui.flipRows` は、行のある三画面ぜんぶが通る**（買うもの・daily・
  **やること**）。組み直す前に行の居場所を測り、組み終わってから `settle()` を
  呼ぶと、動いた行が**もといた場所から**滑ってくる。新顔だけが `is-arriving`
  で名乗る。
  - やることは長いあいだ**呼んでいませんでした**——`.tl-row` には前から
    `data-flip` が付いていたのに、見る人が居なかった（目印だけあって、
    使われていない。`--m-sheet-close` や `--m-reorder` と同じ形の見落とし）。
    時間割に一件足すと、その下の行がいっせいに瞬間移動していたのはこれ。
  - **丸ごと入れ替わるときは、向こうが見送ります**（新顔が半分を超えたら
    「編集ではなく行き先の変更」）。日を替えたときに全部の行が「もといた
    場所」から飛んでくると、別の日の行が滑ってきたように見えるので。
    実測：一件足すと 8 回ぶん置き直され、暦で昨日へ移ると 0 回。
  - 紙を横に払って日を替える道は、そもそも組み直しを通らない（`adopt`）ので
    ここには来ません。

### 指を離したあとの滑りは、一本から出す（`KN.motion.glide`）

**決まった時間で滑らせない。** day-swipe 200ms・cal-swipe 200ms・edge-back
260ms・紙の面 280ms と、四か所が自分の数を持っていた。指の速さ（`vx`）は
計算してはいたが、**「行くか戻るか」の真偽にしか使われていなかった**
——だから 27px で離すと 363px を 200ms で駆け抜け、380px まで引いて離すと
10px を 200ms かけて、**同じ時間**。前者は弾かれたように、後者はもたついて
見える。

`KN.motion.glide(dist, v, {span, base})` が `{ms, ease}` を返す。決めるのは二つ：

- **時間** … 勢いがあれば「その速さで行けば着く時間」（`dist / v`）、無ければ
  **残りの道のりに比例**（`span` に対する割合）。短いほうを採り、`base` の
  0.45〜1.6倍で頭打ち。実測：27px→126ms、363px→261ms、363px を 2.5px/ms で
  払えば 145ms。
- **曲線** … **出だしの傾きを、離したときの指の速さに合わせる**。ベジェの
  初速は `p1y/p1x` なので、`p1x` を 0.25 に固定して `p1y` を `v·t/d` に
  合わせる。これが「勢いを引き継ぐ」の正体で、`--ease-out` を一律に当てて
  いたころは、ゆっくり離しても出だしだけ速く、指の動きと繋がらなかった。

決めごと：

- **`dist` も `v` も符号つきで渡す。** 向きが合っているかは glide が見る
  ——呼ぶ側に掛け算させると、いつか符号を落とす日が来る。
- **`span` は必ず渡すこと。** 渡さないと道のりの割合がいつも 1 になり、
  近くで離しても遠くと同じ時間になる。
- **`--m-swipe` が唯一のつまみ。** 上下の頭打ちもそこから出るので、「全体に
  もう少し速く」はこの一行だけ。
- 動きを減らす設定では `ms: 0` を返す。呼ぶ側は `g.ms ? … : ""` で足りる。

**端の向こうは `KN.motion.rubber(over, limit)`。** 行けない向きに引いた指も、
ついてはくるが進まない——止めてしまうと、そこで指と絵が切れる。実測：
-20→-14.3、-100→-33.3、-400→-44.4（limit 50 を越えない）。

### iPhone で、主な押すものを震わせる（`motion.js` の FEEL・C1）

2026年9月27日。iOS の Safari は `navigator.vibrate` を持たない。iOS 18 から、
`<input type="checkbox" switch>`（切り替えのつまみ）は**指で押されて**切り替わると
端末を軽く震わせる。

- **押したことにする（`label.click()`）では震えない。** 最初の版はそうしていて、
  実機で震えなかった。WebKit は click が本物か（`isTrusted`）を見ていて、本物で
  ないときは震わせない（`CheckboxInputType.cpp` の `willDispatchClick` →
  `state.trusted` のときだけ `performSwitchVisuallyOnAnimation` → 触覚。`trusted` は
  `EventDispatcher.cpp` の `event.isTrusted()`。2026年9月に WebKit のソースで確認）。
- だから**指が本当につまみを押す**ようにする：押すもの（button）の中に、見えない
  つまみを同じ大きさで重ねる（`.feel-switch`）。指はつまみを押し（震える）、その
  click は button へ上がって、いつもの動きが走る。**済ませる丸で、実機で震えた**
  （利用者が確かめた）。利用者の希望で、主な押すものへ広げた。
- **どれに重ねるかは `motion.js` の `FEEL` の一覧だけが決める。** 画面に出てきた
  ものへ、見張り（`MutationObserver`）が付けて回る——画面ごとに呼ぶと、組み直しの
  たびに付け忘れが生まれるので。いまの一覧：済ませる丸（手順・買うものも）・★・
  `btn-primary`（保存・追加・記録する）・`btn-danger`（消す・置き換える）・＋・＋から
  出る行き先・数字キー・「入れる」（そろそろ切れそう）。
- **一覧に入れてはいけないもの**：
  - **送る面の上の広いもの**（行・カード・札の並び）。iPhone は、つまみの上で
    始まった指を「つまみを動かす」と受け取り、**画面を送らない**（WebKit は
    つまみの touchstart を自分で受け取る＝`defaultHandled`。WebKit の汎用の道では
    それが「呑んだ」扱いになる。iOS の道は非公開だが同じと見ておく）。小さな丸や
    ★のように、送る指がめったに乗らないものだけにする。
  - **押したまま滑らせるもの**（下の帯の席・掴み手・並べ替え）。つまみは**指を
    離した場所に関係なく**「押した」と受け取る（touchend で click を出す）ので、
    帯の「席の外で離せば変わらない」が崩れる。
  - **a 要素**。中のつまみが押されると、リンクのほうは開かない（一度の click で
    動くのは、いちばん内側の一つだけ）。
  - **form の送信ボタン**（`type="submit"` で form を持つもの）。同じ理由で送信が
    起きなくなる——商品の紙の値段の「追加」（`product-sheet.js`）がこれで、
    `btn-primary` なので一覧に当たる。`attach` が一覧にかかわらず外す。
- つまみは見えない（opacity 0）が**描かれている**こと——WebKit は描かれていない
  つまみの指を受け取らない（`handleTouchEvent` が `renderer()` を見る）。
  z-index で `::after`（指の的）より上へ。つまみは button の枠の中だけで、広げて
  ある指の的（44px）までは広げない。広げた的を押したときは、動くが震えない。
  済ませる丸だけは、見えている輪（縁 2px）まで覆う。
- button が `position: static` なら、付けるときに `relative` を足す（読んでから
  まとめて書く）。押せない button（`disabled`）は `pointer-events: none` が子へ
  継がれるので、つまみも押されない（震えない）。
- 一度の指で click が二度来ても、button へは一度だけ。数えるのは**指を置いた回数**
  （`pointerdown`）——時間で切ると、数字キーの速い連打を落とす。
- 付けるのは Apple の指で触る端末で、`navigator.vibrate` が無いときだけ。ほかの
  端末の DOM は変えない。読み上げにも Tab にも出さない（button が持つ）。
- **送った指は押したことにしない**（2026年9月27日、実機で踏んだ）。iPhone のつまみは、
  上下に送られても指を離したところで click を出す——★や丸の上から送ると、離した
  瞬間に押されていた。ふつうの button ならブラウザが決めることを、つまみが自分で
  決める（`makeSwitch`）：指が `SLOP`（10px）を越えて動いた（touchmove）・何かが
  送られた（`scroll` は泡立たないので window の capture で聞く）・pointercancel の
  どれか一つでも立てば、その指の click は button へ渡さない。印を一つに頼らないのは、
  iPhone でどれが来るかを試験の Chromium では確かめられないから。離した瞬間の震え
  そのものは click の前に鳴るので、ページからは止められないかもしれない。
- **つまみを付けた button は、click で決めること。pointerup で決めない。**
  pointerup で store を書き換えると、その場で行ごと描き直され、つまみが**震える前に
  DOM から外れる**（iPhone のつまみは、指を離したあとの処理で震えて click を出す）。
  手順の丸だけ震えなかったのはこれ（`screen-todo.js`。docs/todo-items.md）。
  試験は `tests/feel-touch.js`：指を受けたつまみが、DOM に居るまま click を出すか。
- 持ち上げて「置いた」・払って「閉じた」は**震わせられない**（そこには指で押す
  つまみが無い）。
- C4（済ませたときの手ごたえ）の見た目——光る・線・丸がひと回り・落ちる——は
  前からある。

### 開いたとき、満ちる（`KN.motion.arrive`・`is-m-arrive`）

2026年9月29日・利用者の声「tasks の人のアニメーションがとてもいい。health の円グラフが、
タブを開いたときにグンとメーターが満ちるように」。道の人が歩く（docs/todo-timeline.md の
「歩く」）と同じ二つの入口——**タブを開いた一拍**（`app.js` の `show`）と**アプリへ戻って
きたとき**（`visibilitychange`・bfcache の `pageshow`）——で、画面に `is-m-arrive` を
しばらく付ける。試験は `tests/arrive.js`。

- **何が動くかは CSS が決める**（`.is-m-arrive .diet-ma7` など）。JS が持つのは時計だけ。
  CSS では揃えられないもの（輪と数）だけ、`KN.motion.onArrive(fn)` で JS が手を出す。
  画面ごとに「開いたら〜を動かす」を書くと、組み直しのたびに誰が何を動かしたかが散らばる。
  新しく「開いたときに動くもの」を足すときは、CSS に `.is-m-arrive …` を一つ書けば済む
  （長さが `--m-fill * 1.4` / `--m-draw` を超えるなら `arrive` の外す時刻も延ばすこと）。
- **付けているあいだだけ動く。** 開いたあとの組み直し（保存・取り込み）では動かない——
  保存のたびに輪が満ち直すと、動きが「開いた」ではなく「何か起きた」を言ってしまう。
  付けているあいだに組み直された中身は、そのとき頭から始まる（まれに輪が二度満ちる。許容）。
- **輪と数は、JS の一つの時計で進める**（`KN.motion.onArrive` に health が名乗る。
  screen-diet.js の `fillRings`）。毎フレーム、輪の `--ring-p`（**周**で 0〜2）と真ん中の
  `data-show` を**同じ進み具合**から書く。曲線は `KN.motion.curve("--ease-out")`
  （CSS の cubic-bezier を JS で引く。数字を二重に持たない）。書く相手は輪そのもの
  （`:root` ではない）。毎フレーム画面の中から輪を引き直すので、途中で組み直されても
  新しい輪がいまの進み具合から続く。
  - **一度 CSS だけで作って、実機で二つ崩れた**（2026年9月29日・利用者の声）。①超えた日を
    「一周ぶん」と「超えたぶん」の二つの keyframes の区切りにしていて、曲線は**区切りごとに**
    掛かるので **100% で一度止まった**。②数を `@property` の整数＋`counter()` で数えていて、
    iPhone の Safari は途中を描き直さず、**数だけ最後に「パン」と出た**。
  - いまは超えた日も 0→1.35 周の**一本の道**（一周目 `min(p, 1)`・二周目 `max(p − 1, 0)` を
    一つの `conic-gradient` で。超えていない輪は二周目の幅が 0 なので同じ式）。超えた日は
    道が長いぶん `--m-fill` の 1.4 倍。数はその道の上の位置から出すので、ずれようがない。
  - `@property` は使わなくなった（登録できないブラウザでも同じに動く）。
- **数は字を書き換えずに数え上げる。** 本当の字を `-webkit-text-fill-color: transparent` にして、
  上に `attr(data-show)` を重ねるだけ。**textContent はいつも本当の数**（読み上げも、
  字を読む試験——`tests/diet.js` の体重など——も、途中の数を拾わない）。数え上げられるのは
  「整数＋単位一つ」（`85%`・`12g`）だけで、それ以外（小数）はそのまま出す（`countUp`）。
- **今日の食事の帯は、入れものごと左から伸びる**（2026年9月29日・利用者の声「棒グラフ全体が
  伸びていく中で、その比率に合わせて朝食や昼食なども伸びていく」）。区分を一つの入れもの
  （`.diet-stack-fill`、幅は摂取の割合、中の区分は入れものに対する割合）に入れ、入れものを
  `scale: 0 1` → 1。区分は**いつも最後の比率のまま**一緒に伸びる。輪と同じ `--m-fill` /
  `--ease-out`。
  - 一度は区分ごとに順に伸ばし、区切りで一瞬ゆるむ曲線を付けた——**遅く見え**、やめた。
  - 超えた日の赤い縁（帯の inset の影）は外した（利用者が選んだ）。伸びる途中だけ空の帯を
    枠が囲み、止まった帯では区分（100%）の下に隠れて一度も見えていなかった。
- **線は `pathLength="1"` で引く。** 実の長さを測らずに `stroke-dasharray: 1 1` と
  `stroke-dashoffset 1 → 0` で済む。量った点は、線がそこへ来たころに出る（遅れは左からの
  位置 `--f` × `--m-draw` × 0.4——`--ease-out` の線は時間の 4 割で道のりの 9 割まで来る）。
  今日の点だけ最後に弾む。
- 動きを減らす設定では付けない（`KN.motion.still()`）。

### ✓は描かれる・空の絵は咲く（2026年9月29日）

- **済ませる丸の✓は、ペンで引くように左から出る**（screens.css の「✓は描かれる」）。✓は塗りの
  形なので線の長さでは引けず、左から開く幕（`clip-path: inset()`）で見せる。丸が満ちるのを
  追って `--m-state` の半分遅れて始まる。`inset()` どうしでないと途中が無いので、既定は
  `inset(0)`、閉じるのは `aria-checked="false"` のときだけ（mixed の −・↻ は幕の外）。
  買うものの丸も、押したそばから `aria-checked="true"` にして満たす（やることと同じ「指には
  すぐ応える」）。
- **空の絵は、開いたとき咲いて一度跳ねる**（components.css、`is-m-arrive` のあいだだけ）。
- ＋から出る行き先の遅れを `62ms` の直書きから `--m-stagger` へ。

### 物から物への変形は View Transitions を使わない（V14・2026年10月4日）

`document.startViewTransition` を、カード→ノートの紙（`growCard`）で今の作りと比べて**採らなかった**。
変形（V15〜V17・V19）は今の作り——写し（`cardGhost`・`pillGhost`）と WAAPI、行き先を毎フレーム
探し直す（`morphBack`・`shrinkCard`）——で作る。
- **重い**：CPU 4倍・3回の中央値で、今の作り 49フレーム・長い（20ms 超）5・95%点 33.3ms ／
  View Transitions 63・10・50.0ms（画面ぜんぶの写しを撮って重ねるので）。
- **動いているあいだ指が届かない**：写しが上に被さり、どこを押しても `html` に当たる。今の作りは
  育つ途中でも下へ払えば、その場所から帰る（notes.md の段4.3）。
- **行き先を追えない**：写しは一度撮ったら決まる。閉じると一覧が組み直され、行もカードも FLIP で
  滑ってくる——今は毎フレーム探し直して終わりの形を書き換えている（`setKeyframes`）。
- 道（V8）は SVG の中なので、もとから使えない。
- 試した台本はリポジトリに入れていない（`frame-pace.js` の測り方で、押す所を
  `startViewTransition` で包んだだけ）。Chromium の数字で、iPhone とは別。
