# やること：手順・長期タスク・期限・くり返し・打った字から読む

CLAUDE.md から見出しごと移した、詳しい決めごと（2026年9月26日）。
本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも
踏む罠は CLAUDE.md にある。**新しい決めごとは、ここ（該当する docs）に書く。**

### 手順（サブタスク）の印は、二つとも色。分けるのは形

済ませた手順は ✓、できなかった手順は −。**どちらも基調色（`--cat`）で塗り、
印は白抜き**にします。できなかったほうを地味な灰色にしていた時期がありますが、
それは「やらなかったことは薄い」と言っているのと同じで、この画面がずっと避けて
きた採点です（済ませた用事を灰色にして縮めないのと、まったく同じ理由）。色は
「もう手をつけ終わった」ことだけを言い、どちらに終わったかは**形**が言う。

**`.check svg` は既定で `opacity: 0`** で、それを 1 に戻す決めごとは
`[aria-checked="true"]` にしかありませんでした——つまり − は、描かれてはいたが
**一度も見えていません**でした（灰色の四角だけが出ていて、「できなかった」は
色でしか言えていなかった）。`[aria-checked="mixed"]` にも同じ一行が要ります。

**手順を並べ替えるのは、詳細の紙の中**（`.sub-line` の `.sub-grip`、四本線）。
`KN.reorder.attach` に `handle` を渡すと、**押した瞬間から**持ち上がります
——長押しを待つ作りはここでは使えません。字を書く欄が並んでいる段で、欄の上で
指を止めるのは「文字の位置を決める」手つきだからです。掴むための場所を別に
置いたぶん、待たせる理由も無くなりました。三本（`list`）ではなく四本にしたのは、
メニューの三本線と紛れないため。

- 並べ替えても **store には触れません**。控えの配列（`subs`）を並べ替えて
  描き直すだけで、保存は紙の「保存」が引き受けます——**書く**のと**やる**を
  分ける、この紙の決めごとです。
- 打った字は `value` **属性**にも書き戻すこと。運んでいるあいだの控え
  （`reorder.js` の ghost）は `cloneNode` で作るので、属性を更新しないと
  控えだけが打つ前の字を出します。
- 持ち上がった行には影が付きます（`reorder.js` の決めごと）。この段の行は地を
  持っていないので、`--c-sheet` を敷いておくこと——さもないと影だけが宙に浮きます。

**時間割の手順の丸は、短いタップを click で決めます**（2026年9月27日）。pointerup で
決めていたころは、その場の描き直しで iPhone の震えるつまみが先に外れ、手順の丸だけ
震えなかった（docs/motion.md の FEEL）。長押し（0.5秒で「できなかった」）はタイマーの
まま。「同じ指の二度目の click を弾く」印（`subGestureAt`、手順の id ごと）は、
**指を置き直したとき**（pointerdown・Enter/Space の keydown）に消えます——pointerId では
見分けません。つまみの出す click は pointerId を持たないことがあり、長押しの直後の
click を通してしまうので。すぐ押し直した新しいタップは、印が消えているので通ります。

### 長期タスクと、期限（`deadline`）

時間割の下に、少し離して「長期タスク」の欄があります（`somedaySection`）。
**`due` を持たない用事**がここに集まります——やると決めているが、いつやるかは
決めていないもの。

- **時刻も、時刻の線も出しません。** 時刻が無いのだから、書けば嘘になります。
  時刻の列は `visibility: hidden` で**空けたまま**（詰めると丸の位置が上の
  時間割とずれて、運べることが伝わらない）。
- ここから時間割へ運べます。`wireDrag` は同じものを使い、`tlDrag.dayList` が
  落とし先を持ちます——長期タスクの欄には空きの行が無いので、空きを開くのも
  狙いを探すのも**その日の時間割のほう**です。
- **欄の中でも並べ替えられます**（`kind: "someday-order"`）。行の上で離すと
  その前後へ。欄の余白（行の無いところ）で離したら何もしません。
- 並びは**手で決めたもの**（`order`）です。期限の近い順には**しません**
  ——並べ替えられるようにした以上、並びの持ち主は一つ（`order`）にします。
  期限は字で見えているので、そちらまで並びを決めると同じことを二か所で
  言うことになります。急ぐものを上に置きたければ、運べば済みます。
- 詳細の紙は時間割の行と**同じもの**が開きます（`itemRow` を使い回して、
  時刻の列だけ空ける）。

`deadline` は `due` と**別の欄**です。`due` は「その日の時間割に居る」＝いつ
やるか、`deadline` は いつまでか。同じ欄で兼ねると、締め切りを書いたとたんに
その日の時間割へ入ってしまいます。持っていない古い記録は null に落ちるので、
`reconcile()` はそのまま通ります。詳細の紙では「時間」の札の下、長期タスクの
行では題のすぐ下（過ぎたものは字で「◯日すぎています」——色だけだと、色の意味を
知っている人にしか伝わらない）。

### くり返しは、先の日にも立つ（`store.fallsOn`）

くり返しの用事は記録としては一件で、`due` は「次にやる日」です。素直に
`due === day` で数えると、毎日のはずのものが一日にしか出ません。`fallsOn` は
**出す／出さないを答えるだけ**で、記録は増やしません——日ごとの控えを作ると、
済ませた印をどちらに付けるかで二重管理になります（Daily Log を「写さず引く」
ことにしたのと同じ理由）。今日から先だけ広げます。過ぎた日には済ませた跡
（trace）がもう並んでいて、そこへ生きている一件を重ねると二行になるので。

くり返しの選択肢から**毎朝・毎晩は外してあります**（時刻が書けるので、毎日との
二通りができていた）。**すでにある記録には手を付けていません**——`part:
"dawn"/"dusk"` も、それを見ている並べ替え・`plan.js` もそのままです。

### 済ませてから◯日（`repeat: "after"`・R6・2026年9月28日）

暦どおりの三つ（毎日・毎週・毎月）とは別の、四つ目のくり返し。「シーツは2週間ごと
（済ませた日から）」のように、**済ませた日から数えて**次が立つ。

- 記録は `repeat: "after"` ＋ `repeatEvery`（1〜365 の日数）。**欄を足しただけで移行なし**
  ——持っていない古い記録は `repeatEvery: null` に落ちるだけ。`after` なのに◯が無い・
  壊れているときは 7。種類を変えると◯は null に戻る。`cleanRepeat` / `cleanEvery` は
  load の道から呼ぶので **function 宣言**（TDZ）。
- `nextDue`：**今日＋◯日**（予定の日ではなく済ませた日から）。先の日を早めに済ませたら、
  やった跡（trace）も**今日**に付ける（跡と数え始めを揃える）。
- `fallsOn`：**次の日（`due`）にだけ立つ。** 先の日に「たぶんこの日」と立てると、済ませた
  日しだいで嘘になる。だから暦の先の日にも、bell の7日先の列にも、次の一回しか出ない。
- 逃したら（`rescheduleOverdue`）今日へ。赤くしない・繰り越す、は今と同じ。
- 紙：くりかえしの五つ目「済ませてから」。◯は早見（3・7・10・14・30・60・90日）と
  −／＋。**打ちこむ欄は置かない。** 詳細の行の右に「14日ごと」、行の丸の下は
  「14日ごと」、タイルは「済ませてから14日ごと」。
- くり返しなので、通知から来た紙の「あとで」は出ない（R3 と同じ）。
- when-parse：「3日ごと」「3日毎に」「2週間ごと」「2週ごと」「10日に1回／一回」を読む
  （1日ごとは毎日、1週間ごとは済ませてから7日）。**読まないもの**（誤読の表
  `tests/repeat-after.js` で決めた）：
  - **「◯日おき」**：辞書では「1日おき」は隔日＝2日ごとなのに、「10日おき」は10日ごとの
    つもりで打たれることが多い。どちらに決めても片方を黙って読み違えるので、読まずに
    題に残す（紙で選べる）。
  - **「ごと」の直後にくっついた字**（「30日ごとチャレンジ」）・**「ごとの」**（「3日ごとの
    記録をつける」は記録の中身の話かもしれない）。後ろは「に」か空き・読点・端だけ。
  - 月の「2か月ごと」（暦の毎月と日数のどちらか決まらない）・366日以上・「日ごとに」
    （数が無い）・「5分ごと」。

### 打った字から「いつ」を読む（`js/when-parse.js`）

「10:00 病院」と打てば、その日の 10:00 に「病院」が立つ。読むのは
`KN.whenParse.parse(text, {today})` ——**DOM も store も触らない純粋な部品**で、
返すのは `{title, due, time, minutes, repeat, repeatDays, repeatNth, deadline, hits}`。
**見つからなかった欄は置きません**（null と「言っていない」は別のこと。画面の側は
来た欄だけを書き換える）。読むことと決めることを分けてあるので、当たり外れは
node の表で測れます（`icon-eval.json` と同じ考えかた。道具はスクラッチに置き、
コミットしない。`js/util.js` → `js/when-parse.js` の順に読み込む）。

読む言葉：今日・明日・あさって・しあさって／N日後・N週間後・Nヶ月後／9/15・
9月15日・2026/9/15・15日／月曜・今週金曜・来週火曜・来週・週末・月末・来月末／
10:00・10時・10時半・10時30分・午前10時・午後3時・夜9時・朝7時・正午／
10:00〜11:00・10時から11時（**範囲は長さ**になる）／毎日・毎週月曜・
毎週月・金曜・毎月15日・毎月第2火曜／**3日ごと・2週間ごと・10日に1回**（済ませてから◯日。
下の「済ませてから◯日」）／**明日まで・9/15まで・今日中に・今週中に・
今月中に**（`deadline` に入る。下）／**30分・1時間・1時間半**（裸の長さ。下）。

取りかたの決めごと（**誤爆を防ぐほうが本体**です）：

- **頭かお尻のかたまりとしてだけ取る。** 真ん中は取らない——「12時の鐘を鳴らす」の
  12時は題の一部。
- **取ったあと題が空になるなら、取らない。** 「明日」だけを打った人は、題として
  そう書いています。
- **すぐ後ろに「まで・ごろ・くらい・すぎ・前・後・間・分・目」が
  くっついていたら取らない**（「10時までに起きる」）。**あいだに空きがあれば
  別の言葉**（「10:00 前田さんに電話」の前田は「前」ではない）——だから
  ここでは trim しません。
- **境目の助詞は一つまで、しかも次が仮名でないときだけ落とす。**
  「明日の会議」→「会議」、でも「明日のりを買う」「明日からあげを作る」
  「明日はやめる」は**そのまま**（落とすと語が壊れる）。そのぶん
  「3時のおやつを買う」は「のおやつを買う」になりますが、**字を失うより
  余った「の」のほうが安い**。
- **裸の「1〜4時」は昼**（3時→15:00）。時間割が扱うのは 5:00〜23:00 の一日で、
  深夜3時に用事は置きません。**「:」で書いてあればそのとおり**（10:00 は 10:00）、
  午前・午後・朝・夜・深夜が書いてあれば、そちらが勝ちます。
- **過ぎた日付は、次に来るその日**（9月13日に「9/1」なら来年の9月1日）。
  やることは「これからやる」ものなので。**昨日・一昨日は読みません**（同じ理由）。
- **毎朝・毎晩は読みません**（くり返しの選択肢から外してあるものなので）。
- 曜日を数えるとき、**「曜」「曜日」を先に落とすこと**——落とさないと
  「火曜日」の**日**を日曜として数えます（実測：火金のつもりが日火金）。
- **「明日まで」は期限（`deadline`）に入ります、やる日（`due`）ではありません。**
  「いつやるか」と「いつまでか」は別の欄なので（「長期タスクと、期限」）。
  日付を言う語（`DATE_RAW`）はそのまま使い回し、後ろに「まで／迄」が付いた
  ときだけ拾います——**日付ルールより先に試すこと**。先に裸の日付ルールが
  「明日」だけを食べると、残った「まで」が題に残ります。**時刻の「まで」
  （「10時までに起きる」）は、依然として読みません**——締め切りは日その
  ものの話で、時刻の締め切りという欄はこのアプリに無いので。
- **裸の長さ（「30分」「1時間」）は、日付・時刻・くり返し・期限のどれかと
  いっしょに打たれたときだけ読みます**（`guard`）。「10分休憩」「腕立て
  30回」のように、長さでも回数でも読める言葉が日本語には多く、単独では
  区別が付きません（実際に「10分休憩」を長さとして誤読しました）。
  「10:00 30分 ジョギング」のように、いつ・どれくらいを続けて打つ人の
  字だけを読みます。**直後に境目（空きか文字列の端）が無ければ止める**
  ことも要ります——「今日 10分休憩」の「10分」の直後に「休憩」が続くのは、
  長さではなく活動の名前の一部だからです。
- **`takeOne` の返り値には `kind` を必ず入れること。** 一度、この一行が
  抜けていて、`parse()` の `taken[hit.kind] = true`（重複防止の排他制御）が
  常に `taken[undefined] = true` を書いているだけの死んだコードでした。
  `due`・`time`・`repeat` は別に明示の if 文で `taken.date` 等を立てていた
  ので表には出ませんでしたが、`deadline`・`minutes` はこの仕組みだけに
  頼っていたため、guard も排他制御もまるごと効かず、二つ目の長さが
  無条件に上書きされる形で埋もれていました。**新しい `kind` を足すたびに、
  この経路が生きているか表で確かめること。**

紙の側（`screen-todo.js`）が持つのは、読めたものを欄へ移すところだけ：

- **移すのは、題の欄から離れたとき**（`change`・Enter・「追加」を押したとき）。
  打っているあいだは頭の「いつのことか」に**点線で予告**するだけ
  （`.hero-cap.is-peek`）。一文字ごとに落とすと、「10:00くらいに」と続けて
  打つ人の字が打っている最中に消えます。**予告に新しい札は置かない**
  ——あそこはもともと「いつのことか」を言う場所です。
- **トーストに「戻す」。** 落とした字も、入った欄も、押せば元どおり。読み違えは
  必ず起きるので、逃げ道のほうを先に置きます。保存のときだけ黙って移します
  （すぐ後ろに「◯◯を9/14 15:00までに」が続くので、二枚で同じことを言わない）。
- **直しに来ただけの紙では読みません**（`titleTouched`）。「9/15 資料」という題の
  用事を開いて保存を押しただけで日付が動くのは、書いていないことを勝手に決めるのと
  同じです。**宣言は紙の頭に置くこと**——組み立ての途中（`paintRows` →
  `paintHeroFacts`）から読まれるので、下に `let` で書くと TDZ で落ちます
  （実際に落として、紙の「追加」が押せなくなりました）。
- **時刻だけを言われたら、その日は「いま出している日」。** 日付が無いまま時刻を
  持たせると、保存のところ（`const at = fixed ? time : null`）で時刻ごと落ちます。
- **期限だけ読めたときの予告は、`due` の側（「日付なし」）を借りません。**
  借りると「やる日が明日になった」と誤解させます。**新しい札は置かない**
  決めごとのまま、`.js-hero-when` に「◯◯まで」とだけ言わせます
  （`peek.deadline && !peek.due` のときだけ）。
- **新規の紙は最初から `due` が「いま出している日」で埋まっています**
  （上の「一日ずつになってからは〜」）。「明日まで」だけを打っても、この
  `due` は動きません——期限は別の欄なので。

### カレンダーに入れる（`js/ics.js`・D3）

2026年9月27日。詳細の紙の決めごとの並び、「時刻に知らせる」のすぐ下の一行
（`.js-row-cal`）。最初は頭の「⋯」の中に置いたが、利用者の希望で並びへ移した
——日付と時刻を決めたその場で押せるように。渡すのは**この紙にいま出ている中身**
（保存前に直した日付・題・メモも、見えているとおり）。

- 時刻があればその時刻から長さぶん（長さが無ければ 30分＝`plan.DEFAULT_MINUTES`）、
  無ければ**終日**。日付が無く期限だけなら、期限の日に終日で「題（期限）」
  （行の右に「期限の日に」）。どちらも無ければ行は押せない。
- **くり返しは次の一回ぶんだけ**。くり返しの決まり（RRULE）まで写すと、「第2火曜」
  「平日」などの読み方がアプリと端末でずれた日に、二か所で違う日に立つ。
- 時刻は TZID も Z も付けない「浮いた時刻」。UID は「用事の id-日付」。
- 一行 75 オクテットで折る。**字の途中で切らない**（字ごとに UTF-8 の長さを数える）。
- **ファイル名は英数字**（`yotei-2026-09-27.ics`）。日本語の名前を受け取れない端末で
  「download」になり、拡張子ごと落ちた（机の上の Chromium）。
- **渡し方は端末で分ける**（`KN.ics.offer`）：
  - パソコン・Android・iPhone の Safari のタブ … `data:text/calendar` に `download` を
    付けて開く（`save`）。
  - **iPhone のホーム画面のアプリ** … `save` では**カレンダーに入らなかった**（利用者が
    実機で確かめた）。ホーム画面のアプリは、Safari と違ってカレンダーのファイルを
    受け取る口を持っていない。そこで**押したらすぐ** Safari 本体で受け渡しのページを
    開く（`x-safari-https://…/tools/calendar.html#<中身>`。Safari で開け、という iOS の
    書き方）。
  - 受け渡しのページ `tools/calendar.html` は、`#` の後ろ（UTF-8 の base64url）から
    .ics を戻し、題と日時を見せて、**開いたとたんに一度だけ**「カレンダーに追加」を
    出す（中身の種類を text/calendar にした `blob:` を、ページとして開く）。出した
    あと URL から `#` の後ろを消す——Safari がタブを開き直したとき、もう一度出して
    同じ予定を二つ入れないように。同じものを出すボタンを一つだけ残す。
  - 実機で通ったのは `blob:` をページとして開くほう。`data:` ＋ `download`（ファイルとして
    落とす）は Safari でも「カレンダーに追加」が出なかった。
  - 最初は「Safari で開く／共有シートで渡す」を選ぶ紙を挟み、受け渡しのページにも
    ボタンを二つ置いていた。**手数が多い**と言われ、通った道だけを残した。
  - **いまの手数**：「カレンダーに入れる」→（Safari が開き、「カレンダーに追加」が
    出る）→ 追加 → どのカレンダーか（自宅・職場など）→ くらしノートへ戻る。最後の
    二つ（カレンダーを選ぶ・戻る）は iPhone の側の決まりで、ページからは省けない。
    省く道として、下の「ショートカットで入れる」を作った。
- **ショートカットで入れる**（2026年9月26日。`KN.ics.send`・設定
  `settings.calShortcut`、既定はオフ）：利用者がショートカット App に一度だけ
  「くらしノートの予定」（`KN.ics.SHORTCUT`）を組めば、押すだけで決めた
  カレンダーにそのまま入る。組み方は設定（やること）の「ショートカットの組み方 ›」。
  終日の予定は二つ目の「くらしノートの終日」（`KN.ics.SHORTCUT_DAY`）へ渡す。

    - 利用者の実機（2026年9月26日）で、行は「start から end までの title という名前の
      予定を追加」。続きには 場所・カレンダー（既定「全ての予定」）・終日・通知・メモ・

  - キーの名前は、設定の組み方のページ（`calHowRows`）と `shortcutText` の**一対**。

  - 設定の行はショートカット App のある端末（iPhone・iPad・Mac。`KN.ics.apple()`）
    だけに出す。**既定オフ**なのは、組む前にオンにすると押しても「見つかりません」
    になるから。オフなら今までどおりの .ics の道。
  - 実機（iPhone）で、押すとすぐショートカットに飛んで入った（2026年9月27日、
    利用者が確認）。iOS の版でアクションの名前が少し違うことがある。
  - **入れたあと、くらしノートへ戻る**（2026年9月27日、利用者の希望「追加のあと、
    そのまま戻れるとベスト」）。JSON に `back`（このアプリの URL の `#` から後ろを
    `cal-back` にしたもの。`KN.ics.BACK`）を足し、ショートカットの最後に「URLを開く」
    （URL は辞書のキー `back`）を足してもらう。組み方のページの12番。
    - `#` の後ろだけが違う URL なので、アプリが開いたままなら**読み直さない**
      （`hashchange` で印だけ `#<いまの画面>` に戻す。詳細の紙の保存前の直しも残る）。
      閉じていたなら起動で**やること**へ（`HOME` は daily なので、そのままだと
      daily に出る）。
    - **ホーム画面のアプリに戻るか、Safari のタブが開くかは iOS の版次第**で、
      机の上では確かめられない（ホーム画面のアプリには URL で開く口が公式には無い）。
      Safari で開いた場合、そこは**アプリとは別の保存の置き場**なので記録が空か古く
      見える——「消えた」と読まれないよう、`cameBack()` が「ここは Safari です。
      記録はホーム画面のくらしノートにあります…『URLを開く』は消して」と出す
      （ホーム画面のアプリ・机の上では何も出さない）。
    - **「停止して…を出力」の行があると、戻らない**（2026年9月27日、利用者の実機）。
      ショートカットの中に「停止して 新規予定 を出力」があり、「URLを開く」はその下
      だった——ショートカットはそこで終わるので、**アプリにも Safari にも行かず、何も
      開かない**。アプリの側の不具合ではない（URL まで届いていない）。組み方の12番と
      終わりの注意に「その行は × で消す・『URLを開く』はいちばん下」と書き足した。
      「何も開かない」は「停止」の行、「Safari が開く」は iOS の版、と切り分ける。
    - **「停止」を消したら Safari が開いた**（2026年9月27日、利用者の実機）。ホーム画面の
      アプリへ URL で戻る道は無い、と確定。**組み方から「URLを開く」の段を外した**
      （戻りは「◀ くらしノート」）。JSON の `back` と `cameBack()` は残してある——前に
      その行を足した人が Safari に着いたとき「ここは Safari です…消して」と出すため。
    - アプリの側を x-callback-url の `x-success` にしなかったのは、Safari が開く版で
      利用者が止められなくなるから。ショートカットの中の一行なら、消すだけで戻せる。
    - 試験 `tests/cal-shortcut.js`。
  - `#` の後ろはサーバーへ送られない（Safari の履歴には残る）。受け渡しのページは
    アプリの一部ではない（ASSETS にも standalone にも載せない）。

### 通知を押したら、その用事が開く＋「あとで」（`js/due-sheet.js`・R3・2026年9月28日）

- 時刻の通知は `data.due` にその時刻の用事の id を持つ（開いているときの `notify.js` の
  `tick()` も、閉じているときの `sw.js` の `push` も。後者は**端末の写し**から引く——
  中継所へは今までどおり時刻だけ）。写しに無い押しは `due: []` で、押すとやることへ。
- 押すと `sw.js` の `notificationclick` が `#due=id,id` で開く（開いていればその窓を
  `navigate`、閉じていれば `openWindow`）。`app.js` は起動でも `hashchange` でも
  これを受けて、やることを出し、印を `#todo` に戻し、`bell.absorb()` のあとで紙を開く
  （受け取る前に時刻を直すと、古い回が鳴り直す）。
- 紙は用事ごとに大きな二つ：**済ませた**（`store.toggleTodo`）／**あとで**（四択 15分・
  1時間・3時間・明日。`store.updateTodo` で `due`・`time` を直すだけ）。15分〜3時間は
  **いまから**数え、日をまたげば日も進む。明日は明日の同じ時刻。どれもトーストで元に戻せる。
  同じ時刻に何件もあれば一枚に並び、片づけ終えたら閉じる。「用事の紙を開く」でいつもの紙
  （`KN.screens.todo.open`）。済んだ・消えた用事の通知なら紙は出さず「もう片づいています」。
- 直したら `notifiedFor` と回が食い違うので、新しい時刻にもう一度鳴る。閉じていても鳴る
  列へは**その拍で** `bell.sync()`（bell の3秒待ちを待たない——通知から来た人はすぐ閉じる）。
- **くり返す用事には「あとで」を出さない。** 記録は一件なので、時刻を直すと次の回からも
  動く。一回ぶんだけずらすには新しい欄か写しが要り、「データの形は変えない」に当たるので
  見送った（分かれ道。要るなら利用者に聞く）。
- 通知の押しボタン（`actions`）は本体にしない（iPhone のウェブ通知で当てにできない）。
- 試験は `tests/due-sheet.js`（紙・あとで・bell の列）と `tests/bell.js`（押しの data・
  押したときの行き先）。

### 期限切れは作らない（`store.rescheduleOverdue`）

2026年9月27日（利用者の希望：「ルーティンは期限切れにならないでほしい。期限切れの
（ルーティンではない）タスクは自動で今日に」）。起動したとき・日の変わり目・
**戻ってきたとき**（`visibilitychange`。30秒の見回りを待たない）に運ぶ。

- くり返しでない用事で、やる日（`due`）が過ぎたもの → 今日へ。（ここまでは前からあった。）
  - **時刻は外す**（2026年9月29日・段3で利用者が選んだ。前は持ったまま）。昨日の
    「13:00 病院」が、今日の 13:00 の停留所として道に立っていた——一日の道では
    停留所＝本人が決めた約束なので、決めていない約束になる。外した時刻は印
    `carried: { on, time }` に控え、置き直しの紙で「前は 13:00」と言うのにだけ使う。
  - 運んだもの（①と②）は、朝に一度選び直せる（docs/todo-timeline.md の
    「崩れたときの置き直し」）。選ばなければ今日に居続ける——ここの決めごとは変えていない。
- **長期タスク（`due` なし）で、期限（`deadline`）が過ぎたもの → 今日へ。** 期限の
  当日はまだ動かさない（「今日まで」は切れていない）。
- **くり返しの用事（ルーティン）で、次にやる日を逃したもの → 今日から先で、決まりに
  当たる最初の日へ**（`firstFallOn`＝`fallsOn` で一日ずつ見る）。毎日なら今日、毎週
  火曜なら次の火曜、毎月31日なら次の31日。**逃した日には何も残さない**（やった・
  やらなかったのどちらの印も）。
  - 前はくり返しを対象外にしていて、逃したルーティンが「期限切れ」に並び続けた。
    しかもそれを今日済ませると、`toggleTodo` が写し（trace）を **due の日＝逃した日**に
    残し、元は今日へ進むだけ——**今日のぶんが済んでいないまま残った**。運ぶように
    したので、済ませた写しはいつも今日に付く。
- 買い物の一件（`shop`）は一日に一つ。今日にもうあるなら、昨日のぶんは運ばない
  （二つ並ぶので）。そのぶんは「期限切れ」に残る。
- 済んだもの・しまったもの（アーカイブ）には触れない。何も動かさないときは書かない。
- 時間割の頭の「期限切れがあります」（`.tl-late`）と一覧の「期限切れ」の棚は残して
  ある。ふだんは空で、運べなかったもの（上の買い物）だけの受け皿。

### 一行に並べたものを、分けて入れる（R1・2026年9月28日）

やることは**改行だけ**で分ける（「銀行、郵便局に寄る」は一件の用事）。部品は
`js/split-items.js` の `todo()`（表は `tests/split-items.js`）。

- **題の欄は一行の textarea**（`rows="1"`・`wrap="off"`）。input は貼りつけた改行を
  黙って消すので。Enter は止めたままなので、改行が入るのは貼りつけたときだけ。
  行の数だけ欄が伸びる（6行まで）。見た目は input のころと同じ（`.hero-title` に
  `appearance: none; resize: none; overflow: hidden`）。
- 運んでいるあいだの控え（cloneNode）のため、`setTitle` は `textContent` にも書く
  （input のころは value 属性だった）。
- **分けるのは新しく足す紙だけ。** 直しに来た紙に貼りつけた改行は空きにする。
  **手順を書いた紙も分けない**（手順がどの行のものか分からないので）。分けないときの
  改行は「、」にして一件に。
- 改行があるあいだは、題全体では「いつ」を読まない（予告も出さない）。**保存のときに
  行ごとに** `when-parse` を通し、読めた欄だけ差し替える（`whenApply` と同じ移し方）。
  紙で決めた日・時刻・長さ・くり返し・期限・メモ・旗は、どの行にも。絵は行ごとに
  おまかせ。
- ボタンが先に「3件に分けて追加」と言う。トーストの「ひとつにする」は、足した行を
  消して、行を「、」でつないだ一件を紙で決めたことだけで入れ直す（行ごとに読んだ
  「いつ」は使わない）。
- **`hasBreak` / `flatTitle` は function で書く。** `whenPeek` が組み立ての途中から
  読むので、const にしたら TDZ で紙が開かなくなった（実際に踏んだ）。
