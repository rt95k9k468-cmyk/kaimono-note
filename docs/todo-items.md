本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも

### 手順（サブタスク）の印は、二つとも色。分けるのは形

済ませた手順は ✓、できなかった手順は −。**どちらも基調色（`--cat`）で塗り、
印は白抜き**にします。できなかったほうを地味な灰色にしていた時期がありますが、
それは「やらなかったことは薄い」と言っているのと同じで、この画面がずっと避けて
きた採点です（済ませた用事を灰色にして縮めないのと、まったく同じ理由）。色は
「もう手をつけ終わった」ことだけを言い、どちらに終わったかは**形**が言う。

**`.check svg` は既定で `opacity: 0`** で、それを 1 に戻す決めごとは
`[aria-checked="true"]` にしかありませんでした——つまり − は、描かれてはいたが
**一度も見えていません**でした（灰色の四角だけが出ていて、「できなかった」は
色でしか言えていなかった）。`[aria-checked="mixed"]` にも同じ一行が要ります。

**手順を並べ替えるのは、詳細の紙の中**（`.sub-line` の `.sub-grip`、四本線）。
`KN.reorder.attach` に `handle` を渡すと、**押した瞬間から**持ち上がります
——長押しを待つ作りはここでは使えません。字を書く欄が並んでいる段で、欄の上で
指を止めるのは「文字の位置を決める」手つきだからです。掴むための場所を別に
置いたぶん、待たせる理由も無くなりました。三本（`list`）ではなく四本にしたのは、
メニューの三本線と紛れないため。

- 並べ替えても **store には触れません**。控えの配列（`subs`）を並べ替えて
  描き直すだけで、保存は紙の「保存」が引き受けます——**書く**のと**やる**を
  分ける、この紙の決めごとです。
- 打った字は `value` **属性**にも書き戻すこと。運んでいるあいだの控え
  （`reorder.js` の ghost）は `cloneNode` で作るので、属性を更新しないと
  控えだけが打つ前の字を出します。
- 持ち上がった行には影が付きます（`reorder.js` の決めごと）。この段の行は地を
  持っていないので、`--c-sheet` を敷いておくこと——さもないと影だけが宙に浮きます。

### 長期タスクと、期限（`deadline`）

時間割の下に、少し離して「長期タスク」の欄があります（`somedaySection`）。
**`due` を持たない用事**がここに集まります——やると決めているが、いつやるかは
決めていないもの。

- **時刻も、時刻の線も出しません。** 時刻が無いのだから、書けば嘘になります。
  時刻の列は `visibility: hidden` で**空けたまま**（詰めると丸の位置が上の
  時間割とずれて、運べることが伝わらない）。
- ここから時間割へ運べます。`wireDrag` は同じものを使い、`tlDrag.dayList` が
  落とし先を持ちます——長期タスクの欄には空きの行が無いので、空きを開くのも
  狙いを探すのも**その日の時間割のほう**です。
- **欄の中でも並べ替えられます**（`kind: "someday-order"`）。行の上で離すと
  その前後へ。欄の余白（行の無いところ）で離したら何もしません。
- 並びは**手で決めたもの**（`order`）です。期限の近い順には**しません**
  ——並べ替えられるようにした以上、並びの持ち主は一つ（`order`）にします。
  期限は字で見えているので、そちらまで並びを決めると同じことを二か所で
  言うことになります。急ぐものを上に置きたければ、運べば済みます。
- 詳細の紙は時間割の行と**同じもの**が開きます（`itemRow` を使い回して、
  時刻の列だけ空ける）。

`deadline` は `due` と**別の欄**です。`due` は「その日の時間割に居る」＝いつ
やるか、`deadline` は いつまでか。同じ欄で兼ねると、締め切りを書いたとたんに
その日の時間割へ入ってしまいます。持っていない古い記録は null に落ちるので、
`reconcile()` はそのまま通ります。詳細の紙では「時刻と長さ」の下、長期タスクの
行では題のすぐ下（過ぎたものは字で「◯日すぎています」——色だけだと、色の意味を
知っている人にしか伝わらない）。

### くり返しは、先の日にも立つ（`store.fallsOn`）

くり返しの用事は記録としては一件で、`due` は「次にやる日」です。素直に
`due === day` で数えると、毎日のはずのものが一日にしか出ません。`fallsOn` は
**出す／出さないを答えるだけ**で、記録は増やしません——日ごとの控えを作ると、
済ませた印をどちらに付けるかで二重管理になります（Daily Log を「写さず引く」
ことにしたのと同じ理由）。今日から先だけ広げます。過ぎた日には済ませた跡
（trace）がもう並んでいて、そこへ生きている一件を重ねると二行になるので。

くり返しの選択肢から**毎朝・毎晩は外してあります**（時刻が書けるので、毎日との
二通りができていた）。**すでにある記録には手を付けていません**——`part:
"dawn"/"dusk"` も、それを見ている並べ替え・`plan.js` もそのままです。

### 打った字から「いつ」を読む（`js/when-parse.js`）

「10:00 病院」と打てば、その日の 10:00 に「病院」が立つ。読むのは
`KN.whenParse.parse(text, {today})` ——**DOM も store も触らない純粋な部品**で、
返すのは `{title, due, time, minutes, repeat, repeatDays, repeatNth, deadline, hits}`。
**見つからなかった欄は置きません**（null と「言っていない」は別のこと。画面の側は
来た欄だけを書き換える）。読むことと決めることを分けてあるので、当たり外れは
node の表で測れます（`icon-eval.json` と同じ考えかた。道具はスクラッチに置き、
コミットしない。`js/util.js` → `js/when-parse.js` の順に読み込む）。

読む言葉：今日・明日・あさって・しあさって／N日後・N週間後・Nヶ月後／9/15・
9月15日・2026/9/15・15日／月曜・今週金曜・来週火曜・来週・週末・月末・来月末／
10:00・10時・10時半・10時30分・午前10時・午後3時・夜9時・朝7時・正午／
10:00〜11:00・10時から11時（**範囲は長さ**になる）／毎日・毎週月曜・
毎週月・金曜・毎月15日・毎月第2火曜／**明日まで・9/15まで・今日中に・今週中に・
今月中に**（`deadline` に入る。下）／**30分・1時間・1時間半**（裸の長さ。下）。

取りかたの決めごと（**誤爆を防ぐほうが本体**です）：

- **頭かお尻のかたまりとしてだけ取る。** 真ん中は取らない——「12時の鐘を鳴らす」の
  12時は題の一部。
- **取ったあと題が空になるなら、取らない。** 「明日」だけを打った人は、題として
  そう書いています。
- **すぐ後ろに「まで・ごろ・くらい・すぎ・前・後・間・分・目」が
  くっついていたら取らない**（「10時までに起きる」）。**あいだに空きがあれば
  別の言葉**（「10:00 前田さんに電話」の前田は「前」ではない）——だから
  ここでは trim しません。
- **境目の助詞は一つまで、しかも次が仮名でないときだけ落とす。**
  「明日の会議」→「会議」、でも「明日のりを買う」「明日からあげを作る」
  「明日はやめる」は**そのまま**（落とすと語が壊れる）。そのぶん
  「3時のおやつを買う」は「のおやつを買う」になりますが、**字を失うより
  余った「の」のほうが安い**。
- **裸の「1〜4時」は昼**（3時→15:00）。時間割が扱うのは 5:00〜23:00 の一日で、
  深夜3時に用事は置きません。**「:」で書いてあればそのとおり**（10:00 は 10:00）、
  午前・午後・朝・夜・深夜が書いてあれば、そちらが勝ちます。
- **過ぎた日付は、次に来るその日**（9月13日に「9/1」なら来年の9月1日）。
  やることは「これからやる」ものなので。**昨日・一昨日は読みません**（同じ理由）。
- **毎朝・毎晩は読みません**（くり返しの選択肢から外してあるものなので）。
- 曜日を数えるとき、**「曜」「曜日」を先に落とすこと**——落とさないと
  「火曜日」の**日**を日曜として数えます（実測：火金のつもりが日火金）。
- **「明日まで」は期限（`deadline`）に入ります、やる日（`due`）ではありません。**
  「いつやるか」と「いつまでか」は別の欄なので（「長期タスクと、期限」）。
  日付を言う語（`DATE_RAW`）はそのまま使い回し、後ろに「まで／迄」が付いた
  ときだけ拾います——**日付ルールより先に試すこと**。先に裸の日付ルールが
  「明日」だけを食べると、残った「まで」が題に残ります。**時刻の「まで」
  （「10時までに起きる」）は、依然として読みません**——締め切りは日その
  ものの話で、時刻の締め切りという欄はこのアプリに無いので。
- **裸の長さ（「30分」「1時間」）は、日付・時刻・くり返し・期限のどれかと
  いっしょに打たれたときだけ読みます**（`guard`）。「10分休憩」「腕立て
  30回」のように、長さでも回数でも読める言葉が日本語には多く、単独では
  区別が付きません（実際に「10分休憩」を長さとして誤読しました）。
  「10:00 30分 ジョギング」のように、いつ・どれくらいを続けて打つ人の
  字だけを読みます。**直後に境目（空きか文字列の端）が無ければ止める**
  ことも要ります——「今日 10分休憩」の「10分」の直後に「休憩」が続くのは、
  長さではなく活動の名前の一部だからです。
- **`takeOne` の返り値には `kind` を必ず入れること。** 一度、この一行が
  抜けていて、`parse()` の `taken[hit.kind] = true`（重複防止の排他制御）が
  常に `taken[undefined] = true` を書いているだけの死んだコードでした。
  `due`・`time`・`repeat` は別に明示の if 文で `taken.date` 等を立てていた
  ので表には出ませんでしたが、`deadline`・`minutes` はこの仕組みだけに
  頼っていたため、guard も排他制御もまるごと効かず、二つ目の長さが
  無条件に上書きされる形で埋もれていました。**新しい `kind` を足すたびに、
  この経路が生きているか表で確かめること。**

紙の側（`screen-todo.js`）が持つのは、読めたものを欄へ移すところだけ：

- **移すのは、題の欄から離れたとき**（`change`・Enter・「追加」を押したとき）。
  打っているあいだは頭の「いつのことか」に**点線で予告**するだけ
  （`.hero-cap.is-peek`）。一文字ごとに落とすと、「10:00くらいに」と続けて
  打つ人の字が打っている最中に消えます。**予告に新しい札は置かない**
  ——あそこはもともと「いつのことか」を言う場所です。
- **トーストに「戻す」。** 落とした字も、入った欄も、押せば元どおり。読み違えは
  必ず起きるので、逃げ道のほうを先に置きます。保存のときだけ黙って移します
  （すぐ後ろに「◯◯を9/14 15:00までに」が続くので、二枚で同じことを言わない）。
- **直しに来ただけの紙では読みません**（`titleTouched`）。「9/15 資料」という題の
  用事を開いて保存を押しただけで日付が動くのは、書いていないことを勝手に決めるのと
  同じです。**宣言は紙の頭に置くこと**——組み立ての途中（`paintRows` →
  `paintHeroFacts`）から読まれるので、下に `let` で書くと TDZ で落ちます
  （実際に落として、紙の「追加」が押せなくなりました）。
- **時刻だけを言われたら、その日は「いま出している日」。** 日付が無いまま時刻を
  持たせると、保存のところ（`const at = fixed ? time : null`）で時刻ごと落ちます。
- **期限だけ読めたときの予告は、`due` の側（「日付なし」）を借りません。**
  借りると「やる日が明日になった」と誤解させます。**新しい札は置かない**
  決めごとのまま、`.js-hero-when` に「◯◯まで」とだけ言わせます
  （`peek.deadline && !peek.due` のときだけ）。
- **新規の紙は最初から `due` が「いま出している日」で埋まっています**
  （上の「一日ずつになってからは〜」）。「明日まで」だけを打っても、この
  `due` は動きません——期限は別の欄なので。

### カレンダーに入れる（`js/ics.js`・D3）

2026年9月27日。詳細の紙の「⋯」に「カレンダーに入れる」。**この紙にいま出ている
中身**（保存前に直した日付・題・メモも、見えているとおり）を、.ics 一枚にして端末へ。

- 時刻があればその時刻から長さぶん（長さが無ければ 30分＝`plan.DEFAULT_MINUTES`）、
  無ければ**終日**。日付が無く期限だけなら、期限の日に終日で「題（期限）」。
  どちらも無ければ「日付を決めると…」とだけ言う。
- **くり返しは次の一回ぶんだけ**。くり返しの決まり（RRULE）まで写すと、「第2火曜」
  「平日」などの読み方がアプリと端末でずれた日に、二か所で違う日に立つ。
- 時刻は TZID も Z も付けない「浮いた時刻」（どの端末でも 17:00 は 17:00）。
  UID は「用事の id-日付」——入れ直したとき、カレンダーが同じ予定と分かるように。
- 一行 75 オクテットで折る。**字の途中で切らない**（字ごとに UTF-8 の長さを数える）。
- 渡し方は `data:text/calendar` に `download` を付けて開く。iPhone の Safari は
  カレンダーのファイルを受け取ると「カレンダーに追加」を出す、とされる（**実機では
  未確認**）。共有シートは使わない——iPhone の共有シートにはカレンダーが並ばない。
  `download` があるので、アプリの画面が .ics に置き換わることはない。
- **ファイル名は英数字**（`yotei-2026-09-27.ics`）。題を名前にしていたら、日本語の
  名前を受け取れない端末（机の上の Chromium）で名前が「download」になり、拡張子
  ごと落ちた。題はファイルの中（SUMMARY）にある。
