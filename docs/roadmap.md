# くらしノートの行き先（方針と道のり）

2026年9月29日（火）に書いた。main の `b46497f` までのコード・docs と、ほかのアプリの
2026年9月時点の動き（出典は最後）を突き合わせて決めた**方針**と、そこへ行く**順番**。

- 項目（R1〜）は **1セッションで終わる大きさ**に切ってある。手を付けたら「5. 道のり」の
  表の「状態」を書き換える（`docs/improvements.md` と同じ使い方）。
- **項目に手を付けるセッションは、1〜4節を読み直さなくてよい。** 5節のその項目と、表の
  「先に読む docs」だけ読む。
- CLAUDE.md の約束と、`docs/improvements.md` の「提案しないもの」は、ここでも全部守る。
- **ここにある項目は、R26 を除いて、どれもデータの移行を含まない。** 「足す」ものは
  `reconcile()` の既定値で後方互換にする。作っている途中で移行が要ると分かったら、そこで
  止めて報告する。**R26 は記録の置き方を変える（移行）ので、要判断・実行前に報告。**
- 段7〜段9（R21〜R29）は、同じ日の二回目の全体評価で足した（本番へ流す仕組み・保存の道・
  3年ぶんの試しの記録での実測から。「段7〜9」の節の頭に、見たものと数字）。

## 1. 一言でいうと

**書くのは一度だけ。あとは、くらしノートが運ぶ。**

思いついたことを一度入れたら——

1. **行き先へ行く**（やること・買うもの・からだ・日記のどれか）
2. **戻るべき時に戻ってくる**（時刻・くり返し・切れる頃）
3. **済んだら、その日の記録になる**（daily は写さず引く）
4. **年を重ねるほど、読み返す価値が増える**（あの日・同じ日の年々・年の本）

いまのくらしノートは、3 はできていて、4 の入口（あの日）もある。足りないのは
**1 の「入口から行き先へ」**と、**2 の「戻ってきたときの一押し」**、そして **4 の深さ**。
だから方針は「機能を増やす」より、**すでにある部品をつなぐ**。

> 厳密に言うと：外から出た案（「Personal Life OS」：思いつく→入れる→整理→今日→記録→
> 記憶）と、輪の形は同じ。違うのは重心で、あちらは「アプリが整理してくれる」、こちらは
> 「一度で済む」。整理を AI に任せると、合っているかを確かめる手間がもう一度生まれる。

## 2. いまの立ち位置

### 2-1. よく「作ろう」と言われるが、もうあるもの

| よく出る提案 | くらしノートでは |
|---|---|
| daily をホーム（入口）に | 開くと daily から始まる（README「daily」） |
| On This Day | 「あの日」（`screen-archive.js` の `thenCard`）。**無い過去は言わない** |
| 自然文で日時 | `when-parse.js`。今日〜来月末・第2火曜・「〜まで」は期限・範囲は長さ |
| Someday／Anytime | 長期タスク（期限も持てる） |
| 期限切れの繰り越し | `store.rescheduleOverdue`。赤くしない |
| サブタスク | 手順 |
| いつもの買い物を覚える | そろそろ切れそう（D6。買うものの紙の終わり） |
| リストの共有 | このリストを送る（D4） |
| 閉じていても鳴る | 中継所から Web Push（D1） |
| Siri から追加 | 受け箱から買うものへ（D2） |
| カレンダー連携 | .ics とショートカット（D3） |
| アイコンに残り数 | 設定でオン（時刻が来るまで数えない） |
| 健康は採点しない | 「気づいたこと」は関連まで。片側3件未満は言わない |
| AI の結果はプレビュー | 写真の推定は「推定」の印。直せば外れる |
| 触りごこち | 振動（C1）・丸薬が伸びる（C2）・済ませた手ごたえ（C4） |
| ガラスは操作の層だけ | `docs/glass.md` |

### 2-2. 足りないところ（コードで確かめた）

1. **入口がタブごとに別。** 買うものの＋に「明日 病院」と打つと、品物になる。
   Siri の受け箱は買うものへしか入らない。
2. **一行に並べても一件。** 「牛乳、卵、洗剤」は、その名前の品物が一つできる。
3. **通知を押しても、その用事は開かない。** `sw.js` の `notificationclick` は `#todo`
   へ行くだけ（`data: { screen: "todo" }`）。探して、開いて、直すまでに手数がある。
4. **さがすのはタブの中だけ**（`ui.js` の `wireSearch` を画面ごとに結ぶ）。
5. **くり返しは暦どおりだけ**（毎日・毎週・毎月）。「済ませてから2週間」
   （シーツ・浄水器のフィルター）が書けない。
6. **先の予定を一覧で見る場所が無い。** 日ごとの時間割と、暦の印だけ。
7. **買うものに「組」が無い。** カレーの材料を毎回ひとつずつ入れる。
8. **起動の約270msの固まり**（C3 の残り。正体は daily の最初の組み立て）。

### 2-3. PWA であることの天井（iOS 27、2026年9月）

| 仕組み | ネイティブのアプリ | くらしノート（ホーム画面のウェブアプリ） |
|---|---|---|
| 新しい Siri（iOS 27） | App Intents で差し出した操作を、会話から組み合わせて使う | 差し出せない。**ショートカット経由**（D2 の道）だけ |
| ウィジェット・Spotlight・Live Activities | できる（Things 3.24 は特大ウィジェットと Spotlight） | できない |
| 通知 | 押しボタン・先送り | 届く（D1）。**押しボタンは当てにできない**（公式の明記が見当たらず、開発者フォーラムでも不確か） |
| アイコンの数 | できる | できる（すでにある） |
| ヘルスケア | 直接読める | ショートカット→中継所（すでにある） |
| 端末の中の AI | Foundation Models | ショートカットの「モデルを使用」（iOS 26〜、iPhone 15 Pro 以降）なら使える |

ここは PWA が正面から勝てない場所。だから、**アプリの中の入口を賢くする**（R1・R4）と
**ショートカットの橋を太くする**（R5）で応じる。それでも足りなくなったら、
「6. 分かれ道」の X1（薄いネイティブの殻）を考える。

> 厳密に言うと：Safari 27 の「MCP」は、開発者が AI の道具に Safari を触らせるための
> もので、Siri からウェブアプリを操る道ではない。ページが道具を差し出す WebMCP は
> W3C の草案の段階。

### 読みとったこと

1. **大手は「入口の賢さ」と「OS とのつながり」で競っている。** OS とのつながりは
   PWA には開かない。入口の賢さは、`when-parse.js`・絵の辞書（`findKey`）・覚えた
   カテゴリという、**もう持っている部品で作れる**。
2. **記録アプリは AI の要約と連続記録へ寄っている**（Day One Gold・ジャーナルの連続
   記録・ヘルスケアの Health Age）。くらしノートの「採点しない」「日記を外へ出さない」は、
   遅れではなく、**はっきりした違い**になった。守る。
3. **買い物アプリは献立へ伸びている。** くらしノートには、リストのアプリがまず持たない
   **価格の記録**と**手描きの絵**がある。献立は小さく（組）足して、この二つに結ぶ。

## 4. 方針（五つの柱と土台）

### 柱1 入口は今のまま、行き先を賢く

新しい入口（5つ目の席・AI の席・「なんでもボタン」）は作らない。**どのタブの＋も
今までどおりそのタブのものを入れる**が、打った字がほかの行き先らしければ
**行き先の札**がそっと出て、一押しで行き先を変えられる。

- 同じ場所・同じ手つきで入れられることが、いちばん続く（8節の Wood ほか）。
  入口を増やすと「どこから入れるんだっけ」が生まれる。
- 読むのは端末の中の決まりだけ。通信も費用も要らず、機内モードでも同じに動く。

### 柱2 戻ってきたとき、一押しで片づく

通知・暦・くり返しは「知らせる」で終わらせず、**その場で済ませる・先へ送る**まで。
iPhone のウェブ通知では押しボタンを当てにできないので、**押したら、その用事が
開いていて、大きな二つ（済ませた／あとで）が待っている**形にする。

- 知らせは増やさない。**時刻を決めた用事だけ**が鳴る今の約束を守る（8節の Fitz ほか）。

### 柱3 年を重ねるほど、読み返す価値が増える

「あの日」を、**同じ日の年々**・**ぜんぶをさがす**・**年の本**へ広げる。どれも
**写さず引く**（新しい記録の入れ物は作らない）。

- 無い過去は言わない。数えない。比べない（daily の決めごとのまま）。
- 思い出には、つらい日も混ざる。**出したくない日を黙らせる手**を一緒に置く。

### 柱4 組で入れて、価格と絵につなぐ

「カレー」と打てば、材料のうち**リストに無いものだけ**が入る。組の品は、いつもの
品物（絵・カテゴリ・価格）とつながる。献立の暦までは作らない。

### 柱5 採点しないまま、確かさを一段上げる

「気づいたこと」が増えるほど、**たまたま**の当たりも増える。言う前に、記録の
**前半と後半のどちらでも同じ向き**かを確かめ、揃ったときだけ言う。

### 土台 速さと守り

入口の速さは、続くかどうかをそのまま決める（開いて打てるまでが遅いと、書かれない）。
起動の固まり（C3 の残り）を iPhone の実測から詰め、復元の練習を試験にして毎回回す。

- `index.html` に `<meta http-equiv="Content-Security-Policy">`：`script-src 'self'`（直書きの
  スクリプトは今ゼロ）・`object-src 'none'`・`base-uri 'self'`・`img-src 'self' data: blob:`・
  `style-src 'self' 'unsafe-inline'`（style 属性を使っているので）・`connect-src 'self' https:`
  （中継所・AI の窓口・Dropbox は、利用者が決める URL なので広く）。
- いまの字の無害化（`html`）はよくできている。これは「もし一か所漏れても、よそのスクリプト
  は動かない」ための二つ目の鍵。
- 厳密に言うと：iPhone で何かが黙って動かなくなるおそれがある（.ics の blob・写真の data:・
  push）。全試験と、R16 の確かめ表で一度見る。`tools/diary-import.html` は別の頁なので、
  別に決める。

- おすすめ：**今はしない。** R1〜R11 は、殻を被せても全部そのまま使える。

**X2 家族と使う**
- 双方向の同期（同じリストを二人で）は、サーバー・ログイン・食い違いの解き方が要り、

  しまう資格なので、家族には渡せない。足すことしかできない別の合言葉を中継所に足す
  （中継所の置き直しが要る）。
- 本当に双方向が要るなら、そのときはローカルファーストの同期（CRDT）で設計する
  （8節の Kleppmann ほか）。
- → **利用者の答え（2026年9月28日）：家族と使う予定は全く無い。** 手前の段も作らない。

**X3 AI の使いどころ**
- 使う：品物の写真・レシピの文から組（R12）・（将来）乱れた文の振り分けの「もっと読む」。
  どれも**プレビューしてから入れる**。
- 使わない：**日記を AI に送ること**（要約・問いかけ・「昨日はこんな一日」）。深く個人的な
  中身で、要約は評価の言葉に寄る。
- 端末の中で済むなら、そちら（ショートカットの「モデルを使用（デバイス上）」）。
- → **利用者の答え（2026年9月28日）：写真・レシピまで。日記には使わない（今のところ）。**

**X4 控えの見張りを、設定の外にも出すか（R25）** → **利用者の答え（2026年9月29日）：おすすめどおり、点だけ出す。**

  気づける。
- 出さない：今のまま（設定の中に、前回の書き出しの日付と、Dropbox の失敗の文）。
- おすすめ：**点だけ出す。** 過去に一度データを失っている。いちばん痛いのは「控えが
  あると思っていたのに、無かった」（8節の Reason）。点は押すまで何も言わないので、
  「催促はしない」の理由（読み飛ばす癖）には当たりにくい。

- おすすめ：目安（150万字、または保存1回0.1秒）を越えるまでは、しない。越えたら
  1（日記）→ 2（AI の原文）の順に。3（棚ごと）は、1・2 で足りなかったときだけ。

## 7. やらないこと（理由つき）

| やらないこと | 理由 |
|---|---|
| 5つ目の席（AI・検索・思い出など） | 帯は場所を移るためのもの。価格・設定も席を持たない方針 |
| daily に数字の一覧（体重の7日平均・やることの数） | daily は採点しない。「平均」は daily-rules の禁止語 |
| 連続記録・ポイント・バッジ・達成率 | 決めごと。習慣は一日抜けても崩れない（8節 Lally） |
| 通知を増やす（励まし・「今日は書きましたか」） | 知らせは時刻を決めた用事だけ（8節 Fitz） |
| 押しボタンつき通知を本体にする | iPhone のウェブ通知で当てにできない。R3 の形で |
| 日記を AI へ | X3 |
| 日記に写真 | 端末の保存場所と、控え・書き出しが膨らむ。データ保全が先 |
| 意味で探す（埋め込み） | 重い。言葉と日付で足りる（R8） |
| 全部をガラスに | ガラスは操作の層だけ（docs/glass.md） |
| 家族との常時同期を先に | X2 |
| 既に外してあるもの | 買うものの合計金額・歪むレンズ・夜の色・引いて更新・daily の目標と連続記録・飲みたい気持ちの採点とタイマー（docs/improvements.md） |
| ビルドで縮める・束ねる（minify） | 起動の得は小さく（R14 の実測約1秒には iOS 側の起動も入る）、壊れたときに iPhone で読めなくなる。重さの正体は、R26 の「ぜんぶを書く」のほう |
| リポジトリを非公開に | GitHub の無料の枠では、非公開にすると Pages が使えない。記録そのもの（体の数値・日記・中継所の URL）はリポジトリに載っていないことを確かめた（2026年9月29日）。**docs に個人の実測の数値や中継所の URL を書かない**を、これからも守る |
| 通知を Declarative Web Push に作り替える（様子見） | Service Worker を起こさずに iPhone が通知を出せる仕組み。D1 は実機で鳴っているので、困ってから |

## 9. 進め方（制限の節約）

- 1セッションに1〜2項目。終わったら「5. 道のり」の状態を書き換えて、main まで流す。
- 各項目は「先に読む docs」だけ読む。この文書は、その項目の節だけ読めばよい。
- 次のセッションに貼る文の型：

docs/roadmap.md の R1 と R2 をやって。この文書は5節のその項目だけ、docs は表の

tests/ に台本を足し、daily-rules.js と触った画面の試験を通して、main まで流して。
