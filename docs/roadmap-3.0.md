## 1. 一言でいうと

**記録が、次の一日の組み立てに戻ってくるアプリにする。**

```
積み上げ（何を積んできたか）
  → 時間（今日それにどれだけ使ったか）      … 段A
  → 道（今日が実際どう流れたか）             … 今ある道
  → 組み直し（崩れたら今の現実に合わせる）    … 段B
  → 崩れ方（何がいつも動くか。事実だけ）      … 段D
  → AI（大きすぎるものを小さくし、次の一歩を作る） … 段C
  → 季節（同じ毎日ではなく、暮らしが移っていく） … 段E
```

利用者の四つの願い（2026年10月6日）：

1. 読書・学び・種・ノートで**考えたことに使った時間**を、一日の道に入れたい。
2. なかなか終わらない大きなタスクに「AIでほどいてみませんか」と言ってほしい。AI に渡す文を作ってほしい。
   ただし一つの文で AI は背景まで分からないので、**まず AI とやり取りしてから**分けたものを取り込みたい。
3. 長期タスクの箱に、「本当にいつでもいい」「やってもやらなくてもいい」「やらないといけないが今ではない」が
   混ざっていて終わらない。「いつかやればいい」の**いつか**を決めるのが苦手。
4. daily に、日ごとか七十二候ごとに変わる、**とても薄い季節の背景**が欲しい。

## 4. 全体の決まり（どの段でも）

- **評価しない**：目標・達成率・連続・点数・生産性・赤い警告・「遅れ」「できなかった」「失敗」。
  言うのは**数と事実**（「4回置き直し」「最初は9月12日」）と、**次に試せる選択肢**だけ。
  「この時間帯が原因」のような**因果も言わない**。
- **黙って動かさない**：組み直しも AI の分け方も、まず候補を見せ、本人が選んでから書く。どれも「元に戻す」。
- **割り込まない**：開いたときに出る紙・吹き出しは作らない。出すのは頭の一行（段3・段5 と同じ置き場
  `.js-late`）か、詳細の紙の中の一つの札まで。
- **道を見づらくしない**：活動は道の上で一段控えめに。新しい札・印は、既存の札の置き方（`marks`）の
  あとに置き、ぶつかったら出さないほうを選ぶ。
- 画面の言葉は短く大きく。説明が要るなら `more()` で畳む。絵文字は出さない。

### T0 受け皿

`reconcile()` は、やること（`todos`）を**知っている欄だけで組み直す**（`store.js` の 860行あたり）。
知らない欄は保存のたびに消える。だから新しい欄は、**書く画面より先に**受け皿だけ出す。

やること（`todos[]`）に足す欄：

| 欄 | 形 | 無いとき | 意味 |
|---|---|---|---|
| `act` | `{ type, entry, note }` か無し | 欄を足さない（`carriedField` と同じ書き方） | 活動（A1）。`type` は積み上げの種類（`reading`・`study`・`seed`・`done`・`change`）、`entry` は結んだ積み上げの id、`note` はノートの id |
| `shelf` | `"wait"` \| `"someday"` \| null | null | 待つ・いつか（B1）。`due` があれば null に落とす |
| `waitFor` | 30字までの字 \| null | null | 何を待っているか（B1。任意） |
| `review` | `"YYYY-MM-DD"` \| null | null | 次に見直す日（B1） |
| `slips` | `[{ on, from, time, how }]`（新しい20件まで） | `[]` | 置き直しの控え（B2）。`how` は `carry`（日の変わり目に運んだ）・`passed`（時刻を過ぎて決め直した）・`hand`（自分で後ろへ） |
| `editedAt` | ISO の時刻 \| null | null | 最後に手で直した時刻（B1 の「変わっていない」に使う。無ければ `createdAt`） |

積み上げ（`archive.entries[]`）に足す欄（entries は**組み直さず欄を補う**作りなので、知らない欄も残る。
それでも読み方の既定は書いておく）：

| 欄 | 形 | 無いとき | 意味 |
|---|---|---|---|
| `minutes` | 5〜720 の5きざみ \| null | null | 使った時間（A1） |
| `at` | `"HH:MM"` \| null | null | 始めた時刻（A1。道に描くのは `at` と `minutes` の両方があるときだけ） |
| `todo` | やることの id \| null | null | 結んだ活動（A1） |
| `note` | ノートの id \| null | null | 結んだノート（A2） |

- どれも **function 宣言**の掃除役で（CLAUDE.md の TDZ）。
- 試験：`tests/shelf-base.js`（新）——欄の無い古い保存がそのまま読める・欄が読み直しても残る・崩れた値は
  既定に落ちる・`restore-practice.js` が通る。
- **済み（2026年10月6日）**：`store.js` の `reconcile()` と `actField`・`cleanShelf`・`cleanWaitFor`・
  `cleanIso`・`cleanSlips`。積み上げの欄は、無ければ足さず（読むときは null）、崩れた値だけ null に。

### A1 積み上げを道へ置く

**一つの活動を、予定・実績・積み上げの三つの見方で扱う。二度入れさせない。**

- **予定**はやること一件（`act` 付き）。道・時刻の紙・運ぶ・通知・置き直し、今ある仕組みが全部そのまま効く。
- **実績**は積み上げの一件（`minutes`・`at` 付き）。済ませた時に生まれ、二つは互いの id で結ばれる。
- **道は実績を引く**（写さず引く）：結んだ積み上げがあれば、道に描く長さと時刻はそちらから。無ければ予定から。
  片方を消しても、もう片方は残る（結びが切れたら、ふつうの用事・ふつうの記録に戻るだけ）。

入口（どれもタップ2〜3回）：

| どこから | 何が起きる |
|---|---|
| 記録の紙（daily の積み上げ）「道に置く」 | 時刻の紙（今あるもの）→ その日に `act` 付きの用事。題は記録の題（「読書『…』」）、長さは札（15・25・30・45・60） |
| 道の空きを押す（段2「道の上で決める」） | 選ぶものに「活動」の行：覚えている本・最近の積み上げの題から |
| 過去の積み上げの紙「道に記録する」 | 始めた時刻と長さだけ聞き、その記録に `at`・`minutes` を書く。**用事は作らない** |

済ませるとき：

- 活動の丸を押す → **予定の長さで済ませ**、積み上げが一件生まれる。下の知らせに「30分で残しました · 直す」。
  **タイマーは作らない**。違えば「直す」から長さだけ（札と ±5分）。
- 積み上げの題・種類は予定から写す（読書なら本の題・著者も）。メモは空のまま。

見た目：

- 道の上では**一段控えめ**：塗りの丸薬ではなく、積み上げの種類の色の**縁取り**の丸薬（中は紙の色に寄せる）。
  チェックの丸は出さない（済ませるのは押すだけで同じ）。形は見比べの画像で決める（2.0 の V5 と同じやり方）。
- 道で押すと、詳細の紙の頭に「積み上げ『…』」「ノート『…』」の札（押せば元へ）。
- daily のその日の積み上げに「30分」と小さく。その日の活動の合計は出してよい（事実）。**月比べ・平均は出さない**
  （`daily-rules.js` の言葉）。

試験：`tests/activity.js`（新）。`day-road.js`・`road-done.js`・`road-carry.js`・`carry.js`・`daily-rules.js` を回す。

### A2 ノートから道へ・道から元へ

- ノートの「⋯」小窓に「道に置く」→ 長さの札（15・20・25・45）と時刻 → `act: { type: "seed", note }` の用事。
  題は「『ノートの題』について考える」。「書く」かどうかは分けない（言葉が一つ増えるだけなので）。
- 道からその活動を押すと、詳細の紙の「ノート『…』」でノートが開く。閉じれば道へ戻る（`edge-back` の戻り）。
- 済ませた積み上げは `note` を持つので、daily の記録から同じノートへも行ける。
- ノートが消えていたら札を出さない（ノートは IndexedDB で、別に消えうる）。
- 試験：`tests/activity.js` に足す。`notes.js`・`note-v19.js` を回す。

### B1 五つの状態と「見直す」

状態は**保存しない**——`due`・`shelf` から毎回読む（一つの事実を二か所に持たない）。

| 状態 | 読み方 | 置き場所 |
|---|---|---|
| 今日 | `due` が今日 | 道・時間割（今のまま） |
| 予定あり | `due` が明日以降 | 暦・これからの二週間（今のまま） |
| これから | `due` なし・`shelf` なし | 時間割の下の欄（いまの「長期タスク」）。道のくぼみ（段B）もこれだけ |
| 待つ | `due` なし・`shelf: "wait"` | 同じ欄の下に畳んで「待つ n」。開けば「返事」など `waitFor` が小さく |
| いつか | `due` なし・`shelf: "someday"` | 同じ欄のいちばん下に畳んで「いつか n」 |

- **今ある長期タスクは書き換えない。** 欄が無い＝「これから」として読まれる。待つ・いつかへは本人が移す。
- 日を決めれば（`due` を書けば）`shelf` は外れる（`updateTodo`）。
- **見直す日**：「これから」へ入れたとき2週間後、「いつか」は1か月後、「待つ」は1週間後を `review` に書く
  （設定で変えられる。2節の答え）。今ある長期タスクには書かず、**読むときに** `editedAt`（無ければ `createdAt`）
  ＋2週間とみなす（移行しない）。
- 見直す日が来たものは、やることの頭（`.js-late`）に「見直す n」。押すと一件ずつの紙：
  - 頭に事実だけ（「9月12日から · 3回置き直し · 期限 10月31日」）。
  - 選択肢：**今日やる**／**日を決める**／**まだこれから**（次の見直しを2週間後）／**待つ**／**いつかへ**／
    **小さくする**（C1 へ）／**やめる**（アーカイブ。消さない・赤くしない）。どれも「元に戻す」。
  - 選ばなければ何も変わらない。**日をまたいでも数は増えるだけで、色は変えない**。
- 期限（`deadline`）は今のまま：過ぎたら今日へ運ぶ（期限切れは作らない）。見直す日は期限ではないので、過ぎても運ばない。
- 見た目（欄の分け方・畳み方）は**見比べの画像で決める**：(a) 今の欄に小見出しで三つ、(b) 欄の頭に「これから｜待つ｜いつか」の切り替え。
- 試験：`tests/shelf.js`（新）。`carry.js`・`passed.js`・`road-carry.js`・`upcoming.js`・`repeat-*.js`・`restore-practice.js` を回す。

### B2 置き直しの回数と選択肢

- 控え（`slips`）を書くところ：日の変わり目に運んだ（`rescheduleOverdue`）・段3の紙で明日／今週を選んだ・
  段5の紙で明日／時刻を外すを選んだ・自分で `due` を後ろへ動かした。くり返しには書かない（くり返しは毎回が別の回）。
- **3回目から**、段3・段5・見直すの紙のその行に「4回目」と事実を一つ。選択肢に足す：
  - **今日は15分だけ**（長さを15分に。元に戻せる）
  - **時間を変える**（時刻の紙へ）
  - **小さくする**（C1 へ）
  - **いつかへ**・**待つ**・**やめる**
- 言わないこと：「先送り」「また」「失敗」「この時間帯が原因」。!も赤も出さない（Marvin の印は借りない）。
- 試験：`tests/slips.js`（新）。`carry.js`・`passed.js` を回す。

### B3 組み直し（入りきらないとき）

出すのは**理由があるときだけ**、時間割の頭に一行（今の「寝る時刻を ◯ すぎます」を押せるようにする）：

- 今日の残り（いま〜寝る時刻）に、まだの用事が入りきらない（`plan.over > 0`、いまから数えた見積もり）
- または、時刻を過ぎたものが2件以上（段5の数）

押すと組み直しの紙：

1. **入るもの**：時刻の決まったもの（動かさない）と、期限が近いもの、それ以外は今の並び順で、残りの時間に
   入るところまで。長さは `plan.minutesOf`（決めた長さ → いつもの長さ → 30分）。
2. **入らないもの**：一件ずつ行き先の札。既定は「明日」。3回以上置き直したものは既定を「これから」に。
   ほかに「後日（日を選ぶ）」「分ける（C1）」「いつかへ」。
3. 「この形にする」で全部を一度に書き、**元に戻す一回で全部戻る**。紙を閉じれば何も変わらない。

- 伸び縮み（Reclaim）：長さが45分以上の用事は「今日は半分」の札も出す（長さを半分に）。
- 試験：`tests/refit.js`（新）。時計を止めて、入る／入らないの境目・時刻の決まったものは動かない・元に戻す。
  `day-road.js`・`timeline-overlap.js` を回す。

### C1 AI とほどく（外の AI と往復）

**アプリは AI を呼ばない。** 文を作り、本人が運び、本人が選んで取り込む。

1. 入口：詳細の紙の「⋯」に「AIとほどく」。見直す・置き直しの紙の「小さくする」からも。
   **すすめるのは静かに**：次のどれかに当てはまる用事だけ、詳細の紙に「AIとほどく」の札を一つ出す
   （紙・吹き出しで割り込まない）——置き直し3回以上／これから・いつかで21日以上手が入っていない／
   長さ60分以上で手順なし。「出さない」を一度押した用事には二度と出さない（store の外の鍵に id を控える）。
2. **渡す中身を選ぶ紙**：題（必ず）・メモ・手順・期限・長さ・いつから／置き直しの回数・「困っていること」
   （一行。打てば足す）。チェックを外したものは文に入らない。**日記・ノート・からだ・買うものは候補にも出さない。**
   下に、できあがる文をそのまま見せる。
3. 「コピーして開く」：文をクリップボードへ → ChatGPT か Claude を開く（どちらにするかは一度選べば覚える）。
4. AI とやり取り（文が順番を指示する：質問 → 理解の要約 → 本人の確認 → 分ける → 決まった枠で出す。下の文の見本）。
5. 戻ってきて「答えを貼る」→ 枠を読み、候補を並べる：完了条件・前提・**次の一歩**・手順（長さ・「◯のあと」）・
   さらに分けるもの。枠が読めなければ、行ごとの候補として出す。
6. 選ぶ：チェックした手順だけ取り込む。行き先は「この用事の手順」（`subs`。既定）か「別の用事としてこれからへ」。
   **次の一歩だけ**「今日の道に置く」を選べる（全部を今日へは入れない）。完了条件と前提は「メモに残す」（既定で入）。
7. 「ほかの AI にも相談する」：同じ文に「ここまでの結果」（貼った答えの要約部分）を足してコピー。

- 貼った答えは**保存しない**（取り込んだものだけが記録になる）。紙を閉じたら消える。
- 試験：`tests/ai-unfold.js`（新）。文に選んだ欄しか入らない・日記の字が混ざらない・ChatGPT 風／Claude 風／
  枠の崩れた答えの読み・選ぶまで何も変わらない・取り込みの元に戻す。

**AI に渡す文の見本**（C1 で作る文の土台。今すぐ手で使ってもよい）：

```
あなたは、大きすぎて進まないタスクを一緒にほどく相手です。いきなり分解しないでください。

## タスク
題：{題}
メモ：{メモ}
すでにある手順：{手順}
期限：{期限}
見込みの長さ：{長さ}
いつから：{作った日}
置き直した回数：{回数}
困っていること：{一行}

## 進め方（この順を守ってください）
1. まず質問だけをしてください。一度に3つまで。聞くのは「どうなったら終わりか」「まだ分かっていないこと」
   「使える時間・お金・人などの制約」。私の答えを待ってください。
2. 答えがそろったら、「こういう背景・目的・完了条件だと理解した」を5行以内でまとめ、合っているか
   私に確かめてください。違っていれば私が直します。
3. 私が「それで合っている」と言ってから、初めて分けてください。
4. 分け方の決まり：
   - 一つの手順は、だいたい15〜60分。やり始め方が分かる動詞で書く（「調べる」「考える」だけで終わらせない）
   - 全部で7つまで。細かく刻みすぎない
   - 60分を超えそうなもの、中身がまだあいまいなものは「さらに分ける」に番号を書く
   - 今日やるのは「次の一歩」の1件だけでよい
5. 最後の答えは、下の枠の形だけで出してください（アプリに貼り戻します）。

<<くらしノート>>
完了条件：…
前提：…
次の一歩：…｜15分
1. …｜30分
2. …｜45分｜1のあと
さらに分ける：2
<</くらしノート>>
```

### D1 崩れ方の事実

`slips` が溜まってから（B2 の3週間後）。出すのは**数の並びだけ**：

- 見直す・置き直しの紙の頭に、その用事の「最初に置いた日・置き直しの回数・前に置いていた時刻」。
- 設定 → やること の奥に「置き直しの控え」：この4週間に置き直したもの n 件、置いていた時刻
  （朝・昼・夕・夜）ごとの件数、長さ（決めていた長さ）ごとの件数。**並べるだけで、多い・少ない・原因は言わない。**
  横に「次に試せること」の札（15分だけ・時間を変える・小さくする）を並べてよい。
- daily には出さない（daily は評価しない）。

### E1 七十二候と絵

- **出どころ**：パブリックドメインの浮世絵だけ。主に歌川広重『名所江戸百景』（1856〜58年、広重の118図を含む全120図。
  春・夏・秋・冬の部に分けてある）と、広重ほかの花鳥画（燕・鶺鴒・雉・蛙・菖蒲・桜・菊など、候の名に出る生き物と花）。
  - NDL イメージバンク：著作権の切れた資料で、**転載に申請は要らない**（商用も）。出典の表示を求めている。
  - ColBase：規約を守れば自由に使える。
  - どの絵も、元の所蔵先・作者・題・取得した URL を対応表に書く。**出どころの分からない絵は使わない。直リンクもしない。**
- **対応表**（`docs/season-art.md`、新）：候の番号・名前 → 絵の題・作者・所蔵・URL・選んだ理由（一言）。
  候の名の生き物・花が描かれた絵を先に、無ければ同じ時期の景色。72枚がそろわない候は、同じ節気の隣の候と
  一枚を分け合ってよい（24枚まで減らしても成り立つ作りにする）。
- **加工**（`tools/season-art.js`、新。ローカルで一度だけ）：短い辺 720px・彩度を落とす・少しぼかす・
  WebP（無理なら JPEG）で**1枚25KBまで・72枚で2MBまで**。絵の平均の色も取って表に書く（下の「下地の色」）。
  置き場は `img/season/k00.webp`〜`k71.webp`。
- **敷き方**：
  - daily の画面だけ。紙の**後ろ**に一枚。上（日付・頭の帯のあたり）でいちばん見え、下へ向かって紙の色に溶ける
    （`mask-image` の上下のぼかし）。濃さは 6〜10%（iPhone で決める）。暗い色のときはさらに薄く。
  - まず絵の平均の色を下地に敷き、絵は読めてから重ねる。**読めない間・オフラインでまだ持っていない絵でも、
    色だけは候ごとに変わる**（色と光の層が、いつも土台）。
  - 選んだ日の候（`season.js` に日を渡す）。過去の日を開けばその日の候。日付が変われば次の候。
  - 動きは「ゆっくり入れ替わる」だけ（`--m-*` の一つ。動きを減らす設定では切り替えるだけ）。
- **読み込み**：72枚を前もって読まない。`sw.js` の `ASSETS` には**入れず**、`img/season/` だけ
  「先にキャッシュ、無ければ取りに行って覚える」。今の候と次の候を、手の空いたとき（`requestIdleCallback`）に。
  同じ配信元（GitHub Pages）なので、外の画像を都度取りに行くことにはならない。
  - **置くキャッシュは別の名前に**（`kaimono-note-` で始めない）。今の `sw.js` は、同じ配信元のものを
    何でも版のキャッシュに入れ、`activate` で `kaimono-note-` で始まる古い版を消す。そこに入れると、
    出すたびに見た絵が消え、オフラインで色だけに戻る。
- **出典**：設定の奥（`more()`）に一覧。NDL の求める書き方で。daily には書かない。今の設定に出典の置き場は
  無いので、E1 で一つ作る。
- **設定**：daily に「季節の絵」のスイッチ（既定は入）。
- 試験：`tests/season-art.js`（新）。72候のどれも絵か色を持つ・過去の日・オフラインで色だけ・字の濃さの比
  （本文の字と背景の、いちばん濃い所で 4.5:1 以上）・大きさ（1枚25KB・合計2MB）を門で見張る。
  `season.js`・`daily-rules.js`・`offline.js` を回す。

## 6. データを守る（3.0 全体）

- **移行は無い。** 今ある長期タスクは「これから」として**読まれる**だけで、記録は書き換えない。
  見直す日も、欄の無いものは読むときに出す。
- **古い版に注意**：古い版の `reconcile()` は、知らない欄（`act`・`shelf`・`review`・`slips`・`editedAt`）を
  保存のたびに捨てる。用事そのものは残るが、待つ・いつかが「これから」に戻る。だから **T0 を一人で先に出し**、
  iPhone で一度開いて新しい版になってから、A1・B1 を出す。
- 結び（`act.entry`・`entry.todo`・`note`）は**切れても壊れない**：相手が無ければ、ふつうの用事・記録として読む。
  消すときに相手を一緒に消さない。
- 書き出し・復元・自動の控え：新しい欄は state の中なので、そのまま乗る。`restore-practice.js` を毎段で回す。
- AI に渡すのは、本人がチェックした欄だけ。アプリは通信しない（コピーするだけ）。
- 背景の絵は記録ではない。消えても何も失わない。

## 7. やらないこと（3.0 で決めたもの）

| やらないこと | 理由 |
|---|---|
| アプリの中で AI と会話する（窓口・API キー） | 2節の答え。費用と設定の手間。外の AI で足りる |
| AI が用事を作る・直す・道へ置く | 本人が選んでから。分けるだけ |
| 「AI でほどきませんか」を紙や吹き出しで出す | 割り込まない。詳細の紙の札一つまで |
| タイマー・計測の強制 | 「25分やった」を後から書けば足りる |
| 状態を五つより増やす（文脈タグ・優先度・プロジェクト） | GTD の細かい分類はやらない、のまま |
| 置き直しの!・赤・「先送り」 | 責める色と言葉 |
| 活動の目標時間・合計の月比べ・平均 | daily は評価しない |
| 365枚の背景・写真・外の画像の直リンク | 重さと権利。七十二候の72枚まで |
| 背景をほかのタブへ広げる | daily の紙の後ろだけ（貼られた案のとおり） |

## 8. 進め方（制限の節約）

- 1セッション1項目。終わったら5節の表の状態を書き換えて、main まで流す。
- 画面が大きく変わるもの（A1 の活動の見た目・B1 の欄の分け方）は、先に見比べの画像を作って利用者が選ぶ。
- E1 は絵を何十枚も見るので重い。始める前にそう言い、候を四季ごとに4回に分けてよい。
- 次のセッションに貼る文の型：

```
docs/roadmap-3.0.md の T0 をやって。この文書は5節の表とその項目の節、4節・6節だけ読む。
docs は表の「先に読む docs」だけ。触った画面の試験と daily-rules.js・restore-practice.js を通して、
main まで流して。終わったら roadmap-3.0.md の状態を書き換える。
```
