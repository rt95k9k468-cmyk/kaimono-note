# ノートの画像（docs/notes.md の段5）設計書

ノートに画像を貼る段の設計。**2026年10月11日に書き、同日に利用者が六つの論点すべてを勧めのとおり承認した。
まだ実装していない**。記録（store）・日記・時間割には触れない。

## 決めること（案A／案B と勧め）

| 論点 | 案A | 案B | 勧め |
|---|---|---|---|
| 1. 置き場所 | ノートの入れ物 `kaimono-note-notes` の meta 棚に `img:<id>`（前の版 `ver:<id>` と同じ手。版1のまま・移行なし） | 別の入れ物 `kaimono-note-images`（版1の決め打ち・新しく作るだけ＝移行なし） | **B**。画像は文字の数百倍重く、iOS の IndexedDB は大きな値で入れ物ごと読めなくなった前歴がある（WebKit の Blob の不具合）。壊れても、落ちても、ノートの本文の入れ物を道連れにしない。ノートの読み込み（全件を記憶へ）にも乗らない |
| 2. 縮める大きさ | 長辺1600px・JPEG 0.8（1枚 約250〜450KB。紙の字・レシートが読める） | 長辺1024px・JPEG 0.82（約100〜200KB。`diet-ai.js` の `shrink` と同じ） | **A**。iPhone の画面幅は約1179px。ノートは読み返すための場所なので、写真の中の字が読めるほうを取る |
| 3. 控えに載せるか | 自動の控え・「バックアップを保存」には載せない。Dropbox には別のファイルで一枚ずつ一度だけ送る（`images/<id>.jpg`）。ノートの書き出し（zip）に同梱 | どれにも JSON の中に base64 で入れる | **A**。下の「容量」 |
| 4. 消え方 | 参照が無くなった画像は、さらに30日待ってから消す（二段の待ち） | 画像は消さない（増える一方） | **A**。ただし止める条件つき（下の「消え方」） |
| 5. 容量不足 | 書いて落ちたら断る（`QuotaExceededError`） | 書く前に残りの枠を見て、余白が足りなければ断る | **B**。同じ枠を記録の写し・日記の写し・自動の控えが分け合う。画像で枠を食い切ると、守りの側が書けなくなる |
| 6. 参照の書き方 | Markdown の画像の一行 `![](img:<id>)` | 独自の印 `[[img:<id>]]` | **A**。素の文字のまま、ほかのアプリでも「画像の行」と分かり、書き出しの md では行き先を差し替えるだけ |

**選ばない案**：ノートの入れ物に棚を足す（版1→2）。古い版（iPhone に残る前の版）は版1で開こうとして
`VersionError` になり、ノートが一冊も開けなくなる。後戻りできないので移行と同じに扱う——**とらない**。

## 決めたこと

1. 画像は別の入れ物に置き、ノートの本文には参照の一行だけを書く。ノートの形（`shape`）・版・noteBook（`v:1`）は変えない。
2. 画像を先に書き、書けたと分かってから本文に参照を入れる。「参照はあるのに画像がどこにも無い」瞬間を作らない
   （逆の「画像だけある」は、下の消え方が拾う）。
3. 参照が指す画像が見つからなくても、本文の行は消さない・書き換えない（橋と同じ。画像は同じ id で戻ってくる）。
4. 画像は端末の中の元。端末の外の控えは Dropbox（と人が読む zip）だけ。

## データ

### 入れ物 `kaimono-note-images`（新・版1の決め打ち）

`idb.js` は使わない（版を上げる作りなので。鳴らす役の入れ物と同じ理由）。棚は二つ：

| 棚 | 一件 | 書く人 |
|---|---|---|
| `img {keyPath:"id"}` | `{id, type:"image/jpeg", w, h, at, bytes: ArrayBuffer}` | 貼るとき一度だけ。以後は変えない（消すときだけ） |
| `meta {keyPath:"k"}` | `k:"sent"`（Dropbox へ送れた id の列）・`k:"orphan"`（参照が無くなった id → 初めて見た時刻） | 送ったあと・掃除のとき |

- `bytes` は Blob でなく ArrayBuffer（古い iOS の Blob の不具合を避ける。読むときに Blob にして `URL.createObjectURL`）。
- id は**縮めたあとの中身の SHA-256 の頭16字**。同じ画像は同じ id＝二度貼っても一件、Dropbox の名前が決まり、
  控えから戻しても食い違わない。
- 読むのは開いたノートが参照するものだけ（一覧・起動時に全部は読まない）。起動時に開くのは入れ物だけ。
- 入れ物が使えない・開けない日：画像の道具を出さない。参照の行は枠だけ（下の画面）。本文の保存には関わらない。

### 参照（本文の中）

- 一行に一つだけ：行頭から `![](img:<16字の16進>)`、ほかの字を同じ行に置かない。それ以外の形は素の文字として読む
  （利用者が打った `![...](http...)` を画像にしない＝外へ fetch しない）。
- `note-format.js`：読むときはその行を画像に。`plain` は画像の行を空にする（`headOf`・カードの冒頭・検索が
  `![](img:…)` を拾わない）。打ったまま保存する・行頭を削らない決めごとはそのまま。

### 容量（論点3の理由）

- 自動の控えは毎回まるごと（約62件）で、1件あたり約97万字（`BUDGET_IDB_MAX` 6,000万字÷62）を越えると細かい控えから
  間引かれる。base64 の画像は1枚 約35〜60万字なので、**2〜3枚で記録とノートの控えが押し出される**。入れない。
- Dropbox の日付の控え（30＋月の背骨12）も毎回まるごと。JSON に入れると全部の画像が約42回重なり、毎回送り直す。
  別ファイルにすれば一枚一度。Dropbox の無料枠2GBで、450KB なら約4,000枚。
- R26（元の枠150万字の目安）には効かない：画像は localStorage にも記録にも入らない。設定の「iPhone の枠の約◯割」も
  変わらない（あれは元の枠）。

### 消え方（論点4）

- ノートを最近削除へ：画像はそのまま（ノートを戻せば出る）。
- 本文から画像の行を消した：前の版（30まで）が参照を持つあいだは残る＝「この版に戻す」で画像も戻る。
- 掃除（開いたとき一度）：参照を数えるのは、すべてのノート（最近削除も）の本文と、すべての前の版（meta `ver:*`）。
  どこにも出てこない画像に `orphan` の時刻を付け、30日たっても出てこなければ消す。また出てきたら印を外す。
  つまり本当に消えるのは、ノートが30日で消えて（`purge`）さらに30日、早くても60日後。
- **掃除をしない日**：ノートか画像の入れ物が `on` でない・前の版を読めなかった・ノートが0件・
  `backup.doubt()` がノートの減りを言っている（入れ物が消えて控えを合わせる前に、画像が全部「参照なし」に
  見えるので）。印を付けるだけで、消すのは30日あと。
- Dropbox の画像は消さない（送るだけの片道。下の「やらないこと」）。

### 容量不足（論点5）

- 書く前に `navigator.storage.estimate()`：残り（quota − usage）が「画像の大きさ＋控えの上限（`backup.budgetIdb`）の
  2倍」より少なければ書かずに「画像を保存できませんでした」。`estimate` の無い端末は、書いて落ちたら同じ一言。
- 落ちても本文は書ける（入れ物が別）。ほかのデータを消して場所を空けることはしない（`makeRoom` は今のまま）。

## 画面（最小。言葉は要る一言だけ）

- 書く紙の道具の帯に画像の絵（Phosphor の `image` を `icon("image")` として足す。描き方は docs/icons-drawing.md）。
  押した流れで `<input type="file" accept="image/*" multiple>` を click（iOS はカメラ・写真を選ばせる）。
- 選んだら縮め（`createImageBitmap` か Image → canvas → `toBlob`。向きは端末が直す）→ 書く → カーソルの行の下に
  参照の行。書いている途中は帯の絵を薄くするだけ（字は出さない）。
- 読むとき：幅いっぱい・角丸の画像。押すと黒地の一枚で全体（`KN.ui.sheet`、払って閉じる）。
- 書くとき：参照の行は印のまま見える（段4の「書くときは印」）。消すのは行を消すだけ。
- 画像が見つからない・入れ物が開かない：同じ比の灰色の枠に絵だけ（字は出さない）。行は残る。
- 一覧のカード・検索・ぜんぶをさがすには出さない。

## 書き出し・控え・Dropbox

- 「バックアップを保存」・自動の控え：今のまま（本文に参照の文字が入るだけ）。
- ノートの書き出し：1件ずつ（zip）に `images/<id>.jpg` を同梱し、md の参照を相対の道（ノートブックのフォルダからは
  `../images/<id>.jpg`）へ差し替える。1つにまとめる（md）は画像を入れず、参照の行は打ったまま。
- Dropbox：JSON を送ったあと、`sent` に無い画像を一枚ずつ `images/<id>.jpg`（`mode:"add"`）。同じ名前が
  あれば送れた扱い。落ちたら次の回。JSON の「前と同じなら送らない」には入れない（画像は id が名前なので
  変わらない）。止める門は JSON と同じ（`lost` の `held` のときも、上書きしない形なので送ってよい）。
- Dropbox の控えから戻す（B2）：ノートを合わせたあと、参照があって手元に無い画像だけ `images/<id>.jpg` を読み、
  中身の SHA-256 が名前と合うものだけ書く。`dropbox.download` が読む名前の形に三つめを足す。

## 旧データ（移行なし）

- 記録・ノートの形・ノートの入れ物と版・noteBook・自動の控え・`idb.js` の入れ物は変えない。今のノートは一文字も変わらない。
- 新しい入れ物は作るだけ。無ければ「画像は0枚」。
- 古い版（iPhone に残る前の版）：参照の行はただの文字として見え、そのまま保存・書き出し・合わせられる。
  画像の入れ物は知らないので触らない（掃除もしない）。
- 段5より前の書き出し・控えから戻す：参照が無いので何も起きない。

## 壊れないことの確かめ

理屈は三つ。画像は別の入れ物で、本文は参照の文字しか持たない——画像の側で何が起きても、ノートの本文・記録・
控えは今と同じ道を通る。画像は先に書き、書けてから参照（逆は掃除が拾う）。見つからなくても参照は消さず、
画像は60日より早く消えない。

| 場面 | 画像と参照 |
|---|---|
| 画像を書けない（容量・入れ物が開かない） | 参照を入れない。一言だけ。本文は書ける |
| 画像は書けたが、本文の保存に失敗 | 画像だけ残り、参照が無いので掃除が60日で拾う。本文は今の失敗の扱いのまま |
| 本文から画像の行を消す → 元に戻す・前の版に戻す | 前の版が参照を持つので画像は残っている |
| ノートを最近削除へ → 戻す | 画像はそのまま |
| ノートが30日で消える（`purge`） | 画像は印を付けられ、さらに30日。そのあいだに控えから合わせれば参照が戻り、印が外れる |
| 空のまま閉じた新しいノート（`drop`） | 画像を貼ったノートは本文に参照があるので空ではない＝消えない |
| ノートの入れ物だけが消えた日（B4） | `doubt` のあいだ掃除をしない。控えのノートを合わせれば参照が戻る |
| 画像の入れ物だけが消えた日 | 参照は残り、枠で出る。Dropbox の控えから戻すと、手元に無い画像を読み直す |
| 「バックアップを保存」→ 同じ端末で復元 | 本文の参照が戻り、画像は手元にある |
| ファイルを新しい端末で復元 | 参照は残り、枠で出る。Dropbox の控えから戻せば画像も戻る（ファイルだけでは戻らない——下の論点） |
| 自動の控えから戻す | 本文を合わせる。画像は控えに無いが、手元のものを指す |
| Dropbox へ送る | JSON は今と同じ中身・同じハッシュ。画像は別ファイルで一度だけ。上書きしない |
| 同じ画像を二度貼る | 同じ id・一件。二つの参照 |
| 記録の写し（live-idb）・日記の写し・点検（B4） | 触らない（画像は記録にもノートの数にも入らない） |
| 枠が残り少ない | 画像を断る。控え・写しの書く場所を残す |
| 古い版で開く | 参照は文字。画像の入れ物に触らない |

## 試験

新しい台本 `tests/note-images.js`（`open()` を使う。書き方は tests/README.md。画像は台本の中で canvas から作る）：

1. 貼る：大きな画像（4000×3000）が長辺1600に縮み、入れ物に一件、本文に参照の一行。読むときに画像が出る
2. 順序：画像の書き込みを落とすと、本文に参照が入らない・一言だけ
3. 同じ画像を二度 → 一件。ノートの形（`shape` の欄）・noteBook の `v` が変わらない
4. 本文から行を消す → 前の版に戻す → 画像が出る
5. 掃除：参照の無い画像に印 → 時計を30日進めて開き直す → 消える。途中で参照が戻れば印が外れる
6. 掃除をしない日：ノートの入れ物を塞ぐ・ノート0件・`doubt` のとき、画像が消えない
7. 見つからない：画像を消して開く → 枠、本文の文字は同じ
8. 容量：`estimate` を小さく返すと断る。`IDBObjectStore.prototype.put` を投げさせても本文は書ける
9. 画像の入れ物が開かない日：道具の絵が無い・ノートは書ける
10. 書き出し：zip に `images/<id>.jpg` と相対の参照。まとめる md は参照の行のまま
11. Dropbox（fetch を差し替え）：JSON は前と同じ中身、画像は一度だけ、二回目は送らない。戻すと手元に無い画像を読む・
    名前とハッシュが違うものは書かない
12. `plain`・検索・カードの冒頭が `![](img:…)` を出さない。`![](http…)` は画像にならず fetch もしない
13. 古い形：段5より前のノートは読み込みの前後で同じ文字列。版1の入れ物の版が上がらない

回す既存：`notes.js`・`note-v19.js`・`notes-format.js`・`note-typing.js`・`notes-restore.js`・`notes-settings.js`・
`dropbox.js`・`backup-budget.js`・`break.js`・`csp.js`・`update-path.js`・`daily-rules.js`。共通の部品（`sw.js`）を
触るので最後に `run-all.js`（裏で）。

## やらないこと（いまは）

- 画像を「バックアップを保存」のファイルに入れる（ファイルだけで新しい端末へ画像を戻す道は無い。Dropbox が要る）
- 自動の控えに画像を入れる
- Dropbox の画像を消す・二台で画像を合わせる
- 切り抜き・回転・書き込み・並べ替え・一行に二枚・題の横の小さな絵・一覧のカードの絵
- PDF・動画・音・ほかのファイル
- 取り込み（Evernote の `.enex` の画像を含む）
