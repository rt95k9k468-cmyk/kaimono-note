## 3. 方針（前の五つの柱に足す二つ）

### 柱6 止まっているものを、先に動かす

作りかけ・確かめかけを残したまま新しいものを足すと、どれが動いているのか分からなく
なる。**R30（写真から推定）を最初に**済ませる。

### 柱7 出している事実を、正しくする

くらしノートが出すのは、入れた値段や記録そのもの。だからこそ、**事実が場面ごとに
違う意味を持つとき**（特売の値段、元の暦にある予定）は、混ぜずに分けて持つ。

- いま実際に起きていること：特売で ¥198 と記録し、翌週に通常の ¥248 を入れると、
  「気づいたこと」が**「値上がり」を注意の色で**出す（`js/insights.js` の `priceMoves`。
  同じ店の、一つ前の値段と比べるため）。王冠（最安）も、一度きりの特売の店へ行く。

### 段10 止まっているもの

**R30 写真から推定を動かし終える**
- なぜ：2026年の食事記録は、写真一枚で一食が当たり前になった（2節）。くらしノートの
  画面と窓口の見本は済んでいて、止まっているのは Cloudflare の**道の一致**だけ
  （improvements.md の「19 の続き」）。利用者は Anthropic のクレジットをもう買っている。
- 利用者がすること：「19 の続き」の再開の4手（道を Rotate に貼る → Deploy → Safari で
  `{"ok":true,…}` → アプリに完成形の URL を貼って「確かめる」）。
- セッションですること（小さく）：
  - 窓口の道の比べ方を見直す。`ai/worker.js` は `url.pathname !== env.AI_PATH` の完全一致。
    いまの形の確かめ（`/^\/\S{8,}$/`）は空白・改行ははじくが、**ゼロ幅の空白などは
    通してしまう**。貼るときに混ざる見えない字を、比べる前に両側で落とす案。
    `main` への push で Cloudflare が組み直すので、利用者の置き直しは要らない（「19 の続き」）。
  - アプリの「確かめる」の失敗の言い方を、返ってきた状態ごとに分ける
    （時間切れ／`not found`／500）。いまの言い方はコードで確かめてから決める。
  - iPhone で 19 が通ったら、improvements.md の 19 を ◯ に。
- 厳密に言うと：費用は写真一枚で数円（README の目安。実測ではない）。Console で月の上限額を

### 段11 事実の質

**R32 長いノートの見出しへ飛ぶ**
- なぜ：Apple メモ（iOS 27）が節へのリンクを入れた。長いノートは、送って探すのが手間。
- 何を：見出し（`# ` `## ` `### `）が三つ以上あるノートだけ、「⋯」の小窓に見出しの
  並びを出す。押すと、読むときの姿（`.note-view`）のその見出しへ送る。送る器は
  `scrollerOf()`（docs/traps.md）。
- 保存の形は変えない（本文の印を読むだけ。`note-format.js` の `HEAD`）。
- 試験：`tests/notes-format.js` に、見出し三つで出る・二つで出ない・押すと見出しが紙の
  上に来る、を足す。

**R33 特売の印**（X7 の答え次第）
- なぜ：3節の柱7のとおり、特売の値段が「いつもの値段」に混ざると、王冠と「値上がり」が
  事実と違う向きを言う。価格帳アプリは特売と通常の値段を分けて持つ。
  品物のメモの例にも「特売のとき」がある（`product-sheet.js`）。
- 何を：
  - 値段を入れる紙に「特売」の切り替え（既定はオフ）。
  - 特売の値段は**記録にも推移のグラフにも残す**（消さない・隠さない）。ただし、
    **王冠（最安の店）・1個あたりの比べ・「値上がり／値下がり」には使わない**。
    `priceMoves` は「一つ前の**通常の**値段」と比べる。
  - 行に出すのは事実だけ（特売の値段に小さな印）。説明の文は書かない。
- データ：値段の記録に `sale: true` を足す。無ければ通常（今までの記録は全部そのまま
  通常として読む。移行なし）。復元・点検（`audit.js`）・書き出しが新しい鍵を落とさないか、
  試験で見る。
- 厳密に言うと：「特売のときだけ買う」品物では、通常の値段が一度も無い。そのときは
  特売の値段で比べる（何も言わないより、事実を言うほうがよい）。

### 段12 入口と時間割

**R34 声で食事を入れる**（X8 の答え次第）
- なぜ：食事の記録は、手間と気の重さでやめられやすい（7節の Cordeiro）。声の入口は
  もうある（Siri の受け箱。R5）のに、行き先がやること・買うものだけ
  （`capture.js` の `dest` は `todo` と `list`）。
- 何を：頭が「朝・昼・夜・間食」なら食事の枠へ。その日の、その枠の書く欄に書き足す
  （10月4日の「その場で書く欄」の形のまま）。行き先の札（R4）で言い直せる。
- 中継所の置き直しは要らない（振り分けはアプリの中）。
- データ：なし（いまの食事の記録に書く）。
- 厳密に言うと：「昼 銀行」はやること。食べもの・飲みものの言葉（絵の辞書 `findKey`
  の食べものの仲間）が続くときだけ食事にする。迷えばやること（いまのまま）。

**R35 端末のカレンダーの予定を、時間割に重ねる**（X6 の答え次第。大）
- なぜ：TimeTree（1月）や Structured は、ほかの暦の予定を自分の一日に重ねる。
  くらしノートは .ics で「出す」だけ（D3）で、iPhone のカレンダーにある予定は時間割に
  出ない。だから空いて見える時刻に、用事を置いてしまう。
- 何を：ショートカット（「カレンダーの予定を探す」今日から14日ぶん）→ 中継所の新しい棚
  → アプリが覗いたときに読み、時間割に**薄い丸薬**で重ねる。済ませる・運ぶはできない
  （元はカレンダーにある）。
- データ：store の外の鍵に、毎回まるごと置き換えで持つ（`kaimono-note-errors` と同じ
  扱い）。バックアップには入れない（元はカレンダーにある）。daily には出さない
  （daily は写さず引く。カレンダーの予定は、くらしノートの記録ではない）。
- 中継所の置き直しが要る。**予定が端末の外（Cloudflare）を通る**ので、D1 と同じく
  **時刻と長さだけ**（題は送らない＝「予定あり」の塊）から始めるのがおすすめ。
- 厳密に言うと：PWA はカレンダーを直接読めない（roadmap.md 2-3）。URL でホーム画面の
  アプリへ渡す道も、Safari が開いてしまうので使えない（improvements.md の D3）。
  残る橋は中継所だけ。

## 6. やらないこと（今回の調べで新しく出たもの）

| やらないこと | 理由 |
|---|---|
| AI の週のふりかえり・献立の提案（あすけん） | 採点と提案。「言える事実だけ」 |
| 気分や体調を、つまみで数に（Daylio の Scales） | つけた数は点数として読まれる。daily は評価しない |
| 賞味期限の管理 | 書く手間と知らせが増える。そろそろ切れそう（D6）で足りている |
| 店の外から値段を取ってくる | 通信と費用。出す数字は、入れた値段そのもの |
| 外の AI にノートを読ませる口（Bear の MCP） | 日記と同じ（roadmap.md の X3） |
| 大きいファイルを分けるだけの作業（`screen-todo.js` 約5,500行ほか） | 分けるときに読み込み順・TDZ・3か所の登録を踏みやすい。読むのは節ごとで足りている。触るついでに（E4 のまま） |
