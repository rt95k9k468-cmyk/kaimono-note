ここからは見えないので、数字は docs・コード・設定に出る一文から。次に点検するときは、

## 守り（堅牢さ・消失を防ぐ仕組み）

二度の消失（9月の TDZ で空を書いた件・10月6日に localStorage だけ落ちた件）の形は、どちらも
いまは**訊かずに戻る**。一か所だけ消える分には黙って戻り、端末ごと失っても外から戻せる。

1. **書くたびの写し**：元と同じ文字列を大きな保存場所へ（1秒に一度まで）。開いたとき元が無い・
   古ければ写しを元へ。元が書けなかった日（容量）も写しには書く。
2. **日記の写し**：開くたびに突き合わせ、写しの行は消さない。
3. **自動の控え**：開いているあいだ一時間おき。直近2日は一時間おきのまま、14日までは一日一つ。
   決めて変える直前（復元・すべて削除・大きく減る前・日記を外す前・取り込み前など）は間引かない。
4. **見張り**：元を書く直前に「使っているうちに消えた」「一度に大きく減った」を見て、減る前を控えに。
   開いたとき元・写し・控えの数を比べ、食い違えば設定の頭に一行。
5. **端末の外**：Dropbox は中身が変わったときだけ送る。外の控えが14日古い（Dropbox が送れない
   まま3日）と、歯車に点。
6. **消さない約束**（`navigator.storage.persist()`）を開くたびに頼む。
7. **開いた記録**：開くたびの元・写しの数と番号、約束の有無、使用量。次に消えたときの手がかり。
8. **試験**：壊し方を一本にした `tests/break.js`・復元・立ち上げ・CSP などが、push のたびに門で回る。

## 残りの容量

- 決め手は**元（localStorage）の枠**：iPhone でおよそ5MB＝日本語で約260万字（目安。正確な値は
  端末も教えない）。記録はここへ毎回まるごと書くので、ここが先に尽きる。
- 分かっている最後の本物の数字：**2026年9月29日、記録は約50万字（枠の約2割）**。
- いまの数字：設定 → バックアップの使用量の一文（「iPhone の枠（約260万字）の約◯割」）。6割を
  越えると「記録が大きくなってきました」。

| 記録の大きさ | 起きること |
|---|---|
| 150万字（枠の約6割） | R26（記録を軽くする）を始める目安 |
| 200万字 | 日記の取り込みを断る（`DIARY_LIVE_LIMIT`） |
| 約260万字 | 元が書けず、保存の失敗になる（写しには残るが、元へ戻せない） |

- 大きな保存場所（IndexedDB）の枠は端末の空きに合わせて大きい（Safari 17 以降。WebKit の
  「Updates to Storage Policy」）。控えの上限はアプリの決めで2,000万字。ただし控えは毎回まるごと
  なので、**1件が約32万字を越えると段（約62件）の全部は入らず**、細かいほう（一時間おき）から
  間引かれる。約50万字なら40件ほど。一日一つの背骨と間引かない控えは残る。
  - 訂正（同日）：設定の「◯件まで」は、入る件数が14件を割ったとき（約143万字〜）だけ出る。
    50万字では、出ないまま間引かれていた。→ 案B を入れ、上限を記録の大きさに合わせて広げた
    （約97万字まで段が全部入る。下の表）。
- 伸び方：日記が年を重ねると効く（docs の見積もりで3年ぶん約285万字＝枠越え）。日記を記録から
  外す（設定 → バックアップ →「日記を記録から外す」）と、元の伸びはずっと小さくなる。

## 消失を防ぐために、利用者ができること

1. **週に一度、書き出しを iCloud Drive へ**：7日たつと「週に一度の控え」のトーストが出る（10月8日から）。
   「保存」→「ファイルに保存」→ iCloud Drive。Dropbox と別の場所に、30日を越えて残る控えができる（いちばん効く）。
2. **ときどき見る**：同じ画面の「記録の写し：◯月◯日 ◯:◯◯の状態」が今日か。歯車に点が出たら書き出す。
3. **次の前は必ず書き出す**：アイコンを消す・入れ直す／機種変更・初期化・iOS の大きな更新／
   GitHub のユーザー名を変える・独自ドメインにする。
4. **Safari で開かない**：同じ住所でも、ホーム画面のアプリとは別の保存場所（空に見える）。そこで
   書かない・Dropbox をつながない。
5. **iPhone の空きを残す**：足りなくなると、端末がサイトの保存を消すことがある（消さない約束で
   外れる決まりだが、念のため）。
6. 何か消えたら、まず設定 → 一般 →「困ったときの記録」をコピーして貼る。

無くても読める）・記録の点検（設定 → バックアップ →「記録を点検する」）・R26 の見直しの時期。

**足すと良いもの（案。決めてもらう）**：

| 案 | 中身 | 効くこと | 大きさ | 移行 |

## 制限の節約（Claude Code の読み方）の点検

- リポジトリは約14MB（写真4.2MB・コード3.5MB・docs 1.2MB・履歴9MB）。**制限を使うのは、読んだ・
  探して出た分だけ**。写真・履歴・開かないファイルは0。だから消す・動かすは効かず、参照
  （二十数か所）を壊すほうが高い。動かしていない。
- 当たると重いのは一行が巨大なファイル → `.ignore` 済み（pdf.js・`relay-code.js`・絵の生データ）。
  ほかに数千字の行を持つファイルは無い（2026年10月8日に全部測った）。
- docs の節はどれも2万字以下。見出しから節だけ読めば足りる。
- 残る大物は、頭から開くと2,000行が載る `.js`（`store.js` 約4,800行・`screen-todo.js` 約6,000行・
  `screen-diet.js` 約5,000行）と `tests/INDEX.md`（約3万字）。→ CLAUDE.md の行の中に「grep で引いて
  前後だけ」を足した（行は増やしていない）。理由は docs/dev.md。
- いちばん効くのは読み方より**会話の長さ**（1ターンごとに前の文脈を読み直す）。一つの話題で
  一つのセッション（docs/dev.md「セッションの区切り」）。
