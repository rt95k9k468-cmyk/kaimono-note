# 下の帯（押してふくらむ・席の印・外したレンズ）

本文は移す前と一字も変えていない。入口（どの docs を読むか）と、どの画面でも

### 帯を押しているあいだ、その席がふくらむ

**一度だけ出る絵では、「まだ押している」を言えない。**

ここは二度作り直している。はじめは中心から広がる閃光（**波紋**。Android の
作法で、ガラスの言い方ではない——ガラスは波紋を出さない）、次がその作り直しで、
押したところに窪みが立ち上がって戻る `tab-dimple`。**絵としてはそこまで来て
いた**。それでも直っていなかったのは、絵の中身ではなく**時計を誰が持っているか**
のほう——0.46秒で終わるので、長く押しても、押したまま指を滑らせても、絵はもう
終わっている。指はまだそこに居るのに、画面のほうが先に離れている。**指と絵が
切れている**、というのが紙の節（「紙は、指につく」）で三つとも同じ形で直した
ことで、帯にも同じものが残っていた、というだけ。

だから**動きではなく状態**にした。押しているあいだ膨らんだまま、離すと戻る。
**時計を持っているのは指のほう。**

- **膨らむのは二段。** 席ぜんぶ（`.tab`、1.09倍）と、その中の選択カプセル
  （`.tab-ico`、さらに 1.05倍＝合わせて **1.14倍**）。押されているのは「絵」
  ではなく**その席**なので、絵・字・点がまとまりごと動く。カプセルが席より
  わずかに大きく膨らむぶんで、**カプセルが押されている**と読める
  （実測：40×26px → **45.8×29.8px**）。
- **倍率は `scale:` 独立プロパティで書くこと。`transform` ではない。**
  `.tab-ico` の `transform` は選ばれている印（`translateY(-1px)`）が使って
  いて、しかも `.tab[aria-selected="true"] .tab-ico` と `.tab.is-held .tab-ico`
  は**詳細度が同じ**（0,3,0）——同じプロパティに書くと、あとに書いたほうだけが
  効いて、「選ばれている席では膨らまない」か「選ばれていない席が 1px 落ちる」
  のどちらかになる（時間割の `is-clash-above` とまったく同じ踏み方）。
  `scale:` は `transform` と**掛け算で重なる別のプロパティ**なので、二つは
  取り合わない。
- **行きと帰りで速さを分ける**（class の付け外しで分ける、動きの節の決めごと）。
  行きは `--m-press` を `--ease-out`（指に遅れない）、帰りは `--m-state` を
  `--spring`（わずかに行き過ぎてから収まるのが、離した手ごたえ）。
- **押しているあいだ、ガラスは光を集める**（`.tab-hold`）。膨らむだけだと、
  ガラスではなく**絵を拡大した**ように見える。指の下（`--gx` / `--gy`）に
  うすい光を**置いたままにする**——広がるのが波紋、その場に居るのが変形。
  **タブごとに分けない**（カプセルは一枚のガラスなので、分けると隣との境目で
  光が四角く切れる）。`--gx/--gy` に transition は置かない——遅れて追うと、
  そこでまた指と絵が切れる。
- **光は、カプセルに収まる楕円にすること。** 閃光の名残で 132px の丸を置いて
  いたら、60px のカプセルの中で上下が切り落とされて**まっすぐな縁**になり、
  左右は隣の席まで届いた（実測：押した席の左右に一つずつ、**三席ぶん**が
  染まった——絵としては「光」ではなく染み）。一席ぶんの幅に合わせて 96×46px。
  濃さも落とす（白 .62 → **.20**、主色 18% → **7%**）——一度きりなら強くても
  消えるが、**居座るもの**が同じ濃さだと、そこだけ染みに見える。言いたいのは
  「ここに光が寄った」で、「ここが光っている」ではない。
- **指が席から外れたら、いったん戻す。離さずに戻れば、また膨らむ。**
  押した席の外で離してもタブは変わらない（`click` は押したところと離した
  ところが同じでなければ出ない）ので、膨らんだままだと「ここへ行く」という
  嘘になる。行き先を言うのは**指の居場所**で、最初に触れた場所ではない。
- **見張りは `document`。** `pointerdown` は帯で拾えるが、離す指は帯の外に
  居ることがある（マウスで押したまま外へ出る）。帯だけで見ていると
  `pointerup` が降りてこず、**膨らんだまま戻らない席**が残る
  （`reorder.js` / `day-swipe.js` と同じ理由・同じ手）。`pointercancel` も
  同じところへ帰す（iOS の長押しメニュー、着信）。
- **`.tabbar .tab { touch-action: none }` が要る。** 無いと、押したまま指を
  動かした瞬間にブラウザが「送るつもりだな」と判断して `pointercancel` を
  投げ、以後の `pointermove` も `pointerup` も来ない——実測で、隣の席へ
  滑らせたところで見張りが黙り、**離さずに戻っても膨らみ直さなかった**
  （光も指についてこなかった）。帯は送る面ではないので、渡すものは何もない。
  **詳細度を上げること**——`.tab` だけだと `components.css` の
  `button, [role="tab"], …{ touch-action: manipulation }` と同じ（0,1,0）で、
  あちらが後ろに読み込まれるぶん勝つ（実測で `manipulation` のままだった。
  `manipulation` は送りを許すので、指が滑った瞬間に持っていかれる）。
- **動きを減らす設定では膨らませない**（倍率を 1 に戻すだけ）。`is-held` の
  行そのものは残すので、光は静かな状態変化としてそのまま出る——押した
  手ごたえがまるごと消えるほうが不親切なので。
- **二段目の膨らみ（`--hold-c`）は、いま居る席では「印の一枚」が受け持つ**
  （次の節）。`.tab-ico` の行はそのまま残してあるが、あそこはもう地を
  持っていないので、膨らんで見えるのは印のほう。押しているのが別の席なら、
  印は動かない——そこはまだ行き先ではないので。

### いま居る席の印は、席から席へ滑る一枚（`js/tab-lens.js`）

印は長いあいだ**席ごとの小さな丸**だった（`.tab-ico` 40×26px に
`--c-primary-soft`）。席を移ると前の丸が消えて次の丸が出る——**動いたものは
何もなかった。** いまは一枚だけあって、席から席へ滑る。

**大きさも席ぜんぶに広げた**（70×48px ＝ 絵と名前の両方が入る丸薬。参考画面
Structured の実測 75×53px／カプセル 70px ＝ 0.757 を、この帯の丈 64px へ
写した数）。小さな丸が絵の後ろにだけあったころは、「いまここ」が**絵の
持ちもの**に見えて、席の持ちものに見えていなかった。

- **`.tab-ico` はもう地を持たない。** `background` をここに戻すと、印の下に
  もう一枚の丸が出る——滑っているあいだ、置いてきたほうの席に丸が残る。
  持ち上げ（`translateY(-1px)`）と押しているあいだの倍率はそのまま。
- **席の絵と字の後ろにいる**（印が z-index 0、席が 1）。印は地であって、
  字の上に乗るものではない。
- **席の箱は `offsetLeft` / `offsetWidth` で測る。`getBoundingClientRect`
  ではない。** あれは transform のかかったあとの箱を返すが、印が動き出すのは
  指が席を押した直後——`.tab.is-held` の 1.09倍がまだ掛かっている最中。
  実測で行き先の席が 75.5px ではなく **76.2px** と返り、着地のたびに印が
  わずかに太って、指を離したあと縮んだ（「押すと横に伸びる丸薬」に見えた）。
- **滑る長さと曲線は `KN.motion.glide`。** タップには「離したときの速さ」が
  無いので、glide はそのとき**道のりの割合**で答える——隣の席へは短く、端から
  端へは長く（実測：端から端で 151ms）。決め打ちの一つの数で送ると、その二つが
  同じ時間になる。
- **長さは `--lens-ms` へ書き、`transition` の宣言は CSS に置く**（どこが
  どう動くかは CSS が持つ、という決めごと。`cal-peek` の `--cal-ms` と同じ手）。
  **既定は `0ms` ＝ 跳ぶ**なので、組み直し・回転・キーボードで置きなおすときは
  何も渡さなくていい。滑り終わったら 0ms へ戻すこと——戻さないと、次に幅が
  変わったときの置きなおしまで滑って見える。
- **滑りと膨らみは、一本の `transition` に並べる。** 別々の規則に分けると、
  二つが重なったとき**あとに書いたほうだけ**が効いて、もう片方が跳ぶ
  （`.tab-ico` の `transform` で一度踏んだ、同じ詳細度どうしの取り合い）。
  膨らみは `scale:` の独立プロパティで書くこと——`transform` は位置に
  使っている。
- **印は「カプセルの形をしているもの」四つに入らない。** あれは帯いっぱいに
  広がっていて＋の手前で終わらせる必要があるもの（地・縁の光・縁の屈折・
  押した光）。印は席一つぶんで、位置も大きさも JS が席の箱から測って書くので、
  ＋のぶんはすでに入っている（席がそのぶん狭い）。`.has-fab` の一か所に
  足すと、`right` と `transform` が取り合って行き先がずれる。
- **二段目の膨らみ（`--hold-c`）は、いま居る席ではこの一枚が受け持つ。**
  押しているのが別の席なら、印は動かない——そこはまだ行き先ではないので。
- **`.is-on-dark` では、印の地も夜へ返すこと。** 明るい面の
  `--c-primary-soft` は `#fdeceb` ＝ ほとんど白の桜色。帯が夜になると
  選ばれている席の字は**白を38%混ぜた薄いコーラル**へ振られるので、その字が
  白い丸薬の上に乗る——実測 **1.9:1** で読めなかった。基調色から出した暗い地
  （`color-mix(in srgb, var(--c-primary) 30%, #1a1a20)`）へ返して **5.01:1**。
  **`#3a201f` のような決め打ちに戻さないこと**（暗い面のテーマが持っている値
  だが、基調色を変えている人の帯だけ色が外れる。`--c-primary` を上書きしては
  いけないのと同じ理由。実測で7色ぶん、地が基調色についてくることを確認済み）。
  - **これは印が席ぜんぶを覆うようになって、はじめて出た。** 小さな丸だった
    ころ、丸は絵の後ろにあるだけで名前は帯の地の上に乗っていた——字と丸が
    重ならないので、丸が明るいままでも困らなかった。
  - 明るい面の 4.15:1（`--c-primary` が `--c-primary-soft` の上）は前からの
    ままで、**色の節の「未決」**（基調色そのものを濃くするかどうか）と同じ話。

#### 席の印を歪ませるレンズは、試して外した

参考画面（Structured）の印は**ガラスのレンズ**で、滑っているあいだ**帯自身の
字を曲げる**（後ろのページではなく、帯に載っている絵と名前のほうを）。動画を
実測して、一度**そのとおりに作った**——そして**採らなかった**。絵としては
届いていたが、**この帯が言いたいことに対して、仕掛けが重すぎた**。
残したのは、印が席ぜんぶを覆う薄い色の丸薬であることと、滑ること、押している
あいだ膨らむこと——動画を見て良いと思ったのは、結局そこだった。

**復活させるなら、ここから始めること**（全部、一度通った道）：

- **実測**（動画 1284×2776＝3倍・60fps・356コマ。3で割った CSS px）：
  休みは **75×53px の丸薬**（地 233／帯の白 253）、滑ると **77×71px の
  ほぼ丸**（**横幅は変わらない。育つのは丈だけ**で ×1.34）、地は乳白 246・
  縁の輪 232。中身は**真ん中が空**で、字はふちへ押し出されて弧になり、
  進む先に桃・後ろに黄の色ズレ。
- **曲げる相手は自分の DOM。** Safari は `backdrop-filter: url(#…)` を
  受け付けないが（ガラスの節）、`filter: url(#…)` は要素に効く。だから
  印の中に**帯の行の写し**を置いて、写しにフィルタを掛ける。
- **中身がふちへ行く仕掛けは「虫めがね＋ふちの圧縮」。** 出したい点の半径 r に
  対し、引いてくる元の半径 s(r) を、中（r ≤ RC）では `r/MAG` の一様な拡大、
  ふちでは s(1)=1 へ滑らかに戻す。中の拡大率がどこも同じなので**絵の形が
  崩れず**、ふちでは ds/dr が大きいので元の広い輪がせまい輪へ潰れる
  ——角度はそのままなので**弧になる**。地図は canvas で焼いた PNG を
  `feImage` で読み、色ズレは同じ地図で押し出す量だけチャンネルごとに変えて
  三度走らせる。実装値は MAG 1.62・RC 0.34・色ズレ ±5.5%。
  - **一本のべき乗（s(r) = r^3.6）ではない。** 真ん中は空くし字もふちへ行くが、
    あれは**ふちの拡大率が 1/P ＝ 0.28倍**で、字が 1px の輪に潰れる。実測すると
    参考画面の歯車も「設」も**読める大きさのまま**弧になっていた。潰す式と
    拡大して押し出す式は、絵を並べるまで見分けがつかない。
  - **倍率の上限は「中身が外へ出ていかないこと」で決まる。** 席の中身は印と
    ほぼ同じ幅なので、いちばん外の字は r ≒ 0.6。MAG 2.55 だと出口が 1.53 ＝
    **ふちの外**で、席の名前がまるごと消えてかけらだけが貼りついた。
- **`feImage` に x / y / width / height を書かないこと。** 書かなければ
  フィルタの領域いっぱい＝箱ぴったりになる。`width="100%"` と書いた時期が
  あるが、百分率の基準を決めるのは `primitiveUnits`（既定 userSpaceOnUse）で、
  そこでの基準は**地図を入れてある SVG の viewport**——あれは 0×0 なので、
  **100% が 0px** になった。地図が真っ黒＝どこも (0,0) なので、ずらす量は
  `scale × (0 − 0.5)` の一定値、つまり**全体が同じだけ平行移動しただけ**。
  色ズレだけはきれいに出るので**いかにも効いているように見える**
  （一度これで通しかけた）。
- **壊れ方は安全側に。** ①地図の下に「ずらさない灰」（128,128,128）を敷く
  （`feFlood` → `feComposite operator="over"`）——`feImage` が絵を出せなければ
  歪まない札に落ちる。②写しは**元の行とぴったり重なる場所**に置く——ずらすと、
  フィルタの効かない環境で**字が二重になる**。③地図と `scale` は**対で返す**
  ——二か所で計算すると、片方だけ直した日に押し出す量が倍になり、絵は壊れず
  「なぜか効きが弱い」形で出る＝見つけにくい。
- **写しの入れものを `<i>` にするなら `font-style: normal` が要る。**
  `<i>` の既定は斜体なので、写しの中の名前だけが合成斜体で傾く（絵は傾かない
  ので、字だけ斜めという妙な絵になる）。歪んでいる最中は歪みのせいに見えて
  気づかず、**フィルタを殺した試験の絵**——いちばん「ふつうに見えるはず」の
  ところ——で見つかった。
- **重なりの順を入れ替えることになる。** 歪んだ写しで元を覆わないと、歪んで
  いない元が二重に見える。だから滑っているあいだだけ席の絵と字の**前**へ出す
  （休み 0 ／滑り 2）。`--lens-warp` が 0 のところ（滑り出す瞬間と着いた瞬間）は
  地も写しも元のままなので、そこで入れ替えれば跳ねない。
- **地を明るくしないこと。** 実測では中は帯より **7階調暗い**。レンズを
  「そこに在る」と言っているのは地ではなく**縁の輪**（−21）のほう。
  `--glass-cast-lit` の 94% で置いたら帯より **+19** 明るい白い玉になって、
  ガラスではなく「白い風船」に見えた。
- **費用は問題にならなかった**（実測 2026年9月21日・CPU 4倍・390×844）：
  10回滑らせて p50 16.6ms・p90 17.7ms・落ちるフレーム 1／197。歪み無しが
  p90 17.3ms なので**取り分は +0.4ms**。地図は大きさごとに覚えるので焼くのは
  一度だけ（1.2〜2.6ms、初回のみ 8〜11ms）。**外した理由は速さではない。**
- **実機（iOS Safari）では一度も確かめていない。** `feImage`（データURI）と
  `feDisplacementMap` の組み合わせがあちらで効くかは未確認のまま。
- **＋との融合（metaball）は、そのときも見送った。** 参考画面では滑っている
  あいだ＋の左に橙の首が伸びてカプセルと融ける（実測：休んでいるコマには首が
  無い）。作れないわけではないが、あちらの＋は**べた塗りの橙の円盤**で、
  こちらの＋は**ガラス**（`--glass-*` に主色を 12% 差したもの）。融ける首を
  出すには `feGaussianBlur` ＋ アルファを立てる `feColorMatrix` が要り、その手は
  **不透明な塗り**でないと閾値が立たない——つまりカプセルと＋のあいだの、
  ページが透けて見える隙間に、**両側のどちらとも違う不透明な材**を一枚置く
  ことになる。「材は一か所から」と正面からぶつかる。やるなら、先に＋の材の
  ほうを決め直すこと。
