## 2. 重いモデルだけで進める割り方（守4・sync 段3〜5・B2・構7）

1. **案と作るを分ける。** 案のセッションはコードを書かない——変える所・変えない所・試験の場面の表・戻し方を、該当の docs の節へ短く。利用者が読んで決める。
2. **試験を先に。** 作るセッションは、まず落ちる試験を今ある台本に足し、赤を見てから直す。
3. **一棚ずつ。** 同期の段4 は 買うもの → やること → からだ・daily → 日記 を一つ＝一セッション。保存の背骨（B2）も棚ごと。
4. **見直しだけのセッション。** 保存の層に触った段は、main へ流す前に**別の新しいセッション**が差分だけを読む（`git diff origin/main...HEAD`）。
   物差しは `shots/audit-2026-11-16.md` の 3節と docs/storage.md「守りの地図」。直さない・指摘だけ（重い・高）。
5. **effort**：設計と保存は 超高、ほかは 高。最大は使わない。同じ所で試験が二度赤なら止まり、「何・どこまで・なぜ」を一行で利用者へ。

貼るプロンプト：守りは `shots/audit-2026-11-16.md` の「貼るプロンプト」、同期は docs/sync.md、構7 は `shots/vision/stages.md`。
