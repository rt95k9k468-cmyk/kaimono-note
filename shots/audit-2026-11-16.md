## 0. 結論（忖度なし）

**完成度**：毎日使う道具としては完成域。保存の守りは、個人の PWA としては上限に近い厚さ（下の3節）。
「今すぐ記録が消える・漏れる」種類の問題（P0）は**見つからなかった**。
ただし「作り終えて静かに使う段階」にはまだ居ない。11月10日から全面リデザイン、15〜16日に席の組み替え、
配信は1,405回。**いま品質をいちばん揺らしているのはコードの質ではなく、変える速さ**で、実機で確かめる人は一人。

| 面 | 見立て | 根拠 |
|---|---|---|
| 記録の保全 | 強い | 多重の写しと控え・読めなければ書かない・復元は確かめてから。門に壊し方の試験 |
| セキュリティ | 強い（個人用の脅威に対して） | CSP・既定でエスケープ・部屋は端末で暗号・資格情報の混入なし |
| 複数の端末 | 道半ば | 今は「iPhone が主、ほかは写し＋受け箱」。対等な同期は段2（影）まで |
| 保守しやすさ | 中 | 依存ゼロ・ビルドなしは長寿の強み。一方 7,000行級のファイル・docs 1.7万行は AI 前提の作り |
| 試験 | 強い（Chromium では） | 230本。ただし本番は WebKit で、保存の試験は WebKit で回っていない |
| 画面 | 高い（静止画では） | 3つの幅で崩れなし。実機の手ざわりは未確認 |

**致命的になりうる所**（重い順）
1. **元が localStorage 一本**（約5MBの枠・書くたびにまるごと）。年を重ねると枠と重さの両方で詰まる。計画済み（B2）で方針は正しい。

4. **土台がよそのもの**：iOS の PWA の扱い・`github.io` の住所・Dropbox 一か所の外の控え。どれも代わりの道を持っておく。

**維持か、見直しか**：**今の設計を維持して育てるべき。** フレームワーク化・全面書き換え・正本をクラウドへ——はどれも害のほうが大きい。

## 2. 優れている点（維持する設計）

- **読めなければ書かない**（`store.js:710` `rescue`・`loadError`）。過去の消失の形を、仕組みで塞いでいる。
- **元と写しを番号で比べる**（`lsSeq`。`live-idb.js` の `boot`）。置き換える前に、負ける側を控えへ。
- **控えの間引きが丁寧**（`backup.js` の `prune`・`PINNED`・`fullest`）。戻せない操作の直前の控えは間引かない。
- **復元は確かめてから**（`store.js:5213` `readBackup`・`NOT_BACKUP`）。別の種類の .json で全部が置き換わる事故を塞いでいる。
- **Dropbox は空・欠けを送らない**（`dropbox.js:432` `run`：見当たらない日・本文を読めない日・空・送る役でない端末）。
- **知らない欄を残す**（古い版が新しい記録を開いても欄を落とさない）。設定は `reconcile()` で後方互換。
- **画面の守り**：`html` は既定でエスケープ（`util.js:18-39`）、CSP は `script-src 'self'`、リンクは `note:`・`http(s)`・`mailto:` だけ（`note-format.js:51`）。
- **配り方**：中身の印（sha-256）が合うものだけ控える・css/js が一つでも欠けたら入れ替えない（`sw.js:150-181`）。押しは必ず何か出す。
- **同期の部屋**：端末で AES-GCM・名前は HMAC、版で断る、同じ操作は二度当てない、消しすぎを断る、古い約束の版は書けない（`sync/room.mjs`）。
- **実行時の依存がゼロ・ビルドなし・出口は JSON と .md。** 10年もつ作りの第一条件を満たしている。
- 購読は9か所・`setInterval` は5か所で、どれもモジュールに一つ（描き直すたびに積もる型が無い）。
- 資格情報・個人情報のリポジトリへの混入なし（機械で確かめた。出たのは試験の作りものの URL 一つ）。
- 「評価しない」が試験（`daily-rules`）で守られている。思想がコードの決まりになっている。

### 監-1（P1）保存の層の退行が、全部の試験より先に届きうる

- どこ：`tests/run-all.js:31`（`GATE`）・`.claude/ship.js:35`（`gate()`）・CLAUDE.md「流し方」「テスト」。
- 事実：門の約80本に入っている保存の台本は break・restore-drill・restore-practice・unknown-keep・traps・startup・offline・update-path・
  todo-out・todo-past・live-slim・backup-budget・desk-replica・desk-inbox・sync-room・sync-device。
  **入っていない**：live-idb・diary-idb・diary-out・lost-record・dropbox・notes-restore・notes-sync・offdevice-watch・
  backup-notes-only・note-files・inbox-take・siri-inbox・desk-windows・diary-import・diary-lock・lock（16本・合わせて270秒）。
- 条件：保存に関わるファイルを直した段で該当の台本を名指しし忘れる／共通の部品の直しが間接に壊す。
  決まりは「先に main まで流し、全部は裏で」なので、配信のほうが先に終わる。
- 影響：退行に気づくのは裏の全部が赤になってから（見落とせば翌朝3時の毎日の全部）。そのあいだ iPhone は新しい版で書く。
- 直し：`ship.js` が、取りこんだあとの差分に保存の層のファイルがあれば、上の台本を門に自動で足す（守1）。アプリは変えない。

### 監-2（P2）復元の「入りきりません」が、ノートの字数まで数える

- どこ：`js/store.js:5227` `inspectBackup` の `size: JSON.stringify(next).length`。`next` は `reconcile(parsed)` で、
  一番上の `noteBook`（ノート丸ごと）・`exportedAt`・`app` が残ったまま。これを `js/settings-backup.js:375` が 260万字（682行）と比べる。
- 確かめ（試しの記録）：記録 2,226字＋ノート 300万字の控え → `size` は 3,002,367 → 断られる側。
  ノートは localStorage に書かれない（`notes.merge` で別の入れ物へ）ので、数える理由が無い。
- 条件：日記を外していない端末（新しい iPhone・iPad など）で、記録＋ノートが260万字を越える控えを戻す。
- 影響：機種変更・紛失の日に、戻せるはずの控えが断られ、「先に日記を記録から外す」と見当違いの案内が出る。
  儀式をすれば通るので記録は失わないが、いちばん慌てている日の障害になる。
- 直し：大きさは `applyBackup` が元へ戻す欄だけで量る（`…Book`・`exportedAt`・`app`・`lsSeq` を除く）。読むだけの関数の中の一行（守2）。

### 監-3（P2）同じ端末の二つの窓が続けて書くと、片方が消える

- どこ：`js/store.js:1449` `watchBefore` は元の番号が自分より大きいとき `"other"` と記すだけで、`writeLive`（1375行）がそのまま上書きする。
  `js/app.js:1155` `otherWindow` → `reloadHere`（2029行）の読み直しの直前に、pagehide の `flush`（1695行）が古い記憶を丸ごと書く。
- 再現（試しの記録・二つの窓）：窓A が用事を足して保存待ち（120ms）のあいだに、窓B が別の用事を足して書き終える
  → 最後に元に残ったのは A の分だけ。**B の変更は両方の窓から消えた**。開いた記録（journal）にも残らなかった（0件）。
- 条件：同じ端末・同じ保存場所の窓が二つ開いていて、0.5秒ほどのうちに両方が書く。
- 影響：今は起きにくい（iPhone は窓が一つ・写しにしている iPad とパソコンは記録に書かない）。**同期の段4でパソコンが書くようになると現実の道になる**
  （入れたアプリの窓＋ブラウザのタブ）。日記の本文だけは写しが正しい決まりで守られる。ほかの欄は守られない。
- 直し：元の番号が自分より大きく、利用者の選んだ入れ替え（bulk）でないときは**上書きしない**——自分の記憶は控えへ、元を読み直す（守4）。
  保存の心臓部なので、先に案を出して訊く。段4 で三方の合わせができたら「ほかの窓＝もう一台」として合わせる。

### 監-4（P2）端末の外の自動の控えは最長12か月

- どこ：`js/dropbox.js:46-47`（`KEEP = 30`・`MONTHS = 12`）・`keepers`（298行）。端末の中の控えは14日（`backup.js:77`）。
- 影響：一年以上あとに気づいた消失・書き損じは、自動の控えからは戻せない（手の書き出しだけ）。
  ノートには前の版が30あるが（`notes-idb.js:35`）、日記には無い。日記は自動で保存されるので、古い日を読み返していて誤って消した字は、
  12か月を過ぎると戻る先が無い。「人生の記録」としては、ここがいちばん薄い。
- 直し：**年の背骨**——各年で最初の控えを一つ、ずっと残す（`keepers` に数行。一年に一ファイル）。利用者は了承済み（11月16日。守3）。

### 監-5（P2）保存の試験は Chromium だけ

- どこ：`.github/workflows/tests-daily.yml:80` の WebKit の列は見た目の6本（scroll-anchor・fit-fields・typeface・text-size・top-tap・feel-3）。

- 直し：毎日の WebKit の列に break・live-idb・diary-idb・restore-drill・notes-restore・lost-record を「知らせるだけ」で足す（守1 に含める）。

### 監-6（P2・未検証）空の端末で大きい控えを戻す通し

- 事実：`tests/diary-out.js` は「記録のある端末」で、断り → 外す儀式 → 復元を確かめている。空の端末（新しい iPhone）での通しは試験に無い。
  空の端末では、儀式の「書き出して外す」で空の書き出しを保存することになる（`saveBackup` に空の断りは無いので、通るはず——未確認）。
- もう一つ：新しい端末は Dropbox につないだ時点で「送る役ではない」になる（`dropbox.js:359` `role`）。戻したあと
  「この端末から控えを送る」を押すまで、Dropbox へは送られない（設定の頭に「端末の外の控えが、まだありません」は出る）。
- 直し：`restore-drill` に空の端末の通しを足す（まず試験だけ。守2 に含める）。通らなければ直さずに報告。同期の段5 の条件「戻しの稽古」にも使える。

### 監-7〜10（P3）

- **監-7 中継所の KV**（`relay/worker.js:441-455` 受け箱の継ぎ足しと控え・`262`／`308` 鳴らす時刻）：読んで書くので、Siri で続けて足した二通・
  見回りと時刻の送りが重なると、一通が落ちうる（買うものの一行・通知一回。記録は失わない）。直すには利用者の置き直しが要るので急がない。
  受け箱を将来「部屋」（Durable Object は一つずつ処理する）へ移せば消える。
- **監-8 写真**（`js/note-img.js:123`）：`createImageBitmap(file, …)` に大きさの指定が無く、原寸で開いてから縮める。48MP は約190MB。
  iPhone で頁が落ちるかは実機でしか分からない。`resizeWidth`／`resizeHeight` を渡せば展開が小さくなる（守5）。
- **監-9 番号の鍵**（`js/lock.js:45`・`js/store.js:5171-5179`）：PBKDF2 10万回の崩した形が、書き出しと Dropbox の控えに載る（外すのは URL 二つだけ）。
  4〜6桁は総当たりできるので、控えが漏れると番号そのものが分かる。中身は控えに平文であるので番号は要らない——害は「同じ番号をよそでも使っている」場合。
  設計どおり（別の端末へ持っていくため）。README に「iPhone のパスコードと同じ番号にしない」の一行で足りる。
- **監-10**：pdf.js は2024年の同梱（`tools/vendor`）。`isEvalSupported: false`（`note-import.js:313`）と CSP で既知の主な穴は塞がっている——年に一度の更新を。
  Actions は `@v6` など動くタグ・`tests/` に lock なし。権限は読むだけで秘密も渡していないので害は小さい。

## 4. 重点項目ごとの評価
